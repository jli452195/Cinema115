# 转存再分享与 Telegram

在「分享播放 / STRM」页面打开「转存再分享」。开关保存在服务端，网页生成和 Telegram 消息共用；关闭时仍直接使用原分享生成 STRM。

开启后的流程：

1. 读取原分享的完整目录树，在指定的 115 父目录下创建 `Cinema115-临时-随机编号`。
2. 将分享条目转存到新目录。115 可能在顶层目录创建后继续异步转存子文件，必须递归核对所有路径、文件类型和大小一致后才继续。
3. 为完整转存后的条目创建自己的分享，显式设置 `share_duration=-1`（长期），并回读确认。再等待完整快照并逐项核对。
4. 使用新分享的文件 ID 生成 STRM，保持原有目录结构。同名 STRM 替换为新分享的内容，按本次成功写入数显示新增数量。
5. 将本次新建的临时目录移入 115 回收站，再次读取新分享确认快照仍可访问。

115 的分享快照需要时间生成。不能在转存未完成时创建快照，也不能拿到分享码后立刻删除文件。新分享设为长期，不按日期到期；手动取消分享、账号状态和 115 审核等仍可能影响可用性。

父目录 ID 默认为 `0`（网盘根目录）。它是 115 网盘目录 ID，与 NAS 的 STRM 输出目录无关。每次只清理本任务创建的临时目录，不删除配置的父目录，不操作其他目录，不清空回收站。

转存、分享、快照校验或 STRM 生成失败时保留临时目录。任务记录位于 `data/reshare-jobs/任务编号.json`，包含目录名称、ID、新分享链接和最后执行阶段。进程中断后不会自动重新转存或自动删除遗留目录；可按任务记录检查，使用已创建的分享关闭转存开关后继续生成。`deleting` 表示删除请求可能已经执行，需核对网盘和回收站；`deleted` 表示已删除但后续校验尚未完成；`completed` 表示整个流程完成。

单任务最长 5 分钟，每个等待阶段最多 90 秒，最多 1000 个顶层条目、20000 个总条目、20 层目录。转存再分享任务串行执行。网页通过流式响应显示当前阶段、读取条目数、等待原因及已用时间，可点击「停止等待」取消请求；浏览器最多等待 5 分 30 秒。旧 JSON 生成接口仍可使用。

网页与 Bot 共用的 115 管理请求串行执行，每次请求结束后至少间隔 1 秒。只读 GET 遇到 HTTP 405/429 时，分别等待 5 秒、15 秒，最多重试两次；115 返回更长的 `Retry-After` 时以服务器要求为准。等待可取消，重试耗时计入任务超时。创建目录、转存、创建分享、修改期限和删除等 POST 不自动重试，避免重复写入。播放直链查询不进入目录扫描队列。

「查看日志」会明确显示每次任务的转存开关及只读重试进度。Bot 读取服务器保存的开关；看到「转存再分享已关闭」时，需要在「分享播放 / STRM」页面打开开关。HTTP 405 本身不能证明请求方法错误或风控，最终失败会保留实际方法和固定接口路径以便排查。

## Telegram 配置

在侧边栏进入「Telegram 配置」，点击「Bot 配置」卡片，填写 BotFather 提供的 Bot Token 和允许的聊天 ID。点击「测试连接」可读取 Bot 身份和 Webhook 状态，不会发送消息。启用消息接收并保存后自动生效，无需重启后端。

Token 在页面中默认隐藏，保存后输入框清空，留空保存会保留原 Token。配置加密保存在 `data/telegram-config.enc`，接口不返回 Token。配置只从网页读取，包含网页保存的停用状态。切换配置时先停止旧接收器再启动新的接收器；进行中的任务可能取消并保留进度记录。

允许多个聊天时用逗号分隔，群组 ID 通常为负数。允许的群组中收到的成员消息都会被处理，请只填写希望接收和回复的聊天。当前处理普通文本消息及媒体说明文本，不处理编辑消息或频道推送。

在页面设置 STRM 播放地址、输出相对目录、后缀、大小和递归选项，然后点击「保存生成设置」。Bot 从服务端配置读取这些选项，不依赖浏览器保持打开。每条消息发送一个 115 分享链接，可在链接内带 `password`，也可另写 `提取码：abcd`。

只有修改 `.env` 或部署新版本时需要重启后端，例如 NAS 执行：

```sh
docker compose up -d --build
```

接收器使用长轮询，不需要增加端口或设置 Webhook；同一个 Token 不能同时被其他长轮询程序使用，也不能保留已启用的 Webhook。Bot 所在容器需要能够访问 Telegram API。没有配置 Token 或停用时不启动接收器。「Telegram 配置」页面区分未配置、已停用、连接中、接收中和连接异常，定期刷新真实接收状态。

Bot 会回复生成结果和自己的分享链接。消息处理进度按 Bot ID 分开保存在 `data/telegram-state-机器人ID.json`。回复失败会重试回复，不重复转存。进程中断时记录中的待处理任务会提示人工检查，不自动重放云端变更。由于 Telegram 发送消息没有幂等键，发送成功但保存进度之前中断仍可能产生重复回复。

## NAS 路径

继续使用单端口容器和单一媒体库挂载，例如：

```yaml
volumes:
  - "./data:/data"
  - "/vol1/1000/媒体库:/strm"
```

页面填写 `strm` 或 `strm2`，分别写入 NAS 的 `媒体库/strm`、`媒体库/strm2`，不需要增加独立挂载。
