# 转存再分享与 Telegram

在「115分享STRM」页面打开「转存再分享」。开关保存在服务端，网页生成和 Telegram 消息共用；关闭时仍直接使用原分享生成 STRM。

开启转存模式后，使用本功能所选账号的 Cookie 请求分享目录，将接口返回的 `data.userinfo.user_id` 与 Cookie `UID` 的用户编号比较。本人分享直接使用原链接生成 STRM，沿用原分享有效期，不创建临时目录或转存任务；其他账号的分享按下面的流程转存，再用新分享生成 STRM。分享者编号来自 115 接口，并非链接参数；编号缺失或无效时停止本条，不猜测归属。本人审核中的分享只要带 Cookie 能正常读取，也可直接生成。

「固定分享密码」仅用于新建分享，可填写 4 位英文字母或数字，通过右上角「保存生成设置」保存；留空则每次随机生成四位密码。原链接的提取码不再决定是否转存，即使密码相同，他人的分享仍需转存。手动填写的提取码优先于链接内密码。

开启后的流程：

1. 带当前 Cookie 读取原分享完整目录树，同时检查每页响应的审核与分享者信息。他人待审核分享（或待审核且无法确认属于本人）即使返回可读列表也立即停止，不创建临时目录；确认本人且列表可读的分享继续。检查通过后才在指定的 115 父目录下创建 `Cinema115-临时-随机编号`。
2. 将分享条目转存到新目录。115 可能在顶层目录创建后继续异步转存子文件，流程按当前生成配置统计达到最小大小的视频数量，并在配置了元数据后缀时同时统计元数据数量；两类数量与原分享一致后继续，不比较文件名、目录路径或大小。
3. 为数量完整的转存条目创建自己的分享，显式设置 `share_duration=-1`（长期）以及固定或随机 `receive_code`，并回读确认两项均生效。再读取新分享并确认视频及元数据数量。密码未确认时保留临时目录，停止后续生成和清理。
4. 将数量确认后的新分享目录页保留在当前任务内存中，直接复用其中的文件 ID 生成 STRM，不再重新读取同一分享。保持新分享返回的目录结构；相同内容直接复用，同名但内容不同则保留旧文件并使用稳定数字后缀另存。
5. 将本次新建的临时目录移入 115 回收站。删除接口成功后保存 `deleted` 与 `completed` 检查点，不再阻塞等待第二轮远端复查。

115 的分享快照需要时间生成。不能在转存未完成时创建快照，也不能拿到分享码后立刻删除文件。新分享设为长期，不按日期到期；手动取消分享、账号状态和 115 审核等仍可能影响可用性。

父目录 ID 默认为 `0`（网盘根目录）。它是 115 网盘目录 ID，与 NAS 的 STRM 输出目录无关。每次只清理本任务创建的临时目录，不删除配置的父目录，不操作其他目录，不清空回收站。

生成页面集中展示模式、分享链接、输出目录和转存父目录，粘贴分享文本时自动识别链接与提取码。STRM 输出目录可针对本次提交选择；115 父目录通过弹窗「保存并使用」单独持久化，支持根目录，失败留在弹窗内提示。路径仅用于展示，操作仍使用目录 ID；更换主账号后目录及显示路径均失效。批次等待等长期配置集中在设置页，未保存的配置不会影响手动生成，手动生成使用已保存的规则和本次输出目录。

生成规则中的「分享路径」位于元数据后缀之后，替代原来的「包含子目录」开关。默认 `/` 表示分享根目录，支持 `/电影/2026` 等目录名称路径，并包含所选路径下的子目录。路径按分享内容逐层解析，根路径不增加查询；路径缺失、同名歧义或分页不完整时停止，不回退到根目录。直接生成与转存再分享均使用此范围；转存完成后不会把原路径再次应用到新分享。预览仍浏览整个分享，明确选定的目录 ID 优先于配置路径。

转存、分享、快照校验或 STRM 生成失败时保留临时目录。任务记录保存在 `data/cinema115.db` 的 `reshare_jobs` 表，包含目录名称、ID、新分享链接和最后执行阶段。旧 `data/reshare-jobs/*.json` 首次启动自动导入并保留备份，新记录不再写 JSON。可通过管理员接口查询，详见 [数据库迁移与备份](database.md)。进程中断后不会自动重新转存或自动删除遗留目录；可按任务记录检查，使用已创建的分享关闭转存开关后继续生成。`deleting` 表示删除请求可能已经执行，需核对网盘和回收站；`deleted` 表示删除接口已经返回成功但完成检查点尚未落盘；`completed` 表示整个流程完成。

单条任务执行最长 5 分钟，每个等待阶段最多 90 秒，最多 1000 个顶层条目、20000 个总条目、20 层目录。公共生成队列支持批次并行，同一批次内部按步骤执行。网页通过后台任务接口提交并轮询当前阶段、读取条目数和等待原因，提交成功后关闭页面不会取消任务；只有「停止任务」调用独立取消接口。分享页面最多查询 5 分 30 秒，结束查询不会结束后台任务，可到日志查看结果。旧 JSON 与流式生成接口保留兼容，旧接口仍随其请求取消；新版页面均使用后台任务接口。

网页与 Bot 共用的 115 管理请求串行执行，成功请求之间至少间隔 250 毫秒，在不并发冲击上游的前提下减少多页目录的累计等待。只读 GET 遇到 HTTP 405/429 时，仍分别等待 5 秒、15 秒，最多重试两次；115 返回更长的 `Retry-After` 时以服务器要求为准。等待可取消，重试耗时计入任务超时。创建目录、转存、创建分享、修改期限和删除等 POST 不自动重试，避免重复写入。播放直链查询不进入目录扫描队列。

普通分享直接生成 STRM 时，带当前 Cookie 读取所选目录，不额外预查根目录或按分享归属提前拦截。接口成功且列表可正常读取时，即使 `share_state=0` 也继续生成。读取失败时才检查同一次响应：`data.share_state` / `data.shareinfo.share_state` 明确为 `0`（含字符串形式），或 `error`、`message`、`msg`、`error_msg`、`shareinfo.forbid_reason` 提示「审核中」「正在审核」「等待审核」时，归类为审核并结束本条任务。已观察的审核通过状态为 `1`；顶层 `state=true` 仅表示接口请求成功。

转存再分享的原分享检查更严格：可读目录不能证明可转存。若同次响应明确正在审核，只有 `data.userinfo.user_id` 与当前 Cookie 的 UID 用户编号一致且列表可读才继续；他人或归属未知的审核分享立即标为审核中，启用审核重试时按原模式排队重试。这项判断不增加额外公开预检请求，不改变普通 STRM 生成及本人新分享校验。等待阶段如确实超时，会保留最后一次目录校验或上游错误原因，避免被截止时的请求取消覆盖，超时原因不重复拼接。

缺失列表、条目无法解析、分页不完整等读取失败同样检查审核原因；合法空目录（`count=0`、`list=[]`）表示读取成功，按没有匹配视频处理。缺失或 null 审核字段不按默认零值处理；HTTP 405、网络异常、提取码错误等没有审核证据时保留原错误。审核导致无法读取时记录 WARNING，Telegram 多链接消息结束当前请求并继续下一条；是否安排后台重试取决于基础设置。生成 STRM 仍不代表所有视频都已完成实际播放验证。

「115分享STRM」分为生成 STRM、任务记录、设置三个标签。生成区切换直接生成或转存再分享，Bot 使用设置里保存的默认开关。「分享审核中自动重试」默认关闭，启用后默认每 30 分钟重试、最多 6 次（不含首次执行）；间隔可设 1～1440 分钟，次数可设 1～100。点击右上角保存后生效，关闭后待重试任务在后台下一轮检查时停止。审核重试队列每 15 秒检查一次，同一时间到期的任务串行执行，每次最多运行 5 分钟。

重试任务及生成选项快照保存在 SQLite，关闭网页不影响等待，重启后继续等待任务。仅明确的审核错误进入重试，其他错误不会重新转存。原分享尚未转存时重新按原模式执行；已经创建新分享时，只复用新链接生成 STRM，保留临时目录并在日志提示人工核对，绝不从头转存、重新创建分享或自动重放清理。115 登录变化、重试次数用尽或进程执行中断时停止自动执行。重试结果更新在「日志」任务卡片中；配置独立通知聊天 ID 后，后台重试成功也会发送 Telegram 通知。

转存后自己的新分享使用本次任务固定的 Cookie 完整读取一次目录。即使新分享 `share_state=0`，只要带 Cookie 读取到的视频及已配置元数据数量与原分享一致，就把这些目录页直接交给 STRM 生成器；不比较文件名、目录路径或大小，单链接、嵌套目录和合并批次也不再重复请求相同页面。STRM 成功后直接清理本次临时目录，不再执行清理前和删除后的两轮扫描。Cookie 与远端目录页只在任务内存上下文中传递，不写入任务参数或日志。

旧版本已结束的 `awaiting_review` 记录和遗留目录保持原状，不会因规则更新自动删除或重放。已有审核重试任务仍按保存的新分享进行直接生成，不重复转存或清理历史目录。

「查看日志」默认 INFO，显示消息批次数量与当前序号、遍历模式、分享链接及实际提取码、任务开始、输出目录、转存开关、分享者账号归属判断提示和目录分页，并按每 10 个成功写入文件显示数量进度，末尾补齐最终数量。生成结束的成功与失败数量、生成耗时和任务总耗时也使用 INFO；任务中断会明确显示中断及未处理数量。切换 DEBUG 可查看详细执行阶段和逐文件完整路径；只读重试记录在 WARNING。Bot 读取服务器保存的开关；看到「转存再分享已关闭」时，需要在「115分享STRM」页面打开开关。HTTP 405 本身不能证明请求方法错误或风控，最终失败会保留实际方法和固定接口路径以便排查。

## Telegram 配置

在右上角管理菜单进入「Telegram 配置」，点击「Bot 配置」卡片，可添加多组配置。每组填写名称、BotFather 提供的 Bot Token、允许的聊天 ID 和独立通知聊天 ID；点击「测试连接」可读取 Bot 身份和 Webhook 状态，不会发送消息。启用配置后，再到「115分享STRM」明确选择此 Bot 并保存。

Token 在页面中默认隐藏，保存后输入框清空，留空保存会保留原 Token。配置库加密保存在 `data/telegram-bots.enc`，接口不返回 Token。每项配置有稳定编号；分享功能保存所选 `botId`，切换时先停止旧接收器再启动新接收器。同一个 Bot 只运行一个消息接收器。删除、停用或清空所选配置不会自动改用其他 Bot。

允许多个聊天时用逗号分隔，群组 ID 通常为负数。允许的群组中收到的成员消息都会被处理，请只填写希望接收和回复的聊天。当前处理普通文本消息及媒体说明文本，不处理编辑消息或频道推送。

支持正文和图片／视频说明中的文字超链接，例如海报消息里的「🔗 获取链接」。Bot 从 Telegram 的 `entities` / `caption_entities` 中读取真实的 115 地址，无需复制成明文；可以直接转发保留链接的图文消息。带 emoji 的说明、多个隐藏链接、隐藏与明文链接混排均按原位置解析，沿用相邻提取码匹配及同消息去重规则。只识别直接指向 115 的链接，不点击外站中转页，也不从图片像素中识别地址；普通聊天白名单和忽略其他 Bot 消息的限制继续生效。

在页面设置 STRM 播放地址、从媒体库真实文件夹中选择输出目录、配置后缀、大小和递归选项，然后点击「保存生成设置」。Bot 处理每个链接时读取服务端当前保存的选项，不依赖浏览器保持打开。一条消息可发送多个 115 分享链接，建议每个链接单独一行。可在链接内带 `password`，也可在对应链接后同一行或紧接下一行写 `提取码：abcd`，例如：

```text
https://115cdn.com/s/aaa?password=abcd
https://115.com/s/bbb
提取码：efgh
```

普通分享的单个或多个链接都会先回复「🔄 开始处理 N 个链接…」，保存 Bot 返回的消息 ID 后再开始生成。首条链接完成时使用 `editMessageText` 把开始提示原地更新为成功或失败结果，保留对原消息的引用，单链接只留一条 Bot 回复。多链接后续结果独立发送，避免覆盖前面已完成的结果。引用使用当前聊天收到的原消息，包括转发的图文；群组话题内的回复保留原话题。原消息已删除时允许继续发送结果，旧版本没有保存消息编号的任务照常发送普通回复。

「转存再分享」标签的「批次收集等待（秒）」默认 5 秒，可设置 0～300 秒，0 表示不等待。Telegram 转存模式在同一聊天、同一话题内收集链接，每次新增资源将截止时间重置为本次收到时间加等待秒数，不设最长收集时间；连续一段时间没有新资源后才开始。到期后的资源进入下一批。不同消息重复发送同一链接仍保留原消息结果，但不延长截止时间；同一更新的重试不重复入队。到期发送开始提示，先逐条检查原分享，再将可转存的来源统一转存并创建一个长期分享。

详情页 Bot 搜索与观影搜索也使用这个等待设置：同一弹窗中，首条有效链接成功入队时开始收集；账号、凭据和生成设置一致的后续资源在窗口内合并，每次新增链接后重新等待，去重重复链接及请求重试不延时，不设最长收集时间。截止时间通过状态接口实时返回；到期后即使尚在排队也不再追加，后到资源进入新批次。原有单批 100 条及最多 20 个未完成批次限制保留。搜索仍在收集回复时可以先选择资源，搜索结束后依次向资源 Bot 获取链接；取链串行，但已提交的 STRM 批次不会锁住其他资源。关闭弹窗不取消已经提交的后台任务，尚未取链、未提交的选择会取消。重新打开可恢复多个任务的独立状态；合并批次中某条失败不会使其他成功条目显示失败。“停止已提交批次”停止当前弹窗追踪的批次，合并批次内所有来源一起停止。

公共 STRM 队列固定支持批次并行，不再提供最大并行批次数配置；旧配置中的对应字段不参与调度。仍保留最多 20 个未完成批次的容量保护。收集窗口结束后即可开始，无须等待上一批结束。执行中的批次不接受追加，后到资源进入新窗口。每批仍按核对、转存、分享、生成、清理顺序执行，使用独立临时目录及固定账号设置；115 请求限速、只读重试及本地同名文件写入互斥继续保留。网页普通分享与分享管理页手动提交不加入搜索弹窗的收集窗口。Telegram 自身接收和回复状态机仍保持原有顺序，不会并发操作同一个资源 Bot 的对话。

普通分享模式不进入等待窗口，可先于尚未到期的转存批次处理。转存模式的链接先进入等待队列，执行时查询分享者编号：本人分享直接生成，不纳入合并；其他账号的正常分享合并转存，审核项单独处理。单个 Telegram Bot 的消息状态机仍按批次顺序处理；执行期间 Telegram 暂存该 Bot 的后续消息，但不阻止网页或其他来源的批次并行。等待队列、截止时间与接收游标一起持久化，重启后继续，已经到期的批次立即执行；已经收集的批次沿用入队时的分享模式和等待截止时间。

成功回复显示「✅ 【115网盘】转存再分享再生成 STRM 完成」或普通生成完成、当前链接的成功统计、原链接、新分享、STRM 与元数据的实际成功／失败数量及清理状态。成功结果优先预览新分享；失败结果显示「❌」及具体原因、对应原链接，并预览原链接。已生成部分内容但后续失败时使用「⚠️」提示，保留已创建分享和临时目录信息。文件未处理与文件失败分开统计，不把后续未执行文件计为失败。

普通分享分别生成，多链接逐条结果标明 `【1/2】` 等进度，每条结果中的「链接统计」仅针对当前链接。每个链接独立计算 5 分钟超时，单条失败继续下一条。同一消息内相同分享码和有效提取码只处理一次，不同消息重新发送仍会生成。引用信息、待编辑的 Bot 消息 ID 和预览地址与结果一起保存，编辑失败或重启后继续更新原提示，不重复生成；Telegram 返回「内容未变化」视为已更新成功。只有提示已被删除时才补发结果。


合并转存时，审核中的原分享在任何转存操作之前单独剔除，不影响其他正常来源；其他读取失败也单独记录。开启基础设置中的审核重试后，审核项按保存的间隔和次数写入数据库，到期由后台自动重试，重启仍可继续。关闭重试则保留审核状态，不自动执行。成功来源不会因其他来源的审核被再次转存。

同批正常来源放进一个临时目录，每个来源仅在临时网盘目录中隔离。创建长期分享时选中这些目录里面的原始文件和文件夹，因此新分享根目录直接展示原内容，不再出现「来源-001…」包装层。原文件夹和子目录结构保持不变。同名条目通过完整目录树匹配来源，本地同名 STRM 使用稳定的数字后缀，避免相互覆盖。生成和安全重试使用新分享实际返回的根条目 ID 限定来源范围。

合并批次只发送一条开始提示，完成后将这条提示原地替换为整批汇总，并保留对首条原消息的引用：成功／失败链接数、成功链接列表、失败链接及原因、一个新链接、STRM 和元数据总计。不再为每个来源重复发送结果和新链接。审核项在汇总中显示是否已安排重试，数据库仍分别记录每个来源。长批次只在这一条消息内展示可容纳的明细，并提示剩余条数到网页任务记录查看，不拆成多条刷屏。批次整体超时仍为五分钟。

只有共同目录内的全部来源生成成功、本人 Cookie 校验完整后才自动清理。某个来源生成失败时保留共同临时目录，其他已生成来源不重复执行；若已创建分享中的某来源遇到审核且支持安全重试，重试只读取该来源在新分享中的根条目（兼容旧批次的来源目录），不重新转存、创建分享或自动清理共同目录。若已经发出转存请求后上游才报审核，则保留检查点与临时目录，不自动重放状态不确定的云端操作。

只有修改 `.env` 或部署新版本时需要重启后端，例如 NAS 执行：

```sh
docker compose up -d --build
```

接收器使用长轮询，不需要增加端口或设置 Webhook；同一个 Token 不能同时被其他长轮询程序使用，也不能保留已启用的 Webhook。Bot 所在容器需要能够访问 Telegram API。没有配置 Token 或停用时不启动接收器。「Telegram 配置」页面区分未配置、已停用、连接中、接收中和连接异常，定期刷新真实接收状态。

Bot 会回复生成结果和自己的分享链接。消息处理进度和整条消息的链接队列按 Bot ID 分开保存在 `data/telegram-state-机器人ID.json`。回复失败会重试回复，不重复转存。重启后补发已保存的结果，继续队列中尚未开始的链接；执行中断且没有保存结果的链接会提示人工检查，不自动重放其云端变更。由于 Telegram 发送消息没有幂等键，发送成功但保存进度之前中断仍可能产生重复回复。

## STRM 成功通知

在「Telegram → Bot 配置」为具体 Bot 填写独立通知聊天 ID，再在「115分享STRM」明确选择该 Bot 并启用 Telegram。只填写一个数字 Chat ID；私聊需先与 Bot 发起会话，群聊需将 Bot 加入群并授予发言权限。未选择、配置停用、删除或凭据清空时不发送，也不回退其他 Bot。

网页分享页面、影视详情的 Bot 搜索生成、追更自动生成以及后台审核重试，只要任务至少写入一个 STRM，就使用任务启动时固定的 `botId` 通知对应聊天；部分 STRM 或元数据失败会显示警告。消息包含原链接、转存后的新链接、生成与元数据数量、清理结果以及链接预览。没有生成文件的任务不会冒充成功。Telegram 内提交的即时任务继续在原聊天更新已有回执，不再向独立目标重复发送；这些任务后续由后台审核重试成功时，再发独立通知。

成功任务落盘后将通知保存到 SQLite，由独立后台发送器发送；通知网络失败不改变任务结果、不重复生成或转存。每秒最多发送一条，最多尝试 8 次，失败从 30 秒起逐步延长间隔，最多 15 分钟。重启后恢复待发送通知，同一任务、Bot 和目标去重；修改 Bot 或目标后，不将旧通知改发给新目标。记录最多保留 7 天，投递结束即清空正文。发送结果在「查看日志 → Telegram」中查看。Telegram 不提供发送幂等键，发送成功但响应丢失或本地确认前进程退出时，重试仍可能出现重复通知。

## NAS 路径

继续使用单端口容器和单一媒体库挂载，例如：

```yaml
volumes:
  - "./data:/data"
  - "/vol1/1000/媒体库:/strm"
```

页面选择 `/strm/已整理` 或 `/strm/待整理`，分别写入 NAS 的 `媒体库/已整理`、`媒体库/待整理`，不需要增加独立挂载。
