## 打卡规则

- `- [ ]` 表示待完成；`- [x]` 表示已完成并具备本项完成标准要求的证据。部分完成时保持未勾选，在执行记录写明进展。
- 每个任务保留固定编号。完成后更新勾选、阶段统计和完成记录，填写日期、相关文件及验证结果；发现回归时取消勾选并记录原因。
- 设计任务只证明方案已整理或审阅，不代表业务功能实现。代码任务包含必要验证；阶段验收还需对应的审查与回归，不能只以代码已写完为准。
- 前端布局、交互调整按用户约定由 Gemini CLI 参与讨论和审查；后端逻辑由 Codex 设计、实现及审查。页面验收覆盖实际代码与必要截图。
- 按依赖推进，已满足依赖的任务可在同阶段内调整顺序。普通接口验证与测试优先使用只读请求、模拟上游、临时 SQLite 和模拟浏览器数据。
- P0～P4 属于核心实施任务；E 系列为后续扩展，不计入核心完成率。方案继续调整时同步修改任务与验收标准，不把建议自动标为用户已确认。
