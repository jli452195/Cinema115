# 115 生活事件共享消费

生活事件由 `DriveSTRMEvents` 统一采集。STRM 和 115 自动整理分别消费同一份内存事件，目录核验、扫描安排及重试在消费者内执行。CD2 继续使用独立的存储监控入口。

## 请求与存储

- 定时采集、同步检查及异步刷新共用一个采集器，并发请求合并。后台运行时，调用者取消等待不会取消共享采集。
- 内存保存最多 20,000 条事件、256 批；不新增事件表、事件文件或外部存储服务。
- 缺父目录先查已有文件索引，再通过共享的精确身份查询定位；STRM 新目录沿父链找到各映射已知的监控祖先。查询结果短期缓存，后续相关事件使其失效。网络错误进入重试，不按文件不存在处理。
- 复用已有 `drive_strm_cursors` 保存共同安全进度。消费者将扫描范围持久交接到已有任务队列后才确认，所有订阅者确认后才推进游标。已有整理任务记录保存必要扫描范围，不保存原始事件历史。

## 新功能接入

服务启动并开始采集前，调用 `events.Hub.Subscribe("功能名")` 注册独立订阅。每个订阅由所属功能管理消费循环及退出：

```go
batch, ok := subscription.Read() // 同步读取缓存，不请求网盘
batch, err := subscription.Wait(ctx) // 异步等待下一批
err = subscription.Acknowledge(ctx, batch) // 安全交接任务后确认
```

同一个订阅的 `Read` 和 `Wait` 共用进度。不同功能需要不同订阅，禁止未经任务交接就确认批次。缓存返回副本，不包含 Cookie；功能需要网盘请求时自行遵守主账号及任务固定凭据约定。

`events.Check(ctx)` 等待共享采集完成，不等待消费者完成；`events.RequestRefresh(ctx)` 只申请后台刷新，要求常驻采集器已运行。两者都不应在每次页面读取或每个消费者循环中调用。状态接口可读取采集错误及各消费者的积压、错误。

## 恢复边界

进程重启从共同安全游标重新读取。已交接的队列任务负责恢复；未交接的事件可再次消费，因此消费者必须允许重复通知。缓存溢出时只要求落后的消费者补扫；旧批次确认返回 `ErrLifeEventExpired`，应重新读取当前批次。

115 历史有条数和覆盖范围限制。首次基线、历史截断或身份无法定位时仍需补扫，部分操作可能没有事件，须保留低频完整核对。异步消费不能消除上游接口自身的网络超时。
