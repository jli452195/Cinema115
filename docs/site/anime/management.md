# 订阅管理与故障排查

保存后的订阅可以在「我的订阅」中查看状态、修改来源和查看下载记录。先区分订阅状态、下载阶段和整理阶段，再决定要不要重试操作。

## 找到已有订阅

从选番页右上角进入「我的订阅」，选择「已启用／已暂停／已归档／全部」，也可以按订阅名称搜索。点击卡片打开配置窗口，切换「基本」「备用 RSS」或「下载记录」。

「刷新订阅列表」读取本地订阅状态；下载记录中的「刷新记录」读取本地执行记录，都不是立即向 AniBT 强制拉取全部历史的按钮。

## 订阅状态操作

在订阅配置的公共管理区可以看到这些按钮：

| 操作 | 作用 |
| --- | --- |
| 暂停订阅 | 停止新的 RSS 检查，保留配置和已有记录 |
| 继续订阅 | 恢复暂停或归档的订阅 |
| 归档 | 停止常规检查并保留配置、来源和执行记录 |
| 删除订阅 | 删除本地订阅、下载和整理记录，保留 115 文件 |

归档后新增或启用字幕组，保存按钮会变成「保存并继续订阅」。删除订阅不会删除 115 网盘文件，但再次订阅同一资源可能再次下载。

执行暂停、归档或删除等状态操作前，先保存当前表单修改。未保存的来源、规则和 TMDB 目标不影响后台；**目录设置会立即保存**，不属于这个草稿。已有任务固定账号和目标，保存新配置不会把它们改派到新账号或新目录。

暂停不是撤销已经提交到 115 的离线下载。任务若显示「等待恢复订阅」，继续订阅后再按原任务处理。

## 下载和整理是两个阶段 {#download-records}

打开「下载记录」，展开一条资源，可看到执行时目录、115 状态、文件清单、整理进度和最近结果。下面使用已有 AniBT 订阅《至高之力》的记录演示：

![AniBT 下载记录：刷新、任务状态、执行详情与整理预览入口](/images/anime/anibt-jobs.webp)

1. 「刷新记录」只重新读取本地任务信息。
2. 一条记录对应一份发布资源，右侧显示当前阶段；点击展开或收起。
3. 执行详情：执行时路径、115 状态、文件清单、整理进度、整理目录2和最近结果。
4. 「查看整理预览」入口。

任务详情会记录执行时的路径，不会追踪用户后来在 115 中手动移动的位置。常见状态如下：

| 阶段 | 可能看到的状态 | 含义 |
| --- | --- | --- |
| 提交 | 待提交、正在提交、结果待核对 | 115 离线任务请求仍在处理或回执不确定 |
| 115 | 115 已接收、115 下载中、网盘已完成 | 115 任务已进入对应阶段；网盘已完成只代表离线阶段结束 |
| 文件 | 文件清单已保存、需要处理 | 后端正在保存或核对离线任务返回的文件清单 |
| 整理 | 待整理、正在整理、整理结果待核对、整理需要处理、已整理 | 文件正在按命名计划移动，或需要核对结果 |

只有看到「已整理」才表示整理阶段完成。目标目录同名文件会跳过，不覆盖已有文件。

### 查看整理预览

展开任务后点击「查看整理预览」，可查看原任务保存的文件清单和命名方案；需要时使用「重新读取整理预览」。它不查询文件此刻在网盘的实际位置，也不会执行改名或移动。

如果你已经手动移动文件，要结合 115 的实际目录核对，不能把记录中的执行路径理解为当前位置。

## 待确认时怎么做

出现以下按钮时，优先核对原操作：

- **核对原任务**：确认提交是否已经产生 115 离线任务，不重复提交。
- **核对整理结果**：确认改名和移动是否已经完成，不重复发送同一指令。
- **重试读取**：重新读取原任务状态或文件清单。
- **继续准备下载**：原任务已确认但文件清单仍需继续处理。
- **重新整理／继续整理**：在已有文件清单基础上继续整理。
- **核对原保存请求／核对原操作**：保存或状态变更的回执不确定时使用。

SUBMIT_UNCERTAIN 表示只核对原任务；TASK_MISSING 表示找不到原离线任务，不会自动重下；DOWNLOAD_ACCOUNT_CHANGED 表示固定主账号发生变化，需要人工处理原账号任务。

## 常见问题排查

| 现象 | 先检查什么 | 处理方式 |
| --- | --- | --- |
| 预览没有符合资源 | 来源站点、字幕组、规格和排除正则 | 切换“全部发布”，核对标题；必要时重新读取来源样本 |
| 预览数量很少 | AniBT 近期窗口和读取上限 | 预览不是完整历史，保存后等待后续 RSS 检查 |
| 集号错位 | 目标季、集数偏移、集号正则 | 用一条已知标题计算“来源集数 + 偏移”，再重新预览 |
| 网盘已完成但目录没有文件 | 整理阶段是否仍为待整理或待确认 | 打开任务详情，使用“核对整理结果”或“重新整理” |
| 任务提示目标冲突 | 整理目录中已有同名文件 | 保留其他文件，处理冲突后继续原任务；系统不会覆盖同名文件 |
| 备用 RSS 没有结果 | 备用是否启用、来源是否已确认 | 打开备用 RSS，检查「启用此备用 RSS」、条目和规格；备用源独立运行 |
| 保存提示回执尚未确认 | 页面是否出现核对入口 | 等当前请求结束后使用“核对原保存请求” |
| 删除后再次订阅又下载 | 本地记录已清除但 115 文件仍保留 | 删除前确认需求；再次订阅可能重新创建下载任务 |

整理结果不确定（ORGANIZE_UNCERTAIN）时，只核对已经记录的对象，不要重放改名移动。其他文件继续、冲突处理完成后再点击继续原任务（ORGANIZE_TARGET_CONFLICT）。

## RSS 与通知设置 {#rss-and-notifications}

在「动漫订阅设置」中：

- **RSS 设置**：调整检查间隔、齐集整理后自动归档和长期不活跃归档。默认检查间隔为 15 分钟，可填 10–1440 分钟。
- **下载与整理**：设置共用的「下载目录1」和「整理目录2」。选择后立即保存；已有任务沿用执行时目录。
- **Telegram 通知**：分别配置下载完成、整理完成和异常提醒，通知预览不会触发订阅下载。

### 归档条件

「齐集整理后自动归档」要求所有启用来源的目标集数都整理成功；只下载完、只有主源齐集或仅预览显示符合，都不能等同于齐集整理。

「长期停更归档」可选 60 天、90 天或关闭。连续 14 天没有新匹配资源时显示提示，30 天后改为每日检查一次。RSS 读取失败不作为停更依据，有未完成或待确认任务时继续处理。

归档保留配置、执行记录和网盘文件。需要补番或新增字幕组时，可以继续订阅。

### Telegram 提醒

先在「Telegram 配置」中准备已启用的 Bot，并配置通知聊天 ID；再在动漫订阅设置的「Telegram 通知」中选择它。

按需要开启「下载完成」「整理完成」「异常提醒」。若希望收到可用于入库的完成提醒，应关注「整理完成」，不要只看「下载完成」。

模板、配图和事件预览用于检查通知外观，修改后需要保存。通知状态与下载记录是不同入口；排查实际执行结果时，以任务记录为准。
