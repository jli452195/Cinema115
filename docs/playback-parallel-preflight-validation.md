# 秒传并行预检与灰度验证

2026-10-06：目标账号明确未命中可用文件且写入冷却已结束后，保存目录核验与上传凭据准备并行。固定本次目标账号、UID 和 Cookie；两个分支都完成后再次检查授权，才保存上传意图并提交秒传。任一分支失败取消另一分支并等待退出，保留原错误类型。恢复目录核验沿用原 5 秒预算，同时响应并行分支取消。

正常路径请求数不变，减少的是串行等待。目录失败时，并行的上传凭据读取可能已经发出，较原串行失败路径最多多一次只读请求，但不会上传。目标副本命中不启动预检；上传凭据仍缓存 5 分钟。分段日志分别记录缓存锁等待、本地副本查询、并行预检与上传意图保存；预检两个分支的时间不可相加。

动态池与受播放会话管理的用户没有启用 PlaybackInfo 提前预热：现有入口不足以可靠确认正式播放，不绕过设备、用户和池准入。play115 仍仅在缺少二次校验片段时读取来源。不能据此承诺后台预热后立即播放，也不能把本次预检收益套用到已经缓存上传凭据的日志。

## 真实账号只读灰度

```powershell
$env:CINEMA115_REUSE_CANARY_ROOT='D:/code/Cinema115'
try {
  go test ./internal/service -run '^(TestPlaybackWritePreparationLiveCanary|TestPlay115TargetFirstLiveCanary)$' -count=1 -v -timeout=120s
} finally { Remove-Item Env:CINEMA115_REUSE_CANARY_ROOT }
```

只读打开业务数据库，使用一个已记录管理员小号，账号凭据仅内存解密。传输白名单拦截上传与其他非允许请求。每组使用全新预检缓存，共用 HTTP 连接并交替顺序；无主账号请求、云端写入或真实业务状态变更。

| 轮次 | 串行预检 | 并行预检 | 每组 115 请求 |
| --- | ---: | ---: | --- |
| 1 | 175 ms | 228 ms | 目录 1 + 上传凭据 1 |
| 2 | 223 ms | 98 ms | 目录 1 + 上传凭据 1 |
| 3 | 225 ms | 100 ms | 目录 1 + 上传凭据 1 |

这三个样本的中位数从 223 ms 降至 100 ms，相差 123 ms；第一轮并行反而较慢，说明小样本和网络波动不支持稳定提速比例的结论。上传凭据已缓存时，六次后续预检都只请求目录一次，耗时 229–388 ms，未额外获取凭据。样本受网络和客户端限速影响，不能用冷热组直接比较缓存收益。

同次文件取链灰度：

| 路径 | 耗时 | 115 请求 |
| --- | ---: | --- |
| 空本地副本缓存，play115 SHA1 命中目标 | 780 ms | SHA1 查询 1 + 取链 1 |
| 已有本地目标副本 | 259 ms | 取链 1 |

文件取链两个场景的目录请求、主账号请求及写入均为零。本次未进行真实秒传提交或播放器长时间播放，二次校验和提交由隔离回归覆盖；以上是对应阶段耗时，不是 Emby 入口至首帧时间。未替换或重启正在运行的服务。
