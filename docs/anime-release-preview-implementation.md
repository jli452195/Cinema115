# 资源预览对照与当前最高版本

日期：2026-10-20。对应调整任务 R-07、R-08；不提前验收 P4。

## 预览交互

通过用户 Chrome 只读核对 ANI-RSS 的资源预览，采用紧凑的原标题、重命名、规则结果对照表。顶部展示共用整理目录和作品文件夹，行内展示实际目标季文件夹、分集名称、发布编号、规格、大小和修订版本。

按用户后续明确要求，桌面和手机均保留表格：名称单行完整输出，表格内部左右滚动，不省略、不折叠；删除“展开完整名称”开关。勾选列固定左侧，表头固定顶部，文本可独立选择复制。手机上下滚动到边界后可继续滚动页面，横向手势保持在表格内。筛选、分页、CAS、旧选择核对、过期保护沿用原逻辑。

命名预览只使用已读取的 TMDB 资料、发布解析及当前来源映射。更改偏移即时重算名称，不重读 RSS/TMDB/115，不改变勾选或页码。未知编号、忽略例外、缺失 TMDB 季集和无效映射分别说明，不编造目标。

新增 `animeNamingPreview.ts` 供真实发布预览和映射示例共用。Go 模型将 `AnimeNamingPath`、`AnimeNamingFolder` 提取为实际整理与预览的共用函数，保持原整理路径行为，修正旧预览对长文件名没有应用字节上限的问题。Go/TS 使用同一份 JSON 样例核对偏移、分段、SP、复合例外、缺失资料、Unicode 清理和 UTF-8 字节限制。预览不含扩展名；实际整理保留原扩展名，并按所需字节进一步缩短超长名称。

## 当前最高版本且不洗版

最终用户要求优先于旧文档中的“同来源修正版全部下载”：

- 按每个已配置 RSS 来源内的普通集编号和解析出的规格分组。来源固定一个字幕组；不同来源、不同字幕组和不同画质、字幕语言、内封方式、编码等规格保持独立，不跨站猜测字幕组身份。
- 未标修订号视为初版；`v2`、`V3`、`rev3` 按数字比较。先应用范围、起点、关键词及规格规则，再从实际已加载、符合条件的发布中只保留最高版。更高版被过滤、没有可靠发布时间或已明确排除时，不压掉符合条件的版本。
- 同一修订号重复发布按稳定原帖键只保留一条；“修正版”等无数字标记或相互矛盾的版本号保持待确认，不猜版本。规格互相冲突也保持待确认。
- 低版本仍在“本页全部发布”显示，复选框禁用，标注“同集已有更高版本”；“本页符合规则”自然隐藏它们。版本号在原发布元信息中显示，不增加设置项。
- 开始订阅或后续 RSS 批次授权选定一版时即固定选择。后续更高版、重复发帖在 SQLite 本地按原授权快照跳过，不取种子、不查 115、不覆盖或删除旧文件；排队、核验失败、下载失败、完成和进程重启均不解除该固定选择。
- 当前预览加载到更高版本时，旧低版选择进入待核对，不静默替换为高版；用户核对并开始后才产生授权。首次启用事务再次检查最高版及每集规格唯一选择，直接请求不能绕过页面。
- 下载认领事务额外拒绝已建立任务的同来源同集同规格新资源。相同已核验 BT Hash 的重复帖子仍可关联原任务，保持原来的幂等；这不是新的 115 下载。

版本选择不增加数据表、迁移、后台循环或 115 请求。预览指纹增加独立的版本策略版本，更新前的预览需重新核对；已授权任务保持原快照。不清理数据库或重建既有任务。
