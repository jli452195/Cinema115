# 动漫订阅统一配置弹窗方案

状态：已实现并完成相关验证。日期：2026-10-20。弹窗只保存订阅配置，RSS 初始化、检查及下载由后台各自的生命周期推进；预览独立、只读，不再使用“保存并下载所选 N 条”。

## 调查结论（重构前）

已通过用户 Chrome 查看 ANI-RSS 的添加入口、修改订阅基本页、备用 RSS 页及独立预览弹窗，并使用 Gemini CLI 对当前前端组件做了两轮交互方案讨论。

ANI-RSS 的可借鉴点：配置按页签收拢，操作栏固定，备用 RSS 用紧凑行呈现；预览另开更宽的弹窗，用表格对照原标题、重命名、字幕组和下载判定。当前视口下配置窗约 800px、预览窗约 1400px。借鉴其信息组织方式，视觉仍使用项目已有浮层样式。

当前项目的问题不仅是表单过长：

- `AnimeSubscriptionEditorView.vue` 将 TMDB 目标、篇章集号、来源配置和完整预览堆在同一页面。
- `AnimeSubscriptionDialog.vue` 展示只读配置和执行记录，没有可用的完整编辑入口。
- `useAnimeSubscriptionEditor.ts` 明确拒绝 `firstEnabledAt` 非空的订阅。
- 后端 `PATCH /subscriptions/:id` 被禁用，存储配置接口也拒绝已启动订阅和带活动基线的来源。
- 现有未提交任务授权关联来源版本、运行代次、规则及基线，直接移除上述限制会使旧任务授权与新配置冲突。需要独立的已启动订阅更新流程，不能仅把开始订阅接口再次用于编辑。

### 生命周期代码审查

目前实际链路是：

```text
浏览器生成预览并保存选中资源 ID
  → POST /subscriptions/start
  → 保存配置 + 根据预览建立首次基线 + 将选中历史标为 selected
  → 后台核验资源并创建下载意图
  → 115 提交、跟踪、整理

首次激活后，后台 RSS worker 才按自己的到期时间继续检查新发布
```

RSS 并非依赖页面保持打开。`cmd/server/main.go` 在服务生命周期中运行 `AnimeDiscoveryRunner` 和 `AnimeStatusRunner`，RSS 检查时间、租约、冷却及执行记录已持久化。需要调整的是首次初始化与配置保存的耦合，而非重写全部 worker。

具体代码依据：

| 位置 | 当前行为 | 重构要求 |
| --- | --- | --- |
| `useAnimeSubscriptionEditor.ts` 的 `start()` | 没有有效预览则先生成预览；提交预览引用及选中资源 ID | 保存配置不以预览、选中资源或预览有效期为前提 |
| `storage/anime_start.go` | 同一事务保存配置，再调用首次激活逻辑 | 配置事务只保存定义及必要的本地调度标记 |
| `storage/anime_activation.go` | 从预览建立 T0/基线并授权选中历史，要求预览未过期 | 将首次资源发现、历史边界及选集交由后台初始化步骤 |
| `storage/anime_config.go` | 已启动订阅或带活动基线的来源不可编辑 | 配置版本和运行进度分开，可编辑启用及暂停的订阅 |
| `storage/anime_discovery.go` | 旧记录只要不是 `seen` 就跳过，包括已过滤记录 | 规则变化后允许后台重算受影响的未执行候选，不重下已领取版本 |
| `storage/anime_control.go` | 恢复要求基线来源版本与当前来源版本相等 | 保留暂停/恢复生命周期，避免普通编辑使恢复失效 |
| `storage/anime_downloads.go`、`anime_submit.go` | 新下载授权严格关联来源版本、代次、规则及基线 | 保留旧请求失效保护，重算未提交候选，独立保护已受理及未知写入 |

现有预览服务本身没有 115 执行接口，预览不是直接提交 115。问题在于保存/首次激活把预览结果转换为执行授权，把本应独立的初始化绑到了表单提交。

## 统一入口

日历和三个资源站点卡片的新建入口打开同一个配置弹窗。已有订阅卡片直接打开同一组件的编辑模式，默认显示基本配置。原本的只读详情不再单独叠一层，执行记录移到窗内页签。

保留可直达、可刷新的路由，路由负责确定弹窗及宿主页面。关闭后恢复日历或订阅列表的站点、筛选、分页、滚动和卡片焦点。直接打开链接时使用明确的宿主页面，不依赖浏览器上一页必然存在。

新建和编辑共用一套表单组件、校验及预览状态，不复制两份结构。两种模式都通过“保存”提交完整订阅配置，不恢复保存草稿功能。新建默认启用，编辑保留已有启用/暂停状态；保存与启停分别表达不同操作。表单关闭前的临时输入只存在当前组件内存中。

## 配置弹窗

建议桌面宽约 860px，最大高度约视口的 88%；手机使用接近全屏的容器。标题、页签和操作栏固定，仅正文纵向滚动。复用现有 `AnimeFloatingDialog` 和 `floating-surface`，减少大海报、独立卡片背景和说明文字，不引入新装饰图标体系。

```text
新增订阅 / 修改订阅                                  关闭
小封面  番剧名称 · Bangumi / TMDB 关联摘要 · 当前状态

基本          备用 RSS（数量）          下载记录
────────────────────────────────────────────────────
当前页签正文，内部纵向滚动
────────────────────────────────────────────────────
取消                           预览                 保存
```

### 基本

- TMDB 目标与目标季，默认关联结果直接呈现；更换目标作为次级操作。
- 主 RSS 的站点、字幕组和规格摘要；点击修改进入现有来源选择器。
- 补番起点、主源编号映射和必要规则。用具体例子显示 `发布 25 → S02E01`，不只显示一个缺乏方向的偏移数字。
- 每个 RSS 保留自己的编号映射，备用源不会被主源偏移覆盖。
- 包含词、排除词、编号范围和复杂映射放在就近的展开区域。
- 篇章完整集号列表默认折叠，展开或预览时查看，不再占据顶部大块空间。
- 下载、整理共用目录压成一行摘要，提供现有设置入口；不新增按订阅选账号、选目录的选项。

下载起点、范围、规格和是否补当前可见历史属于持久化规则，由后台解释。沿用用户此前“默认从指定集数补齐当前能找到的资源”的约定；预览不再承担额外历史下载授权。

### 备用 RSS

最多 4 个备用源，沿用总计 5 个来源的约束。每行展示站点、字幕组、规格、编号对应摘要及启用状态，提供编辑和移除，新增入口复用三个站点按钮。不新增排序、主备提升或无用途的自定义页签。

主、备用名称沿用现有功能语义，各字幕组仍可独立下载，不改为主源成功就停止其他源的故障转移模型。

### 下载记录

仅已有订阅显示，复用现有本地执行记录和必要恢复操作。暂停、恢复、归档及移除放在此页签或稳定的更多操作区，避免和保存配置混淆。

记录读取与编辑表单分开：后台更新下载进度不能重新灌入配置并覆盖未保存输入。离开记录页签后停止仅为该页签服务的轮询；本地已保存的执行状态不代表文件仍在 115 原位置。

## 独立预览弹窗

桌面最大宽 1600px、高 760px，均受视口约束；手机使用接近全屏的容器。与配置窗复用当前未保存输入的预览状态，打开时不重建编辑器。工具区压成两行，表格承担主要滚动，分页及返回按钮固定可见，避免正文与表格出现两根纵向滚动条。

工具区只展示有用的来源筛选、结果筛选和重新预览。技术性读取配额、完整性及过期提示放到次级说明，不抢占主要操作。

来源和结果筛选复用 `SelectMenu.vue` 的动漫样式：使用白底/深色实底浮层、浅灰选中背景和蓝色选中文字，替代原生操作系统菜单。菜单使用浏览器 Popover 顶层避免被原生配置对话框遮挡或裁切；支持方向键、首尾键、回车、ESC、外部点击及触摸选择。ESC 先关闭菜单，保留预览及编辑弹窗。

| 列 | 内容 |
| --- | --- |
| 规则匹配 | 符合、过滤或待确认，不承诺再次下载 |
| 下载记录 | 本地已选定、下载中、已整理等执行状态 |
| RSS | 主/备用 |
| 字幕组 | 当前来源的字幕组 |
| 原标题 | 完整发布名，固定列宽内换行 |
| 重命名 | 完整标准名称，不含扩展名 |
| 发布时间 | 来源解析得到的发布时间；缺失时明确显示未提供 |

表头固定，桌面前两列、手机第一列固定；表格区域内部左右滚动，完整名称不省略。多语言标题列最小约 600px，字号 13px、行高 1.6、单元格上下各 8px 留白。规格、大小、版本、篇章名称及过滤原因由“详细信息”统一展开，默认避免重复信息撑高行。状态统一采用浅蓝与中性灰，异常使用克制的提示色。目标目录在上方集中显示，不在每行重复长路径；扩展名尚未获取时，明确显示名称预览而非虚构完整文件名。分页和继续加载历史放在底部，关闭或返回只回到配置窗，保留输入、来源、筛选与滚动位置。

不提供“保存并下载所选 N 条”，不将预览中的勾选列表作为保存前提。预览只解释当前输入的匹配及命名结果；是否自动补已有资源由保存的下载规则决定。预览可以存临时缓存，但不创建正式下载意图或授予执行权限。若未来需要单条手动重下，应作为独立功能另行设计，本轮不新增。

来源选择器和预览互斥打开，最多同时存在配置窗与一个子窗。ESC 只关闭最上层，关闭预览后焦点回到预览按钮；背景保持锁定，避免滚动穿透和多次加深遮罩。配置窗的关闭按钮、ESC、遮罩及路由离开共用未保存检查，使用窗内放弃修改提示，避免形成第三层配置弹窗。提交结果未知时保留原请求并提供核对操作。

## 配置、RSS 与下载各自的生命周期

| 责任 | 输入/操作 | 结果 |
| --- | --- | --- |
| 配置弹窗 | 保存来源、规格、下载范围、编号映射及命名规则 | 保存完整定义和配置版本，不拉取 RSS，不生成离线下载任务 |
| 独立预览 | 查看当前未保存配置的匹配及名称 | 展示估算结果，不保存正式配置，不创建执行授权 |
| 后台初始化 | 发现已启用且尚未初始化的新订阅/新来源 | 按保存的规则读取当前可见资源、建立持久运行边界，并产生候选 |
| 后台 RSS 调度 | 到期、重试、配置版本变化 | 按最新有效配置匹配候选、去重并创建下载意图 |
| 下载执行 | 已持久化的下载意图 | 固定账号及目录快照，完成 115 下载、改名、移动和回收 |

后台 RSS 生命周期为“待初始化 → 正常检查”，错误进入退避/冷却，可独立暂停及恢复；初始化是运行状态，不是用户草稿。状态、到期时间及进度持久化，关闭页面及服务重启不重做首次下载。预览未生成、过期或关闭均不能阻止保存合法完整配置。

配置提交成功后可以发送容量为 1 的本地通知，让后台及时发现版本变化；实际初始化/检查仍由 worker 按持久化状态、到期时间和冷却推进，不在保存 HTTP 请求内执行。

保存后已启用的订阅可能很快按规则开始后台下载，这是后台读取配置后的正常工作，不表示“保存绝不会带来后续下载”。编辑已暂停订阅不会恢复运行。

是否处理旧资源由规则决定，而不是由用户刚才有没有打开、勾选预览决定。例如最低下载话数从 7 改为 1，若配置采用从指定话数补齐，后台可重新评估当前能找到的 1～6 话；已领取或已处理的相同字幕组/规格不重新下载。只追新模式则继续遵守自己的历史边界。仅改命名不重整已经完成的文件。

预览默认以本地执行记录区分已选、已提交及已整理，不向 115 查询文件是否还存在。已处理的同字幕组同规格版本不自动重下或洗版；不同字幕组仍可分别选择。

## 后端更新边界

后端由 Codex 单独设计、实现和审查，Gemini 仅讨论前端交互。

1. 恢复完整配置的新建和更新接口，校验管理员、订阅及来源版本、来源身份、命名映射和幂等键；请求不再携带执行用预览引用及所选资源 ID。保留订阅当前启用/暂停状态，不通过暂停再开始来模拟编辑。
2. 相同站点、条目和字幕组只更新规则及映射，保留来源身份、已处理记录及历史边界。来源身份真正变化时建立新来源并保留旧来源的执行关联，不把旧字幕组历史改写成新字幕组历史。
3. 将首次基线初始化从 `StartAnimeConfiguration`/预览授权事务移到后台，保存初始化完成标记及读取进度。相同来源普通编辑不重置首次边界或清空集数/版本领取记录。后台按规则及配置版本重算未执行候选，可复用来源缓存，不重新读取所有未变化来源。
4. 已由 115 接受的任务继续使用原账号、目录及命名快照。结果未知的写入保留核对路径，不重新提交、不改写原目标。需要审查并更新相关授权检查，确保新配置版本不会误阻塞这些任务的继续追踪与整理。
5. 对受影响且尚未发出 115 写入的旧意图，事务失效旧授权，防止旧规则继续提交；后台再按最新配置重新判定是否生成新授权。已过滤记录可在规则版本改变后重新判断，已领取或处理的版本不重下。未受影响来源不无故失效。
6. 现有暂停、移除、账号及目录归属规则继续生效，配置修改不能绕过它们。
7. 保存配置不产生 RSS 拉取及 115 文件请求。打开配置、切换页签及本地预览不查询 115；目录设置沿用已有核验规则，独立预览需要资源站点数据时按来源缓存及明确刷新操作读取。任务真正启动时固定主账号及设置，配置变更不使同一任务中途换号或改目标。
