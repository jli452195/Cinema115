# 动漫订阅配置与 RSS 生命周期

当前实现，2026-10-22。以下规则取代开发期间的预览选集、首次启用、历史跳过及解析基线授权方案。来源规则详见[正则规则重构](anime-source-rules-refactor.md)。

## 配置与执行

新建、修改共用配置弹窗，包含基本配置、备用 RSS、下载记录。保存只提交完整订阅定义，不提交资源选择或预览引用，不读取 115 文件。新建默认启用；修改保留启用或暂停状态，启停使用独立操作。

每个 RSS 独立配置订阅首话、匹配正则、排除正则和命名偏移。首话按字幕组发布编号填写，支持 `0`、`1`、`49`；已读取样本含普通集 0 或 1 时直接建议，否则只有明确读到来源末尾时才建议最小编号，截断窗口不猜。首话尚未确定也可预览，保存前须确认。匹配正则须全部满足，排除正则任一命中即跳过；每行一条，逗号不作为分隔符。规格选择只生成可编辑的匹配正则。符合范围与规则且尚未处理的发布由后台自动下载整理，不按发布时间划分新旧资源。

总集数独立于 TMDB，默认取 Bangumi 的 `eps`，可手动修改，清空恢复默认；`eps` 为 0 或缺失时保持未定，不使用 `total_episodes` 或 TMDB 季长度兜底。下载范围、缺集与齐集归档共用“订阅首话＋总集数”：首话 0、总数 13 对应 00～12；首话 49、总数 12 对应 49～60。总数未定仍检查首话至已发布末集的缺口，保留原停更/手动归档能力。

命名只设置一个目标季和有正负号的偏移，目标集号＝发布编号＋偏移；例如发布 25、偏移 -24 对应 E01。更换 TMDB、季、日期及命名偏移不改变订阅范围。删除独立的范围开关、篇章编号对应、归档编号高级区及 TMDB 总集数建议。分段、单集例外、补番起点与自定义集号解析统一收进一个“自定义”区域，复用原验证和执行链路；补番起点只排除更早资源及相应缺口，不改变范围终点。完整文件名保留在独立预览中。

后台流程：

```text
保存完整配置
  → 立即唤醒后台，按站点上限首次读取可见历史（蜜柑 2000、AniBT 100、AnimeGarden 1000 条）
  → 按规则选择未处理发布、核验资源、创建下载任务
  → 提交目录 1、等待离线完成、按 TMDB 映射重命名并移到目录 2
  → 整理完成后清理本任务下载子目录

后续按持久化时间检查 RSS，继续处理新增发布
```

首次读取失败保留订阅并按退避时间重试。初始化成功后重启继续普通 RSS 检查，不重新初始化。调整规则后后台重新判断未执行资源；已经处理的版本不重复下载。

来源读取成功后立即唤醒资源核验，下载任务落库后立即唤醒执行器；每批到达处理上限后继续领取已到期工作，不额外等待调度间隔。正常 RSS 周期、错误退避与 115 状态查询频率保持不变。来源读取阶段记录本地订阅编号和耗时，便于区分等待来源与等待下载。

同一次读取只选择符合规则的最高版本。已经选定或下载后，后发 v2/v3 不触发换版。不同字幕组保留独立规则及版本记录；相同 BT 资源仍共享必要的防重记录。

修改配置会使受影响的旧读取授权失效。尚未提交的同一任务可按新规则重新授权；已受理或结果未知的写入保留原账号、目录及命名快照，不重放写入，不中途换号。

解析器、规则引擎和时间解释版本仅用于缓存失效与诊断，不作为执行放行条件。升级后重新判断未选中的资源，已选任务继续使用冻结的来源解释；单条无法解析时跳过该条，不停用整个 RSS。账号、凭据及实际下载目录变化仍须校验，单独修改整理设置不阻塞未变化的下载目标。

## 预览与交互

预览使用独立宽弹窗，只展示规则匹配、实际处理状态、原标题和重命名结果。已读取发布全部显示，表格内部滚动；预览读取、刷新及关闭都不授予下载权限，不改变 RSS 生命周期。长名称在表格内部横向滚动。

日历、三个资源站点卡片及已有订阅共用配置入口；关闭后保留宿主页的分页、筛选、滚动和焦点。手机、深浅主题、键盘及嵌套弹窗滚动锁均由共用组件处理。

主 RSS 与备用 RSS 各自编辑规则。来源选择中的单选模板可生成匹配正则，并可恢复打开时的原规则；排除正则和集号提取规则不随模板改变。规则语法由后端 Go/RE2 校验，错误返回对应来源及字段，弹窗自动打开该来源并聚焦错误输入。

## 开发数据清理

SQLite v56 一次性清空动漫订阅、来源、发布、任务、操作记录、预览及关联缓存，删除旧历史成员表和解析基线表。保留动漫目录设置、115 账号及其他功能数据。后续正常启动不再次清空。

删除旧首次启用服务、接口、保存选集字段、持久基线授权及旧规格/包含词过滤代码，不为废弃测试规则增加兼容分支。不操作已整理的 115 媒体文件。

回归使用临时 SQLite、模拟资源站点和模拟 115；浏览器测试拦截所有 API，不再向实际环境写测试订阅。

v59 仅让旧进度摘要失效一次，后台按本地记录重算；订阅、任务和整理回执不删除。删除 TMDB 开播日期推断，命名和日期变化不再重算缺集。尚未确认首话的旧订阅显示真实已整理数量及“范围待确认”，不凭空推断齐集；确认一次首话即可使用新范围，无须重新下载。

## 验收

- 未预览也能保存；关页后后台独立检查与下载。
- 旧时间、未来时间及没有发布时间的发布使用相同下载规则。
- 起点调整后可以补齐符合条件的未处理资源，已整理任务保持不变。
- 暂停时保存保持暂停，恢复后继续后台检查。
- 自定义集号与默认解析共用预览、发现、认领和提交链路；同一发布在两个来源中可独立解释。
- 引擎升级不会要求重新确认订阅，已选任务继续执行；未选条目重新判断，明确排除的条目不自动恢复。
- 重启不重下、不重放未知写入；账号与目录归属校验保持有效。
- 清理事务失败全部回滚，其他业务和目录设置保持不变；成功后仅执行一次。
