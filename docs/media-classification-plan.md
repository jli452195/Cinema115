## C-01 YAML 结构

默认文件位于 `backend/internal/mediacategory/default.yaml`，后续内核直接嵌入此文件，不在文档、Go 代码或前端重复维护默认规则。运行时可编辑文件由 C-03 放入现有持久化数据目录，文件名为 `classification.yaml`。本阶段尚未接入运行时配置。

顶层仅有 `version`、`movie`、`tv`；`version` 必须为整数 `1`。`movie` 和 `tv` 都必须提供 `fallback` 与 `rules`，其中 `rules` 可显式填写为空列表。每条规则包含 `name`、`path` 和 `match`。

| 字段 | 含义 | 校验 |
| --- | --- | --- |
| `fallback` | 当前类型未命中时的分类目录 | 非空相对目录 |
| `rules` | 按优先级排列的规则列表 | 顺序就是优先级 |
| `name` | 页面显示及结果解释使用的规则名 | 非空，同一作品类型内唯一 |
| `path` | 命中后的分类目录 | 非空相对目录 |
| `match` | 同时满足的匹配条件 | 至少一个已支持的条件 |

例如将日本动漫与其他动漫分开，只需将默认的动漫规则替换为以下两条，保留其他剧集规则：

```yaml
- name: 日本动漫
  path: 剧集/日本动漫
  match:
    genres: [16]
    origin_countries: [JP]
- name: 其他动漫
  path: 剧集/其他动漫
  match:
    genres: [16]
```

这里的“其他动漫”是前一条未命中后继续判断的结果，无需额外的排除条件或逻辑表达式。

## 匹配语义与字段来源

1. 先按作品类型选择 `movie` 或 `tv`，按规则顺序判断，第一条完全命中立即返回；全部未命中返回该类型的 `fallback`。不支持的作品类型报错，不自动归入剧集。
2. `match` 中不同字段是 AND，同一字段列表内是 OR。类型、国家等多值作品字段与配置列表存在交集即满足该条件。没有填写的条件不限制；显式空列表或 `null` 报错。
3. 作品缺少某项事实时，对该字段的条件不命中；继续后面的规则或兜底。原产地、制作国家、原始语言互不推断，不自动补为同一种国家信息。
4. 多国合拍时仅按 YAML 规则顺序决定，不受 TMDB 国家数组顺序影响。默认优先级为国产剧、日韩剧、欧美剧；用户可通过排序调整。
5. 分类内核只接收已取得的事实，不请求 TMDB、115，不读文件、不移动文件。分类测试与正式整理共用同一内核。

| YAML 条件 | 输入类型 | 现有 TMDB 字段 | 示例 |
| --- | --- | --- | --- |
| `genres` | 正整数列表 | `Detail.Genres[].ID` | `[16, 99]` |
| `origin_countries` | 两位国家代码列表 | `Detail.OriginCountryCodes` | `[JP, KR]` |
| `production_countries` | 两位国家代码列表 | `Detail.CountryCodes`，来自 `production_countries` | `[US, GB]` |
| `languages` | 原始语言代码列表 | `Detail.OriginalLanguage` | `[zh, cn]` |

国家代码按大写、语言代码按小写比较，配置及事实中的代码去除首尾空白后规范化；同一列表规范化后不允许重复。代码采用 TMDB 的两位字母值，包括现有华语判断使用的 `zh` 和 `cn`；不把配音、字幕或地区名称当作语言条件。页面显示中文名称，YAML 保存代码或类型 ID。

第一版只开放上述四种条件。年份范围、评分、演员、关键词、正则、嵌套逻辑和可执行表达式留在范围之外。

## 默认行为与目录边界

默认规则保留现有电影的动画、华语、其他分类；剧集保留动漫、纪录片、综艺、国产、日韩、欧美及其他分类。类型优先于地区，动画纪录片优先归动漫。华语电影继续按原始语言 `zh`、`cn` 判断。

现有多国剧集是按上游国家数组先后决定地区，新规则改为按配置顺序决定；这是本轮明确的行为调整。除该多国交叉情况外，默认分类应与现有函数一致。

`path` 和 `fallback` 统一使用 `/` 表达多级目录。拒绝绝对路径、盘符或 UNC 路径、反斜线、空路径段、`.`、`..`、控制字符以及现有公共命名路径规则不接受的目录名。不得通过路径清理把非法输入转换为其他有效目录；输出必须位于调用方目标根目录内。

## 后续保存与编辑约束

- 全局配置以 YAML 文件为唯一来源，不另存一份数据库全局配置。批次中的不可变规则快照用于重启和重试，不能反向修改全局配置。
- 加载和保存严格检查字段与类型，拒绝重复键、未知字段、多份 YAML 文档、别名、合并键及自定义标签；不静默忽略拼写错误或其他格式。
- 首次缺少文件时创建默认配置；已有配置损坏时不覆盖为默认。保存或重新加载失败保留最后有效快照并明确报错；没有有效快照时禁止启动需要分类的任务。
- 可视化和源码使用同一份编辑文档，保留普通注释及规则顺序，允许统一格式。不能通过转为普通 JSON 再整体序列化的方式丢弃注释。
- 源码未通过语法与结构校验时保留原文，显示行列及字段位置；修正后才切回可视化或保存。切换模式本身不保存配置。
- 保存基于所读取的版本校验，防止多个页面或外部修改互相覆盖；成功写入后才替换内存快照。运行中的批次继续使用原快照。
- 前端继续使用现有蓝色与中性色、SVG 图标及深浅主题；C-05/C-06 的具体页面交互再交由 Gemini CLI 讨论和审查。

## C-01 自查

- 一个动画且原产地为日本的剧集只命中顺序最前的对应规则；默认文件将其归入 `剧集/动漫`。
- 类型同时含动画与纪录片时归动漫；真人秀或脱口秀任一类型可命中综艺。
- 原产地 `[JP, CN]` 与 `[CN, JP]` 在默认规则下均归国产剧。
- 只有制作国家为日本、缺少原产地的作品不命中日本原产地条件。
- 缺少类型、国家或语言不猜测补全；无规则命中进入当前类型的兜底目录。
- 空规则列表有效，空 `match`、空条件列表及越出目标根目录的路径无效。

C-01 交付配置约定与唯一默认 YAML，不改变现有自动整理行为。解析内核、保存接口、页面与实际整理接入由后续任务完成。
