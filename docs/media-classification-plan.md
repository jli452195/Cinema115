## C-01 YAML 结构

默认文件位于 `backend/internal/mediacategory/default.yaml`，内核直接嵌入此文件，不在文档、Go 代码或前端重复维护默认规则。C-03 已将运行时可编辑文件放入现有持久化数据目录，文件名为 `classification.yaml`；C-04 已接入通用自动整理。

顶层仅有 `version`、`movie`、`tv`；`version` 必须为整数 `1`。`movie` 和 `tv` 都必须提供 `fallback` 与 `rules`，其中 `rules` 可显式填写为空列表。每条规则包含 `name`、`path` 和 `match`。

| 字段 | 含义 | 校验 |
| --- | --- | --- |
| `fallback` | 当前类型未命中时的分类目录 | 非空相对目录 |
| `rules` | 按优先级排列的规则列表 | 顺序就是优先级 |
| `name` | 页面显示及结果解释使用的规则名 | 非空，同一作品类型内唯一 |
| `path` | 命中后的分类目录 | 非空相对目录 |
| `match` | 同时满足的匹配条件 | 至少一个已支持的条件 |

例如将日本动漫与其他动漫分开，只需将默认的动漫规则替换为以下两条，保留其他剧集规则：

```yaml
- name: 日本动漫
  path: 剧集/日本动漫
  match:
    genres: [16]
    origin_countries: [JP]
- name: 其他动漫
  path: 剧集/其他动漫
  match:
    genres: [16]
```

这里的“其他动漫”是前一条未命中后继续判断的结果，无需额外的排除条件或逻辑表达式。

## 匹配语义与字段来源

1. 先按作品类型选择 `movie` 或 `tv`，按规则顺序判断，第一条完全命中立即返回；全部未命中返回该类型的 `fallback`。不支持的作品类型报错，不自动归入剧集。
2. `match` 中不同字段是 AND，同一字段列表内是 OR。类型、国家等多值作品字段与配置列表存在交集即满足该条件。没有填写的条件不限制；显式空列表或 `null` 报错。
3. 作品缺少某项事实时，对该字段的条件不命中；继续后面的规则或兜底。原产地、制作国家、原始语言互不推断，不自动补为同一种国家信息。
4. 多国合拍时仅按 YAML 规则顺序决定，不受 TMDB 国家数组顺序影响。默认优先级为国产剧、日韩剧、欧美剧；用户可通过排序调整。
5. 分类内核只接收已取得的事实，不请求 TMDB、115，不读文件、不移动文件。分类测试与正式整理共用同一内核。

| YAML 条件 | 输入类型 | 现有 TMDB 字段 | 示例 |
| --- | --- | --- | --- |
| `genres` | 正整数列表 | `Detail.Genres[].ID` | `[16, 99]` |
| `origin_countries` | 两位国家代码列表 | `Detail.OriginCountryCodes` | `[JP, KR]` |
| `production_countries` | 两位国家代码列表 | `Detail.CountryCodes`，来自 `production_countries` | `[US, GB]` |
| `languages` | 原始语言代码列表 | `Detail.OriginalLanguage` | `[zh, cn]` |

国家代码按大写、语言代码按小写比较，配置及事实中的代码去除首尾空白后规范化；同一列表规范化后不允许重复。代码采用 TMDB 的两位字母值，包括现有华语判断使用的 `zh` 和 `cn`；不把配音、字幕或地区名称当作语言条件。页面显示中文名称，YAML 保存代码或类型 ID。

第一版只开放上述四种条件。年份范围、评分、演员、关键词、正则、嵌套逻辑和可执行表达式留在范围之外。

## 默认行为与目录边界

默认规则保留现有电影的动画、华语、其他分类；剧集保留动漫、纪录片、综艺、国产、日韩、欧美及其他分类。类型优先于地区，动画纪录片优先归动漫。华语电影继续按原始语言 `zh`、`cn` 判断。

现有多国剧集是按上游国家数组先后决定地区，新规则改为按配置顺序决定；这是本轮明确的行为调整。除该多国交叉情况外，默认分类应与现有函数一致。

`path` 和 `fallback` 统一使用 `/` 表达多级目录。拒绝绝对路径、盘符或 UNC 路径、反斜线、空路径段、`.`、`..`、控制字符以及现有公共命名路径规则不接受的目录名。不得通过路径清理把非法输入转换为其他有效目录；输出必须位于调用方目标根目录内。

## 后续保存与编辑约束

- 全局配置以 YAML 文件为唯一来源，不另存一份数据库全局配置。批次中的不可变规则快照用于重启和重试，不能反向修改全局配置。
- 加载和保存严格检查字段与类型，拒绝重复键、未知字段、多份 YAML 文档、别名、合并键及自定义标签；不静默忽略拼写错误或其他格式。
- 首次缺少文件时创建默认配置；已有配置损坏时不覆盖为默认。保存或重新加载失败保留最后有效快照并明确报错；没有有效快照时禁止启动需要分类的任务。
- 可视化和源码使用同一份编辑文档，保留普通注释及规则顺序，允许统一格式。不能通过转为普通 JSON 再整体序列化的方式丢弃注释。
- 源码未通过语法与结构校验时保留原文，显示行列及字段位置；修正后才切回可视化或保存。切换模式本身不保存配置。
- 保存基于所读取的版本校验，防止多个页面或外部修改互相覆盖；成功写入后才替换内存快照。运行中的批次继续使用原快照。
- 前端继续使用现有蓝色与中性色、SVG 图标及深浅主题；C-05/C-06 的具体页面交互再交由 Gemini CLI 讨论和审查。

## C-02 分类内核

模块：`backend/internal/mediacategory`，仅依赖现有 YAML 库及公共命名目录校验；不依赖 TMDB 客户端、服务层、数据库或网盘。现有 `yaml.v3` 由间接依赖调整为直接依赖，未新增版本或引入其他库。

- `DefaultYAML()` 返回唯一内置默认文件内容。
- `Compile(source)` 一次解析并完整验证 YAML，成功后返回不可变的 `Classifier`。文档上限 256 KiB；拒绝未知字段、重复键、错误标量类型、缺失字段、空匹配、空条件列表、规范化后重复的代码、别名、锚点、合并键、自定义标签和多文档。
- `Classifier.Classify(facts)` 按作品类型与规则顺序计算，返回 `path`、`ruleName`、`fallback`。输入包括 `kind`、类型 ID、原产地代码、制作国家代码和原始语言；输入切片不被修改或持有。已编译规则可并发复用，分类时不再次解析 YAML。
- 字段错误提供 `ConfigError` 的字段位置、行、列和原因，可用 `errors.As` 读取；语法错误保留 YAML 解析器的诊断。配置与事实错误分别支持 `errors.Is(err, ErrConfig)`、`errors.Is(err, ErrFacts)`。
- 分类目录复用 `naming.ValidateDirectory`，与字幕伴随命名共用既有路径段校验。校验不清理或改写配置路径，保留 240 字节目录段限制及跨平台目录名约束。

编译只读取调用方传入的源码，不重新输出 YAML；源码与注释仍由调用方保留。C-03 管理持久化与快照，C-04 已替换自动整理中的旧分类函数；前端编辑文档由 C-05/C-06 接入。

## C-03 文件保存与内存快照

由 `service.MediaClassification` 管理 `DATA_DIR/classification.yaml`，服务启动时装配，并注册在现有管理员鉴权路由下。全局规则只存这一份文件，不新增数据库表、文件监视器或后台轮询。

| 接口 | 用途 |
| --- | --- |
| `GET /api/admin/classification` | 返回磁盘原文、文件版本、当前生效版本、校验错误及内置默认模板；读取不会激活外部修改 |
| `PUT /api/admin/classification` | 提交 `yaml` 和读取时的 `revision`，校验、保存并激活 |
| `POST /api/admin/classification/reload` | 显式重新读取磁盘规则，校验通过后激活 |

- 版本使用原始文件内容的 SHA-256，注释、换行及格式原样保留。文件不存在时版本为空字符串；已有空文件有自己的内容哈希。
- 保存前编译全部规则，同一进程内串行校验磁盘版本，再写临时文件、同步关闭、复查版本并替换。初次创建不覆盖同时出现的文件，保存失败清理临时文件。相同内容的重复提交可确认此前保存结果，不重复写入。
- 页面版本过期返回 `409 REVISION_CONFLICT`；错误 YAML 返回 `400 INVALID_CLASSIFICATION`，字段错误附带字段、行列诊断；请求体上限 1 MiB，YAML 原文仍限制 256 KiB。文件 I/O 错误不向接口暴露内部路径，响应禁止缓存。
- 坏 YAML 仍可通过读取接口取得原文和版本，修正后正常保存。重新加载或保存失败不丢失最后有效内存快照。启动时已有文件损坏不覆盖为默认，管理接口继续可用；从未成功加载时 `Snapshot()` 明确报错。
- `Snapshot()` 只读内存，不读文件或编译 YAML，取得的快照不会随后续保存变化。C-04 已将它固定到整理批次并保存，以支持重启、修正和重试。
- 外部编辑后需显式重新加载或保存才生效。版本复查可发现读取后的外部改动，但不提供与任意外部编辑器协作的跨进程文件锁；请避免同时在页面和外部编辑器保存。
