# 动漫下载：资源目录与一次文件清单（P2-07）

日期：2026-10-20。进度见[任务表](anime-subscription-tasks.md)。按用户最新要求收敛为下载、整理，尽可能少请求115；本项不实现P3改名、移动，也不开放公开下载开关。

## 本步实现

复用现有下载任务、115客户端和UID/资源协调，SQLite升至v50，只给 `anime_download_jobs` 增加两个JSON列：

| 字段 | 用途 |
| --- | --- |
| `directory_operation_json` | 单次目录创建许可、结果与未知回执恢复记录 |
| `files_json` | 一次取得的文件ID、父级、名称、类型、列表附带大小和收集时间 |

不增加文件注册表、第二套任务队列或常驻文件扫描循环。清单是本次执行的历史快照，不是网盘实时索引；不包含Cookie、签名、直链或文件SHA1。资源BT info-hash仍用于既有资源幂等，与文件内容校验无关。

`file_state=verified`沿用已存在的状态枚举，现在仅表示“文件清单已收集”，不表示校验过文件内容。根目录ID和名称来自已保存的创建回执，清单项来自该ID的有界目录列表，不伪称重新读取了根目录的当前路径。

### 目录创建

每个下载任务使用固定 `anime-<随机任务ID>` 子目录，在固定主账号与固定下载父目录创建。先在事务中记录唯一创建许可，再发送一次POST。成功回执中的合法CID直接保存，接着提交下载，不补发目录元数据查询或父目录扫描。

超时、取消或回执丢失后保留未知记录，下一次仅列固定父目录，找到唯一完全同名目录才绑定；列表已经包含ID、类型、名称和父级，不再追加GET。没有结果、重名、缺页或读取异常都不重新创建。固定父目录最多4096项、每页100项，45秒预算；不是全盘或模糊搜索。

创建许可、账号、UID、目录及代次在本地事务复核；凭据固定在内存会话，网络访问不持有数据库事务。创建后账号发生变化则受阻，不切换到其他账号。

### 下载完成后的收集

现有状态追踪保存远端completed后，直接调用 `CollectDownloadedFiles`，只列已绑定的任务子目录。结果ID等于根目录时直接复用该页；结果ID是直接文件时保存该行；结果是内层目录时只继续列该结果树。所有文件复用列表行，不逐文件GET，不读取或比对SHA1，也不通过下载正文判断身份。

每页100项，最多512个对象、32个目录、8层和45秒。重复项、分页数量变化、错误父级、目录跳转、结果ID不在任务目录、空文件集合或读取失败都保留待处理，停止该条自动查询，后续由显式恢复处理；不启动另一个后台检查器。

清单保存、结果类型、停止离线轮询在同一事务提交，并校验已确认提交记录、固定账号、任务版本与代次。旧回执、任务状态冲突或不完整清单不能推进完成。

| 情况 | 正常请求量，不含既有离线状态查询 |
| --- | --- |
| 创建资源子目录 | 1次POST，成功后0次补查 |
| 结果是任务目录内的文件 | 通常1次目录列表 |
| 结果就是任务目录 | 通常1次目录列表 |
| 结果是任务目录内的子目录 | 通常2次目录列表 |
| 多页或嵌套目录 | 仅增加必要页/子目录列表 |
| 已收集完成，再次触发或用户二次整理 | 0次115请求 |

应用装配的文件客户端不在405/429后立即重试，沿用客户端冷却并将本次失败留待显式恢复。正常任务不预先扫父目录，不逐文件读元数据。

未配置命名时保存清单后以 `original_saved` 结束；已配置命名时保留active、文件清单就绪，等待P3原文件改名/移动，离线状态仍停止轮询。

## 后续计划调整

P2-08已接入[执行恢复](anime-download-recovery-implementation.md)：正常提交直接记录成功回执，不立即精确查询；首次状态检查至少两分钟后，等待任务五分钟、下载中两分钟并有错峰，异常退避。恢复目标不再读取父目录；已保存completed及结果ID的任务直接收集文件。复用同一任务租约和追踪循环，无新增队列、表或循环。

P3复用同一任务的文件清单和操作记录，目录缓存与同目录冲突列表按批次共享，尽量批量改名、移动。明确成功回执即完成该步骤，不追加正常读回；只有超时、回执丢失等未知结果才按固定对象最小补查。改名/移动全部成功后结束，不复制视频再删除原文件。

结束后不查询115离线列表或文件位置，不检查原位置是否仍有文件，不跟踪用户后续的二次整理、改名、移动或删除，不恢复原目录或自动重下。保留本地资源处理与完成记录，避免RSS或115历史被清理后重复提交。页面只读本地执行历史，完成路径不承诺是文件的实时位置。

以上替代P0草案中的独立文件注册表、独立后处理队列、逐文件SHA1及成功后的强制读回；旧DDL保留为历史材料，实际结构以Go迁移为准。

## 验证

新增16项顶层测试：客户端3项、存储6项、服务7项。专项五轮、相关12包完整测试及vet、全后端编译通过；修改目录回执复用后亦包含在完整回归中。覆盖：

- 单次创建许可并发单胜、先持久化再写入、成功创建后不读目录、超时/取消后仅只读恢复。
- 文件、根目录及内层目录结果；正常请求数、分页/树完整性、越界、状态冲突和账号变化。
- 收集后停止离线轮询；重复调用与二次整理不访问115。
- 旧版本/代次和未确认提交拒绝、写回失败回滚、真实关闭重开以及v49→v50保留任务。
- SHA1字段即使缺失、格式异常或别名互相不同也不参与解析决策；文件模型不保存该字段。

本机CGO关闭且没有C编译器，未运行race；并发许可行为以常规测试验证。

受控实站只读共3次GET：5条任务列表、一个完成结果目录的精确元数据、该目录的一页列表。使用唯一明确主账号，在只读SQLite中取凭据并在内存核对UID；固定HTTPS主机、拒绝重定向、最多3次、遇错停止，不输出实际标识、名称或凭据。

结果：任务结果ID与目录ID相同，父级与任务下载目标相符，目录列表可由本步客户端成功解析，返回0项。因为没有子文件，探测在“无子文件样本”处停止，未通过完整子文件样本验证；没有继续扫其他目录或新增下载补样本。报告不将空目录、模拟测试或历史离线记录包装成真实文件下载成功。未执行真实创建、下载、改名、移动或删除；公开下载/整理能力仍关闭，完整流程验收留在P2-12/P3。
