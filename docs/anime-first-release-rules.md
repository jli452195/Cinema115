# 动漫订阅首版规则与阶段边界（P0-04）

日期：2026-10-18。依据[总体方案](anime-subscription-plan.md)及 [Bangumi](anime-bangumi-api.md)、[蜜柑](anime-mikan-api.md)、[115](anime-p115-api.md)验证报告。本文件固定后续实现采用的首版行为，不代表业务代码或页面已完成；DDL、状态字段与 API 细节见 P0-05 的[数据与接口契约](anime-subscription-contract.md)。

2026-10-20 用户修订：115 请求尽量少。下载完成只列任务目录和必要结果子目录一次，不逐文件取元数据、不读取或比对文件 SHA1。正常创建、改名与移动信任明确成功回执，回执不明才按固定对象补查；目录与冲突列表按批次复用。整理结束即终态，之后用户二次整理、移动、改名或删除均不复查、不定位、不恢复、不自动重下。此修订优先于下文旧版严格读回要求；任务执行进度见任务表。P2-08已将提交成功后的检查合并至首次状态追踪，恢复会话及换号仅做本地检查；换号后重新选择目录，不新增探测或迁移。

## 1. 来源、画质与标题条件

一个订阅绑定具体篇章/发行版本，包含一个主 RSS 和可选备用 RSS 列表；每条 RSS 分别绑定已确认的蜜柑条目及该条目实际提供的一个发布组 ID。联合发布组按上游组 ID 整体处理，不拆开，不从标题方括号猜组，不把同系列篇章自动合并。

### 1.1 主 RSS、备用 RSS 与版本共存

参考 ANI-RSS 的“多字幕组共存模式”，主、备用 RSS 中符合各自已确认规则的资源都可下载，不等待主源失败或某集缺失后才允许备用源。主/备用用于组织配置和展示，主源不是覆盖其他版本的优先权；不提供洗版开关。

- 首版一个主 RSS、最多 4 个备用 RSS，数量上限是实现保护默认；备用可为空。每条 RSS 都有独立的条目、组、筛选、起始下限、编号对应、启用状态与检查记录。
- 首版限已验证的蜜柑来源。支持从条目/组生成 RSS；粘贴蜜柑 RSS 时校验为同一受控来源并确认条目/组，不接受任意外部 URL。其他站点适配留到扩展，不影响主/备用配置先实现。
- 主源与备用源均可来自不同已确认蜜柑条目或组，但必须属于当前篇章/发行版本。相同规范化 RSS 不重复配置；不同 RSS 不能因为名称相同而共享编号偏移。
- 添加备用源逐条配置和预览；未确认的备用源只保留配置，不参与下载，不阻塞已确认主源。卡片显示中性“未配置草稿”状态并允许单独移除。删除/停用一条 RSS 只阻止它的新意图和写阶段，保留其在途核对、已存文件与处理历史。
- 主源读取失败不阻止其他已启用来源；单源故障/冷却分别记录，共享站点限流仍对所有来源生效。暂停整个订阅才暂停所有来源。
- 每条 RSS 可采用不同字幕组标题编号，例如主组第 25 话、备用组第 1 话都对应篇章第 1 集。两份资源可共存，编号对应只决定归属、展示与可选命名，不用于跨组互斥。

卡片以主源概况和“备用 N 个”摘要展示；详情按来源展示规则、读取状态、已选数量和实际字幕组，避免把主源失败显示成全部来源停止。源列表说明“主、备用均会按规则下载，已有版本保留”。

### 1.2 每条 RSS 的画质与标题条件

跨篇章来源必须确认适用编号范围或其他可靠范围条件，不能只填“从 25 开始”就接收所有后续篇章。未确认来源/范围时仅将该来源保存为草稿，不阻塞其他有效来源；新建订阅仍须先配置有效主源。没有 TMDB 仍能配置并在 P2 启用下载。

| 条件 | 首版规则 |
| --- | --- |
| 画质初值 | 不替管理员预选；必须明确选一个标题画质或“不限制” |
| 标题画质选项 | 720p、1080p、2160p、不限制；按明确的标题标记识别，`4K` 可归为 2160p，不能把编码、年份、文件大小当画质 |
| 明确画质 | 未识别、多个冲突画质标记不满足精确条件；不自动回退其他画质，1080i 不当 1080p |
| 不限制 | 不按画质排除；符合其他条件的不同 Hash 都可以保存，同集也不互斥。需要限定版本时使用画质/关键词条件或历史清单选择 |
| 包含关键词 | 可空；所有非空词都要出现在同一原始标题中 |
| 排除关键词 | 可空；任一词出现就排除，排除优先于包含 |
| 文本匹配 | 去词首尾空白，仅 ASCII 大小写不敏感，其余文字、空格和标点按字面子串匹配；不解释 `*` 等模式语法 |
| 规则上限 | 包含/排除各最多 10 个去重词，每词最多 64 个 Unicode 字符；空词移除，超限明确拒绝 |
| 高级规则 | 首版不提供任意正则、脚本或自动编码择优；本项目不提供自动洗版、替换或删除已有版本 |

画质、语言和编码标签来自发布标题，表示筛选依据，不宣称已检测视频流。可用关键词进一步限定简繁、编码或来源特征；不根据第一次点中的资源悄悄新增过滤条件。

匹配顺序固定为：来源/组 → 原始编号解析 → 版本/篇章范围 → 该来源持续下限与首次范围 → 排除/包含词 → 标题画质 → 发布/Hash 幂等判断 → 保存决定。预览保留每步结果，展示最先阻止执行的原因；未知编号、归属不明与“被过滤”分别记录。

首版自动处理 BT v1 单集资源。RSS GUID、Episode 路径、种子 URL 文件名均不直接充当已验证 Hash；优先复用已核验网页磁力与对应关系，必要时 P2 仅对实际选中资源受控读取种子元数据、计算 info-hash。预览不逐行下载种子，不读视频正文；身份核验失败或协议不支持就不提交 115。

## 2. 编号、起始值与同集版本

每条 RSS 的持续下限使用该字幕组原始正片整数编号，允许 1～99999，包含本集。常规输入初值为 1；只有已确认“源第 25 话 = 篇章第 1 集”时，才向管理员建议用 25 作为当前篇章起点，保留其实际输入，不从最小已见编号或缺第 1 集推断偏移，也不将主源下限原样套给另一个编号体系。

**持续下限与对应基准分开保存**。例如来源 25 对应篇章第 1 集/目标 S02E01，选择从 30 补，第一条可执行资源为来源第 30 话，已确认的目标回显仍为 S02E06；不能把 30 重新解释为 S02E01。TMDB 对应只影响 P3 命名，不影响下载是否需要它。

12.5、SP、OVA、A/B 后缀、复合编号、合集、多集范围、样片、无可靠编号等保留原文及类型；首版不自动作为普通正片整数集提交。P3 支持的特别篇逐集指定用于已确认文件的命名，不使 P2 未支持的资源自动获得提交资格；无法唯一对应或需要切割/合并的文件仍不自动整理。

| 同集情况 | 决定 |
| --- | --- |
| 同一个已验证 Hash 被重复轮询，或出现在多个发布记录 | 处理记录和提交意图幂等；保留来源关联，不反复提交同一资源 |
| 同集来自两个字幕组、两个不同 Hash 均符合条件 | 两份都允许；首次历史按各来源确认清单选择，不因另一组已下载而排除 |
| 同组同集不同画质、编码或 v2，Hash 不同 | 不按集号拦截，也不自动挑一个替换另一个；条件通过时可保存多份，旧文件保留 |
| 该 Hash 已排队、结果不明、下载中或已完成 | 不因新一轮轮询再建同资源任务；不影响同集其他 Hash |
| 管理员重试同一失败 Hash | 先核对前次尝试与 115 结果，再显式建立新尝试；不是用另一个资源覆盖旧文件 |

发布时间和稳定标识只用于列表排序，不实现版本优胜或互斥。只保留资源 Hash、来源发布和操作幂等约束，不建立“篇章+集号只能有一个资源”的占位/唯一约束。修改筛选、解析升级、暂停恢复和移除重建均不能清空同一资源的处理依据。

同一 UID、协议、Hash 的外部任务协调仍遵守 P0-03：本工具之外的已有任务或不同目标归属不明时保持待核对，不盲目接管或重提。这里限制的是同一外部资源的写操作，不是同一集或同一字幕组的其他版本。

## 3. 首次历史与读取预算

默认模式为“从指定集数补已有资源”；保留“仅新发布”和“选择当前历史资源”两种明确选项。初批只使用有效预览中已选发布，记录实际集号与跳过原因，不把未加载部分变成后台全量补番。

只读取已配置来源及组，不做全站或所有组预抓。主源、备用源逐条复用缓存并按需预览；每次继续加载明确针对哪条 RSS，预算在本次操作内共享，不能因为备用源数量增加而一次展开所有历史。需补历史时使用累计 `take` 展开，沿用页面经校验的下次值或本地 `take+50`；不能把累计结果当作增量直接追加。RSS 本身不证明历史读完整。

| 项目 | 首版默认预算 |
| --- | --- |
| 每次生成/继续历史预览 | 最多 3 次未命中缓存的来源元数据请求，整体最多 45 秒，单请求最多 20 秒；无自动立即重试 |
| 正文预算 | 单响应最多 4 MiB，每次操作总读取最多 8 MiB；达到上限明确为未读完整 |
| 条数保护 | 单响应最多 2000 条原始发布；同一创建/编辑预览各来源已加载快照合计最多 2000 条，包含过滤及待确认行，不按 Hash 合并后计算；累计请求 `take` 不大于 2000，先校验再请求 |
| 来源协调 | 同一蜜柑站点请求至少间隔 1 秒，交互/后台共享限流、进行中合并与冷却，不因多订阅并发绕过 |
| 预览有效期 | 每条来源从各自首次成功生成起绝对 15 分钟；继续加载不延长，过期保留输入/已选身份并重新预览；整体预览只汇总各来源有效期，不共用或续期 |
| 页面投影 | 资源列表每页默认 50 条；保存稳定选择，不用“只返回这一页”冒充只选这一页 |

这些是新动漫模块预算，不修改现有蜜柑网页客户端的 16 MiB 或 `take<=10000` 保护，也不声称上游支持精确这些数值。读取到更早内容需管理员继续加载；到硬上限后保持已加载范围，可按当前选择继续，不自动扩大预算。

完整响应必须先校验结构和原始行数，再合并发布身份。只有解析可靠且原始行数小于请求 `take`，才可表述“已读到本次来源的可见末尾”；取满、坏行、异常、无进展或列表变化都不能推断全部历史完整。新发布导致累计前缀变化时保留已选身份并刷新摘要，不静默改变已确认的初批清单。

预算耗尽前完整取得的页面可以保留为部分历史预览；中止的响应不参与新清单或末尾判断。首次来源读取失败不能建立历史基线；从未取得有效预览时保留输入、禁用首次启用，提供重试或保存暂停。继续加载失败但已有未过期有效预览时，可保留明确清单并说明本轮未加载成功，不能把它改成无资源。未加载集数不标缺集；已加载范围内的缺口只表示当前来源/条件未找到。

### 3.1 初批与日后新发布的边界

各来源首次成功预览分别固定时间边界 T0、已见发布身份集合、所选历史清单及来源/规则/目录版本；新增备用源有自己的基线，不继承主源的已见集合或起点。整体预览记录本次涉及哪些来源及各自版本/有效期，首次启用的每条来源都必须有效。新增发布不会自动修改初批清单；来源规则、账号目录版本变化或该预览超时才需重新预览。保存/启用前服务端仍校验有效版本，不能只信前端状态。

P0-05 明确时间含义：T0 取首读有效快照的实际成功读取时刻，并按来源发布时间精度取整；缓存命中沿用该 observedAt，不把页面生成时刻当作新读取。预览绝对15分钟另从首次成功生成时计算，普通规则编辑与恢复不重置已确认 T0。保存草稿/暂停只保留表单选择，实际基线和初批执行决定到首次启用时才提交。

- 默认补历史：只对确认清单建立初批意图；未加载旧资源不自动加入。
- 仅新发布：首读结果作为历史基线，本次初批数量为 0。
- 选择当前历史资源：只对逐条选中的发布建立初批意图。
- 三种模式都持续检查 T0 之后的新发布，并遵守同一篇章范围、字幕组、起始下限及条件；预览至启用之间发布的资源不会因采用启用时刻而被跳过。

蜜柑 `torrent/pubDate` 无时区。首版**明确采用 `Asia/Shanghai` 解释无偏移时间**，属于来源适配默认值，不是 P0-02 已证明的事实；保留原文与解释版本，不使用浏览器或后端机器时区。自带偏移时尊重偏移，HTML 分钟时间不覆盖 RSS 时间，不擅自拼成 UTC。

只有“未在基线中、发布时间可解析且不早于 T0、没有超出本轮读取时间 5 分钟、其他条件明确通过”的资源进入正常新发布选择。时间缺失、冲突、异常、早于 T0 的补录或可疑未来时间保留待确认，不以第一次看到直接认定新发布。后续时间解释变更需预览边界影响，不能清空历史重跑。来源窗口截断或长时间暂停导致覆盖不明时展示检查范围，不承诺追齐全部遗漏。

## 4. 预览与保存结果

后续页面沿用总体方案的渐进配置和通用卡片，不新增视觉组件。本节固定交互语义；页面实现后的 Gemini CLI 审查仍在 P1/P2/P3。下表的读取、匹配与待确认结果按来源判断；首次启用校验本次选择启用的来源，未完成的备用源保持草稿，不将它的失败扩成整个订阅无法保存或启用。

| 情况 | 操作与结果 |
| --- | --- |
| 没有有效主源、发布组或可靠篇章范围 | 继续配置/保存草稿，不显示已启用；未配置完成的备用源不阻塞其他有效来源 |
| 有完整配置但首次来源读取失败 | 重试；可保存暂停，不创建下载意图 |
| 有效预览且明确匹配 0 条、无待确认项 | P2 可“启用并等待资源”，说明本次 0 条；也可保存暂停 |
| 没有可执行资源，但有解析/归属待确认项 | 主操作查看待确认，可保存暂停；不包装成普通零匹配后直接启用；多个符合条件的 Hash 本身不算歧义 |
| 有已选 N 条，另有 M 条待确认 | P2 可启用并下载已选 N 条；摘要同时显示 M 条待确认，它们不会被提交 |
| 部分历史未加载或读到预算 | 可继续加载；也可在说明边界后启用当前明确选择，不要求加载完整历史 |

“N 条”指选择的发布，不表示 N 个实际文件、N 个新任务或 115 已成功接收 N 次；多个发布核验为相同 Hash 时关联同一资源任务。按来源展示数量，同集不同版本单列，不将它们统计为多个已确认剧情集。保存成功后分别反馈已建立任务、已关联既有任务、待核验/提交、已接受数量，异步失败保留到任务详情。不能把解析不明或上游失败合并成“0 条”。

普通零匹配使用中性次要文字“当前条件下暂无匹配发布”，不使用黄色警告或整卡警报。P1 配置完整时主操作固定“保存配置”，结果为暂停配置；不渲染禁用的“启用/下载”占位，配置不完整才显示保存草稿。P2 有资源时主操作“启用并下载已选 N 条”，待确认 M 条放在邻近说明，不塞进冗长按钮；零匹配为“启用并等待资源”。

按实际选择数量显示动作摘要，跨页选择始终保留；勾选项明确为“选择当前来源已加载的 N 条匹配发布”，禁止孤立“全选/下载全部”，页面 50 条不是选择边界。取消勾选只排除本次具体发布，不暗中增加永久集数/关键词排除规则；这次明确取消的发布不能在下一轮又自动选中。预览过期显示“预览需要更新，你的选择已保留”，提供重新预览，未真正核对前不提示“已自动核对”。规则改变或保存失败也保留输入、选择和滚动；重新预览后按稳定发布身份核对变化，不把后来才出现的历史条目自动加入确认清单。

新建时“保存为暂停”只保存配置及本次输入，不创建云端或本地待提交下载任务；第一次启用仍需有效预览。已启用过的订阅暂停时，已经确认的任务意图保留，恢复按第 5 节处理，不能将确认后的执行计划因预览过期而丢弃。

## 5. 暂停、恢复与结束

暂停停止自动抓取、领取新提交意图及新的网盘写阶段。手动“检查更新”仍可只读更新候选；不隐式提交、改名或移动。暂停不是停止 115 已接收的离线任务。

| 所处阶段 | 暂停后的行为 |
| --- | --- |
| 尚未领取/尚未获准写入 | 保留队列与资源幂等记录，不发新的提交、建目录、改名或移动请求 |
| 已发出或已获准的单个外部写操作 | 允许完成该操作的结果确认与持久化，不启动下一个写操作；无法确定则保留待核对 |
| 115 已接受、下载中 | 继续只读追踪，取得完成文件事实；到“待整理”后等待恢复 |
| 改名已完成、移动未开始 | 保留部分阶段与原文件 ID，暂停移动；已确认改名不补查，只有未知步骤才读回再接续，不从头重放 |
| 原名保存已核对/整理已完成 | 保持终态，不因暂停恢复或检查更新重新轮询、下载或整理 |

暂停事务使旧领取代次失效，写阶段在共享协调内复核状态/版本。暂停响应说明“已停止后续提交，正在执行的操作会确认结果”，不能承诺撤回已发请求。已签发单个写操作与后续阶段分开处理，浏览器关闭不会丢弃结果。

恢复前校验来源规则版本、明确主账号、实际 UID、凭据可用性与目录归属。未变更的已确认本地任务可继续，写入结果不明的先对账，已完成的不重开。暂停期间待发现的新发布沿用 T0 和已见记录检查；不把恢复时刻当作新起点，也不自动加载更早历史。

修改某来源的组、编号范围、筛选或下限需要该来源的新预览；旧的未提交选择不能套用新规则继续执行。已接受下载保留原尝试快照和追踪；相同 Hash 已处理时说明关联结果，不删除完成记录，不将同集其他版本当作冲突。暂停后的显式写入重试也要求先恢复并通过后端校验，不能借“重试”绕过暂停。

归档停止采集和新写阶段、保留历史；移除取消未执行意图、保留未结束任务入口与文件。二者均继续必要只读核对，不清空 115 任务或删除云端文件。失败由管理员显式重试，首版不自动删除任务重提、不跨账号重试；其他已配置来源继续自己的订阅，不承担覆盖该失败资源的替换流程。

离线完成并核对到实际文件后，停止该条离线状态轮询。原名保存到此结束；启用整理则只推进原文件改名/移动，正常成功不再读回，成功后停止该条调度，保留去重记录。附件、空目录及其他版本不随视频移动自动删除，115 列表记录也不要求自动清除。

## 6. 调度与请求默认值

| 项目 | 默认值与边界 |
| --- | --- |
| 启用订阅 RSS | 主源、已启用备用源各 15 分钟一次，加入不超过 60 秒错峰；相同来源/组共享读取，不逐卡请求 |
| 手动检查 | 同来源/组 60 秒内复用最近有效结果；已有请求则合并，失败冷却不因点击重置 |
| 来源失败 | 保留旧成功快照，依次至少 1、5、15、30 分钟退避，之后最多每 30 分钟一次；成功恢复正常周期 |
| 401/403/风控 | 标为来源不可用，暂停自动请求；显式恢复后才作一次受限探测，不循环撞鉴权错误 |
| 429 | 遵守 Retry-After 且共享来源冷却，不能由手动检查旁路 |
| 115 活跃离线任务 | 仅到期未完成任务精确查询；下载中约2分钟，等待约5分钟，异常退避，同UID共享预算及冷却，不扫描完整列表 |
| 115 已完成/未知写入 | 已完成并取得一次清单就停；未知写入只读对账，不能因重试次数达到阈值就重放写入 |
| 页面状态 | 仅可见列表/详情约 30 秒读取本地状态；切回先恢复成功缓存，后台页面停止轮询，上游调度不依赖页面 |
| 网盘写入 | 同一实际 UID 保守串行，手动与自动共享对应资源/目录协调；任务固定凭据和目标，不中途换号 |

这里是首版实现默认值。缓存、退避和预览的结构化字段在 P0-05 固定，性能与失败行为需 P1/P2 验证；不将这些数值写成上游服务承诺。

## 7. 分阶段交付

| 阶段 | 实际交付 | 启用/完成边界 |
| --- | --- | --- |
| P1 | 周历、历史搜索、主/备用 RSS 与独立规则预览、草稿与暂停配置、列表恢复 | 不提交 115、不建云端目录；仅提供保存配置，不展示“启用并下载”占位，也不伪造已启用运行状态 |
| P2 | 自动发现、持久化去重与提交意图、主账号目录、一次提交、状态追踪、实际文件核对及恢复 | 下载执行能力验收后开放启用；实际文件在任务目录核对成功才显示原名保存完成。TMDB 不参与下载前提 |
| P3 | 可选 TMDB 资料/编号快照、字幕组到季集映射、路径预览、自动命名与归档 | 下载可独立运行；仅符合已确认规则的新任务自动整理，原文件直接改名移动、明确成功回执后结束 |
| P4 | 一致状态、任务入口及独立完整流程验收 | 不配置媒体服务器也能完成；异常恢复、暂停和终态行为有对应证据 |
| 后续扩展 | 季度浏览、其他站点适配、复杂合集等 | 主/备用 RSS 与版本共存已纳入首版；本项目不提供自动洗版、替换、删除已有版本或视频切割/转码 |

P2 实现任务目录的一次文件清单，通过模拟上游、临时 SQLite 及适用的受控只读样本验证；不为验收新增真实下载或多次逐文件查询。真实样本目录若已空，如实记录无子文件证据，不声称完成真实下载闭环；空/缺页或结果对象不在任务目录时保持待处理。跨源多视频、同名冲突和外部既有任务归属不明均不自动整理。

P3 启用自动整理不自动追改旧的 P2 完成文件；已有文件需单独选择、预览并执行。资料或规则保存不等同于已整理，整理失败也不能把已下载文件改成未下载或自动重下。

多字幕组归档文件名必须保留实际来源字幕组，不统一写主源组名；同一 S01E01 对应组 A、组 B 是正常共存。相同组名清洗后重名、同组多画质/v2 等导致**完整目标路径**相同，才让该文件整理进入命名冲突，保留独立下载目录，不覆盖旧文件，也不为了避免冲突而禁止其他版本下载。后续可明确版本标签并重新预览，不随机改名掩盖冲突。

命名冲突的任务提示“整理已暂停：目标文件名已存在”；详情说明“文件保留在原下载目录中，未覆盖已有文件”，同时保留已下载事实，不显示成下载失败。

## 8. 后续契约与验收样例

P0-05 应把以下行为落为独立状态/决定原因、不可变快照、版本与请求契约，避免一个状态同时表示配置、下载、文件与整理。此表是待实现的验收依据，不是已执行测试。

| 样例 | 预期 |
| --- | --- |
| 组 A 1080p、含 HEVC、排除合集，720p/未知画质资源混入 | 只有条件明确满足者可选，其他记录具体过滤原因 |
| 主组 A、备用组 B 的同集资源 Hash 不同 | 条件通过时均可下载，按实际组名归档并存，不互相覆盖 |
| 同组同集两个 1080p Hash，或 v1 已排队后发现 v2 | 不按集号拦截，按各自条件与初批选择处理；原版本不被替换，完整路径冲突仅阻止对应整理 |
| 主源失败、备用源读取正常 | 单源显示失败及冷却，备用源继续；不是等待主源补发后删除备用文件 |
| 同一 Hash 被主/备用源同时发现或两轮并发处理 | 仅一个同资源意图，保留双方来源关联；不扩大成同集互斥 |
| 来源 25 对应篇章第 1 集/S02E01，从 30 补 | 25～29 不执行；30 显示篇章第 6 集/S02E06 |
| 已读 5、6、8、9，其他历史未加载 | 7 仅在已读范围提示未找到；未读集数不判缺失，也不后台补全集 |
| take=65 返回 65；下一次读取超预算或失败 | 保留成功清单与历史未读完整，不标已到末尾，不用失败内容建基线 |
| 预览后新增发布与旧帖补录 | T0 后的可信新发布按规则处理；T0 前补录先待确认，不混入初批 |
| 无时区日期、机器使用另一时区 | 按来源的 Asia/Shanghai 默认解释，保留原文；不随机器时区移动边界 |
| 预览过期、切组、修改过滤或主账号目录 | 输入保留、原预览失效；旧未提交选择不套用新规则 |
| 暂停发生在建目录、提交或改名请求期间 | 记录已获准操作的结果，阻止下一写阶段；115 已接受任务只读核对 |
| 改名成功、移动回执丢失后重启 | 按精确文件 ID 读回；已到目标则完成，否则保留待核对，不直接重放 |
| 整理成功后 115 记录被清理/外部删文件 | 本地任务保持完成、保留去重，不定期复查或自动重新下载 |
| 尚在 P1，点击保存完整订阅 | 保存暂停配置，明确未启动下载；不存在隐藏的真实提交路径 |

P0-04 完成标准为规则、默认值与阶段边界已固定且交互语义完成审阅；不要求也不声称业务实现验收。后续调整必须同步本文件、总体方案和任务表，不把新增默认值追溯成用户已确认。
