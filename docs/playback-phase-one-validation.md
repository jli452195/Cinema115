# 播放租约第一阶段修复与隔离验证

日期：2026-10-03。

第二阶段已完成：同设备当前片与预加载现在共用稳定名额，满池时可复用原 UID 名额。本文保留第一阶段结果；最新范围及验证见 [设备名额验证](device-slot-validation.md)。

## 已实现

- 普通已签发会话故障切换的旧 UID 记录标记为残余，到期上限为 `min(原到期时间, 切换时间 + 2 分钟)`；旧事件与轮询不续租残余。正常停止、跨 UID 设备接替同样采用最多两分钟。
- 用户播放记录失联期限从 240 分钟改为 5 分钟。池默认 5 分钟，已有池设置仍优先；不批量重写历史记录。
- Emby 会话轮询只认精确匹配服务、用户、PlaySessionId、条目的 LastPlaybackCheckIn；证据须在最近 90 秒内且不在未来，不早于当前代次最近签发。LastActivityDate 不能证明播放。
- 轮询延长至“证据时间 + 租期”，不会因为重复轮询同一个快照而延长。真实播放事件按接收的有效事件续期。
- 尚未签发的准备记录不参与旧正式会话候选选择；多个已签发记录仍不猜测合并。
- GET/HEAD/Range 的取链成功本身不确认接替。缺少新播放证据时保留旧会话，按独立容量提交；满池时撤销本次准备并拒绝签发，不退休旧播放。
- 已匹配且由 Emby 接受的播放事件可以在准备期间记录；签发后收到事件或可靠轮询证据，也可触发同设备、同来源、唯一静默旧会话的接替。提交重新检查旧代次、活动、在途引用和候选唯一性。
- 同 UID 接替通过 SQLite 事务删除旧计费记录、提交新记录并封锁旧会话；跨 UID 保留旧目标残余。用户和池内存只在事务成功后更新。
- 正常停止/播放事件更新用户记录和池记录使用同一 SQLite 事务；旧事件按捕获代次处理，不影响重播或接替后的新代次。

## 隔离场景

使用临时 SQLite、模拟 Emby/115 和模拟时钟，不访问真实网盘、不注入运行中的用户请求，不修改当前账号、池设置或历史租约。真实多 UID 灰度需要多个真实小号，本次提供可重复的隔离灰度验证。

| 场景 | 验收结果 |
| --- | --- |
| 三 UID 连续故障切换 | 刚切换为 1 当前 + 2 残余；3 分钟后仅剩 1 当前 |
| A 静默，B 只取链，容量充足 | A 保持可取链；A/B 暂时各占一个名额 |
| 上述过程重启，B 再报告播放 | 唯一静默 A 被事务接替，同 UID 总占用恢复为 1 |
| 池满时 B 未确认播放 | B 被拒绝，A 保留，准备记录无泄漏 |
| 新播放证据在准备期间到达 | 可以在满足旧会话静默、代次与活动复核后继承满池名额 |
| 浏览活跃，播放证据缺失、过期或位于未来 | 不续租用户记录或池记录 |
| 重复轮询相同播放快照 | 到期时间不随轮询时间后移 |
| 之后无有效播放事件 | 默认 5 分钟失联期限后逻辑占用归零 |
| 停止时注入 SQLite 池表写入失败 | 用户删除和池停止一起回滚；恢复后重试成功 |
| 接替后的旧进度与停止乱序到达 | 不续租旧残余，不停止新会话 |
| 其他设备、多个正式候选、当前片恢复心跳、准备失败、并发停止 | 保留独立会话及已有代次隔离行为 |

## 检查命令

从 `backend` 运行：

```powershell
go test ./internal/service ./internal/httpapi ./internal/storage ./internal/client/emby -count=1 -timeout=180s
go test ./internal/service ./internal/httpapi -run 'TestPlaybackPhaseOne|TestPlaybackHandoff|TestMultiUIDAnalysis|TestPoolProtocol' -count=20 -timeout=180s
go vet ./internal/service ./internal/httpapi ./internal/storage ./internal/client/emby
```

另在 Linux Docker 中对服务、HTTP 与存储相关场景运行 Go race，避免本机缺少 C 编译器导致竞态检查无法执行。

结果：四个相关包完整回归通过；上述关键场景连续 20 轮通过；相关服务、HTTP 和存储的 Go race 通过；go vet 与后端构建通过。

## 尚未解决的边界

第一阶段不实现固定设备槽位。同设备快速换片仍可能暂时累积多个正式记录；正常停止后的残余仍按租约计数；多个真正活跃会话不会强行合并。满池的未确认预加载仍可能失败。

完全早于本地会话建立的播放事件不缓存、不猜测绑定，依赖后续 Progress 或可靠 Emby 轮询；不能据此承诺所有第三方播放器都能满池预加载。缺少 LastPlaybackCheckIn 的客户端必须有匹配的播放事件，否则按失联期限回收；逻辑回收不撤销已签发 CDN 直链。

真实 Yamby 的登录设备字段、预加载事件时序、停止/强退表现仍需实机验证。此次测试不代表已完成真实流量灰度，也不证明真实 CDN 连接并发。
