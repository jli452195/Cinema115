# P1-02 Bangumi 客户端与缓存

完成日期：2026-10-18。依据：[接口验证报告](anime-bangumi-api.md)、[最终契约](anime-subscription-contract.md)、[实施任务表](anime-subscription-tasks.md)。实现位于 `backend/internal/client/bangumi`。

## 已实现入口

| 方法 | 读取范围 | 本地校验与投影 |
| --- | --- | --- |
| `Calendar(ctx, weekday)` | 一次 GET `/calendar` | weekday=0 为整周，1～7 在同一快照本地筛选；返回七天分组中的所选范围，缺失分组为空数组；不逐卡补详情 |
| `Search(ctx, options)` | POST `/v0/search/subjects` | 关键词去首尾后 1～128 个 Unicode 字符，拒绝控制字符；只接受 match，limit 默认20/最大50，offset=0～1000；明确发送 type=[2] |
| `Subject(ctx, id)` | 按需 GET `/v0/subjects/:id` | 正十进制 ID；核对实际返回身份和动画类型，保留简介、平台、eps/total_episodes，不据此判断下载完成 |
| `Relations(ctx, id)` | 按需 GET `/v0/subjects/:id/subjects` | 独立读取并筛选动画关系，保留上游关系文字；不递归、不生成篇章或 TMDB 编号对应 |
| `Episodes(ctx, id, offset)`（2026-10-19 补充） | 按需 GET `/v0/episodes?subject_id=:id&type=0&limit=100&offset=:offset` | 只读正片，一次一页，offset 为 100 的倍数且小于 2000；核对篇章身份、类型、分页与重复 ID；分别保留显示编号及篇章内编号，不生成 TMDB 对应 |

输出 ID 全为字符串，时间为 UTC Unix 毫秒。中文名为空时回退原名；日期保留上游文字，原始放送星期不表示资源已可下载。卡片直接使用周历/搜索资料。

上游 DTO 与输出 DTO 分开；允许上游添加字段，但 null、错误容器、缺失必需字段、错误分页、非动画搜索结果及多段 JSON 不会变成成功空列表。有效的零搜索结果会正常缓存。

## 网络与缓存行为

- 固定 `https://api.bgm.tv`，公共无凭据请求；User-Agent 为 `jli452195/Cinema115/1.0 (https://github.com/jli452195/Cinema115)`。禁止跟随重定向，错误不回显上游正文或请求地址。
- 整个读取/等待最多20秒，单次 HTTP 最多15秒，正文最多2 MiB，归一化结果也最多2 MiB。默认同站串行且相邻请求至少1秒，是本地预算，不声明为 Bangumi 官方限额。
- 一个 Client 实例提供共享缓存、进行中合并与站点冷却；P1-07 装配时复用一个实例，不按页面或卡片新建。没有新增服务层、HTTP 路由或应用启动逻辑。
- 周历、详情、关系默认本地新鲜度上限1小时；搜索5分钟。采用更短的上游 max-age/s-maxage，考虑 Age、Date 和响应耗时；命中 CDN 不重新计满一小时。no-cache 保持需验证状态，no-store 不保留正文或验证器。
- GET 分别保存 ETag/Last-Modified；只有实际发送验证器且存在成功旧正文时接受304。304 更新成功核验时间，保留内容版本；其新 Age/Date 仍参与计算，省略 Cache-Control 时沿用对应旧策略。POST 不发送条件请求。
- 缓存仅保存白名单归一化 JSON，最多128条、正文合计8 MiB，按最近访问淘汰；成功旧资料最长保留24小时供失败回退，可能因容量压力提前淘汰。缓存为进程内数据，不跨重启持久化。
- 缓存键完整包含搜索词、match、动画筛选和分页，只去首尾空白，不删除标点、内部空格或合并不同关键词。
- `fetchedAt` 为最后一次成功200读取/304核验时间，`expiresAt` 为计算后的新鲜度截止；失败不推进时间。`dataVersion` 为投影内容摘要，内容未变时保持稳定。这里的 Bangumi 核验时间不替代蜜柑资源基线 T0。

上游失败且仍有有效保留快照时，返回旧内容、`stale=true` 和结构化 issue，方法 error 为 nil；调用方必须展示其旧数据状态。无成功旧数据时返回真实分类错误，不伪造空周历、零搜索或空详情。404 返回 `UPSTREAM_NOT_FOUND`，不会修改本地订阅历史。访问拒绝、繁忙等仍按现有契约投影为 `UPSTREAM_UNAVAILABLE`，另保留安全状态信息。

普通失败按同一键15秒、30秒、1分钟、5分钟退避；404和401/403至少5分钟。429与带 Retry-After 的503发布全站冷却，秒数/HTTP日期均支持；排队请求发出前再次复核，其他接口不能旁路。429未给有效期限时至少1分钟。没有立即自动重试；新的有效200/304清除本键失败状态。

同键首个调用者同步执行网络请求，其他调用者可独立取消。首个调用者取消时，仍存活的等待者可以接手；实际上游失败由等待者共享。最多16个不同键在途，没有脱离请求生命周期的自建后台协程。返回结果和 issue 均隔离，调用方修改不会污染缓存或其他等待者。

## 图片与阶段边界

仅保留固定 `lain.bgm.tv` 的已知封面路径，HTTP升级为HTTPS；拒绝自定义主机/端口、userinfo、查询/片段和编码路径。优先使用 medium，缺图或非法图引用返回空值，不使正常资料读取失败。

本项不下载图片。现有图片缓存的 Bangumi 来源适配与同源代理在页面/API接入时完成，不能把这里的受控上游引用直接当作已经可用的本地图片接口。不逐卡请求详情，不预读蜜柑、不访问115、不变更数据库结构，不关联媒体服务器。
