# Telegram 用户账号与资源搜索

右上角管理菜单 → Telegram 配置 →「用户账号 / 资源搜索」（`/telegram/user`）。

1. 填写自己的 Telegram API ID / API Hash，点击「保存 API 配置」。从 https://my.telegram.org/apps 申请。
2. 输入带国家区号的手机号，例如 `+8613800000000`，请求验证码并在页面填写。若账号启用了二步验证，继续填写密码。
3. 账号必须已经获得 `@ayclub_bot` 的使用权限。本项目不会代替 Bot 的认证、订阅或配额规则。
4. 打开电影或剧集详情，点击「Bot 搜索」。后端读取 TMDB 中文标题，向固定 Bot 发送查询；每次搜索可能消耗配额。
5. 浮窗展示版本名称、大小、TMDB 匹配标识、页码和剩余次数。在资源卡片点击「分享 STRM」，自动获取该资源的 115 链接，使用「115分享STRM」中已保存的播放地址、输出目录、后缀和过滤设置。后端按每条任务启动时的转存开关与所选账号处理：开启时比较分享者 user ID 和 Cookie UID，本人分享直接生成，其他账号的分享先转存、再用新分享生成；关闭时直接生成。卡片显示进度、成功数量或失败原因；一个资源返回多个链接时依次生成，单条失败继续处理其余链接。
6. 搜索和资源获取结果在后端内存缓存五分钟，明确的「未找到资源」也缓存；重复打开弹窗无需再次查询 Bot。缓存最多保留 64 项，退出账号或重启后清空。点击「刷新搜索」主动绕过搜索缓存，可能消耗 Bot 配额。缓存中的剩余次数是上次查询时的值。

此功能使用 Telegram 用户账号，通过 MTProto 访问；与 `/telegram/bot` 中用于接收生成任务的 Bot Token 配置相互独立。当前使用直连网络。

「实时日志」模块可选择「全部 / STRM / Telegram」。Telegram 记录用户配置和登录操作、搜索结果摘要，以及 Bot 接收器启动、连接变化、分享消息入队、批次开始和回复失败；资源缓存命中、操作开始和回复更新记录在 DEBUG。不会记录手机号、API Hash、验证码、二步验证密码、Token、会话或 Bot 原始消息。空轮询不写日志，连接失败与回复失败在状态变化时记录。所有模块共用最近 2,000 条内存日志，重启清空；STRM 生成详情仍归 STRM，任务结果继续独立保存在 SQLite。

## 会话与请求

- API 凭据保存为 `data/telegram-user-config.enc`，用户会话保存为 `data/telegram-user-session.enc`，使用项目的加密存储。备份时保留 `JWT_SECRET` 和整个 `data` 数据卷。
- API Hash 不回显；验证码和二步验证密码不落盘。手机号及验证码散列仅保留在十分钟登录流程内，重启后未完成的登录需重新发码。
- 服务重启后，在配置页检查连接或从详情发起搜索即可恢复会话。页面显示的登录状态以最近一次操作为准；实际请求仍检查授权。
- 每次网络操作独占一个名额，完成后关闭连接。不会常驻轮询整个账号，也不会扫描其他聊天。
- 搜索前记录目标聊天快照，收集本次新增或编辑的 Bot 消息；约两秒没有新结果后返回。多个回复合并，编辑消息覆盖旧内容。不要同时在官方客户端向同一 Bot 发起其他查询。
- 搜索最多等待约一分钟。关闭浮窗取消等待，已经发送的消息仍可能消耗配额；失败后短暂冷却，避免迟到回复混入下一次请求。
- 资源动作仅接受服务端生成的十分钟有效标识；只跟进 `ayclub_bot` 自身的资源深链接或上一页／下一页回调。不会点击悬赏、支付、订阅或权限申请按钮。
- 支持消息文本、Telegram 隐藏链接实体、直接返回的一个或多个 115 链接。单独一条链接可补齐消息中的提取码；多条裸链接不会猜测独立密码的对应关系。无法识别的内容保留在原始回复中。
- 只有点击资源卡片的「分享 STRM」才提交任务，打开弹窗和命中搜索缓存不会触发生成。全部链接一次提交给后台队列，按保存的转存开关和所选账号逐条执行；审核重试、任务日志和成功通知沿用统一流程。提交成功后关闭弹窗、刷新或离开页面都不会取消转存，重新打开弹窗会按保存的任务编号恢复进度，不自动重复提交。只有「停止任务」会调用后端取消接口，停止当前及尚未开始的链接，已发生的转存需要按日志核对。浏览器只保存任务编号及资源标识，不保存 Cookie、令牌或原分享链接。生成结果不使用搜索缓存代替真实写入，同一弹窗内成功的资源按钮会禁用以避免重复点击。
- 后端每批最多接收 100 条链接，网页队列最多 20 批，按批次顺序串行执行；每条执行最多五分钟，等待排队不占用执行超时。接收前保存所有子任务并固定整批账号凭据和设置。近期进度保存在内存中，保留最多 100 批，提交新任务时清理超过一天的已完成进度；长期结果在分享日志中查看。关闭浏览器不会中断任务，但后端停机仍会取消执行并保留检查点，不自动重放不确定的转存或删除操作。

## 构建

引入纯 Go 的 `github.com/gotd/td v0.110.0`，无需 CGO。开发使用 64 位 Go，编译并发和垃圾回收使用 Go 默认值，无需额外设置 `GOGC`、`GOMAXPROCS` 或 `-p`。Docker 通过 BuildKit 缓存模块和编译结果，支持 Linux amd64/arm64，运行时由单个 Go 服务提供前端与 API。

在 `backend` 目录下编译（PowerShell）：

```powershell
$env:CGO_ENABLED='0'
go build ./cmd/server
```

验证脚本和模拟响应放在 `tests/browser/`，不进入 Git 与 Docker。真实联调只在用户完成登录后执行，避免无授权发送 Bot 消息。
