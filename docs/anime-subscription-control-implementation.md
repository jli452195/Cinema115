# 动漫订阅：暂停、恢复、归档与移除（P2-09）

日期：2026-10-20。进度以[任务表](anime-subscription-tasks.md)为准。本项实现后端控制与本地任务查询，页面交互属于 P2-10。

## 行为

| 操作 | 实际行为 |
| --- | --- |
| 暂停 | 保留确认选择、任务、资源 Hash、来源基线和 T0；停止自动发现及下一写阶段；未提交任务保留为待恢复，不标为文件错误 |
| 恢复 | 仅曾启用的暂停订阅；纯本地复核来源、基线解释版本及固定主账号/目录设置；继续同一任务与操作记录，不重选历史、不重复提交 |
| 归档 | 停止自动发现和后续写阶段，保留全部历史及未结束任务 |
| 取消归档 | 只回到暂停；草稿归档后取消归档也不会取得执行许可，首次启用仍需确认 |
| 移除 | 软移除订阅，撤回本订阅的选择；取消无其他保留授权且尚未提交的本地意图；不取消 115 已接受的任务，不删除文件、空目录或离线记录 |

多个来源可关联同一 Hash 任务。停止一个订阅时，若另一个订阅仍有有效授权，任务继续；另一个订阅已暂停时也保留任务，等待它恢复。移除只撤回自己的关联，不清资源认领，因此移除后重建配置也不能绕过相同资源的处理历史。

整体恢复保留各来源原状态、`runWhenEnabled`、健康、检查期限与 Retry-After。单独停用或草稿来源不会被打开，也不会因它们还有旧任务而阻止其他来源恢复。其他受阻原因不会被恢复操作清除；排队任务领取同时核对父订阅和来源状态，带旧临时读取错误的暂停任务也不会反复领取，原有重试时间保持。目录在途结果恢复不受这一新提交条件阻断。

## 在途操作与最少请求

暂停、恢复、归档、移除和任务列表/详情本身都只操作 SQLite，新增 115 请求为零。不查 SHA1、不验证文件当前位置、不扫描网盘、不新增队列、常驻循环或迁移，SQLite 仍为 v50。

已获准创建目录或提交下载时，保留在途任务的租约和执行代次，让回执落库；下一写操作仍须事务检查当前有效授权。已派发/未知的提交只读核对，不再次 POST。目录创建回执未知时只按保存的父目录和名称恢复；若恢复目录后订阅已移除且无其他授权，取消未提交的本地下载意图，保留该目录。

115 已接受的任务跨暂停、归档或移除继续原有低频只读追踪，完成后取得一次必要文件清单。原名保存到此结束；待整理任务保留下载事实，P3 的写操作必须复用同一授权检查，不得绕过暂停。已完成工作流保持终态，用户自行移动、改名或删除后不再跟踪。

为避免恢复时重写所有确认快照，本项修订旧契约中“暂停递增父 `run_generation`”的做法：父状态改变只增加配置 revision，保留父/来源执行代次及不可变选择快照。事务清除 RSS token、递增未认领选择的核验 generation，并清除尚未取得外部写许可的下载租约。快速暂停再恢复后，旧 RSS、核验者和未授权写入者均不能提交；已经获得单次外部写许可的任务仍允许记录结果。规则变化、单源撤权及其他计划变化原有的代次检查不放宽。

## API

全部位于管理员 `/api/admin/anime` 下，复用鉴权、严格 JSON、版本校验、幂等键和 `no-store`。回执与数据同事务保存；同键同正文先于陈旧版本检查重放，不同正文返回幂等冲突。

- `POST /subscriptions/:id/pause`、`archive`、`remove`、`unarchive`：正文仅 `expectedRevision`，需要 `Idempotency-Key`。
- 回执包括 `id`、`revision`、`status`、`cancelledJobs`（仅本地取消）、`pendingJobs`、`inFlightOperationCount`、`resumedSourceIds` 和 `unchangedSources`。
- `GET /subscriptions/:id/jobs?page=1&pageSize=20`：只读本地关联，包含已撤回的关联与已移除订阅，按创建时间和 ID 稳定分页，不因多来源关联重复展示同一任务。
- `GET /jobs/:id`：本地下载、文件、工作流、固定目标及执行记录详情，不刷新 115。

`resume` 已实现存储、服务与模拟流程，但公开端点与 `enable` 一样保持阶段关闸，`download/organize=false`，等待 P2-10～12 交互及阶段验收。新控制错误使用固定 `STATE_CONFLICT`、`BASELINE_RECONFIRM_REQUIRED` 等分类，不返回底层错误或凭据。首次启用不在此操作中隐式实现。
