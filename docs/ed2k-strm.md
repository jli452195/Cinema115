# ED2K STRM

ED2K STRM 是独立模块，管理入口为 `/115/ed2k-strm`。设置、资源记录、缓存目录、任务和输出均独立于目录 STRM。

## 使用

1. 在 115 助手登录明确配置的主账号。
2. 在 ED2K STRM 页面保存播放器可访问的服务地址和独立输出目录，例如 `ed2k-strm`。
3. 粘贴 ED2K 链接导入，每次最多 50 条；也可在 Telegram 频道搜索结果中点击“ED2K STRM”。
4. 文件完成并核验 SHA1 和大小后，后台生成 STRM。在资源卡片查看输出路径、核验或恢复缓存。

Bot 接收已授权聊天发送的显式命令：

```text
/ed2k_strm ed2k://|file|影片.mkv|字节大小|32位ED2K哈希|/
```

也支持 `/ed2kstrm`。消息可以包含多个链接。命令仅接收并持久入队，生成进度在管理页面查看。

主网盘缓存由模块在根目录创建 `Cinema115-ED2K-*`，每个资源使用独立子目录。本地输出目录不能与目录 STRM 重叠；已经接受的任务保留提交时的输出设置。

## 地址与身份

```text
https://服务地址/api/ed2k-strm/{ed2kHash}/{sha1}/{size}/{编码后的文件名}
```

地址不包含版本段、实例资源编号、账号编号、CID、文件 ID、PickCode 或临时直链。读取路径只做字符串解析，不查询云端，也不提交离线。

| 信息 | 作用 |
| --- | --- |
| ED2K 哈希 + 精确字节大小 | 本地唯一资源键；不同文件名仍命中同一资源 |
| SHA1 + 精确字节大小 | 已完成文件的内容身份；首次核验后保留，恢复不得覆盖为其他内容 |
| 文件名 | 显示和媒体识别；后续不同名称记录为别名 |

SHA1 为首次落盘后读取的真实值。资源未完成时不生成缺少 SHA1 的 STRM。外部实例读取完整地址后，可以直接在固定播放目标查询 SHA1 或尝试秒传；陌生地址不会自动创建本实例的离线恢复任务。

## 播放与恢复

Emby 播放仍经过现有实时授权、本地播放开关及账号选择：

1. 固定本次选择的播放账号，优先核验并复用该账号已有副本，或按 SHA1 查询。
2. 未命中才按完整内容声明尝试秒传；仅缺少二次校验片段时才读取来源。
3. 已登记资源的主缓存缺失时安排后台恢复，播放返回可重试的等待状态。
4. 主缓存恢复先尝试已接受的片段资料和已登记的管理员共享小号副本；小号只提供校验片段，不改变播放目标。
5. 只有明确无法通过秒传恢复时，才向原主账号的专用缓存目录提交 ED2K 离线。恢复结果必须保持首次 SHA1 和大小。

未命中与查询异常分开处理。取链被泛拒绝时按已保存文件 ID 精确核验，确认删除才允许查找替代副本；鉴权失败、超时和未知结果不会直接触发新写入。目录创建、秒传和离线提交意图先持久保存；重启或回执丢失时核对原结果，不盲目重放。

列表刷新、地址解析、核验缓存、HEAD 和独立播放器入口都不会提交新离线。独立入口的 GET/HEAD 仅传输已有原文件；缓存缺失时，可在管理页面明确恢复，或由已授权的 Emby 实际播放准备流程按需安排恢复。播放只提供原文件，不转码、不重新封装。

## 持久化与性能

SQLite 独立保存 `ed2k_strm_settings`、`ed2k_strm_cache`、`ed2k_strm_resources`。资源的内容身份独立于可删除的云端缓存，服务启动后建立内存索引；直链短期缓存在内存，按账号凭据、内容身份和播放器 UA 隔离，不写入数据库。校验片段与目标副本复用现有播放资料表。

日常命中已有位置时直接核验取链；文件位置失效才查询 SHA1。目录扫描仅用于核对已提交任务的结果，限制层级和数量。并发恢复沿用按 115 UID 串行写入的限制。

容灾备份需包含应用 SQLite 数据库及原有加密配置。仅保留 STRM 仍能提供 SHA1、大小和 ED2K 身份，但不会凭陌生地址取得新离线权限；需重新导入原 ED2K 建立资源记录。Cookie 只来自既有加密账号配置，不写入任务记录或 STRM。

账号或凭据变化会阻止旧任务继续执行。更换主账号不能转移旧缓存目录和任务；同账号更新凭据后，可显式核验原资源再继续。

## 真实验证记录

2026-11-17 使用频道 `-1004358697065` 的[第 11055 条消息](https://t.me/c/4358697065/11055)验证了 `重生密码 S01E06`，文件为 191712101 字节，首次 SHA1 为 `3705B4942E23FCD5F8C148047601F95C1BB1944E`。

| 场景 | 结果 |
| --- | --- |
| ED2K 离线、提取资料、生成真实 STRM | 通过 |
| HEAD、Range `bytes=0-31` | 200 且大小正确；206 且读取 32 字节 |
| 改名链接及服务重启 | 复用原资源，新增离线 0 次 |
| 删除本轮主缓存文件，使用已登记小号恢复 | 秒传 1 次，新增离线 0 次，SHA1 不变 |
| 隔离验证中显式关闭秒传资料入口后恢复 | 离线 1 次，SHA1 不变，再次 HEAD/Range 通过 |
| 开发页面实际导入的 `Where.the.Mask.Ends S01E01` | 已生成 STRM，实际 HTTP 入口 HEAD 200、Range 206/32 字节 |

容灾验证使用隔离数据库和输出，只将本轮创建的精确测试文件移入回收站；保留恢复后的文件、小号副本及生成的 STRM。没有改动实际应用的账号和 Emby 配置。没有向频道发送测试消息，也未进行完整 Emby 播放器端到端播放；其鉴权、目标优先与来源凭据固定由专项回归覆盖。
