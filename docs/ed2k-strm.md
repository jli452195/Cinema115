# ED2K STRM

ED2K STRM 是独立模块，管理入口为 `/115/ed2k-strm`。设置、资源记录、缓存目录和输出任务均独立于目录 STRM；资源资料、云端缓存与本地 STRM 文件分别管理。

## 使用

1. 在 115 助手登录明确配置的主账号。
2. 在 ED2K STRM 的“基础设置”页签填写播放器可访问的服务地址；可同时选择“主网盘缓存目录”，再点击“保存设置”。选择目录只更新草稿，不立即修改配置。
3. 在“基础设置”添加可命名的本地输出目录，例如“目录1”对应 `ed2k-strm/电影`，“目录2”对应 `ed2k-strm/剧集`；也可在生成表单的目录旁快捷新建。路径相对于应用 STRM 根目录；本地输出目录不能与网盘目录 STRM 重叠。
4. 在默认“生成 STRM”页签选择输出目录并粘贴 ED2K 链接导入，识别出的链接整批提交；也可在 Telegram 频道搜索结果中点击“ED2K STRM”，有多个目录时选择目标。不按条数截断，超出请求体大小时明确提示并拒绝本次提交。
5. 首次文件完成并核验 SHA1 和大小后，后台输出 STRM。“生成 STRM”显示当前或失败任务，没有任务时仅显示紧凑提示；“资源缓存”长期保留资源资料，支持搜索、状态筛选、核验和恢复缓存。资源行的“生成 STRM”会预填链接、保留所选目录并返回生成表单，需明确提交才生成。

三个页签共用同一管理入口：默认 `/115/ed2k-strm` 为“生成 STRM”，`?tab=resources` 为“资源缓存”，`?tab=settings` 为“基础设置”。页签切换保留链接、所选目录及设置草稿，浏览器刷新、前进和后退按 URL 恢复对应页签；切页、搜索和筛选不会提交离线或输出任务。

“基础设置”中的本地输出目录采用独立卡片展示，包含名称、完整可换行路径、编辑/删除和 Bot 分配状态；路径以简洁文字呈现。“默认目录”只是可修改的目录名称，不代表自动兜底。网格按实际可用宽度自适应一至三列，桌面提供末尾的虚线添加卡，手机保留顶部添加按钮。

STRM 按文件名直接写入所选目录，不增加哈希子目录。例如 STRM 根目录为 `D:\strm`，目标为 `ed2k-strm/剧集`，输入 `影片.S01E01.mkv`，输出为：

```text
D:\strm\ed2k-strm\剧集\影片.S01E01.strm
```

可以在生成后自行移动、改名或整理 STRM。播放地址只依赖文件内容中的资源身份，不依赖本地路径；核验、恢复云端缓存或重启服务都不会在原位置补写。需要另一份文件时，明确提交一次新的生成请求。同目录同名且内容身份相同的 STRM 可复用；同名的其他内容不会被覆盖。

在 Telegram Bot 配置中，将 ED2K STRM 输出目录分配给 Bot，并配置允许的聊天 ID、启用 Bot 后，已授权用户可在私聊直接发送 ED2K，无需命令前缀：

```text
ed2k://|file|影片.mkv|字节大小|32位ED2K哈希|/
```

每条纯 ED2K 消息最多包含 50 个链接，适用目标包括已分配的云下载和 ED2K STRM 目录。只有适用候选恰好一个且可用时才自动处理；多个候选时，先回复一条选择消息，按钮分别标明「生成 STRM · 目录名」「普通转存 · 目录名」，并提供取消。点击前不创建任务，不按第一个目录或上次选择自动提交，也不先过滤未就绪目标，再自动使用剩下的健康目标。就绪判断只读取本地配置，不访问网盘。

每条原消息有独立的 10 分钟选择期限，连续发送的新消息不会覆盖前一条选择。选择绑定原发送者、私聊和提示消息；他人点击、重复点击、过期或取消后均不会重复创建任务。提交前重新校验目标及分配；失效后需重新发送，不切换到其他用途或目录。已接受任务保留当时的目录及地址快照。接收回复只表示任务已接收，STRM 处理进度在管理页面查看。

磁力只进入云下载；与 ED2K 混发时整批走云下载，即使同时分配 STRM 目录也不提供 STRM 选项。仅分配 STRM 时无法处理这种混合消息，整批不提交。115 分享与磁力或 ED2K 混发时整批拒绝；纯分享按已分配的分享转存目录及分享 STRM 用途处理，需要选择时一次选择用途和目录。分享 STRM 使用其当前保存的单输出目录及直接生成/转存再分享策略，独立于本模块。

可选命令 `/ed2k_strm <ED2K链接>`、`/ed2kstrm <ED2K链接>` 限定生成 STRM，`/cloud <链接>` 限定云下载，共用直接发送链接的解析、整批校验和选择规则。显式 STRM 消息含磁力、显式云下载消息含 115 分享时也整批拒绝，不静默丢弃链接。完整分流规则见 [云下载 Bot 接收](cloud-download.md#telegram-bot-接收)。

“主网盘缓存目录”可选择主账号中的已有目录，也可明确选择根目录。点击“使用自动目录”后保存，可恢复模块在主账号根目录自动创建 `Cinema115-ED2K-*` 专用目录的方式。未登录主账号时不能浏览目录；更换主账号后，手选目录必须重新选择或改用自动目录，不沿用旧账号的目录。

缓存目录变更供新缓存和后续恢复使用，已有文件不移动、已有 STRM 继续可用。目录未就绪时不能新导入或手动恢复，主账号可用时仍可核验已记录的缓存文件。每个资源使用独立云端子目录；云端缓存结构与本地输出目录无关，同一资源输出到多个本地目录仍共用一份资料和缓存。

## 地址与身份

```text
https://服务地址/api/ed2k-strm/{ed2kHash}/{sha1}/{size}/{编码后的文件名}
```

地址不包含版本段、实例资源编号、账号编号、CID、文件 ID、PickCode 或临时直链。读取路径只做字符串解析，不查询云端，也不提交离线。

| 信息 | 作用 |
| --- | --- |
| ED2K 哈希 + 精确字节大小 | 本地唯一资源键；不同文件名仍命中同一资源 |
| SHA1 + 精确字节大小 | 已完成文件的内容身份；首次核验后保留，恢复不得覆盖为其他内容 |
| 文件名 | 显示和媒体识别；后续不同名称记录为别名 |

SHA1 为首次落盘后读取的真实值。资源未完成时不生成缺少 SHA1 的 STRM。外部实例读取完整地址后，可以直接在固定播放目标查询 SHA1 或尝试秒传；陌生地址不会自动创建本实例的离线恢复任务。

## 播放与恢复

Emby 播放仍经过现有实时授权、本地播放开关及账号选择：

1. 固定本次选择的播放账号，优先核验并复用该账号已有副本，或按 SHA1 查询。
2. 未命中才按完整内容声明尝试秒传；仅缺少二次校验片段时才读取来源。
3. 已登记资源的主缓存缺失时安排后台恢复，播放返回可重试的等待状态。
4. 主缓存恢复先尝试已接受的片段资料和已登记的管理员共享小号副本；小号只提供校验片段，不改变播放目标。
5. 只有明确无法通过秒传恢复时，才向原主账号的专用缓存目录提交 ED2K 离线。恢复结果必须保持首次 SHA1 和大小。

未命中与查询异常分开处理。取链被泛拒绝时按已保存文件 ID 精确核验，确认删除才允许查找替代副本；鉴权失败、超时和未知结果不会直接触发新写入。目录创建、秒传和离线提交意图先持久保存；重启或回执丢失时核对原结果，不盲目重放。

列表刷新、地址解析、核验缓存、HEAD 和独立播放器入口都不会提交新离线。独立入口的 GET/HEAD 仅传输已有原文件；缓存缺失时，可在管理页面明确恢复，或由已授权的 Emby 实际播放准备流程按需安排恢复。播放只提供原文件，不转码、不重新封装。

## 持久化与性能

SQLite 独立保存以下数据：

| 数据 | 保留内容 |
| --- | --- |
| `ed2k_strm_settings` | 后续输出使用的服务地址，以及手选缓存目录的账号归属、CID 与显示路径；未指定时使用自动目录 |
| `ed2k_strm_targets` | 目录名称、相对路径与 Bot 分配 |
| `ed2k_strm_resources` | 内容身份、别名、账号归属、云端缓存位置及恢复所需状态；不保留本地 STRM 路径、输出设置或“STRM 已生成”状态 |
| `ed2k_strm_tasks` | 当前或失败任务的输出快照；完成后清除文件名、目录及服务地址，仅保留 7 天精简请求收据防止网络或 Bot 重放 |

同资源的新生成请求可输出到另一个目录；同一请求编号重放只返回原任务或收据，不重复输出。失败任务可明确重试或清理。写文件前先保存意图；重启遇到未确认的写入时只核对已有文件，原位置缺失则显示失败，需明确重试才再输出。删除目录配置不会删除资源和文件，已接受的任务仍使用原快照完成。

资源的内容身份独立于可删除的云端缓存，服务启动后建立内存索引。已知 SHA1 的资源再次生成时直接使用本地资料，不读取 115、不安排缓存恢复；首次资料尚未就绪的输出任务等待核验。直链短期缓存在内存，按账号凭据、内容身份和播放器 UA 隔离，不写入数据库。校验片段与目标副本复用现有播放资料表。

日常命中已有位置时直接核验取链；文件位置失效才查询 SHA1。目录扫描仅用于核对已提交任务的结果，限制层级和数量。并发恢复沿用按 115 UID 串行写入的限制。

容灾备份需包含应用 SQLite 数据库及原有加密配置。仅保留 STRM 仍能提供 SHA1、大小和 ED2K 身份，但不会凭陌生地址取得新离线权限；需重新导入原 ED2K 建立资源记录。Cookie 只来自既有加密账号配置，不写入任务记录或 STRM。

账号或凭据变化会阻止旧任务继续执行。更换主账号不能转移旧缓存目录和任务；同账号更新凭据后，可显式核验原资源再继续。

## 真实验证记录

首次实现时，2026-11-17 使用频道 `-1004358697065` 的[第 11055 条消息](https://t.me/c/4358697065/11055)验证了 `重生密码 S01E06`，文件为 191712101 字节，首次 SHA1 为 `3705B4942E23FCD5F8C148047601F95C1BB1944E`。

| 场景 | 结果 |
| --- | --- |
| ED2K 离线、提取资料、生成真实 STRM | 通过 |
| HEAD、Range `bytes=0-31` | 200 且大小正确；206 且读取 32 字节 |
| 改名链接及服务重启 | 复用原资源，新增离线 0 次 |
| 删除本轮主缓存文件，使用已登记小号恢复 | 秒传 1 次，新增离线 0 次，SHA1 不变 |
| 隔离验证中显式关闭秒传资料入口后恢复 | 离线 1 次，SHA1 不变，再次 HEAD/Range 通过 |
| 开发页面实际导入的 `Where.the.Mask.Ends S01E01` | 已生成 STRM，实际 HTTP 入口 HEAD 200、Range 206/32 字节 |

容灾验证使用隔离数据库和输出，只将本轮创建的精确测试文件移入回收站；保留恢复后的文件、小号副本及生成的 STRM。没有改动实际应用的账号和 Emby 配置。没有向频道发送测试消息，也未进行完整 Emby 播放器端到端播放；其鉴权、目标优先与来源凭据固定由专项回归覆盖。

115 删除后的目录、搜索和取链状态存在短暂不同步，真实验证中先等待固定文件 ID 与 SHA1 查询都确认缺失，再验收离线恢复。应用不会把搜索或鉴权异常当成缓存缺失反复提交。

多目录验证复用开发实例已核验的 `Where.the.Mask.Ends S01E01`，SHA1 为 `9CD9250F42D15D770C2AC21FCB64CABB6BBD188A`，大小为 1858982683 字节。两处目录平铺输出后资源仍为一条；移动第二份 STRM、核验缓存和重放原请求均不在原位置补写；删除临时目录配置仍保留资源及文件。HEAD 返回 200、Range 返回 206 和 32 字节。该验证没有重新提交云下载或删除云端媒体。

必要的本地证据位于 `backend/tmp/ed2k-strm-live/run-20261117T053714/evidence.jsonl` 与 `backend/tmp/ed2k-strm-layout-validation/layout-20261117T063623526Z/`；保留真实 STRM、恢复后的缓存和小号副本。
