# 云下载提交

## Telegram Bot 接收

在「Telegram 配置 → Bot 配置」将所需「磁力/ED2K 转存」目录分配给 Bot，配置允许的聊天 ID 并启用后，可在私聊直接发送链接，无需先输入命令。

Bot 也接收手动上传或 Telegram 自动生成的 `.txt` 清单，支持 ED2K、磁力和附提取码的 115 分享。每条正文最多接收 100 条链接。每个 TXT 最大 512 KiB，去重后最多接收 1,000 条。整份清单只选择一次用途和目录，超限会提示重新发送。可在附件说明中写 `/cloud` 或 `/ed2kstrm` 限定用途。

清单支持 UTF-8 和带 BOM 的 UTF-16。普通云下载按每组最多 100 条向 115 批量提交，合并转存按每 100 条分段处理。Bot 汇总提交结果，失败明细可查看 Telegram 日志。ED2K STRM 整份登记后，由后台按实际 115 UID 限速处理。

| 消息内容 | 处理方式 |
| --- | --- |
| 纯 ED2K | 使用已分配的云下载及 ED2K STRM 目标；需要选择时，一条消息同时列出「普通转存 · 目录名」「生成 STRM · 目录名」及取消按钮 |
| 纯磁力，或磁力与 ED2K 混发 | 整批使用云下载目标；即使分配了 ED2K STRM，也不出现 STRM 选项；仅分配 STRM 时明确拒绝，整批不提交 |
| 115 分享与磁力或 ED2K 混发 | 整批拒绝，提示分开发送；不截取其中一类提交 |
| 仅 115 分享 | 使用已分配的分享转存目录和分享 STRM；需要选择时，一条消息列出「转存到网盘 · 接收目录」「生成分享 STRM · 输出目录」及取消按钮 |

先按消息协议及显式用途确定已分配的适用候选，只有候选恰好一个且可用时才自动处理。多个候选先选择用途及目录，点击前不创建任务；不先过滤未就绪目标，再把剩下的健康目标作为默认。就绪判断只读取本地配置，不访问网盘；目标不可用时提示配置，不自动换用途、目录或账号。

「115 分享 STRM」和多个「115 链接转存」目录可以同时分配给同一个 Bot。分享转存保留原分享结构写入所选主账号接收目录；分享 STRM 使用「115分享STRM」当前保存的单个输出目录，并沿用直接生成（`direct`）或转存再分享（`reshare`）策略；选择器不额外配置生成目录或策略。

每条消息独立保留 10 分钟，选择绑定原发送者、私聊和提示消息，并防止重复提交。过期、取消或目标及分配失效后需重新发送；已接受任务继续使用提交时固定的目标和凭据。

`/cloud <链接>` 和 `/ed2kstrm <ED2K链接>`（也支持 `/ed2k_strm`）是限定用途的可选入口。旧写法 `/cloud redo <链接>` 也按普通云下载直接提交。显式 STRM 消息含磁力或显式云下载消息含 115 分享时，拒绝整批。ED2K STRM 的独立资料、缓存和本地输出规则见 [ED2K STRM](ed2k-strm.md)。

## 普通云下载回执

云下载网页、观影及蜜柑的「115 转存」、Telegram 均使用普通提交路径。后端本地校验链接，固定当前主账号凭据和已选目录，并按实际 UID、协议和规范化 Hash 防止并发重复提交。随后直接请求 115。单条使用单条提交接口，同目录的多条使用批量接口，项目按每组最多 100 条分组。

界面和 Bot 根据 115 当次回执显示已提交条数，另报失败、未确认和未发送的条数。普通入口省去旧任务查询、旧记录删除及提交后的状态刷新。需要核对时，可到 115 客户端查看云下载列表。批量回执缺项或提交结果不明时保留相应提示，后台不会自动补查或重发。

网页从 `GET /api/admin/p115/cloud-download/profiles` 读取「磁力/ED2K 转存目录」，通过响应中的 `accountId` 和每项目录的 `ready` 识别当前主账号可选目录。单条走 `POST /api/admin/p115/cloud-download/tasks`，批量走相同路径下的 `/batch`。两者均提交选定的 `profileId`、`accountId` 和 `targetCID`。目录删除、目录编号变更或主账号失效时，提交前返回 HTTP 409 和 `cloud_target_changed`，需要重新确认。单条明确接收后返回 HTTP 202 和 `accepted: true`。批量按原条目编号返回 `start` 和 `result`，`done` 表示本次提交结束。

服务层每组的提交预算为 90 秒，网页单条请求等待 95 秒。同一 115 UID 沿用每秒最多一次请求的节奏。Cookie 仅保存在本次调用的内存快照中。网页和 Telegram 入口统一使用主账号并共用目录列表。网页可使用主账号下的有效条目，Bot 可使用分配给自己的条目。主账号变化后需重新选择目录。

ED2K STRM 和下载后整理沿用各自的任务核对流程。下载整理单独配置下载暂存目录，网页云下载的目录选择只用于普通云下载。

前端构建使用 `npm run build`；云下载提交界面和 Bot 分配说明分别由 `scripts/cloud-download-resubmit-ui.cjs`、`scripts/telegram-bot-modules-ui.cjs` 在已有前端实例上使用模拟接口验证，不删除或提交真实 115 任务。
