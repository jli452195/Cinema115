# 云下载默认安全重提

云下载网页、观影及蜜柑的「115 转存」、Telegram 均使用公共 `CloudDownloadService.Submit`。所有提交默认按资源 Hash 查询旧任务，无需 `redo=true`；原 `Redo` 方法仅作兼容别名。Telegram 的 `/cloud redo` 仍可使用，旧队列是否包含 `cloudRedo` 都不影响默认策略。查询列表、读取设置等只读接口不会触发删除。

1. 校验磁力或 ED2K、明确的 `accountId` 以及目标目录；固定此次操作的账号凭据和设置，不允许空账号或失效账号回退。
2. 对同一账号编号、协议、规范化 Hash 加进程内互斥保护；处理中再次从其他入口提交会被拒绝，不排队再次删除。不同目标目录仍属于同一资源；不同资源及账号互不阻塞。
3. 通过 Hash 精确查询 115 单任务。不存在时直接提交；Hash 完全匹配且任务已完成、失败或停止时，只删除该任务记录，保留网盘文件，再提交到此次指定目录。
4. 任务运行或等待、状态不明、Hash 不符、查询失败时停止，不执行删除。删除失败不继续提交，不因 `10008` 或其他错误码盲目删除、循环重试。
5. 删除后提交失败时保留 `removedOldTask=true` 的回执，明确提示记录已移除而网盘文件保留。网络超时、中断时标记 `outcomeUncertain=true`，先核对 115 任务列表再决定是否重试。删除与提交是两个上游请求，无法原子回滚；不自动恢复旧记录。

网页共用 `POST /api/admin/p115/cloud-download/tasks?accountId=...`，管理员鉴权不变。成功返回 HTTP 202、`accepted: true`、`removedOldTask` 和安全任务字段；运行中、状态不明或并发处理中返回 HTTP 409。失败响应提供中文 `error`、`accepted: false`、`removedOldTask`、`outcomeUncertain`。已接受只表示提交成功，不代表下载完成，不新增进度轮询或 Telegram 长期追踪。

服务层整体超时 90 秒，三个网页入口共用 95 秒等待预算。Cookie 仅保存在本次调用的内存快照中，不写入任务回执、并发锁或日志。各入口原有的明确账号绑定继续独立生效，公共流程不提供全局默认账号。

并发保护作用于单个后端进程；多实例部署需要共享协调机制。它也无法锁住用户直接在 115 官网的操作，因此每次仍需校验查询结果，不宣称跨系统原子保证。

测试全部使用模拟服务：`go test ./...`、`go vet ./...`、前端 `npm run build`。界面回归：`node frontend/scripts/cloud-download-resubmit-ui.cjs`，不删除或提交真实 115 任务。
