# 云下载默认安全重提

## Telegram Bot 接收

在「Telegram 配置 → Bot 配置」将所需「磁力/ED2K 转存」目录分配给 Bot，配置允许的聊天 ID 并启用后，可在私聊直接发送链接，无需先输入命令。

| 消息内容 | 处理方式 |
| --- | --- |
| 纯 ED2K | 使用已分配的云下载及 ED2K STRM 目标；需要选择时，一条消息同时列出「普通转存 · 目录名」「生成 STRM · 目录名」及取消按钮 |
| 纯磁力，或磁力与 ED2K 混发 | 整批使用云下载目标；即使分配了 ED2K STRM，也不出现 STRM 选项；仅分配 STRM 时明确拒绝，整批不提交 |
| 115 分享与磁力或 ED2K 混发 | 整批拒绝，提示分开发送；不截取其中一类提交 |
| 仅 115 分享 | 使用已分配的分享转存目录和分享 STRM；需要选择时，一条消息列出「转存到网盘 · 接收目录」「生成分享 STRM · 输出目录」及取消按钮 |

先按消息协议及显式用途确定已分配的适用候选，只有候选恰好一个且可用时才自动处理。多个候选先选择用途及目录，点击前不创建任务；不先过滤未就绪目标，再把剩下的健康目标作为默认。就绪判断只读取本地配置，不访问网盘；目标不可用时提示配置，不自动换用途、目录或账号。

「115 分享 STRM」和多个「115 链接转存」目录可以同时分配给同一个 Bot。分享转存保留原分享结构写入所选主账号接收目录；分享 STRM 使用「115分享STRM」当前保存的单个输出目录，并沿用直接生成（`direct`）或转存再分享（`reshare`）策略；选择器不额外配置生成目录或策略。

每条消息独立保留 10 分钟，选择绑定原发送者、私聊和提示消息，并防止重复提交。过期、取消或目标及分配失效后需重新发送；已接受任务继续使用提交时固定的目标和凭据。

`/cloud <链接>`、`/cloud redo <链接>` 和 `/ed2kstrm <ED2K链接>`（也支持 `/ed2k_strm`）保留为限定用途的可选入口，共用上述解析、整批校验和目标选择规则。显式 STRM 消息包含磁力时整批拒绝；显式云下载消息包含 115 分享时整批拒绝，不静默丢弃链接。ED2K STRM 的独立资料、缓存和本地输出规则见 [ED2K STRM](ed2k-strm.md)。

## 提交与重提规则

云下载网页、观影及蜜柑的「115 转存」、Telegram 均使用公共 `CloudDownloadService.Submit`。所有提交默认按资源 Hash 查询旧任务，无需额外指定重提参数。查询列表、读取设置等只读接口不会触发删除。

1. 校验磁力或 ED2K、明确的 `accountId` 以及目标目录；固定此次操作的账号凭据和设置，不允许空账号或失效账号回退。
2. 对同一账号编号、协议、规范化 Hash 加进程内互斥保护；处理中再次从其他入口提交会被拒绝，不排队再次删除。不同目标目录仍属于同一资源；不同资源及账号互不阻塞。
3. 通过 Hash 精确查询 115 单任务。不存在时直接提交；Hash 完全匹配且任务已完成、失败或停止时，只删除该任务记录，保留网盘文件，再提交到此次指定目录。
4. 任务运行或等待、状态不明、Hash 不符、查询失败时停止，不执行删除。删除失败不继续提交，不因 `10008` 或其他错误码盲目删除、循环重试。
5. 删除后提交失败时保留 `removedOldTask=true` 的回执，明确提示记录已移除而网盘文件保留。网络超时、中断时标记 `outcomeUncertain=true`，先核对 115 任务列表再决定是否重试。删除与提交是两个上游请求，无法原子回滚；不自动恢复旧记录。

网页共用 `POST /api/admin/p115/cloud-download/tasks?accountId=...`，管理员鉴权不变。成功返回 HTTP 202、`accepted: true`、`removedOldTask` 和安全任务字段；运行中、状态不明或并发处理中返回 HTTP 409。失败响应提供中文 `error`、`accepted: false`、`removedOldTask`、`outcomeUncertain`。已接受只表示提交成功，不代表下载完成，不新增进度轮询或 Telegram 长期追踪。

服务层整体超时 90 秒，三个网页入口共用 95 秒等待预算。Cookie 仅保存在本次调用的内存快照中，不写入任务回执、并发锁或日志。网页和 Telegram 入口统一使用主账号，各入口保留独立的目标目录设置。主账号变化后需重新选择目录，小号不能提交云下载。

并发保护作用于单个后端进程；多实例部署需要共享协调机制。它也无法锁住用户直接在 115 官网的操作，因此每次仍需校验查询结果，不宣称跨系统原子保证。

前端构建使用 `npm run build`；云下载提交界面和 Bot 分配说明分别由 `scripts/cloud-download-resubmit-ui.cjs`、`scripts/telegram-bot-modules-ui.cjs` 在已有前端实例上使用模拟接口验证，不删除或提交真实 115 任务。
