# 每个 Emby 用户只允许一路播放

Emby 服务 ID + 真实用户 ID 决定播放名额；主网盘、个人网盘、动态小号池及播放子账号统一执行。可以多设备登录和浏览，正式原文件取链才占用名额。不同 Emby 用户各有一个名额，所有者与子账号独立计数，个人归属和子账号禁用规则继续生效。

第二个播放会话返回 HTTP 409，正文为 `USER_PLAYBACK_CONFLICT：该用户已在别处播放,请先停止当前播放后再重试`。播放器是否显示正文取决于客户端；有些只显示播放失败。拒绝发生在 Emby 身份和条目验证之后、网盘检查和 115 取链之前；不会为了拒绝第二路访问 115。下载仍按 Emby 下载权限及下载总开关处理，不占用户名额；动态池下载仍占 UID 容量。

## 生命周期

1. 同一用户的准入在互斥锁内完成，SQLite 写入成功后才发布内存状态。不同播放会话只能有一个成功预占。
2. 同一 token、PlaySessionId、条目和媒体源复用名额；并发请求用引用计数，单个失败不会释放其他请求的预占。播放器缺少 PlaySessionId 时按 token、条目和媒体源合并。
3. 准备占用最多 95 秒，覆盖最长 90 秒请求；最后一个未签发请求结束即释放。池内故障切换共用一次用户名额，失败不回退主网盘。
4. 302 签发前复核 Emby 权限、来源及租约版本。签发后保留 240 分钟，可信播放事件或 Emby Sessions 精确活动证据可以续期；心跳持久化最多每分钟一次。
5. Emby 成功接受停止事件后立即释放用户名额。**正常停止允许复用原播放地址原地重播，无需重新进入详情页**；内部代次更新，停止前已准入的请求不能继续提交。停止事件转发前记录代次，迟到的上游响应不能释放重播的新代次。
6. 小号容量独立：停止后保留两分钟 CDN 残余占用。同 token、同片、同媒体源原地重播可复用原小号占用，不重复计数；更换播放会话或影片仍受小号剩余容量限制。
7. 异常退出、客户端未报告停止、Emby 查询失败或缺少匹配字段时，不凭猜测提前释放，使用到期回收；服务重启保留占用。

浏览协商不预占名额。单路限制启用时，所有来源跳过提前文件准备和直链预热，正式取链通过准入后才执行云端准备。配置中的预热开关在此模式下不生效，已有可信文件副本及正式取链缓存仍可复用。

## 管理与存储

「Emby 用户管理 → 用户播放占用」每 10 秒刷新，展示条目 ID、准备/已签发状态及预计到期时间。管理员释放必须提交所查看的代次；会话已变更返回 409，避免旧页面释放新播放。

管理员强制释放与正常停止不同：强制释放后拦截旧会话的新取链 24 小时，用户需发起新的播放会话；不能撤销已签发 CDN URL。正常停止不写入该拦截记录。

接口均使用现有管理端鉴权，不提供普通用户的释放或 Emby 播放权限写接口：

- `GET /api/admin/member-playback/playback-sessions`
- `POST /api/admin/member-playback/playback-sessions/:key/release`，正文 `{"generation":当前代次}`。

SQLite 结构版本 34，独立表 `user_playback_leases` 保存用户租约、强制释放摘要及单调代次。不保存原始 token、Cookie 或直链；管理列表去掉会话匹配摘要。最多 4096 个有效租约、4096 个在途代次、8192 个租约与拦截记录合计，同代次最多 128 个在途请求；超过上限返回 503。

## 验收清单

- [x] 32 个不同会话竞争同一用户，只允许一个成功。
- [x] 同会话并发重试、请求取消、未签发失败释放。
- [x] 主盘、个人盘、动态池、真实子账号均执行限制；所有者独立，下载隔离。
- [x] HTTP 第二路 409、指定中文正文、无 115 检查或取链。
- [x] 无效停止通知不释放；正常停止后原 URL 重播，单小号容量 1 不重复占位。
- [x] 旧请求提交、迟到事件响应、管理员旧代次均不能覆盖新租约。
- [x] SQLite 重启恢复、取消写入、存储失败不发布内存、过期回收。
- [x] 动态池故障切换保留用户名额，不回退主网盘。
- [x] 管理接口权限、列表脱敏、释放参数及版本冲突检查。
- [x] 管理页展示、轮询过程中确认版本固定、409 提示、释放及窄屏布局。
- [ ] 实际 Emby 播放器联调：停止、原地重播、跨设备并发与错误正文展示。

这是直链签发准入限制，不能精确限制 302 后的 CDN 连接数。同 token、同 PlaySessionId 的多个连接无法区分；缺少会话 ID 的客户端尤其如此。正常停止后再次取链既可能是主动重播，也可能是客户端自动重试，服务端只能按相同准入规则处理。若旧停止请求直到重播后才首次到达反代，且客户端复用了同一个会话 ID，协议没有额外代次可供可靠区分。已签发直链和管理员释放也都无法立即中断 CDN 播放。
