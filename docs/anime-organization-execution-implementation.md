# 动漫自动整理执行（P3-07～08）

2026-10-20。接续目录2、冻结命名方案与单次文件清单；本步接通自动执行，不开放历史文件批量应用。

## 实际流程

1. 清单保存后，现有下载执行循环领取同一个任务，不再查询离线状态或重列来源目录。
2. 从冻结方案生成文件集合。视频、唯一配对字幕必须有明确目标；映射不全、目标路径重复时整条资源保留待处理。附件、忽略项及空目录保留。
3. 按主账号UID、配置编号及版本、目录2 CID、相对路径复用作品/季目录；内存缓存最多256项、10分钟，任务内确认的目录ID另存操作记录。列表仅在本次执行内共享；新建目录收到有效CID不再GET。
4. 写入前统一检查目标同名冲突；来源重名检查复用独立资源目录清单。复用公共整理引擎的目录匹配、同名判断与115批量接口；每批最多50个已确认文件ID。先批量改名，再按目的目录批量移动原文件。
5. 明确同步成功回执直接记录成功，最后一批成功与 `workflow_state=organized` 同事务提交。不追加读回、SHA1、逐文件元数据或原位置检查。

目录锁复用下载整理、自动整理及目录监控的 `ReserveDirectoryWork`，另保留实际UID/Hash协调。网络I/O不持有SQLite事务。本工具之外的客户端不受本地锁约束；本实现不提供强制覆盖或清理接口。

## 操作记录与恢复

SQLite v52只扩展原 `anime_drive_operations.kind` 约束，允许 `organize`；没有新表、文件注册表、并行队列或常驻循环。v51保留现有订阅、任务与提交回执；v51之前仍按已授权的一次性开发库清理规则执行，v51及以后不再次清理。

每个任务最多一条整理操作。`request_json` 固定目录2及文件ID、来源CID、原名称、目标相对路径；`result_json` 保存已确认目录、逐文件改名/移动结果及当前批次意图。只含普通值，不存Cookie、签名、直链或文件SHA1。

每次建目录、改名、移动前先事务保存精确意图，检查原账号、来源授权、任务代次及租约。成功回执事务保存；暂停期间允许保存已发出请求的事实，下一次写入重新检查授权。换号、凭据更新、旧代次、旧租约不能继续签发写入，任务不改绑新账号。

- 超时、回执丢失、逐项/异步/无法解释的批量回执：保留当前意图，只读核对固定对象，不重放原POST。
- 建目录未知：只在保存的父CID按保存名称查找唯一目录。
- 改名未知：一次来源目录列表按保存ID和目标名称确认。
- 移动未知：一次目标目录列表按保存ID和目标名称确认；不搜索全盘、不向原位置追查。
- 部分成功：只标记能确认的文件，剩余待人工处理。界面只能再次核对原步骤，不提供重提或覆盖。
- 读取失败：保留步骤，低频重试；Retry-After跨任务共享，鉴权拒绝停止。完整列表仍无法证明的结果转待处理，不持续扫描。
- 一次恢复只核对该步骤；全部明确后，后续调度才能继续尚未派发的步骤，且仍需有效授权。

完成后停止领取，不因二次整理、改名、移动或删除而扫描、恢复或重下。清单及目标路径均为执行历史。

## 页面与能力

详情补充待整理、正在整理、未知、待处理、已整理及改名/移动计数；未知或部分成功只暴露“核对整理结果”，完成无执行按钮。轮询保留已打开的命名预览。预览仍为本地命名计划，不表示实时位置或云端冲突结果。

`capabilities.organize` 按实际下载依赖与整理网关投影；自动执行已装配。用户已确认取消P3-10，不再接入已有任务或历史文件补整理，既有占位接口继续关闭。

Gemini CLI参与前端讨论、代码及实际PNG审查，后端由Codex设计和自审。实现位于 `anime_organize_execution.go`（model/storage/service）及既有任务视图、恢复调度和115批量客户端。
