# 动漫订阅 Telegram 通知

在「动漫订阅 → 设置 → Telegram 通知」选择已有 Bot，勾选事件并保存。Bot 需要在「Telegram 配置 → Bot 配置」中配置 Token、启用，并填写通知聊天 ID。也可以在 Bot 页面把「动漫订阅通知」模块分配给 Bot，再点击「编辑通知模板」。两个入口共用同一份设置。

支持下载完成、整理完成、异常提醒。默认开启整理完成和异常提醒，下载完成默认关闭，避免同一集连续提醒。正常等待结果目录、状态暂未明确和请求取消不会触发异常通知。整理完成表示原文件已整理到目标目录，Emby 是否入库以实际扫描结果为准。

通知只记录启用后新发生的事件，不补发历史任务。事件与任务状态在同一 SQLite 事务中保存，之后原子转交现有 Telegram 发送队列。发送失败最多尝试 8 次，不会重新下载或整理。未转交事件保留 7 天；解除分配或关闭相应事件后，尚未发送的对应通知会被取消。

异常通知按以下规则确认：

- 初始化、状态暂未明确（`TASK_STATUS_UNKNOWN`）、等待结果目录（`TASK_RESULT_PENDING`）和轮询取消（`TASK_POLL_CANCELLED`）不报警。
- 临时网络、读取或限流错误，需要实际连续失败至少 3 次且持续至少 5 分钟才提醒；成功恢复后重新计算确认窗口。领取任务、刷新租约等内部操作不计为失败。
- 文件读取、文件校验或整理结果待确认时，先等待原有重试与恢复检查；进入需人工复核状态后才提醒。
- 上游明确失败、拒绝提交、账号或目录冲突等已确认需处理的问题及时提醒。

入队和每次发送图片、正文前都会重新核对任务代次、当前问题和通知设置，已恢复、取消或被新任务代次替代的异常不再发送。同一任务代次的同类问题只提醒一次，转交发送队列后仍保留去重记录。尚未达到确认条件的异常不会阻塞成功通知。

发送队列以下载任务、代次、事件、阶段和问题组成业务去重键，不依赖通知事件的自增编号。数据库重建通知表时仍保留已经使用过的编号上限；如队列去重键对应的是其他任务，入队会报错并保留待处理事件，不会静默丢弃新通知。

## 图片

在「通知图片」中选择：

- **自动附带动漫封面**：默认启用，使用订阅保存的动漫封面；没有可用封面则发送文字。
- **使用自定义图片 URL**：填写公开可访问的 HTTP 或 HTTPS 图片直链；不能使用本机、内网地址或带登录凭据的地址。
- **仅发送文字**：不附带图片。

图片显示在文字上方，不能通过模板中的 `<img>` 标签任意穿插。系统把缓存封面路径还原为固定官方原图地址，将图片 URL 交给 Telegram 获取，不要求 Cinema115 自身具有公网访问地址。图片无法被 Telegram 读取时，会降级发送正文。

图片说明的可见文本不超过 1024 个 UTF-16 单位时，使用一条图文消息；更长时先发送图片，再发送完整模板文字。已成功发送图片的进度持久化，后续正文重试不会重新发送图片。

图片功能需要运行包含该功能的新后台版本。页面读取到旧后台接口时，会明确提示更新并重启后端，不会把缺少图片字段的响应当作设置已生效。网页预览成功只表示浏览器可以读取图片；Telegram 是否能读取取决于其访问结果，失败日志会区分配图与正文发送阶段。

## 消息模板

默认模板使用 Telegram HTML 的粗体、引用和等宽路径，并包含 Emoji。可直接编辑模板，点击变量插入，切换三种事件查看预览。预览使用示例数据，不会发送 Telegram 消息。「恢复默认」需要保存才生效。

| 变量 | 内容 |
| --- | --- |
| `{icon}` | 对应事件的状态图标 |
| `{event}` | 下载完成、整理完成，或按问题显示任务异常、持续异常、需要复核 |
| `{title}` | 动漫名称 |
| `{episode}` | 发布集数，或合集、特别篇 |
| `{group}` | 字幕组 |
| `{provider}` | 资源站点 |
| `{resource}` | 原资源名称 |
| `{path}` | 下载或整理根目录 |
| `{reason}` | 状态说明或异常分类 |
| `{time}` | 事件发生时间，北京时间 `+08:00` |
| `{job_id}` | 下载任务编号 |

支持 `b`、`i`、`u`、`s`、`code`、`pre`、`blockquote` 标签，不接受标签属性、链接或可执行 HTML。代码格式不能与其他格式重叠，引用不能嵌套。普通文本中的 `&`、`<`、`>` 请分别写为 `&amp;`、`&lt;`、`&gt;`。变量值由后端自动转义。

模板上限为 2800 个 UTF-16 单位（大多数中文计 1，部分 Emoji 计 2）；消息按 Telegram 的 4096 单位限制自动截短动态字段，并保留完整标签与 Unicode 字符。空模板使用内置默认样式。

多个管理员同时编辑或从 Bot 页面更改分配时，旧版本保存会被拒绝。可以点击「读取最新版本，保留输入」，核对当前输入后再次保存。

## 验证

后端覆盖模板校验、转义与长度、事件事务与设置版本冲突、异常确认窗口与恢复、发送前复核、去重、队列和图片进度持久化以及通知接口；前端提供 `npm run test:anime-notifications-ui`，使用拦截 API 的浏览器测试验证图片模式、旧后台提示、保存、预览、冲突恢复、离开保护及深浅主题移动端布局，全程不发送真实 Telegram 消息。
