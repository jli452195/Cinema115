# 按站点选番：第一步（蜜柑）

日期：2026-10-19。用户确认将 Bangumi 发现入口换成 AniBT、蜜柑、Anime Garden 三个独立站点；每站使用本站卡片、搜索与来源，不合并资料、不增加产地筛选。UI 使用 Gemini CLI 讨论和审查，后端由 Codex 实现和审查。

## 分步交付

1. 站点身份、独立查询/草稿/缓存基础，以及蜜柑日历、搜索、条目到现有配置保存的完整链路。
2. AniBT 本站日历、搜索、来源/字幕组、样本与 RSS 适配及独立卡片。
3. Anime Garden 对应完整链路，保留聚合资源的原发布站点和字幕组。
4. 主/备用来源跨站选择、各站独立状态恢复及完整回归。

当前仅第一步已接入；顶部 AniBT、Anime Garden 显示“待接入”并禁用。直接请求未支持站点返回明确错误，不访问蜜柑代替该站。下载与云端整理仍未开放。

## 第一步实现边界

- 新页面 `AnimeCatalogView.vue` 接管 `/anime`，蜜柑使用自己的 `MikanAnimeCard.vue`、`MikanCatalogItem` 和 `MikanCatalogDialog.vue`，不转换为原来的 Bangumi 卡片。
- `source=mikan`、`item` 为蜜柑身份；配置入口使用 `source=mikan&itemId=...`。`bangumiId` 单独记录，禁止把蜜柑 4058 当成 Bangumi 4058。
- 后端 `GET /api/admin/anime/providers` 返回接入状态；`POST /api/admin/anime/catalog/:provider` 明确指定站点。`mode=calendar` 只接受季度；`mode=search` 只接受本站搜索词。管理员鉴权、请求体字段/大小验证沿用现有边界；不接受任意网址。
- 蜜柑官方按星期季度片段为 `/Home/BangumiCoverFlowByDayOfWeek`，参数 `year`、`seasonStr`。原始分类 `0` 是周日、`7` 是剧场版、`8` 是 OVA，转为页面 `1..7` 星期、`8..9` 剧场版/OVA，保留站点原分类语义。
- 卡片日期来自 `.date-text` 的资源更新日期，不写成首播日期。封面使用蜜柑自己的同源图片缓存（240×336），懒加载；不逐卡请求篇章、字幕组、样本或 TMDB。修复当前蜜柑搜索页面封面与标题链接为兄弟节点时无法取封面的情况。
- 整季一次读取，星期/剧场版/OVA 在本地切换；本站搜索结果本地每页 20 项。前端有界缓存 24 个查询，服务端复用既有 16 项蜜柑缓存、请求合并、站点串行访问/一秒间隔和冷却；读取取消传到上游，单个日历/搜索操作最长 45 秒。
- 刷新失败保留原结果；新查询不借用旧查询结果，过期响应不能覆盖当前查询。滚动、页码、选中条目、季度和搜索输入保存在会话内存及路由，登出/身份变化清空内存，不持久化令牌与结果。
- 点击后才读取该条目的字幕组。按用户追加要求，**原站只有一个有效 Bangumi 外链时默认关联**；多个不同外链不猜测，用户可选择、手工修改或取消。该关联只用于篇章资料，来源归属和规格仍由用户选择、服务端核验。
- 配置直接继承点中的蜜柑条目与组列表，不再搜索一次蜜柑；无 Bangumi 外链也能选择字幕组/规格、读取样本并保存草稿。源名称从服务端新读取的蜜柑条目获得，不信任路由提供的标题。关联 TMDB 的行为沿用独立命名方案。
- 三个站点入口共用 `AnimeProviderButton.vue`，分别使用蜜柑角色与字标、AniBT 官方标识、Anime Garden 官方花形标识。素材来源见 `frontend/src/assets/anime-providers/README.md`，新增素材约 15 KB，随项目本地打包；按钮不额外请求原站图片。柔和品牌底色、短选中指示条与轻微悬停放大共用，支持减少动效偏好；手机三列排列且按钮高度 66 像素。按用户最新要求，待接入状态仅保留简单提示。
