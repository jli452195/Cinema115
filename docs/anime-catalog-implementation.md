# 按站点选番与公共订阅配置

日期：2026-10-19。用户确认将 Bangumi 发现入口换成 AniBT、蜜柑、Anime Garden 三个独立站点；每站使用本站卡片、搜索与来源，不合并资料、不增加产地筛选。UI 使用 Gemini CLI 讨论和审查，后端由 Codex 实现和审查。

## 第二步：AniBT 与 Bangumi 公共配置页

2026-10-19 完成 R-02；R-04 的蜜柑/AniBT 部分同步实现，Garden 接入后的三站验收仍待完成。

- **页面主体是 Bangumi**：有关联的卡片统一进入 `/anime/new?bangumiId=...`。站点、原站条目和返回位置以浏览器 history state 传递，作为首次来源提示；不把站点放进配置页 URL 身份。保存后继续使用本地订阅 ID 编辑，服务端保持同篇章单一有效订阅约束。未关联条目可建立本地草稿，不按相似名称自动合并。
- **RSS 就地选站**：主 RSS 和每条备用 RSS 旁复用紧凑官方品牌按钮。在同一个浮层里选择站点对应条目、字幕组、规格；原站唯一 Bangumi 关联作为入口默认值，TMDB 命名、下载目录仍属于公共配置。
- **取消与替换**：来源选择操作临时副本，关闭时取消在途读取，不修改原来源。确认后才应用；持久来源换站/条目/字幕组时创建新身份，最终保存同时提交旧来源移除和新来源配置，历史保留。新来源独立核对编号与规则，主/备用不互相覆盖。相同来源更新规格保留原编号及预选，指纹变化要求重新预览。
- **AniBT 原生数据**：通过官方公开 API `/api/seasons/anime` 读季度及本站搜索、`/api/anime/groups` 读字幕组、`/rss/anime.xml` 读单组 RSS。独立卡片显示本站中/日文标题、类型、评分、集数、放送时间和资源数；不逐卡补 Bangumi、TMDB 或字幕组请求。Sunday 0 转周日 7，未排播单列；搜索最多返回 50 项并提示缩小关键词。
- **读取边界**：HTTP 20 秒、操作 45 秒、单响应最多 4 MiB；API/RSS 共用 32 项/8 MiB 有界缓存、请求合并、2.1 秒访问间隔及 429/带 Retry-After 的 503 冷却。失败不覆盖成功缓存。条目组 ID 使用原站 slug，不当作蜜柑数字 ID；来源、预算、指纹、去重及数据库身份都包含 provider。
- **历史不是无限分页**：AniBT RSS 最多最近 100 条，50→100 后停止展开。仅当原站组发布总数与已读 RSS 数量一致才声明当前可见末尾；否则标记 `source_limit`，不声称补齐全部历史。条目合并重定向不自动换身份，明确提示重新选择；仅允许同源、同条目/组的有界规范化 RSS 重定向。
- **封面请求**：保留原站封面身份，固定读取 `r2.anibt.net` 的 `v4/w240.webp` 衍生图，经过本站 `/api/anibt/image/...` 缓存与懒加载。缓存 200 MiB、两路下载；不接受任意域名、查询参数或路径。
- **SQLite v43**：事务重建两张 provider CHECK 表，保留 ID、索引、来源历史、预览和基线引用；提交前执行外键检查，退出恢复外键约束。迁移测试使用含真实引用的临时 v42 数据库，不删除业务数据。

## 第一步实现边界

- 新页面 `AnimeCatalogView.vue` 接管 `/anime`，蜜柑使用自己的 `MikanAnimeCard.vue`、`MikanCatalogItem` 和 `MikanCatalogDialog.vue`，不转换为原来的 Bangumi 卡片。
- `source=mikan`、`item` 为发现页蜜柑身份；配置入口已按本文第二步统一为 Bangumi 页面。`bangumiId` 单独记录，禁止把蜜柑 4058 当成 Bangumi 4058。
- 后端 `GET /api/admin/anime/providers` 返回接入状态；`POST /api/admin/anime/catalog/:provider` 明确指定站点。`mode=calendar` 只接受季度；`mode=search` 只接受本站搜索词。管理员鉴权、请求体字段/大小验证沿用现有边界；不接受任意网址。
- 蜜柑官方按星期季度片段为 `/Home/BangumiCoverFlowByDayOfWeek`，参数 `year`、`seasonStr`。原始分类 `0` 是周日、`7` 是剧场版、`8` 是 OVA，转为页面 `1..7` 星期、`8..9` 剧场版/OVA，保留站点原分类语义。
- 卡片日期来自 `.date-text` 的资源更新日期，不写成首播日期。封面使用蜜柑自己的同源图片缓存（240×336），懒加载；不逐卡请求篇章、字幕组、样本或 TMDB。修复当前蜜柑搜索页面封面与标题链接为兄弟节点时无法取封面的情况。
- 整季一次读取，星期/剧场版/OVA 在本地切换；本站搜索结果本地每页 20 项。前端有界缓存 24 个查询，服务端复用既有 16 项蜜柑缓存、请求合并、站点串行访问/一秒间隔和冷却；读取取消传到上游，单个日历/搜索操作最长 45 秒。
- 刷新失败保留原结果；新查询不借用旧查询结果，过期响应不能覆盖当前查询。滚动、页码、选中条目、季度和搜索输入保存在会话内存及路由，登出/身份变化清空内存，不持久化令牌与结果。
- 点击后才读取该条目的字幕组。按用户追加要求，**原站只有一个有效 Bangumi 外链时默认关联**；多个不同外链不猜测，用户可选择、手工修改或取消。该关联只用于篇章资料，来源归属和规格仍由用户选择、服务端核验。
- 配置直接继承点中的蜜柑条目与组列表，不再搜索一次蜜柑；无 Bangumi 外链也能选择字幕组/规格、读取样本并保存草稿。源名称从服务端新读取的蜜柑条目获得，不信任路由提供的标题。关联 TMDB 的行为沿用独立命名方案。
- 三个站点入口共用 `AnimeProviderButton.vue`，分别使用蜜柑角色与字标、AniBT 官方标识、Anime Garden 官方花形标识。素材来源见 `frontend/src/assets/anime-providers/README.md`，新增素材约 15 KB，随项目本地打包；按钮不额外请求原站图片。柔和品牌底色、短选中指示条与轻微悬停放大共用，支持减少动效偏好；手机三列排列且按钮高度 66 像素。按用户最新要求，待接入状态仅保留简单提示。
