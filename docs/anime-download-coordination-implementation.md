# 手动与动漫下载共享协调

日期：2026-10-19。对应任务：P2-03。

## 实现范围

网页单条/批量云下载、Telegram 云下载与动漫任务读取共用一个协调实例，按实际 115 UID、协议、资源 Hash 识别冲突。保留手动下载的查询、只删除已结束任务记录并保留文件、重新提交行为。动漫入口独立读取已持久任务，不能调用手动删除重提逻辑。

本项没有发送动漫下载请求、启动调度或改变任务状态；持久提交意图、不确定结果对账、接口状态严格规范化及实际文件核对分别由后续 P2 接入。SQLite 继续使用 v46。

## 共享实例与身份

[应用装配](../backend/cmd/server/main.go)只创建一个 `CloudDownloadCoordinator` 和云下载客户端，将同一协调指针注入 `CloudDownloadService` 与 `AnimeAdminService`。Telegram 沿用该手动服务；批量入口继续逐条调用固定快照提交函数。缺少协调实例时拒绝操作，不在不同服务中各自创建私有锁。

[协调器](../backend/internal/service/cloud_download_coordinator.go)的身份规则：

| 输入 | 协调身份 |
| --- | --- |
| 手动 `magnet` 与动漫 `bt_v1` | 同一 `bt_v1`，40 位小写十六进制 Hash |
| 手动 base32 磁力 | 原客户端先归一为相同 BT v1 Hash，再进入协调 |
| 手动 ED2K | 独立 `ed2k` 协议，32 位小写十六进制 Hash |
| 不同配置编号、Cookie 设备后缀或目标目录 | 只要实际 UID/协议/Hash 相同就冲突，不将这些字段加入资源键 |
| 不同 UID 的相同 Hash | 可独立操作；不会共享或替换账号凭据 |
| 空/非法 UID、非法 Hash、不支持的协议 | 固定错误并拒绝，不退回配置编号作为身份 |

手动提交从任务固定 Cookie 提取实际 UID，并核对账号保存的 UID。凭据缺失、身份冲突时在请求上游前拒绝。协调器只保存 UID 和资源键，不存 Cookie、目录或响应。

## 并发与生命周期

相同资源正在执行或排队时，第二个入口立即返回原有 `ErrCloudTaskBusy`。同 UID 的不同资源等待容量为 1 的操作闸门，不同 UID 可以并行。登记排队资源只用于拒绝重复请求，不持有另一个资源锁；实际操作先取得 UID 闸门，再进入该资源的回调范围。等待接受 Context 取消和超时。

不启动后台协程。每次释放使用 `sync.Once`，重复或迟到释放不能影响后来的操作；等待取消也会清除登记。最后一个请求离开后删除对应 UID/资源记录。操作结束即释放，不等待整个离线下载完成；网络 I/O 不持有协调器互斥锁或数据库事务。

这是当前应用实例中的操作协调。P2-02 的 SQLite claim 继续负责本地资源幂等；进程重启后的未知提交不能依赖内存锁恢复，必须由 P2-04 的持久操作及后续租约恢复处理。协调器不能控制其他工具对 115 的操作，也不表示 115 下载本身只能有一个任务。

## 动漫入口

[LookupDownload](../backend/internal/service/anime_download_coordination.go)只接受本模块持久任务 ID 和固定凭据会话：

1. 检查会话归属、当前主账号编号/revision/UID、原任务目标及 BT v1 身份。
2. 取得共享 UID/资源协调。
3. 排队后再次核对凭据，重新读取任务；目标、资源或任务代次变化则停止。
4. 用原任务 Cookie 和 Hash 精确读取，上游返回 Hash 不符时拒绝。
5. 读取后再次核对凭据，不回传任意上游错误正文；始终释放协调。

整个读取最多 25 秒。功能默认目录变更不会重定向旧任务；凭据更新或换号会拒绝旧会话。现阶段 `Offline` 只暴露 `CloudTaskReader`，没有删除或重提方法。完成、失败、未知或未查到均只作为本次观测返回，不更新下载状态、不自动创建新尝试，也不将未查到当作可以提交的证明。

私有 `withDownloadResource` 给后续执行阶段复用同一协调边界；新增写阶段还必须在协调内检查持久授权、租约和操作意图，本项只读检查不授予写权限。
