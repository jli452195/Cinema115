下文保留2026-10-18原始能力验证和当时的边界；其中“尚未发送目录列表”仅指旧轮次，本轮已读取空目录列表。

## 结论与证据范围

现有底层接口可以查询同 Hash 任务、读取目标目录和结果标识，并继续精确查询该标识。不过，**任务的 `file_id` 可能是目录 ID**；本次完成样本就是目录，不能当成视频文件 ID。精确查询与列表对同一完成任务返回不同数字状态，不能统一按 `status` 数字判断完成。

本次已实测“离线任务 → 结果目录 → 目录的父级与提交目标一致”。后续读取遇到接口异常，其中一次 HTTP 502，停止重试，**没有完成目录内具体文件的实站核验**。因此后续自动处理必须以本工具专属任务目录、提交记录和实际文件读回为依据；缺少充分关联时进入待核对，不按百分比或名称猜测。

## 只读验证方式

管理页使用已有登录状态调用 `/api/admin/p115/cloud-download/config` 和 `/tasks`，授权值仅在页面函数内使用。直接验证通过 SQLite `mode=ro` 仅读取 `is_primary=1 AND ownership='admin'` 的唯一主账号，在内存解密并固定其凭据，核对 Cookie UID 与该主账号记录相同。未调用可能初始化或迁移数据库的账号/存储入口，未读取个人或其他管理员账号的凭据。

一次性 Go 探测通过 overlay 注入测试包，不改生产代码。HTTP 传输层限定 HTTPS、GET、固定 115 主机及 `task_lists/get_user_task/files/get_info` 读取；后续准备的目录枚举还要求精确绑定已核对的结果目录。禁止重定向；每次 25 秒、整轮 110 秒、最多 6 次请求，顺序调用且请求之间至少间隔 1.2 秒。正文沿用客户端 4 MiB 上限。这些是本次预算，不是上游公布限额。

记录只保留字段名、状态、数量及标识相等与否，不保留真实 Hash、目录 ID、文件名、路径、Cookie、签名或直链。下文用 `HASH_A`、`RESULT_CID_A`、`TARGET_CID_A` 表示同一组实测关系，均为占位符。

本地忽略目录 `tests/anime-p115/` 保存只读探测、解析诊断、脱敏观察和公开参考文件；本报告保留必要事实与复现步骤，后续实现不依赖该本地目录。

## 实站观察

### 管理接口与原始列表

17:33:31 的管理接口返回总数 861、当前 10 条：1 条 `status=1/progress=0`，9 条 `status=2/progress=100`。公开到应用层的字段只有 `doneBytes/error/infoHash/name/progress/status/totalBytes`，没有目录和结果标识。

17:42:00 开始的直接读取请求第一页 5 条，返回总数 861、当前 5 条：1 条进行中、4 条完成。5 条均具有 40 位 Hash、非空 `file_id` 和 `wp_path_id`。**进行中任务也带有 `file_id`**，标识存在不表示文件已下载。

原始列表响应包含 `tasks/count/total/page/page_size/page_count/page_row/state/real_state/errcode` 等字段。任务中可用的关联和状态字段包括：

```text
info_hash: string       file_id: string       wp_path_id: string
status: number          display_status: string
percentDone: number     display_percent: number
move: number            available_actions: array
retry_count: number     retry_limit: number
```

任务还带有名称、URL、pickcode、删除路径等字段，本模块不需要把它们原样保存或返回。`move`、`delete_file_id`、`del_path` 的业务语义未核实，不把这些字段用作自动移动或清理授权。

### 同一完成任务的精确查询

| 字段 | 列表 | 精确查询 |
| --- | --- | --- |
| `info_hash` | `HASH_A` | 精确匹配 `HASH_A` |
| `status` | `2` | `1` |
| 规范化进度 | `100` | `100` |
| `display_status` | 未单独记录其值 | `finished` |

精确响应还含 `state/errcode/percentDone/display_percent/status_text/available_actions`。其缺少 `wp_path_id`，说明精确查询单独不足以证明目标目录，需要保留先前已验证的列表关系、提交快照及结果对象的父级证据。

本次另用构造的合法 40 位未命中 Hash 调用 `LookupTask`，结果 `found=false, error=nil`。现有代码仅将业务错误 10021 映射为任务不存在；本次没有额外保存该响应原文。其他网络、鉴权、格式或业务错误必须保留为错误，不能当作未命中。

### 结果标识对应目录

对 `RESULT_CID_A` 执行一次精确元数据读取，HTTP 成功，`state=true`，`data` 恰好一条：

```text
aid = "1"
cid = RESULT_CID_A
pid = TARGET_CID_A
没有匹配该标识的 fid
```

响应有 `cid/pid/n/pc/aid`，没有文件的 `fid/s/sha` 组合。结合目录 ID 与父级一致，本条结果是目录，不是视频文件。任务的 `file_id` 只是结果对象标识，后续客户端应使用这一含义命名，不能直接投影成“已确认视频文件 ID”。

随后扩展探测准备在该目录内最多读取 5 条，并精确核对一个子文件；但两轮都在第一条列表请求处失败，第二轮明确为 HTTP 502，已停止。**未发送目录内容或子文件请求**，也没有创建真实任务来补样本。第一轮失败未保留状态码，不能同样记作 502。

本次直接请求合计 6 次：4 次成功、2 次失败。未验证失败/取消任务的真实状态全集、分页末尾、外部移动后的关联变化、文件型 `file_id`、完成文件延迟出现或新增任务的完整生命周期。

## 现有实现的复用边界

### 手动提交会删除已结束记录再重提

`CloudDownloadService.Submit` 先精确查询同 Hash；若满足 `RedoReady`，删除该任务记录、保留文件，再提交。现有测试覆盖完成、失败、停止、运行、等待、未知、Hash 不符、查询失败、删除失败、提交超时、并发与凭据固定。

这是当前手动重提行为，**不能把它作为自动订阅轮询入口**。动漫执行器需要独立的“确保提交”流程：持久化意图、核对归属、提交一次、结果不明先对账。当前进程锁按账号配置编号、协议与 Hash；P2-03 要升级为手动/自动共享实际 UID、协议与 Hash 的协调，并保留手动行为测试。

2026-10-19 实现补充：P2-03已将上文验证时的账号编号锁替换为应用共享的实际UID/协议/Hash协调，手动行为回归通过，动漫读取入口独立且没有删除/重提能力；详见[下载共享协调](anime-download-coordination-implementation.md)。P2-04 已接入独立严格客户端、持久提交日志与未知结果只读对账，详见[确保提交实现](anime-submit-implementation.md)；模拟验证不作为真实115提交证据。只有精确Hash及目标关系成立才记已接受，不判断文件完成；派发前发现既有任务则保留归属冲突，不接管其他工具任务。

现有手动服务还会忽略 `ParseCloudTask` 失败；提交被接受不证明回执具备完整任务或文件身份。新执行器必须分别保存已接受、结果不确定与实际文件已确认，不能沿用“有成功响应就完成”的简化。

### 宽松解析不能充当自动完成或不存在判据

本地诊断确认：

| 输入 | 当前行为 | 动漫实现要求 |
| --- | --- | --- |
| 列表 `{"state":true}` | 无解析错误，空列表、总数 0 | 缺少列表结构与分页信息应视为格式不明，不能认定没有任务 |
| 任务 `{"status":null}` | `status=0`、`StatusKnown=true`，可重提 | 空值保持未知，不能变成明确终态 |
| 任务 `{"status":"unknown"}` | 同上 | 非法数值保持未知，原始值只做受控诊断 |
| 任务 `{}` | `StatusKnown=false` | 无身份/状态不能认定完成或未命中 |

这些是现有解析器的诊断结果，未将其写成“应该接受”的回归断言，也未在本验证任务中修改手动流程。P2 状态适配必须校验接口来源、字段类型、Hash、已知显示状态和进度范围；未知或冲突状态转为待核对。

`RedoReady` 同时接受成功、失败、停止，以及 `progress>=100`、非空错误等条件，其含义只是“允许手动移除后重提”，不是下载成功。列表完成样本 `status=2` 与精确完成样本 `status=1/finished` 分别处理；未观察的状态不靠猜测补枚举。

2026-10-19 P2-06 实现补充：自动追踪已接入独立严格状态适配，只读取精确Hash接口，以来源标识区分语义，不接受列表响应作为任务状态或不存在证据。精确status=1、明确完成显示及合法100%进度共同成立才记录远端completed，仍不核验实际文件；缺失/非法状态保持未知，任务消失不重提。相同UID共享间隔和限流等待，成功观测及时间与查询错误分开持久保存。新增19项模拟/临时SQLite测试及相关回归通过；本次没有补充任何实站状态或子文件证据。详见[状态追踪实现](anime-status-tracking-implementation.md)。

### 文件读取需提取基础能力

现有 `DriveFiles` 支持目录分页，但只投影 ID、名称、大小和目录标志，没有完整 SHA1、父级及分页完整性证明，不能原样用作自动整理验收。

已有精确元数据实现可参考 `files/get_info` 的长/短字段别名、唯一结果、ID 与父级核验、删除墓碑 `aid=120` 及未知区域拒绝等处理。应提取独立网盘基础能力，不调用播放取链、播放缓存或其生命周期。文件和目录需要分别解析；别名冲突、缺字段、重复分页、读取不完整不能静默降级为成功。

## 后续自动流程的约束

1. 使用明确主账号，固定账号编号、核验 UID、凭据与目录快照；目录创建也先持久化意图。没有主账号或归属变化就受阻，不借用其他配置。
2. 提交前按实际 UID、协议、Hash 共享协调，精确查询。外部同 Hash 任务即使已完成，也不能仅因结果存在就接管、移走或删除其文件；归属不明转为待核对。
3. 仅在没有未确认提交且精确查询明确未命中时提交一次。提交超时、回执丢失或本地写回失败，保留意图先对账；任务列表缺页或 502 不触发重提。
4. 按接口来源规范化离线状态；完成后核对结果对象类型与目标关系。仅枚举已确认属于本任务的专属目录与其必要子目录，设置深度、条数和时间预算，不做全盘搜索。
5. 下载完成后仅列本任务目录与必要结果子目录一次，保存ID、父级、名称、类型和列表附带大小；不逐文件GET，不取或比对SHA1。文件对应不唯一、未读完整或关联缺失时保持待处理；不为补实站样本新增真实下载，本报告仍不是完整真实闭环验收。
6. 原名保存时，实际文件核对成功即结束该下载任务。启用整理时，使用同一网盘的原文件改名、移动，明确成功回执即记录结束，只有未知回执才按固定文件ID最小补查，不另复制一份原视频，也不执行“复制后删除”。
7. 离线状态已确认完成并取得文件事实后，停止该任务的离线轮询。整理完成后不定期复查或重新下载；仅未完成或写入结果不明的阶段按记录恢复。保留本地 Hash 与来源发布处理依据，避免 115 记录被清理后重复提交同资源；按 P0-04 共存要求，不扩大成同集其他 Hash/字幕组版本互斥。

本地执行记录、115 离线列表记录、云端文件是三类对象。结束本地任务不要求删除 115 列表记录；移走视频后源目录自然不再含该视频，附件、空目录和其他版本仍按现有方案保留。原文件移动与目录清理独立，不由前者推导批量删除权限。
