# 订阅时选择 TMDB 与来源编号映射

本文记录早期实现；当前 RSS 目录与文件命名已接入公共剧集模板，详情见 [N-04](naming-template-plan.md#n-04-动漫-rss-命名2026-10-25)。编号映射独立于公共模板。

实施日期：2026-10-19。对应任务 P3-01、P3-02、P3-03。本轮按用户要求提前接入配置页；115 下载、文件改名和移动仍未开放。

## 当前操作流程

1. 从 Bangumi 选番进入订阅配置，后台用篇章标题和原名搜索 TMDB。搜索移除明确季号及其后的分篇后缀，避免“第三季 反击篇”导致零结果。唯一匹配项或唯一候选可推荐，多个含糊候选交由用户选择；推荐仍需核对。目标季优先采用首播日期相差不到 15 天的正季，其次参考标题中一致且实际存在的季号，否则选第一个正季。不会根据 Bangumi 季号虚构 TMDB 不存在的季。
2. 配置页直接显示作品、整部作品首播年、TMDB ID、目标季和集数。可更换作品、填写 ID、选择本订阅使用的剧集组，或保留发布原名。
3. 来源浮窗只选择条目、字幕组及规格。原来的“来源范围”和“保持原编号／设置编号对应”不再占据必经步骤；范围成为可选的高级下载过滤规则。
4. 在来源卡片填写“发布第 25 话，对应第 2 季、第 1 集”。立即回显 25→S02E01、26→S02E02；下载起点改为 30 时另回显 30→S02E06，基准仍为 25。
5. 分段与逐集例外按需展开。SP、小数集及复合编号必须明确指定目标或忽略，不自动归入第 0 季。目标尚未收录时展示待核对，不生成虚构的文件路径。
6. 保存草稿或暂停配置，同时保存作品快照、各来源映射与表单选择；再次编辑直接恢复。不触发下载或对已有文件进行改名。

普通集默认建议 1→1，不将当前 RSS 窗口最小值当首集。例如窗口始于 8，仍不建议 8→E01；发布编号大于目标季总数时留空，要求填写可信基准。主、备用来源各自设置，不继承其他字幕组的偏移。手动输入不受样本刷新、迟到请求或推荐季切换覆盖；来源季与推荐季不同时就近提示。

## 后端实现与边界

- `model/anime_naming.go`：纯映射计算、分段与例外优先级、同来源范围/目标碰撞校验。普通集例外按解析整数匹配，兼容标题里的前导零和 v2；特殊编号按完整原始编号匹配。不同来源可对应同一个剧情集。
- `service/anime_naming.go`：复用 TMDB 客户端及缓存，但读取原始季集，不读取或修改全站 `tv_numbering`。校验剧集组确属目标作品；保存订阅自己的目标、分集 ID 和名称。
- 快照指纹为 SHA-256；新目标保存时由服务端重新读取核验，变化返回 `NAMING_METADATA_CHANGED`。请求附带已加载季列表，避免移除一个跨季规则后仅因加载集合变化导致错误冲突。已有相同快照的本地修改可以离线保存，新季仍须读取校验。
- SQLite v42 为 `anime_subscriptions` 增加 `naming_json`；`null` 表示保留原名。配置 revision 是本地方案版本，指纹标识外部资料内容。来源临时 ref 在配置事务中转换为稳定 ID，未知/重复 ref 拒绝并整体回滚，不修改调用者对象。
- 映射、订阅配置 CAS 和幂等回执共同提交。回执丢失用原键/原正文重试，不再次读取外部资料。元数据读取有总超时，跨季读取有数量限制，前端对同一缺失季组合不反复请求。
- 当前命名仅生成无扩展名的预览路径：`作品 (首播年) {tmdb-ID}/Season 02/作品.S02E06.实际字幕组`。实际文件扩展名、字幕关联、同名冲突和云端写入另在后续任务实现。

新增管理员接口均为只读，不要求幂等键：

| 方法与路径（`/api/admin/anime` 下） | 输入与用途 |
| --- | --- |
| `POST /naming/search` | `bangumiId` 或 `keyword`；返回有界候选和推荐 ID |
| `POST /naming/target` | `tmdbId/groupId/season?/bangumiId?/extraSeasons?`；读取目标快照 |
| `GET /naming/groups/:id` | 读取目标作品可选剧集组 |
| `POST /naming/preview` | `naming` 与最多 50 条来源标题；服务端解析并生成命名投影 |

页面输入使用即时本地预览，保存由后端再次核验；只读预览 API 提供相同规则的服务端入口。无 TMDB、搜索失败或用户选择原名时，仍可正常保存来源配置。

## 篇章对应集数（2026-10-19）

配置页篇章标题旁新增独立 `AnimeChapterEpisodes` 只读组件，手机下沉到标题区下方。展示当前篇章在所选 TMDB 季/剧集组中的对应编号，超过 12 项折叠，展开列表高度限制为 142px，不占据整页。

- 新增管理员只读接口 `GET /api/admin/anime/discovery/subjects/:id/episodes?offset=0`。使用现有 Bangumi Client 的共享缓存、冷却和取消机制，读取正片 `type=0`，100 项一页，仅在用户继续读取时请求下一页，最多 2000 项。通常篇章只有一次请求；不读取分集图片、剧情简介或逐集详情。
- Bangumi 返回值分别保留显示编号 `sort` 与篇章内编号 `ep`，不将其声称为 TMDB 集号。上游身份、类型、分页完整性和重复 ID 均在缓存前校验，未知/非法日期置空。
- TMDB 命名快照增加可选分集首播日期。前端仅用当前季中唯一标题或准确首播日期作对应参考；同日多集可由标题消歧，冲突和多个 Bangumi 集指向同一 TMDB 集均保持待核对。没有数字直等、连续偏移推算或跨季猜测。
- 无 TMDB 时展示 `BGM 59` 等原编号；未确认关系保留原编号并显示待核对数量。每项提供包含原编号、篇章内编号及依据的悬停文字和屏幕阅读器标签。失败在集数区局部重试，不阻断草稿保存。
- 切换 TMDB 季/分组在内存重算，不重读 Bangumi，不改动 RSS 规则、补番起点或已保存的字幕组命名锚点。切换篇章、令牌及卸载时取消旧读取，避免迟到结果串入。
