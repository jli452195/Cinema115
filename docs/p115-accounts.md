# 115 多账号

打开 `/helper115`（115 网盘 → 115 助手），点击「添加配置」。名称可自定义，每张卡片独立保存 Cookie 或扫码登录，最多保存 20 张配置。

- 「保存配置」会先验证新 Cookie；验证失败保留原凭据。Cookie 留空时只修改名称。
- 「扫码登录」使用该卡片所选客户端类型，确认后自动加密保存到发起扫码的卡片，不改变任何功能的账号选择。
- 所有账号地位相同，没有「设为当前」、主账号或默认账号。
- 「清除登录信息」只清空该卡片的凭据。所有账号都可删除，包括最后一个；删除配置不删除网盘文件，使用它的功能需重新选择。
- 列表只返回名称、配置编号、用户 ID 和状态；需要查看 Cookie 时，管理员可在卡片内手动载入，默认隐藏。页面不会将 Cookie 写入浏览器存储。

「115分享STRM → 基础设置 → 使用 115 配置」下拉框列出已保存账号。选择后点击右上角「保存设置」，普通分享、转存再分享、Telegram 生成与 STRM 播放共用本功能的选择。空值提示「请选择 115 账号配置」，即使仅有一个账号也不会自动选择。配置编号保存在 `automation.json`，不保存 Cookie。账号被删除或清空后停止使用，需重新选择或登录，不会自动换用其他账号。

正在执行的单条或合并生成任务固定使用启动时的设置和 Cookie，切换不会使转存、分享或清理中途改用其他账号。审核重试仍核对当前分享配置所用 Cookie 的指纹，凭据变化后会停止。

现有 STRM 地址不包含账号编号，也没有自动根据分享所有者选择账号。更改分享配置后，旧链接的新播放请求也会使用新的分享账号；只有原分享者可读取的审核中分享可能需要切回原账号。

账号保存在 `DATA_DIR/cinema115.db`，默认目录为项目 `data/`，容器内为 `/data`。账号名称可查询，Cookie 字段使用 AES-GCM 加密并绑定配置编号，密钥由 `JWT_SECRET` 派生。数据库没有全局当前账号字段。

首次自动导入 `p115-accounts.enc`；只有更早的 `p115-session.enc` 时导入一张普通账号卡片。旧系统自动创建的「默认账号」改名为「账号 1」，用户自定义名称及账号编号保持不变。新安装不创建空的默认卡片。导入及迁移标记在同一 SQLite 事务内提交；清除新配置后不会重新导入旧 Cookie，旧文件保留备份。

数据库版本 6 移除全局账号字段。旧分享设置原本采用全局账号时，启动阶段一次性把原编号写成分享功能的明确 `accountId`，保留原功能所用账号；原本明确选择的账号保持不变。成功后删除迁移候选，后续不作默认值或账号回退。

备份和迁移时保留数据目录与原 `JWT_SECRET`，运行中数据库备份使用 `dbtool` 的一致性快照功能。账号无需调整 `.env` 或 Docker 环境变量。加密配置无法读取时会停止启动；存储失败不会改变内存中的账号数据。

新增 115 功能统一复用 `P115AccountSelect.vue`，在本功能设置中持久化 `accountId`，保存时调用 `ValidateSelection` 校验，执行时按编号获取凭据。不得回退到其他功能、首个或唯一账号。账号登录接口只接受 `/api/admin/p115/accounts/:accountID/...`；旧的无账号登录接口及 `/activate` 已移除。
