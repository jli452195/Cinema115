## 1. 本轮讨论的方向

1. TMDB ID 和年份是识别依据，不是所有源文件必须具备的字段。名称可来自文件名或可信的作品目录。
2. 优先使用明确 ID，再匹配标准名、原名、别名；没有合适的精确结果时，再尝试模糊匹配。
3. 同名同年仍有多个候选时，采用 **TMDB 返回顺序中的第一个合格结果**，保存所选作品并保留修正入口。
4. 自动整理遇到完整、有效的 `S00E01`，直接采用第 0 季第 1 集。特殊内容确认规则区分自动整理和磁力整理入口。
5. 区分识别结果和执行结果，不展示中间阶段，也不能用“识别完成”代表移动成功。

第 3 项的当前边界与预算见第 11 节；后续可以根据实际误判继续调整，不能直接把任意关键词搜索的第一条当成匹配成功。

## 2. 优化前的判断逻辑（排查基线）

| 环节 | 优化前行为 | 影响 |
| --- | --- | --- |
| 输入解析 | 从文件名和最近最多两级父目录提取名称、年份、类型、季号、TMDB ID | 不读取 NFO 正文辅助作品匹配；大小和 SHA1 也不用于识别作品 |
| 显式 ID | 有 ID 且类型为 `movie` 或 `tv` 时直接查询详情 | ID 已知但类型未知时，仍依赖名称搜索确定类型 |
| 搜索 | 搜文件片名、父目录片名，特定情况补充去掉季副标题的父目录名称；每次只读第 1 页 | 候选范围与查询变体有限 |
| 名称核对 | 规范化后比较标准名、原名，必要时查别名；别名仅尝试搜索结果前 3 个位置 | 大小写和标点已有处理，繁简、全半角和近似拼写尚无完整匹配策略 |
| 缺少年份 | 并非所有文件都必须有年份，但无年份且规范化名称少于 4 个字符会被排除 | 即使搜索只有唯一准确结果，短片名仍可能失败 |
| 多个候选 | 当前轮次有多个合格候选时返回未匹配 | 同名同年的动画和真人版仍要求人工选择 |
| 类型推断 | 文件解析出了集号就将作品类型设为 `tv` | 电影标题中的数字被误当集号时，会连带查错类型 |
| 特殊内容 | 自动整理已增加完整 `S00Exx` 优先规则；磁力入口保留原确认逻辑 | 季集有效与作品匹配成功仍是两个独立条件 |
| 结果记录 | 分组已有作品 ID、类型、名称和提示，文件已有季集和执行状态 | 缺少统一识别结果快照、候选淘汰依据及稳定原因码 |

优化后仍需识别到作品、获得有效的作品类型和 TMDB ID、满足命名所需信息，且存储操作成功。剧集还需要有效季集；源文件本身不必声明 TMDB ID，年份也不是普遍必填项。

## 4. 建议的匹配策略

### 4.1 先保留输入，再决定采用哪个解释

解析期间按需保留片名备选、目录提示和来源供算法采用，完成后释放临时过程数据。原始文件信息与最终作品分开保存，不持久化另一份完整 `parsed` 快照。

例如 `Blade Runner 2049.mkv` 不应只留下 `name=Blade Runner, year=2049`。应保留完整标题的解释；明确括号年份或其他上下文可加强年份证据，裸数字不能单独决定作品年份和类型。

明确的 `S01E13` 是剧集编号证据；`Planet 51` 中的裸数字是弱证据，不能仅因解析器给出集号就覆盖电影身份。未知类型允许跨电影和剧集搜索。

### 4.2 推荐的选择顺序

1. 已保存的人工选择，或当前分组已经冻结的匹配结果。
2. 来源明确的 TMDB ID。类型未知时，确定其类型；电影和剧集的数字 ID 不能视为同一命名空间。
3. 标准名、原名、已核实别名的精确匹配，再结合已有类型、年份等证据筛选。
4. 规范化变体与模糊候选，计算名称相似度并结合目录关系筛选，过程仅在运行时使用。
5. 同一匹配层级仍有多个合格候选时，采用 TMDB 原始排名中的第一条。
6. 没有相关候选、存在未解决的明确声明冲突时，记录具体原因并保留修正入口；查询超时单独记为可重试错误。

模糊匹配分数只表达名称相似程度，不包装成“正确概率”。不能让一条低相关结果仅凭排名靠前就胜出。明确年份冲突、季年份与作品首播年份的区别，需要在筛选规则中单独处理。

搜索分页、别名查询与模糊比较共用明确预算，复用现有 TMDB 缓存；有充分结果后停止扩展。不为每一集重复查询同一批候选。

### 4.3 “堀与宫村”如何选择

此前查看的 `堀与宫村 (2021)` 搜索结果包含动画 `tv:110070` 和真人版 `tv:113980`，当时动画排在第一位。现有名称、年份判断不能区分两者，所以返回人工确认。

建议采用用户提出的默认行为：如果两个结果都符合现有证据，采用第一条，即当时的 `tv:110070`。如果来源已明确声明真人版，则按该证据筛选。没有动画标记也可以完成匹配。

最终作品随分组保存，后续集数复用，不能因为 TMDB 排序变化静默切换。不保存或展示查询、候选顺序、排名、分数及采用依据解释，也不为复现过去过程补发请求。不同文件和不同版本仍保持独立整理任务，不按作品 ID 合并历史卡片。

## 5. 结果标识

作品码由类型和 TMDB ID 组成，例如 `tv:318902`。日志关联复用已有任务、分组与文件编号，不维护历史尝试面板或重复追踪字段。结果码只需表达当前成功、待匹配、季集缺失／冲突、查询暂时失败、等待主文件、目标冲突或移动待核实等状态。

## 6. 最小保存字段

只保存原始文件身份与来源、最终作品及类型／年份／TMDB ID、最终季集、命名必需规格、目标、当前状态和必要原因。附件保留角色／语言、归属和处理结果。各信息只存一份，空可选值不展示，季号 `0` 保留。

任务固定规则、账号／连接归属、分组依据、当前人工选择、采用季号和外部操作恢复状态继续保留。查询词、候选、排名、相似度、采用解释、字段证据链、历史快照、阶段列表和逐阶段耗时不保存。临时计算不为展示增加工作。

## 7. 页面与日志只看结果

详情页只展示一份主文件结果、来源／目标和紧凑附件列表，取消诊断区和过程面板。保留搜索作品、人工修正与重试。只读参考的两个案例及具体字段见[最新方案](media-parser-refactor-plan.md#11-日志详情展示与持久化收敛)。

日志保留主文件的识别结果、执行结果和批次汇总；正常附件合并统计，异常附件单独记录原因和定位字段。只在必要状态变化时输出，不生成候选或逐阶段 DEBUG。沿用共享日志，不新增诊断表、媒体探测、二次解析或额外请求。

## 8. 季集与附件的独立边界

`S00E01` 只能说明第 0 季第 1 集，不能单独说明是哪一部作品。作品匹配仍按第 4 节处理，但不应因为名称里出现 OVA 就再次否定已明确的季集。

自动整理中，完整有效的 `S00Exx` 优先于 OVA 序号与 `Specials` 目录；没有标准坐标或有真实编号冲突时才继续修正季集。磁力阶段保留特殊内容确认，避免共享函数修改后意外放宽该入口。TMDB 总集数不作为文件集号上限。

已唯一关联的视频尚未匹配或命名完成时，附件应展示“等待主文件”。只有确实存在多个对应视频或没有对应视频时，才展示未关联原因。

此次看到的同路径两份 NFO 是不同文件身份和不同内容，不能因显示名称相同直接合并或删除。“来源目录中已有同名文件”和规则中目标、失败目录配置反向的问题，也需要与作品识别失败分别呈现；它们不靠放宽名称匹配解决。

元数据候选使用固定样本验证算法；实际 TMDB 顺序仅用于单独的只读观察，避免上游排名变化影响回归结果。

| `三体.S01E01.mkv`，没有年份和 ID，只有唯一精确候选 | 可以自动匹配，不因片名短拒绝 |

| 分数集、不完整坐标、多个明确冲突集号 | 保留待修正，并给出具体季集原因码 |

## 10. 建议实施顺序与待讨论项

R-01～R-21 为首轮完成记录，后续实施顺序以[当前待办](media-parser-refactor-plan.md#9-推荐实施顺序)为准；结果与恢复状态保持一致，不恢复过程展示要求。

下面是后续讨论点，不作为当前新增必填设置：

- **第一条策略的适用范围**：建议同层级合格候选默认取第一条；精确候选优先于模糊候选，已有明确声明优先于排名。
- **模糊匹配尺度**：当前按第 11 节的有界编辑距离处理轻微拼写差异，后续继续用实际失败样本调整，不把名称分数当作正确概率。
- **年份冲突如何放宽**：缺少年份正常匹配；明确年份与片名数字要区分。剧集季度年份不能简单等同于整部作品的首播年份。
- **动画与真人证据来源**：可用明确来源标签、规则中的媒体属性或已有元数据；是否增加规则级偏好待讨论，不把它变成所有任务的必填项。
- **NFO 处理边界**：仅作为附件参与归属和同角色留一，不读取正文，不作为作品识别字段来源。
- **查询预算**：沿用查询变体、页数、别名请求与超时上限，已有合格结果后停止；不为展示补查，不持久保存候选。
- **复用范围**：第一步沿用批次内作品分组；跨批次长期记忆和批量套用人工修正需另定范围，避免一个误选扩散到其他作品。

每次讨论确定后，更新对应编号的规则和验收预期；实施及验证完成后再勾选。

## 11. 当前实施约定

已按[最新方案](media-parser-refactor-plan.md#11-日志详情展示与持久化收敛)移除完整识别快照、历史尝试和逐文件阶段数组。以下为当前算法与恢复约定。

- 策略版本：`2026-11-03-v1`。作品码使用 `tv:ID` 或 `movie:ID`，日志关联复用现有任务编号。
- `group.identity` 保持分组依据，`matchedSeason` 保存采用季号；流式扫描新文件复用已选作品和采用季号，各文件独立保存当前执行结果。
- 尾部裸数字不能单独把电影改成剧集。同目录有明确发布编号，或相同基础片名至少有一对连续编号时，可补强其余集号；从第 10 集开始的半季包、`v2` 修订和 `END` 完结标记均纳入回归。同一数字的多个修订版本不作为连续集号证据。
- 没有年份、没有 ID、短片名均可搜索；明确名称、原名和别名优先。同层级合格候选采用 TMDB 原始第一条；明确动画或真人标签按 TMDB 动画类型核对，不根据语言、字幕组或一般片名猜测。
