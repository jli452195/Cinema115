# 网络代理

管理员在「资源配置 → 网络代理」中配置 NAS 访问外部服务的代理，无需修改 Compose 或重新创建容器。

页面右上方的「测试连接」打开服务列表弹窗，逐项显示连接状态和延迟。可以单独测试某项，或点击「测试已选服务」依次测试勾选的服务。打开弹窗不会主动请求，测试不保存表单；取消或关闭弹窗会中止当前请求并停止后续测试。

开启代理、填写地址并选择适用服务后保存，后续网络请求立即使用新设置。支持 HTTP、HTTPS、SOCKS5 和 SOCKS5H，例如 `http://192.168.0.10:7890` 或 `socks5://192.168.0.10:7891`；地址应能从运行 Cinema115 的 NAS 或容器内访问。需要认证时展开认证设置，单独填写用户名和密码。

适用范围包括 TMDB、GitHub 字幕库、蜜柑、AniBT、AnimeGarden、Bangumi、Assrt、观影、蜗牛、Telegram 机器人及 Telegram 用户与频道搜索。选中服务的 API、RSS、图片和种子读取共用该服务的代理策略，保留各站原来的独立缓存、访问限速和重试规则。Garden 的原站种子兜底请求也属于 Garden 范围。

115 的账号校验、扫码、分享、云下载、上传、整理和播放取链始终直连；Emby 和内网 NanShare 同样直连，不提供代理勾选项。关闭代理或未勾选的服务直连，不读取系统代理环境变量。返回 302 后播放器访问 CDN 的网络由播放器所在设备决定。

「测试连接」使用当前表单，但不会保存或改变正在使用的配置。选中的测试服务未启用代理时，测试的是直连。HTTP 服务测试只发起一次固定服务地址请求，最长约 12 秒；HTTP 401 或 404 表示上游已响应，仅证明网络连通，不代表 API 密钥、登录状态或具体业务接口正常。Telegram 用户测试连接固定的数据中心，只验证 TCP 连接或代理隧道能否建立，不执行登录，也不验证频道权限、搜索或 Bot HTTP API。没有定时探针，也不会在代理失败后自动改走直连。

配置保存在数据目录下的加密文件 `network-proxy.enc` 中，密码不回显。留空保留已保存密码；明确勾选清除后才移除。保存失败不会改变当前代理策略。配置变更只作用于后续请求，正在进行的请求按已选定的连接继续，不重放业务操作。

TMDB、三站目录封面与 Bangumi 封面经 NAS 图片缓存加载，字幕库和 Assrt 搜索、下载也由后端处理。点击「查看原帖」等外站链接时，打开的是用户浏览器，使用浏览器所在设备的网络。

Telegram 分为两个独立选项：「Telegram 机器人」控制 Bot HTTP API；「Telegram 用户与频道搜索」控制用户账号的 MTProto 连接，包括登录、频道选择、频道搜索及使用用户账号搜索资源 Bot。两者均默认不勾选，按实际需要开启。用户连接支持 HTTP/HTTPS CONNECT 隧道和 SOCKS5/SOCKS5H；一次操作固定开始时的代理设置，保存新设置只影响下一次用户操作，不会切换正在进行的操作，也不会因代理连接失败而绕过代理直连。
