# 管理员手动选择季集方案

当 TMDB 默认季集与实际发行版不一致时，管理员可在剧集详情的季列表旁点击「设置季集方案」，手动选择 TMDB 默认季集或该作品提供的剧集组，设置对全站该作品生效。普通用户只读取生效方案。

例如《千绪的上学路》（TMDB 80462）默认资料可能列为 29 集，而剧集组 `Season` 提供 12 集电视版。选择前可查看各季分集及 TMDB 原编号；核对后点击「保存为全站方案」。系统不自动推荐或切换，不推测拆分集之间的合并关系。

保存剧集组时，系统持久保存当时的季名、季集编号、分集身份和分集资料。普通元数据刷新、缓存清理和重启保留这份编排。上游后续新增分集或修改日期也不会自动进入已保存方案；连载作品需要管理员定期点击「查看 TMDB 更新」，审核差异后「更新已保存编排」。评分及投票数变化不产生编排更新冲突。

选择「TMDB 默认季集」并点击「恢复默认并保存」，即可重新跟随默认资料的常规刷新。TMDB 暂时不可用时仍可查看已保存编排或恢复默认；恢复默认不会保证上游资料当时可访问。

## 生效范围

- 详情季列表、展开的分集和播出进度使用同一份方案。
- Emby 入库统计、缺集判断、追更完成状态和资源匹配按所选编号解释。切换后追更重新检查，首次检查建立基线，不因更改方案发送入库进度通知。
- 尚未提交生成的自动资源任务重新检查需求；已提交的生成任务继续处理。
- 下载整理预览固定当前季集方案版本。预览后方案发生变化时必须重新预览；已经启动的整理保留固定目标文件名。
- 最近更新中依赖 TMDB 的季集汇总使用生效方案；Emby 索引、文件名和字幕的实际编号仍保留原始事实。

设置不会重命名既有文件、修改 Emby 元数据，或把默认编号的资源自动转换为另一种发行顺序。管理员应核对现有 Emby 编号和待整理资源是否适用该方案。季 0 沿用特别篇规则，不计入正片追更完成判断。

## 一致性与接口

管理接口只注册在管理员鉴权路由下，TMDB 密钥不发送到浏览器：

- `GET /api/admin/tmdb/tv/:id/episode-groups`：当前方案、保存快照、默认季集概况及候选剧集组。
- `GET /api/admin/tmdb/tv/:id/episode-groups/:groupId`：核对作品归属后读取最新预览及内容指纹。
- `PUT /api/admin/tmdb/tv/:id/numbering`：提交 `groupId`、`revision`、`fingerprint`；空 `groupId` 恢复默认。

保存时核对版本与预览指纹，另一管理员已保存或上游内容已变更时返回 409，要求重新读取和预览。保存结果不确定时页面也要求重新读取后再写入。详情分集请求与整理预览携带方案版本，避免页面混用两套编号。多次读取的后端操作固定一份方案快照，追更保存还校验检查版本，旧结果不能覆盖切换后的状态。

快照独立保存在 SQLite 的 `tv_numbering` 表，与可过期的 TMDB 缓存分开；恢复默认也保留递增版本。

## 验证

后端测试覆盖剧集归属、重复或断档编号、快照持久化、版本冲突、预览变化、追更基线、资源缺集和整理失效。前端单元测试使用 `node --test tests/tv-numbering.test.mjs`；本地启动 Vite 后，`npm run test:tv-numbering-ui` 使用完全拦截的模拟 API 检查管理弹窗、显式保存、冲突、恢复默认、普通用户权限、桌面和手机布局，不修改真实媒体库。浏览器测试使用 `PLAYWRIGHT_MODULE` 和 `CHROME_PATH` 指定本机依赖，截图写入已忽略的 `frontend/test-results/`。
