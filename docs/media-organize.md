# 通用自动整理（第一版）

入口：管理员功能导航 → **自动整理**（`/media/organize`）。同一页面通过“整理规则 / 整理记录 / 命名模板 / 分类规则”切换，公共命名和分类分别保存；未保存修改离开前提示确认。只加载当前标签，切换后停止该页轮询，后台任务继续执行。规则、执行记录和工作循环独立保存，不读写动漫订阅任务、RSS 集数或归档状态。

## 配置与使用

1. 添加规则，选择 NAS / 本地挂载或 115 主账号，设置来源与目标目录。可选填写“整理失败目录”，须与来源、目标分开且互不包含；留空时问题文件保留原处。
2. 点击“立即运行”，按当前规则扫描、识别、移动并清理来源，不需要先预览确认。运行时重复提交复用同一次运行；监控暂停时也可以手动执行一次，不会自动开启监控。
3. “启用监控 / 暂停监控”控制后续定时调度。暂停后已经排队或开始的任务按原配置继续完成；修改目录等配置须等待任务结束并重新校验。调度每 30 秒检查一次，本功能内顺序执行。
4. 每张整理记录卡片代表一个视频或 STRM，唯一关联的字幕、元数据和图片归入同一任务。点击查看当前任务及附件的来源、目标、结果；失败时可以修正作品或季集，并仅重试当前任务。已成功的文件不会重复移动。视频成功、附件失败显示“部分完成”。
5. 成功后删除来源文件，目标同名文件保留、不覆盖；单个文件失败不阻止其他作品。配置了失败目录时，无法唯一匹配、季集或命名不明、目标冲突及关联附件保留原名与层级移入失败目录。网络超时、临时查询或网盘故障不移入失败目录。

自动监控同时清理来源目录中的无关文件，包括 TXT、ZIP、RAR、7Z、广告文件等；不检查压缩包内是否含字幕，不增加确认步骤或清理开关。没有唯一对应视频的字幕记为失败并删除；没有对应视频的 NFO、XML、JSON 和图片也会清理，记录删除原因，不会附上其他作品的目标路径。对应视频正在写入时，字幕与附件留待后续扫描；删除前复核来源目录中新到的视频，公共附件所属目录出现待扫描子目录时延后处理。文件处理后从内向外删除确认已空的子文件夹，来源根目录始终保留。“立即运行”和定时监控执行相同清理；单任务修正和重试不扫描或清理其他文件。本地直接删除，115 移入回收站；不递归删除非空文件夹，不清理目标或失败目录。来源文件或目录已变化时保留，后续监控重新扫描；删除超时停止本批后续清理，不把待核实结果记成成功。清理明细保存在原批次，页面按运行汇总清理文件、空目录和失败数量，不生成单文件任务卡片。

NFO、XML、JSON 和常用图片属于媒体附件：元数据须与对应视频同名；图片可同名或带 `-poster`、`-fanart`、`-thumb` 等明确图片角色后缀，随视频重命名。带其他影视名称的附件不会因目录只剩一个作品而跟随移动。仅 `tvshow.nfo`、`movie.nfo`、`season.nfo`（及对应 XML、JSON）、`poster.jpg`、`fanart.jpg` 等固定名称，以及 `.actors`、`extrafanart` 中的图片可按文件夹归属；仍须确定唯一作品和目标目录。已有可能对应的视频但归属有歧义时保留待核对。已关联字幕、字体、常见音轨文件及未支持整理的 ISO 等媒体文件不作为无关文件删除。

公共附件的归属参考完整来源扫描，暂未稳定的视频仍计入判断；执行已保存计划前再次检查附件归属，不继续执行无有效对应视频的附件移动。

默认同时处理 STRM 和普通视频，没有“文件范围”设置。ISO 不处理。STRM 正文保持原样，不请求其中的播放地址；普通视频不转码、不重新封装，规格只取自已有文件名信息。

本地目录必须存在、可访问且不重叠；CD2 等挂载按本地文件系统使用。Docker 中填写容器内路径，例如：

```yaml
volumes:
  - /volume1/media/inbox:/media/inbox
  - /volume1/media/library:/media/library
```

同一文件系统优先使用不覆盖目标的链接后移除来源；不支持时独占创建目标并复制，完成并检查来源未变化后删除来源。跨挂载的大文件需要复制时间。目录内符号链接不跟随，本地文件修改时间不足 30 秒时留待后续扫描。

115 只使用主账号，不提供小号选择；每次处理固定凭据并核验来源和目标目录。主账号更换后需重新配置目录。第一版支持本地到本地、115 到 115，不跨两种存储搬运。

## 识别与命名

识别组合文件名和最多两级父目录中的片名、年份、季号及 TMDB ID。优先核对标准片名和原名，必要时有界查询别名/译名；歧义保留人工确认，不用相似度分数直接决定移动。未知类型的显式 TMDB ID 仍需通过片名搜索确定类型。

自动整理及下载文件清单共用文件季集识别：优先读取完整的 `SxxExx`，分辨率（如 `S01E04 - 1080p`）不参与集数范围；真实连集保持起始集命名。无标准季集时复用字幕组发布命名识别，自动整理可用父目录补充缺失季号。分数集、额外编号冲突和不完整编号留待人工修正，不截取前半段后继续整理。RSS 的发布编号、来源正则、合集判断与订阅映射保持独立。

使用公共电影、剧集命名模板；不把 TMDB 总集数作为整理上限。季号和起始集号可修改。启用分类后，按“分类规则”中保存的 YAML 生成子目录；可视化与源码编辑共用同一份规则，依据 TMDB 类型、原始语言、原产地等信息按顺序匹配。关闭分类后直接使用目标目录。规则格式和匹配语义见 [分类规则计划](media-classification-plan.md)。

## 记录与恢复

扫描只判断来源目录当前存在的文件，不保留“已处理文件”跳过标记；以前成功、失败或删过记录都不影响再次整理。成功搬走后来源中已无文件，自然不会重复；文件重新放回来源目录或重新下载后，按当前规则整理。目标同名文件仍不覆盖，来源变化检查保留。正在运行的规则重复提交复用同一次运行，不并行搬运同一任务。115 不额外读取 SHA1 或文件内容。

服务重启时未完成任务标为中断，不擅自继续写入；可打开对应任务记录核对并重试，重试范围随批次一起持久保存。115 重试会检查原文件 ID 是否已到目标位置，避免重复移动。来源内容变化时保留来源，要求重新扫描。

失败目录不参与扫描。移动前保存意图，成功后记录当前位置；115 响应超时可按原文件 ID 核对确切目标。进入失败目录的文件仍可在对应任务弹窗中修正作品或季集并重试，无需手动搬回。移动失败会显示原因，临时目录故障会停止本批后续失败搬运，防止连续请求 115。失败搬运随实际整理自动执行，没有独立确认按钮。

规则页只管理目录规则、监控开关和立即运行。记录页（`/media/organize/history`）显示媒体任务和折叠的清理摘要。卡片按主文件身份归并，不按 TMDB ID 或季集合并，因此不同集和不同版本仍是独立任务。公共海报、目录 NFO 等只随唯一归属处理一次，不生成独立卡片。卡片显示状态、原名、目标文件名、附件数量和时间，每页 20 个任务；没有记录时显示空状态。

记录页统一提供“全部 / 整理中 / 成功 / 待处理”筛选。排队、扫描和执行中属于整理中；主文件与所有附件完成才算成功；部分完成、失败及需要人工修正的任务归待处理，卡片保留具体结果。搜索按作品名称、原文件名、来源和目标路径匹配，在后端对全部已保留记录先筛选、再分页。筛选、搜索与页码写入 URL，刷新和前进后退可恢复；未产生主文件任务的扫描通过运行提示反馈。

持久化复用现有 SQLite，保存规则、批次执行快照和可检索的任务结果，主文件与关联附件保存在同一任务中。旧 `media-organize.enc` 仅在数据库尚未初始化时导入，事务完成后清除旧文件，后续不双写。记录查询和详情读取仅使用本地数据，不请求 115 或 TMDB；规则启停不需要重写全部历史。移除原先 20/50 批数量限制，记录不会因为达到数量上限阻止新的整理。

可删除单条、勾选当前页记录，或明确清理全部已成功记录；翻页及筛选后清空选择，不能隐藏跨页累选。删除只清理记录及其对应附件和无引用快照，不删除实际文件，不保留墓碑、回收站或已处理标记，也不主动触发扫描。正在处理的批次暂不允许删除，防止运行中的检查点恢复已删记录。删除失败或部分完成记录后失去对应修正重试入口，文件可放回来源目录重新整理。失败目录不属于扫描范围，须先将文件移回来源。删除整理规则也会清理该规则的整理记录，确认弹窗明确提示范围。

单任务修正继续使用独立识别分组，执行仅处理当前任务，成功的视频和同批其他文件不重试。服务重启后已完成结果保留，未完成任务显示中断，可核对后重试。

## 验证

Go 测试覆盖识别、临时本地目录小范围灰度流程、主文件与附件归并、单任务修正重试与重启恢复、STRM 正文、字幕依赖、冲突与来源变化、SQLite 持久化、搜索分页、记录删除、重新放回来源、115 分页、失败重试与凭据固定。`npm run test:media-organize-ui` 验证规则和任务修正；`npm run test:media-organize-history-ui` 验证搜索、筛选、分页及删除边界；`npm run test:organize-workspace-ui` 验证工作区导航、旧地址跳转、未保存保护、轮询停止和移动端布局。浏览器测试使用全模拟接口，无实际 NAS 或 115 写入。
