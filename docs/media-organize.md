# 通用自动整理（第一版）

入口：管理员功能导航 → **自动整理**（`/media/organize`）。规则、执行记录和工作循环独立保存，不读写动漫订阅任务、RSS 集数或归档状态。

## 配置与使用

1. 添加规则，选择 NAS / 本地挂载或 115 主账号，设置来源与目标目录。
   可选填写“整理失败目录”，须与来源、目标分开且互不包含。留空时问题文件保留原处。
   每条规则用独立卡片展示来源、目标、失败目录和处理策略；底部“启用监控 / 暂停监控”切换定时扫描，“扫描预览”打开预览，右上角编辑或移除规则。启停可在任务执行中保存；即使挂载目录或原主账号暂不可用，也可暂停。暂停只影响后续调度，已排队或开始的任务按原配置继续完成；修改目录等配置仍须等待任务结束，并重新校验目录与账号。
2. 点击“扫描预览”，核对识别结果、目标路径和季集。未唯一匹配的作品可搜索 TMDB 手动选择；修改后点击“更新预览”。
3. 确认整理会移动文件。成功后删除来源文件，目标同名文件保留、不覆盖；单个文件失败不阻止其他作品。字幕跟随唯一对应的视频。配置了失败目录时，无法唯一匹配、季集或命名不明、目标冲突及其关联字幕保留原名与相对目录层级移入失败目录；目录已有同名文件时保留来源，不覆盖。网络超时、临时查询或网盘故障不移入失败目录。
4. 确认规则合适后启用自动扫描，按设置间隔扫描并整理明确匹配的文件。第一版使用定时扫描，没有文件事件监听。调度每 30 秒检查一次，任务在本功能内顺序执行。

自动监控同时清理来源目录中的无关文件，包括 TXT、ZIP、RAR、7Z、广告文件等；不检查压缩包内是否含字幕，不增加确认步骤或清理开关。没有唯一对应视频的字幕记为失败并删除；没有对应视频的 NFO、XML、JSON 和图片也会清理，记录删除原因，不会附上其他作品的目标路径。对应视频正在写入或仅因增量规则未处理时，字幕与附件留待后续扫描；删除前复核来源目录中新到的视频，公共附件所属目录出现待扫描子目录时延后处理。文件处理后从内向外删除确认已空的子文件夹，来源根目录始终保留。手动扫描、更新预览和确认整理不触发这项清理。本地直接删除，115 移入回收站；不递归删除非空文件夹，不清理目标或失败目录。来源文件或目录已变化时保留，后续监控重新扫描；删除超时停止本批后续清理，不把待核实结果记成成功。清理结果复用现有记录，未归属字幕同时说明失败原因及删除结果。

NFO、XML、JSON 和常用图片属于媒体附件：元数据须与对应视频同名；图片可同名或带 `-poster`、`-fanart`、`-thumb` 等明确图片角色后缀，随视频重命名。带其他影视名称的附件不会因目录只剩一个作品而跟随移动。仅 `tvshow.nfo`、`movie.nfo`、`season.nfo`（及对应 XML、JSON）、`poster.jpg`、`fanart.jpg` 等固定名称，以及 `.actors`、`extrafanart` 中的图片可按文件夹归属；仍须确定唯一作品和目标目录。已有可能对应的视频但归属有歧义时保留待核对。已关联字幕、字体、常见音轨文件及未支持整理的 ISO 等媒体文件不作为无关文件删除。

公共附件的归属参考完整来源扫描，增量跳过的未处理视频仍计入判断；执行已保存计划前再次检查附件归属，不继续执行无有效对应视频的附件移动。

默认同时处理 STRM 和普通视频，没有“文件范围”设置。ISO 不处理。STRM 正文保持原样，不请求其中的播放地址；普通视频不转码、不重新封装，规格只取自已有文件名信息。

本地目录必须存在、可访问且不重叠；CD2 等挂载按本地文件系统使用。Docker 中填写容器内路径，例如：

```yaml
volumes:
  - /volume1/media/inbox:/media/inbox
  - /volume1/media/library:/media/library
```

同一文件系统优先使用不覆盖目标的链接后移除来源；不支持时独占创建目标并复制，完成并检查来源未变化后删除来源。跨挂载的大文件需要复制时间。目录内符号链接不跟随，本地文件修改时间不足 30 秒时留待后续扫描。

115 只使用主账号，不提供小号选择；每次处理固定凭据并核验来源和目标目录。主账号更换后需重新配置目录。第一版支持本地到本地、115 到 115，不跨两种存储搬运。

## 识别与命名

识别组合文件名和最多两级父目录中的片名、年份、季号及 TMDB ID。优先核对标准片名和原名，必要时有界查询别名/译名；歧义保留人工确认，不用相似度分数直接决定移动。未知类型的显式 TMDB ID 仍需通过片名搜索确定类型。

自动整理、手动整理及下载文件清单共用文件季集识别：优先读取完整的 `SxxExx`，分辨率（如 `S01E04 - 1080p`）不参与集数范围；真实连集保持起始集命名。无标准季集时复用字幕组发布命名识别，自动整理可用父目录补充缺失季号。分数集、额外编号冲突和不完整编号留待人工修正，不截取前半段后继续整理。RSS 的发布编号、来源正则、合集判断与订阅映射保持独立。

使用公共电影、剧集命名模板；不把 TMDB 总集数作为整理上限。季号和起始集号可修改。可选内置分类：

| 类型 | 分类优先级 |
| --- | --- |
| 电影 | 动画电影 → 华语电影 → 其他电影 |
| 剧集 | 动漫 → 纪录片 → 综艺 → 国产剧 / 日韩剧 / 欧美剧 → 其他剧集 |

分类依据 TMDB 类型、原始语言和原产地；关闭分类后直接使用目标目录。第一版没有自定义分类规则编辑器。

## 记录与恢复

自动扫描按文件 ID、文件名、大小及本地修改时间跳过未变化的已处理结果，减少重复识别。临时查询失败会在后续扫描重试；未匹配或冲突文件可手动重新扫描。已不在来源目录的增量索引会清理。115 不额外读取 SHA1 或文件内容。

服务重启时未完成任务标为中断，不擅自继续写入；可打开原记录核对并继续。115 重试会检查原文件 ID 是否已到目标位置，避免重复移动。来源内容变化时保留来源，要求重新扫描。

失败目录不参与扫描。移动前保存意图，成功后记录当前位置；115 响应超时可按原文件 ID 核对确切目标。进入失败目录的文件仍可在原批次弹窗中修正作品或季集、更新预览并继续整理，无需手动搬回。移动失败会显示原因，临时目录故障会停止本批后续失败搬运，防止连续请求 115。失败搬运随实际整理自动执行，没有独立确认按钮；扫描预览和更新预览始终不移动文件。

页面只保留整理规则及实际执行记录，不显示独立“待处理”区块。扫描预览从规则入口打开，执行记录可点击打开原批次查看详情和修正。每条记录显示成功或失败、原名、目标文件名和处理时间，每页 20 项；片名和文件名各占一行，超长省略，悬停显示完整路径。没有结果时隐藏记录区域。更新预览不会生成整理记录，空扫描及仅保留未关联附件的扫描不会挤掉真实结果；重新扫描会替换同规则未执行的旧预览。

最近终态批次保留 20 批，当前预览及失败目录的续办记录可另保留至总计 50 批；仍有移入失败目录或移动待确认文件的批次不会被自动淘汰。移除规则同时移除其历史及增量索引，不删除文件。

## 验证

Go 测试覆盖识别、临时本地目录完整流程、STRM 正文、字幕依赖、冲突与来源变化、持久化、增量跳过、115 分页、失败重试与凭据固定。`npm run test:media-organize-ui` 使用全模拟接口验证页面，无实际 NAS 或 115 写入。
