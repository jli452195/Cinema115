# 通用自动整理（第一版）

入口：管理员功能导航 → **自动整理**（`/media/organize`）。同一页面通过“整理规则 / 整理记录 / 命名模板 / 分类规则”切换，公共命名和分类分别保存；未保存修改离开前提示确认。只加载当前标签，切换后停止该页轮询，后台任务继续执行。规则、执行记录和工作循环独立保存，不读写动漫订阅任务、RSS 集数或归档状态。

## 配置与使用

1. 添加规则，选择 NAS / 本地挂载、115 主账号或 CloudDrive2，设置来源与目标目录。可选填写“整理失败目录”，须与来源、目标分开且互不包含；留空时问题文件保留原处。
2. 点击“立即运行”，按当前规则扫描、识别、移动并清理来源，不需要先预览确认。运行时重复提交复用同一次运行；监控暂停时也可以手动执行一次，不会自动开启监控。
3. 本地和 115 分别提供“事件监控”和“定时完整扫描”开关，新增规则的完整扫描间隔默认 30 分钟，界面按 1 至 1440 整数分钟设置。本地使用文件系统事件，115 复用主账号生活事件读者；CD2 只提供“目录轮询”，默认间隔 20 秒，界面按秒设置，不订阅文件事件。后台统一使用秒。启用后先扫描一次，定时轮次结束后再等待设定间隔；事件局部扫描不推迟完整扫描期限，同一规则不堆积自动任务。
4. 每张整理记录卡片代表一个视频或 STRM，唯一关联的字幕、元数据和图片归入同一任务。点击查看当前任务及附件的来源、目标、结果；失败时可以修正作品或季集，并仅重试当前任务。主视频确认完成即任务成功，附件异常不改变视频状态；当前轮内可单独重试未完成附件，已成功的视频和附件不会重复移动。成功和失败记录均保留，轮次结束或服务重启不会自动移除成功记录。
5. 成功后删除来源文件，目标同名文件保留、不覆盖；单个文件失败不阻止其他作品。配置了失败目录时，无法唯一匹配、季集或命名不明、目标冲突及关联附件保留原名与层级移入失败目录。网络超时、临时查询或网盘故障不移入失败目录。

自动监控同时清理来源目录中的无关文件，包括 TXT、ZIP、RAR、7Z、广告文件等；不检查压缩包内是否含字幕。NAS / 本地挂载、115 直连和 CD2 共用独立的“清理未匹配附件”开关，默认开启，等待时间默认 10 秒，范围 0 至 86400 秒，界面统一输入秒数；明确保存的值（包括 0）在刷新和重启后保持不变。关闭后保留未匹配的字幕和媒体附件，不影响普通无关文件及空目录清理；已匹配视频的字幕和附件始终立即整理。开启时，0 表示关联复核后即可清理。未匹配文件从首次发现起计时，重复扫描、关闭再开启或修改等待时间不重新计时；文件身份或内容发生变化时重新计算。计时持久化保存，不依赖网盘修改时间；115 开启事件监控或定时扫描、CD2 开启目录轮询时，会在宽限到期安排所在作品的局部复查，不必等待下轮全量扫描；实际执行仍受当前任务及网盘响应影响。本地由后续扫描复查。已确认本作品视频全部离开来源时，残留附件可在本轮立即复核清理。对应视频正在写入时，字幕与附件留待后续扫描；删除前复核中新到的视频和共享附件所属目录，不把归属不明的文件附到其他作品。

三种存储均清理来源根目录下的空子目录，保留来源根目录。115 和 CD2 共用逐目录执行器：完整读取当前目录后先整理视频及已匹配附件，作品分支处理完成后复核公共附件，清理空季目录、无用附件及空作品目录，不等待整轮来源扫描结束。纯空分支合并到父目录批量收尾。本地使用非递归删除，115 移入回收站，CD2 经实时查空后删除；不递归删除非空分支，不处理目标或失败目录。读取失败的分支保持未知，已完成分支的成功结果继续保留。

CD2 复用本轮完整扫描的目录树，包含临时、只读和不参与整理的全部直接子项；仅扣除已确认移动、隔离或删除成功的来源项，同目录改名不减少数量。已知仍有内容的目录跳过清理请求，未扫描或读取失败的分支保持未知并实时复核。候选按层级从深到浅处理，同父目录每批最多 20 项，共用一次父目录身份读取和一次删除结果复核；每个候选仍绕过短期缓存完整读取内容，只有确认空目录才使用官方 `DeleteFile` / `DeleteFiles`。不同父目录最多 4 路并行，意图和结果按层合并持久化；子目录确认删除后再释放父目录候选。20 个同父空目录的正常清理路径为 23 次 gRPC 请求，不含扫描及异常核对。批量部分失败逐项保存已确认结果，不重放删除；请求异常后若实时核验确认目录消失，记录该项已删除并保留异常说明，无法核实则不记成功。CD2 官方接口不提供原子的“仅为空时删除”条件，外部客户端在复核后写入的竞争无法完全排除。

固定名称 `theme.mp3`（含复制后缀）作为影视附件，按文件夹归属随视频整理并按同角色留一；没有对应视频时按附件宽限清理，普通独立音频和字体继续保留。NFO、XML、JSON 和常用图片属于媒体附件：元数据须与对应视频同名；图片可同名或带 `-poster`、`-fanart`、`-thumb` 等明确图片角色后缀，随视频重命名。带其他影视名称的附件不会因目录只剩一个作品而跟随移动。仅 `tvshow.nfo`、`movie.nfo`、`season.nfo`（及对应 XML、JSON）、`poster.jpg`、`fanart.jpg` 等固定名称，以及 `.actors`、`extrafanart` 中的图片可按文件夹归属；仍须确定唯一作品和目标目录。已有可能对应的视频但归属有歧义时保留待核对。已关联字幕、字体、常见音轨文件及未支持整理的 ISO 等媒体文件不作为无关文件删除。

同作品、作用域、视频版本、语言、用途与格式的附件冲突自动留一：优先采用已核实的目标文件，否则优先来源原名，再按相对路径与稳定文件身份选定。复制后缀不作为相同内容证明，不同语言、forced／SDH 和视频版本分别保留。选择只在本次内存中使用，处理前后核验双方身份及结果；回执不明确或身份变化时结束本次尝试，保留当前文件，不保存或重放旧回收选择。115 按稳定文件 ID 核验，同名但不同 ID 的文件不能冒充原件；NFO 正文始终不读取。

115 和 CD2 使用精简的成功视频源／目标身份映射关联晚到附件，每次仍核验冻结的存储绑定及目标身份。明确缺失或身份变化的历史目标不再参与关联，未匹配附件按当前来源文件及宽限判断清理；历史成功记录仍保留。目标读取异常只在本轮保护相关附件，不保护整个父目录；其他视频和无关附件继续处理。停止整理会暂停自动触发，并等待已发出的操作核对结果后结束。

公共附件在所属作品分支完整读取后处理，暂未稳定的视频仍计入判断；执行本轮计划前再次检查附件归属，不继续执行无有效对应视频的附件移动。

默认同时处理 STRM 和普通视频，没有“文件范围”设置。ISO 不处理。STRM 正文保持原样，不请求其中的播放地址；普通视频不转码、不重新封装，规格只取自已有文件名信息。

本地目录必须存在、可访问且不重叠；选择 NAS / 本地挂载时，CD2 等挂载按本地文件系统使用。Docker 中填写容器内路径，例如：

```yaml
volumes:
  - /volume1/media/inbox:/media/inbox
  - /volume1/media/library:/media/library
```

同一文件系统优先使用不覆盖目标的链接后移除来源；不支持时独占创建目标并复制，完成并检查来源未变化后删除来源。跨挂载的大文件需要复制时间。目录内符号链接不跟随，本地文件修改时间不足 30 秒时留待后续扫描。

115 只使用主账号，不提供小号选择；每次处理固定凭据并核验来源和目标目录。主账号更换后需重新配置目录。本地、115 直连、CD2 分别在各自存储入口内整理，不跨入口搬运。

## CloudDrive2 原生整理

先在“服务连接 → CloudDrive2”保存官方 gRPC 地址及 API Token，再为整理规则选择 CD2。CD2 是独立通用存储服务，可访问 Token 授权范围内的不同网盘和账号，不依赖 115 主账号。任务固定连接及其修订；更换连接后须重新选择目录。

CD2 通过官方 gRPC 列目录轮询，默认每轮结束后等待 20 秒再扫描，不调用会员文件事件订阅接口。页面只提供一个目录轮询开关和秒数间隔，停止整理会暂停轮询。已保存的间隔在编辑、刷新和重启后保持原值。

每个目录完整读取后立即识别、整理视频及已匹配附件，再扫描下一个目录。写入前只复查当前范围的关联文件，不再为每批视频重扫整棵目录树。同批读取可复用短期目录快照，写入后失效并核验结果；互不相关的目录不共用全局写锁。跳过临时下载文件，未归属字幕和媒体附件按本批次冻结的宽限保留；晚到字幕和附件在后续扫描时按精简源／目标映射补齐。期满仍无对应视频且没有相关临时下载文件时才清理，不按网盘修改时间计时。实际耗时还取决于 CD2、底层网盘和元数据查询。

同一目标目录的多个普通文件自动使用官方 `RenameFiles` 和多来源 `MoveFile` 接口，每批最多 20 项，无需单独开启。批量范围限于当前完整读取的目录，不等待其他目录凑满；零散单文件沿用单文件处理，避免多余批量预检。视频完成并保存后再处理关联字幕及附件。每批共享目录核对并保存必要操作结果，直接复用已核验的文件回执。接口部分失败时逐项记录已确认结果，重试只核对未完成项；改名已生效但回执丢失时，可按原名、预期中间名和精确目标恢复。同目标多来源、失败目录恢复和 SHA1 判重按顺序处理，不覆盖已有文件。

115 直连和 CD2 均提供“自动删除相同文件”开关，默认关闭。开启后，仅在预期目标同名冲突时比较双方接口已有的 SHA1，忽略目标大小和时间；相同则删除来源、保留目标，不同或缺失则保留冲突文件，不下载内容计算哈希。删除前保留来源身份与目标归属核验，115 使用本批次固定的主账号凭据并将来源移入回收站，CD2 使用其独立连接。配置失败目录时，冲突文件按既有失败搬运规则保存。晚到附件沿用精简成功身份映射，并在使用时重新核验目标。CD2 清理已完整扫描并复核的 TXT、ZIP 等普通无关文件，以及满足自定义宽限和关联复核条件的孤立字幕、媒体附件，随后收尾空子目录。普通来源清理按父目录批量提交，115 每批最多 50 项、CD2 每批最多 100 项，统一核验来源身份、视频归属及实际删除结果，不递归删除非空分支。

## 识别与命名

识别组合文件名与规则根内最多 16 层目录的片名、年份、季号及 TMDB ID；目录按作品、季、特殊内容、合集、分类与技术包装角色补缺，文件中的明确声明优先。每个目录在当前批次内复用上下文，不为解析额外列目录。年份和 ID 不是源文件必填项，无年份短片名也可以匹配。明确 ID 优先，随后核对标准名、原名和别名；没有合适的精确结果时，再有界比较轻微拼写差异。名称比较支持全半角及繁简单字归一化。数字片名保留完整标题，电影裸年份保留两种解释，不因尾部数字强制按电视剧搜索。未知类型的显式 TMDB ID 仍需通过片名搜索确定类型。

同一匹配层级有多个合格候选时，采用 TMDB 返回的第一条，核实后停止无必要查询；只保存最终作品。明确动画或真人标签可参与筛选，没有标签也能匹配。无关首条和明确声明冲突仍保留修正入口。一个识别分组选定作品后，后续文件复用作品与采用季号，避免排序变化导致串片。查询超时与未找到候选分别记录，查询异常不按识别失败搬入失败目录。具体边界和请求预算见 [识别改进清单](media-recognition-plan.md#11-当前实施约定)。

自动整理使用独立的标准坐标事实解析：完整有效的 `SxxExx` 覆盖所有季号，数字或中文分集标题不再参与集数范围；真实连集保持起始集命名。扫描期间复用同一文件事实，日志直接读取最终值。无标准季集时复用已有发布编号识别，目录可补充缺失季号。分数集、真实编号冲突和不完整坐标留待修正，不截取前半段后继续整理。RSS 的发布编号、来源正则、合集判断与订阅映射保持独立。

自动整理中的完整 `S00Exx` 直接声明第 0 季特殊集，优先于 `Specials` 目录及 OVA、特典等标记。坐标后的文字分集标题（如 `OVA#13`、`OVA Picture Drama 2`）不替换该集号；缺少标准坐标、坐标不完整或存在其他明确集号时仍待修正。磁力整理保留原有的特殊内容确认规则。已关联但等待主文件完成匹配及命名的字幕与附件显示“等待主文件”。

外挂字幕优先沿用同目录匹配；未找到同目录候选时，在本轮递归扫描范围内按完整视频主文件名匹配，不限制字幕所在目录的名称。例如 `xxx.xxx.mkv` 可关联任意子目录中的 `xxx.xxx.ass`、`xxx.xxx.chs.ass`，字幕随视频最终名称移动到同一目标目录，尾缀保持原样。跨目录不按片名或集号猜测，存在多个同名视频时保留字幕。115/CD2 的同目录文件继续即时整理，跨目录字幕在本轮扫描完整后处理；晚到字幕沿用已有成功视频映射并核对目标身份。未匹配字幕继续遵循原有清理开关与宽限时间。

使用公共电影、剧集命名模板；不把 TMDB 总集数作为整理上限。季号和起始集号可修改。启用分类后，按“分类规则”中保存的 YAML 生成子目录；可视化与源码编辑共用同一份规则，依据 TMDB 类型、原始语言、原产地等信息按顺序匹配。关闭分类后直接使用目标目录。规则格式和匹配语义见 [分类规则计划](media-classification-plan.md)。

电影的国家条件读取制作地区，剧集读取原产地。详情缓存使用包含原产地与原始语言的新版本，旧详情在下一次使用该作品时按需更新，后续集数复用缓存；不因上游确实缺少原产地而反复请求或改用制作地区。已移走的历史文件不会因缓存更新自动重新分类。

## 记录与恢复

扫描只判断来源目录当前存在的文件，不保留“已处理文件”跳过标记；以前成功、失败或删过记录都不影响再次整理。成功搬走后来源中已无文件，自然不会重复；文件重新放回来源目录或重新下载后，按当前规则整理。目标同名文件仍不覆盖，来源变化检查保留。正在运行的规则重复提交复用同一次运行，不并行搬运同一任务。115 判重只使用目录接口已有 SHA1，不读取文件内容。

服务重启时未完成任务标为中断，不擅自继续写入；失败及必要未完成上下文继续保留，可打开对应任务记录核对并重试。主视频移动结果未知时仍记失败，明确重试先用任务冻结的存储、账号或连接身份核对当前位置。115 按原文件 ID 核对目标，同名不同 ID 不视为同一文件。来源内容变化时保留来源，要求重新扫描。附件旧回收选择不从持久化恢复，也不会自动重放。

失败目录不参与扫描。移动前保存意图，成功后记录当前位置；115 响应超时可按原文件 ID 核对确切目标。进入失败目录的文件仍可在对应任务弹窗中修正作品或季集并重试，无需手动搬回。移动失败会显示原因，临时目录故障会停止本批后续失败搬运，防止连续请求 115。失败搬运随实际整理自动执行，没有独立确认按钮。

规则页为本地和 115 提供独立事件监控、定时完整扫描；CD2 只提供目录轮询，各存储均可手动完整扫描。排队或执行中显示停止整理：暂停该规则的自动触发，取消尚未执行的工作，已发出的操作核对结果后结束；未执行文件不记成失败。停止期间禁止重新开启自动触发，结束后可再次手动运行。单独暂停开关只影响后续自动触发，当前任务仍使用启动时冻结的配置。只有实际在途文件受到短暂保护，其他规则和空闲历史不因同批工作锁住；编辑后的设置用于后续任务。

单轮扫描最多 5,000 个目录（包含来源根目录），来源根目录以下最多 12 层。115 和 CD2 按目录完整读取、逐目录执行，每个目录最多 5,000 个文件，不再限制整轮累计文件数；本地保留单轮文件数量限制。目录数量、层级和重复目录分别报出具体原因。未完整读取的分支不能作为附件或空目录删除依据；已经完整处理的作品分支可以先收尾，后续分支失败不会撤销其成功结果。

记录页（`/media/organize/history`）显示成功、失败历史和本轮媒体任务、清理摘要。卡片按主文件身份归并，不按 TMDB ID 或季集合并，因此不同集和不同版本仍是独立任务。公共海报、目录 NFO 等只随唯一归属处理一次，不生成独立卡片。卡片显示状态、原名、目标文件名和完成时间，每页 20 个任务；当前轮可显示关联附件，成功历史不保存附件执行快照。没有记录时显示空状态。

记录页统一提供“全部 / 整理中 / 成功 / 失败”筛选。主视频完成归成功，未完成且正在排队或执行归整理中，其余未完成任务归失败；附件结果不影响主视频状态和完成时间。成功记录持续保留，明确删除记录或清理全部成功时才移除。搜索按作品名称、原文件名、来源和目标路径匹配，后端合并持久历史与本轮活动任务后统一筛选、计数和分页。筛选、搜索与页码写入 URL，刷新和前进后退可恢复；目录扫描和附件收尾使用独立运行提示，不混入视频任务计数。

持久化复用现有 SQLite 任务表，保存精简成功、失败摘要、必要未完成上下文及功能设置。成功视频保留原文件、源／目标、作品、季集、真实完成时间和必要去重动作，带 `Reference` 的身份映射继续用于晚到附件；不保存成功附件执行快照或识别过程，不新增成功表或恢复账本。只有明确完成结果形成成功摘要，晚到附件引用只在本轮使用，不重复保存引用和分组，也不生成成功记录或刷新完成时间。清理仅保留当前轮次的文件数、目录数与失败数，检查点更新数量，重启后保留至下一轮替换，不保存逐附件清理过程。已丢失完成时间的旧成功，仅按留存完成事实恢复并显示“完成时间未知”。成功重试，或相同冻结存储绑定中的同一文件再次成功，会清除对应旧失败历史，并保留本次成功结果。孤立附件宽限等清理所需资料继续按原用途保存。记录查询和详情读取仅使用本地数据，不请求 115 或 TMDB；规则启停不需要重写全部历史，也不因历史数量阻止新的整理。

可删除单条、勾选当前页记录，或明确清理全部可删除的成功记录、失败记录。全部清理覆盖所有搜索、筛选和分页，正在操作文件的记录会保留；勾选删除只作用于当前页，翻页及筛选后清空选择。删除结束对应任务的修正、排队重试和后续恢复上下文，不删除或移动实际文件，也不主动触发扫描。只有实际文件操作在途时短暂保护相应任务，同批其他文件正在处理不限制已结束任务；空闲的未确认移动、失败搬运和旧附件回收标记均不构成永久锁。检查点保存会过滤已经删除的主文件及其附件，不让后台旧快照恢复已删记录。删除失败记录后，对应文件若位于失败目录，须移回来源目录才能重新扫描；失败目录自身不参与扫描。删除整理规则也会清理该规则的记录，确认弹窗明确提示范围。

单任务修正继续使用独立识别分组，执行仅处理当前任务，成功的视频和同批其他文件不重试。其他批次运行时可以提交并排队，重复重试按当前执行权限拦截；手动重试优先于手动扫描，手动扫描优先于自动扫描，同类按入队顺序执行。查看详情独立加载，不占用提交操作的页面锁。服务重启后成功、失败和未完成上下文保留，未完成任务显示失败并注明中断，可核对后重试；成功历史保留原完成时间和结果。

任务详情只展示最终作品、年份、TMDB、季集、已有规格、来源／目标和紧凑附件列表，保留搜索、修正与重试。候选、排名、采用解释、历史尝试和阶段时间线不展示或持久化。已关联附件等待主文件时保留内部依赖信息，不能掩盖主文件的具体失败原因；写入结果未确认及目标冲突以具体失败原因说明，不再增加顶层“待核实”或“部分完成”状态。

详情记录已移除时返回 404，页面关闭对应过时详情并刷新，停止查询该记录；提示任务已结束或记录已移除，不以此判定整理成功。网络和服务异常仍保留真实错误，不从当前分页或筛选中缺少记录推断任务消失。

整理记录页使用一条管理员鉴权的 SSE 连接接收变化通知，再查询现有列表与详情接口。通知不携带任务数据、不查询数据库，服务端按 500 毫秒、页面按 1 秒窗口合并高频变化，查询在途只保留一次待刷新；15 秒心跳不触发查询。连接与查询正常时不定时读取历史，断线或查询失败后每 15 秒兜底补读，连接退避重试。第一页的所有筛选接收更新，历史分页保持位置，运行中的详情继续核对；批量管理和删除确认期间暂存通知，操作结束后补读。页面隐藏或离开会关闭连接，回到前台和重连后重新同步，详情修正保留未提交输入。

共享“整理”日志只记录最终失败，附带文件、必要路径、作品／季集及结果码；成功、正常写入准备、主文件依赖等待和批次成功汇总不记日志。日志在批次结束且对应事务保存成功后发布，保存失败不发布，未变化结果不重复发布。文件时间只随实际结果变化更新，未变化设置和任务摘要不重写。删除及重试权限由当前操作计算，不持久化；附件每轮只执行一次，失败后结束本次尝试，下次按当前文件事实重新判断。主视频必要的写入意图、身份核验和结果保存继续保留。

## 验证

Go 测试覆盖识别、临时本地目录小范围灰度流程、主文件与附件归并、单任务修正重试与重启恢复、STRM 正文、字幕依赖、冲突与来源变化、SQLite 持久化、搜索分页、记录删除、重新放回来源、115 分页、失败重试与凭据固定。`npm run test:media-organize-ui` 验证规则和任务修正；`npm run test:media-organize-history-ui` 验证搜索、筛选、分页及删除边界；`npm run test:organize-workspace-ui` 验证工作区导航、旧地址跳转、未保存保护、轮询停止和移动端布局。浏览器测试使用全模拟接口，无实际 NAS 或 115 写入。

本轮核对旧恢复标记可删除、同批任务独立保护、删除与后台检查点并发、稳定 ID 与同名不同文件、晚到附件失败不阻断新视频、成功后清除旧失败并保留成功历史。当前成功记录约定见 [解析器改进记录](media-parser-refactor-plan.md#18-成功历史保留纠正)。
