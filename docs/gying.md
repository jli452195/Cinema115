# 观影资源搜索

管理员可从右上角管理菜单进入 `/gying`，填写观影站 HTTPS 地址、用户名和密码。保存操作会先完成站点安全验证和账号登录，成功后才替换原配置。配置、密码和 Cookie 使用 `JWT_SECRET` 派生的密钥加密保存在 `DATA_DIR/gying-config.enc`；接口不会返回密码或 Cookie。

电影或剧集详情页的「观影搜索」仅对管理员显示。后端重新读取该 TMDB 条目，先使用 `originalTitle` 搜索，保留搜索页返回的全部有效条目，不按标题合并季度、OVA 或特别篇。原名没有包含网盘或磁力链接的有效结果时，使用 TMDB 的 IMDb `tt...` 编号再搜索一次。前端不能提交自定义搜索词或覆盖 IMDb 编号。

结果使用两级筛选：第一行选择全部或某个影视条目，第二行按当前范围内实际存在的网盘或磁力来源筛选。每个影视条目保留所有已识别的网盘链接、提取码、资源名、大小、更新时间和磁力链接；相同 URL 与相同提取码去重，不合并不同站点条目。网盘分类优先使用链接域名，光鸭网盘与 123 网盘分别展示，观影站返回的类型码只用于未知域名兜底。当前版本只提供复制与打开，不接入 115 账号、转存或 STRM。

管理员可以在观影搜索设置页拖动资源类型，或使用上移、下移按钮调整全局资源优先级。保存后同时影响搜索弹窗的来源筛选顺序和每个影视条目内部的链接顺序，不改变影视条目及同类链接的原始顺序。“全部资源”固定在首位。该设置独立保存，不触发重新登录、不清除搜索缓存，清除观影站登录信息时也会保留。

观影结果中可解析的 115 分享链接会显示“分享 STRM”按钮，复用“115分享STRM”明确保存的账号 `accountId`、生成选项、后台队列、日志和 Telegram 通知。未选择账号、账号被删除或凭据清空时直接提示配置，不回退到其他账号。`anxia.com/s/...` 作为 115 分享别名，在公共 115 分享解析入口严格校验后规范为 `https://115cdn.com/s/...`；该规则同时适用于网页、Bot 和观影搜索。

成功搜索结果在后端内存中缓存 10 分钟，无结果缓存 2 分钟，最多保存 128 个页面。缓存键为影视类型与 TMDB ID；错误不会缓存，配置修改或清除时立即清空缓存，服务重启后缓存自然消失。「重新搜索」会显式绕过缓存并用新结果替换旧项。接口仍返回 `Cache-Control: no-store`，Cookie、账号凭据和搜索结果都不会因为该缓存写入磁盘。

后端独立实现登录和验证协议，不依赖 PanSou：

1. 访问首页建立初始 Cookie 会话；
2. 遇到浏览器 PoW 验证时读取 `/res/pow`，计算并提交结果；
3. 提交 `/user/login` 登录表单；
4. 访问详情页预热防爬 Cookie；
5. 搜索 `/search` 并读取 `/res/downurl/{type}/{id}` 的资源详情。

详情请求最多同时执行 6 个，同一会话的安全验证串行处理。HTTP 403 或登录页响应会触发一次重新登录，仍失败则停止，不无限重试。单次最多读取前 100 个搜索条目，超过时页面会明确显示截断数量。页面逐项展示原名和 IMDb 的查询词、站点匹配数、可用资源数及详情失败数；只有经过确认的空结果才缓存。部分详情失败时展示已成功读取的资源并提示结果不完整，全部详情失败时返回错误且不缓存，避免把网络故障误报为无资源。安全验证计算和 HTTP 响应均设置上限，请求随浏览器关闭弹窗或超时取消。

TMDB 详情缓存键包含结构版本。IMDb 字段加入后，旧详情缓存不会继续向观影搜索返回空编号；首次读取对应页面时会重新取得详情并写入新版本缓存。

修改 `JWT_SECRET` 后旧配置无法解密，需要保留原密钥或移走 `gying-config.enc` 后重新配置。删除配置只清除 Cinema115 保存的账号、密码和 Cookie，不修改观影站账号。
