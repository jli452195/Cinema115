# 字幕组与来源平台识别词表

管理入口：**自动整理 → 识别词表**。词表用于普通文件整理、搜索后的下载整理。RSS 动漫订阅保持原有行为，继续使用来源读取的字幕组。

程序只读取数据目录中的 TXT，不内置名单，也不自动创建或填充词表。文件不存在、为空或只有注释时，对应类别不识别；两个类别独立生效，不回退到旧的平台识别或搜索提供的字幕组。

可选示例位于 `docs/examples/recognition/release-groups.txt` 和 `platforms.txt`。需要时自行导入或复制到数据目录；程序不会自动读取示例。

字幕组示例参考 [MoviePilot 的发布组识别与用例](https://github.com/jxxghp/MoviePilot/blob/HEAD/app/domain/meta/releasegroup.py)及 [TRaSH-Guides 的公开组名规则](https://github.com/TRaSH-Guides/Guides/tree/master/docs/json/sonarr/cf)，补充动画字幕、Raws、中文 PT 和其他影视发布组的名称。这里只参考组名，不引入质量分级或评分，也不保证覆盖所有组。名单核对日期：2026-11-15。

词表按具体组名维护，不提供“任意名称 + 字幕组”通用规则或兜底识别，未列出的组不会识别。同一组名的字形、后缀及系列变体可使用有限的正则分支，例如 `(?:桜|樱)都字幕[组組]`，避免用 `.*` 等宽泛规则。短名和普通单词容易与作品名混淆，新增后建议用真实文件名在页面中测试。规则不带映射时始终保留命中原文，联合组也无需预先枚举组合。

## TXT 规则

配置文件位于数据目录的 `recognition/release-groups.txt` 和 `recognition/platforms.txt`，使用 UTF-8 编码。每行一条正则，默认保留整个命中片段的原文及大小写：

```text
LoliHouse
喵萌奶茶屋
(?:桜|樱)都字幕[组組]
```

需要固定输出名称时，使用 `输出名称 ~= 正则`：

```text
桜都字幕组 ~= (?:桜|樱)都字幕[组組]
NF ~= Netflix|NF
IQ ~= iQIYI|IQ|爱奇艺|愛奇藝
```

空行和以 `#` 开头的整行注释会被忽略；不支持行尾注释。正则采用 Go 的正则语法，默认忽略大小写，可用 `(?-i:...)` 指定需要区分大小写的片段。不支持前后查找或反向引用。正则作用于完整输入，`^`、`$` 分别表示整个文件名或发布标题的开头、结尾，包含输入中的文件扩展名；不单独对括号内部重新匹配。映射左侧为固定名称，不进行捕获组替换。

## 联合组与识别依据

`[喵萌奶茶屋&LoliHouse]` 分别识别两组，按原文顺序输出 `喵萌奶茶屋&LoliHouse`。无需逐个维护联合组组合；组名内部的空格和短横线会保留。

识别器用 TXT 扫描完整文件名或发布标题，支持裸前缀、圆括号、方括号、文件中间和发布组后缀。例如 `EPSiLON -dfaef`、`(EPSiLON) 示例电影.mkv`、`[EPSiLON 1080p] 示例电影.mkv`、`示例电影-EPSiLON[1080p].mkv` 都可识别词表中的 `EPSiLON`。联合组不依赖预先切割分隔符，`喵萌奶茶屋&LoliHouse 示例动画.mkv` 也可分别命中。

命中两侧必须是输入边缘或非字母、非数字、非组合附加符的分界，避免从 `NotEPSiLON`、`LoliHouse的故事` 中截取组名；组名和标题完全连写时保持不识别。三字符以内的英文短组名还需独立输入、发布分隔符、括号标签或附近资源规格作为依据，减少普通句子中的撞词；这仍无法完全区分组名与同名作品，歧义名称建议按实际命名进一步限制规则。

普通名称编译为共享只读索引，复杂正则单独编译复用，逐文件不重新读取 TXT 或计算完整词表哈希。单个名称的规则命中总量最多 8192 处，超过时明确报错，避免重复或过宽规则导致内存膨胀，不静默截断结果。

识别以实际文件名为准。普通下载整理只在明确对应单个视频时，允许用原始发布标题补充缺失信息；多视频合集不把总标题的组名分配给所有文件。搜索结果提供的字幕组字段不再用于补全文件命名。

同一片段同时命中普通规则和映射规则时，映射优先。多个映射给出不同名称时视为冲突，不按行号静默选择。短平台代码还会检查词边界和资源规格上下文，避免作品标题中的短词被误认为平台。

## 编辑与生效

两类词表分别保留编辑草稿，切换词表不会丢失修改。导入 TXT、清空当前词表只修改草稿；保存后才生效。草稿测试使用后端实际识别器，不保存也能检查结果、命中原文、行号和规则映射冲突。

保存会用当前两个草稿覆盖对应 TXT，缺失的目录和文件在保存时创建，不检查编辑版本。直接编辑或删除磁盘文件后，需要从管理页重新读取并应用文件修改，或重启后端。删除文件并应用后，该类别停止识别，另一类别不受影响。无效规则会报告文件及行号，不会替换最后一次有效的配置。

已确认的整理计划固定识别规则和命名结果；后续词表修改不改变原任务的目标路径。

页面底部的“词表参考”提供 MoviePilot 和 TRaSH-Guides 的公开资料链接，便于核对组名与平台写法。它们原本使用 Python 或 JSON，须整理为本项目支持的 UTF-8 TXT 和 Go 正则后手动导入；不会从链接拉取、保存或自动更新词表。
