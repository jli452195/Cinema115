## 对查询必要性的结论

- 移动文件不要求重新按 SHA1 搜索或精确查询，原 PickCode 在本次实测中保持可用。
- 复制再删源不会让旧 PickCode 自动指向相同 SHA1 的副本；若要复用副本，仍需获取副本自己的 ID/PickCode。已有本地副本记录可减少搜索，否则需查询网盘。
- 若接受不寻找副本而直接秒传，SHA1 搜索可从该策略中省略，但可能多写一个重复文件。
- 对本次回收操作，50015 与随后精确查询的 20018 一致；精确查询没有帮助恢复旧文件。不能据单个账号、小文件样本断言所有 50015 都只表示删除，更不能把所有取链错误统一视为缺文件。
- SHA1 快速接口可能返回刚回收的文件；快速接口命中不等于文件可读。普通搜索在本样本中区分了回收文件和有效副本。

本轮没有改变播放恢复策略。此前“用精确查询替换 SHA1 搜索就能省掉一次请求/固定节省约 300 ms”的说法不成立：一查换一查仍是一次请求，耗时取决于接口；只有省略两种补查才能真正减少一个步骤。
