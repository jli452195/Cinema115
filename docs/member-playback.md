# Emby 个人中心与播放授权

普通用户使用 Emby 账号登录个人中心，邀请码注册直接创建 Emby 账号。没有独立网站用户密码、二次注册、同名关联或接管邀请。管理端使用独立的管理员登录入口。

本地 `emby_profiles` 仅保存 Emby 身份投影，以服务 ID 和用户 ID 的摘要作为归属键；用户名不是身份。每次验证个人中心会话都查询 Emby 状态，已停用、已删除、管理员身份或服务器变更均拒绝访问。密码、Emby 登录令牌不写入数据库或响应。账号改名、密码修改在 Emby 完成。

## 邀请与小号池

邀请类型固定为 `personal`（自备网盘）或 `assigned`（管理员小号池）。服务端存储待遇，邀请限用一次；注册请求不能自行更改待遇。新建用户先应用并读回禁用策略，再设置密码和名称。持久化随机预约名与固定 Emby ID，超时重试不会重复创建或认领同名已有用户。邀请核销、身份投影与播放配置在同一事务提交。

自备网盘注册后可浏览，绑定并验证个人 115 后开通播放。共享池注册不分配具体小号。实际播放按会话选择健康且有容量的 UID，同一会话重复取链保持目标；目标故障在原请求预算内有界切换其他 UID。空池、全失效或繁忙拒绝取链，不回退主网盘。

管理员在 `/users` 管理邀请及新账号媒体库模板，在 `/emby/proxy` 管理 302 和原文件下载入口，在 `/emby/users` 管理播放来源及状态。没有特别指定的已有用户默认使用主网盘，个人邀请仍需本人扫码；停用用户拒绝播放。管理员可设置主网盘或动态共享池用于播放，媒体库和分级权限在 Emby 中维护，管理身份不变。所有接入播放的用户强制禁止音视频转码和重新封装。已有用户的设备、远程访问、下载及其他常规权限保留 Emby 设置；Cinema115 创建账号时应用初始安全设置。

## 权限归属与注册模板

普通用户（包括邀请注册用户）及管理员的播放权限统一以 Emby 为准。管理页不显示播放开关或只读播放权限，也不提供普通用户播放权限写接口；管理员在 Emby 中维护全局播放权限。Cinema115 在自己的反代请求中读取并遵守权限，网盘不可用时拒绝本次取链，不通过关闭全局播放权限影响其他工具。

媒体库、分级、设备、远程访问和下载权限由 Emby 管理。用户列表只读取权限；使用反代时同时检查实时 Emby 授权、网盘凭据和绑定，不依赖本地授权开关、同步版本或接入标记。个人网盘失效或解绑时拒绝新请求，恢复后重新按实际条件判断，不自动开关 Emby 播放权限。下载需全局入口与 Emby 下载权限同时允许，并检查同一网盘绑定，独立于播放开关。

本地仅保存身份、来源、绑定、创建进度、子账号业务状态和最近网盘检查结果；网盘检查结果用于展示，不是永久授权。界面显示播放来源、网盘状态和子账号信息，网盘未检查不会妨碍实时鉴权。原文件播放的禁转码与禁重新封装限制由 Emby 与反代同时执行。

用户页统一使用“刷新状态”：先读取 Emby 用户和最新权限，再异步检查相关网盘。网盘健康结果按配置编号、实际凭据和目录共享，不按 UID 跨配置共享；凭据或目录变化使旧结果立即失效，提交后自动检查，单纯改名保留结果。个人网盘清空凭据、删除、解绑或撤销直接显示不可用，不回退其他来源；共享池隔离故障账号，后续请求可选择池内其他 UID。检查按账号串行且每次最多 8 秒，失败不阻断其他账号，过期的检查结果不会覆盖新配置。缓存仅用于展示，重启后重新检查，不保存 Cookie 或凭据摘要到数据库。

页面先显示用户卡片，再更新网盘状态和检查时间；等待检查时每 1.5 秒读取状态，其他时间每 15 秒读取，隐藏页面暂停读取，返回时重新读取 Emby 权限。后台状态读取不触发重复 115 检查、不覆盖未保存的用户设置；刷新接口不写 Emby 策略。实际播放仍实时校验权限、网盘和子账号条件。

子账号的暂停、停用、撤销和所有者个人绑定继续在本地强制约束。暂停播放不改变 Emby 开关；停用和撤销还会禁用 Emby 登录。外部重新打开 Emby 权限不能恢复已撤销身份。后台只重试必要的子账号登录禁用/恢复，不重放管理员播放开关操作。

注册媒体库模板仅在邀请注册或新建子账号时应用一次，之后在 Emby 中维护。新账号完成创建后初始化播放和原文件下载能力；未绑定个人网盘仍只能浏览，反代拒绝取链。模板清空禁止新建账号，不影响 302 或已有用户。

## 个人网盘与换号

UID 用于凭据及文件身份核验，不作跨配置唯一绑定。同一个 115 账号可由不同用户独立扫码，各自保存凭据，互不复制或同步 Cookie。个人扫码入口同时支持重新登录和换号；扫码会话固定原账号、来源与版本。

新账号验证成功后事务保存待绑定配置，创建并校验独立目录，最后事务切换当前关联并清除旧账号凭据。目录创建结果不明时保留原关联，用户本人可核查并填写目录；用户再继续或取消。旧目录及文件记录保留，不继承到新账号，也不删除云端文件；历史 UID 不占用账号。主动解绑会在事务内清除该用户所有个人配置、凭据及关联，个人来源暂停且不回退主网盘。取消后仅撤销待绑定凭据。池用户可先准备个人网盘，再主动切换来源。

接口：`/api/auth/login` 为 Emby 登录，`/api/auth/admin/login` 为管理登录，`/api/auth/register` 为邀请注册。个人网盘使用 `/api/me/playback` 下的 `qrcode`、`disconnect`、`drive-change` 和 `use-personal`，个人目录确认使用 `directory`。管理员共享小号池入口为 `/115/pool`，用户个人网盘入口为 `/account/playback`；管理接口仅返回个人连接状态，不返回个人 Cookie、UID 或目录，也不能修改个人目录。旧网站用户 CRUD、接管、二次注册和通用绑定写接口已移除。

## 测试环境重建

不迁移旧网站用户。停止后端后，在 backend 目录运行：

```powershell
go run ./cmd/dbtool -data-dir ../data -action reset-portal -output ../data/backups/before-emby-portal.db
```

工具先创建 SQLite 一致性备份，再清空用户投影、旧网站用户、邀请、播放关联、个人网盘配置、个人副本、用户追更订阅和通知。管理员网盘、全局播放设置、媒体资料及共享追更任务保留。原 Emby 账号与云端文件不删除；已有 Emby 用户重新登录后默认使用主网盘。备份路径必须尚不存在。

Emby `/Users/New` 不能原子设置权限，源站应限制为仅反代可访问。已发出的 CDN 链接无法立即撤回。

验证：backend 中 `go test ./...`；frontend 中 `npm run build` 和 `node scripts/emby-portal-ui.cjs`。浏览器测试使用模拟 API，不修改真实 Emby/115 数据。

管理员可在原账号卡片保存新 Cookie 或扫码换号。共享小号换号时填写新网盘目录编号，验证凭据与目录后一次切换，旧会话的新取链需重新选择并核验目标，不迁移旧目录或副本。主账号换号会更换内部配置编号，各功能旧目录必须重新配置。同 UID 刷新凭据保留目录。


播放授权性能：浏览请求不执行完整媒体授权；直链请求复用用户 token 查询得到的 Emby 权限，单次检查网盘登录和目录。相同配置与凭据的并发请求仅共享正在进行的网盘检查，完成即移除，无跨请求成功授权缓存。具体影片访问权限继续使用用户 token 校验；返回前复核撤销、解绑及配置版本，授权准备耗时达到 5 秒时再次读取 Emby 用户权限。所有来源使用[独立播放会话记录](single-playback.md)，同用户允许多会话；跳过推测预热，正式取链才建立会话并准备网盘文件。正常停止可原地重播。强制禁转码和子账号登录禁用仍按业务约定执行。

绑定网盘使用一次带固定 Cookie 的 `/files?cid=...&limit=1` 实时请求合并确认登录可用性和保存目录身份，不再先单独查询登录状态。响应必须成功且目录身份匹配，失效凭据、目录回退到根目录、缺失身份或网络错误均拒绝；主网盘保留登录状态查询。合并核验使用独立于普通扫描及播放 SHA1 查询的凭据级限速队列，成功结果写入现有上传目录预检缓存，避免随后秒传再次查询同一目录。新播放请求不使用该缓存授权，仍执行实时核验；缓存按配置、Cookie 和目录隔离，失败清除原成功记录。调试日志将“业务身份与网盘实时核验”从 Emby 用户 HTTP 耗时中分离，并记录合并核验的请求数、HTTP 耗时、排队及重试次数。

正式取链优先复用同一次实时条目权限查询返回的静态 STRM 媒体源，避免再次请求 PlaybackInfo；首次播放协商仍保留 Emby 完整 PlaybackInfo，因此不减少播放器用于分辨率、HDR/DV、音轨、字幕和会话的字段。动态或来源不明确时回到原流程。

动态池参数、会话回收与验证边界详见 [动态播放池](dynamic-playback-pool.md)。
