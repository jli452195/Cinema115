# P1-03 蜜柑 RSS 与累计历史读取

完成日期：2026-10-18。依据：[实际接口验证](anime-mikan-api.md)、[首版预算](anime-first-release-rules.md)、[数据与接口契约](anime-subscription-contract.md)。本项交付后端读取能力，不装配动漫 HTTP API、页面、预览持久化或下载调度。

## 已实现

- `backend/internal/client/mikan/source.go`：受控单组 RSS 地址与 ID 转换、条目/单组 RSS/累计历史三类有界元数据请求，以及预算和上游 HTTP 错误类型。
- `backend/internal/client/mikan/source_parse.go`：RSS 结构与字段校验、原帖身份、原始日期/大小、原始行数、累计历史与可见末尾判断。
- `backend/internal/service/anime_mikan.go`：调用现有 MikanService 的共享协调，先确认条目实际列出的组，再读取该组 RSS 或历史；来源缓存、合并及继续读取比较。
- `backend/internal/service/anime_mikan_budget.go`：一次操作的请求、时间、正文和原始行数预算。由后续预览服务从可信快照提供当前各来源 rawCount，不能信任浏览器声称的计数。

来源仅为 `https://mikanani.me/RSS/Bangumi?bangumiId=条目ID&subgroupid=组ID`，必须明确一个发布组。粘贴地址被转换成 ID 后重新构造请求，不允许其他主机、端口、用户信息、片段、额外参数或重复参数；历史展开使用另一个已验证参数 `subtitleGroupId`。条目页确认组 ID，不从资源标题猜组，不将 RSS 正常零条当成绑定成立。

RSS 只读取 XML，不执行 description、不解析外部实体、不跟随重定向或 enclosure，不下载种子、图片或视频。保留原帖 PostKey、GUID、标题、原始发布时间、大小与受控链接；RSS 无磁力是正常情况。GUID 可重复，不作为唯一键；同原帖完全相同行可以合并展示，但 rawCount 不减少，同原帖内容矛盾则整次读取失败。HTML 磁力只保留为待核验线索，Episode 路径和种子文件名不升级成已验证 BT info-hash。

本步不解释集数或时区：时间原文保留，RSS 的 torrent/pubDate 与可能的顶层日期分别保存，HTML 分钟日期不覆盖 RSS 时间。集号、时间和解释版本由 P1-04 的[独立发布解析器](anime-release-parser-implementation.md)提供，业务接入在后续来源确认与预览任务完成。

## 预算和结果

| 范围 | 已实现的约束 |
| --- | --- |
| 一次生成/继续操作 | 同一目标来源；最多3次实际元数据请求、从预算创建起绝对45秒；组确认也占请求预算 |
| 单次请求 | 至多20秒、正文最多4 MiB；若操作剩余正文额度更少，使用较小值 |
| 操作正文 | 最多8 MiB；正常响应、失败及中断正文都计费，缓存/进行中合并不重复计费；检测超限最多读取额外1字节，超限响应不参与有效快照 |
| 原始发布 | 单响应最多2000条；最多5个来源的批次快照合计2000条，包含重复行；继续读取替换当前来源计数，不累计追加 |
| 历史请求 | `take=1..2000`，请求前先预估其他来源占用；取满时建议 `min(take+50,2000)`，不自动发下一次请求 |
| 共享协调 | 旧搜索/条目和新 RSS/历史使用同一个访问 gate，相邻请求至少1秒，进行中请求总数最多32；同类新读取按来源/类型/take合并 |
| 新来源缓存 | 最多32条、归一化正文估算最多8 MiB；条目组资料10分钟，RSS/历史1分钟，均从实际 observedAt 计算 |

旧浏览器搜索保持原16 MiB正文及 take<=10000保护，缓存结构与新读取分开。新增动漫入口必须复用现有 MikanService 实例，不能另建一个实例规避站点协调。HTTP 403/429/503 更新共享冷却，至少30秒，有更长 Retry-After 时遵守服务器期限；强制刷新也经过相同协调。有效缓存仍可读取。

缓存命中不更改 observedAt 或到期时间；返回切片与缓存隔离。首个读取同步执行，等待者可以独立取消；首个调用者取消、超时或受其自身预算约束时，仍存活的等待者可在自己的预算内接手。没有新增脱离请求生命周期的 goroutine。

结果边界：

- 有效零资源：成功且 rawCount=0，资源数组为空；RSS 仍为 partial，不能证明全历史已读完。
- 有效历史：仅结构与原始行数可靠且 rawCount<take 时，可表示本次来源的 visible_end；不是全集或全站完整性承诺。
- 取满/达到上限：partial，分别说明 more_available/limit；不会请求2000以上。
- 继续读取带可信旧快照：窗口前缀发生变化时保守标记 partial 和 windowChanged；增加 take 后没有新原帖时返回 no_progress 并停止建议展开。不修改旧快照或已选身份。
- 读取失败：返回真实 error，不返回伪造的成功空页、不替换既有计数、不覆盖缓存成功值；后续 P1-06 从持久预览保留旧清单并附 issue。
- 预算失败：LimitError.Kind 区分 rows/body/bytes/requests；时间和取消保留 context 错误。不得把正文或时间耗尽显示成2000条已到上限。

缓存的 ExpiresAt 仅是元数据新鲜度，不是预览的绝对15分钟有效期，也不能代替首次启用的 T0/基线。来源配置、解析规则、预览选择和发布入库分别由 P1-04～P1-07接入；本项不写 SQLite。
