# 稳定设备播放名额与第二阶段隔离验证

日期：2026-10-03。

## 当前行为

容量键来自服务、Emby 用户、成功登录响应中的设备与播放器关联摘要。Token 改变不改变同设备容量身份；播放 URL 声明、IP、UA 均不能替代认证关联。用户会话仍分别存储代次、条目、播放证据和停止生命周期。缺少可信关联的旧记录不补绑。

- 同设备同 UID 的准备、已签发记录和停止残余按一个逻辑名额统计。统计页、准入检查、日志容量诊断使用一致的聚合口径：活跃优先于准备，准备优先于纯残余。
- 健康设备目标优先于其他 UID 的空闲容量及副本亲和；当前会话和下一片都优先复用，账号失效才在原有有界重试规则内切换。配置凭据、目录、文件归属和写入目标仍独立固定。
- 一次最多一个新准备任务，已有会话刷新可以并行，不再持有跨网络 I/O 的设备大锁。提交前检查用户代次、池代次、停止状态和更新的账号故障。
- 没有播放上报时保留一个保护中的首播和一个最新候选。存在已确认播放时，保留已确认的各会话和最多一个未确认候选。新候选成功提交后才淘汰旧候选；在途候选不强行删除。候选最初签发起固定 90 秒到期，重复 GET 不延长，播放确认后改按播放 TTL 续租。
- 当前片刷新不会淘汰已有预加载。预加载失败、取消或数据库失败保留已有状态。候选淘汰记录短期事件封锁，并禁止歧义的缺会话 ID 旧事件匹配新候选。
- 正式会话接替仍要求唯一静默旧会话与新播放证据；持续活跃的多个正式会话不被合并或强制结束。同一可信设备的这些会话共享容量名额，其他设备各自计数。这是逻辑设备容量策略，不能宣称是 CDN 真实连接限制。
- 正常停止只结束对应子会话；同 UID 的残余可由该设备下一次成功签发承接，旧代次不能签发或释放新会话。管理员强制释放仍校验对应会话代次并禁止旧会话重播。
- 跨 UID 切换后旧目标最多保留两分钟残余，按设备 + UID 合并；每设备最多涉及三个未到期 UID。第四个 UID 要等残余到期后再分配，避免无限故障链。目标写入不确定仍禁止跨账号重试，公共池不回退主网盘。
- 用户记录与池记录通过同一 SQLite 事务提交，成功后发布内存。设备容量通过持久租约中的 SlotKey 聚合，重启不依赖临时内存索引。下载和管理员手动秒传不复用设备播放名额。

## 隔离灰度场景

使用临时 SQLite、模拟 Emby 与 115、模拟时钟。多 UID 均为虚拟测试账号，未对真实账号触发秒传或修改池配置、未清理历史租约；本次不是 Yamby 实机流量灰度。

| 场景 | 预期与验证 |
| --- | --- |
| 同设备连续切换 100 次，不发停止 | UID 稳定、容量始终 1、无上报的当前记录最多 2 |
| 同设备连续切换 100 次，每次正常停止 | 残余名额复用，容量始终 1 |
| HTTP 入口连续 100 次 GET/HEAD | 真实授权与提交路径保持同一设备 UID、候选有界 |
| UID 上限为 1，A 播放 + B 预加载 | 共计 1 个名额，A 保持可取链 |
| B 准备期间 A 继续取链，或 B 准备失败 | A 不被设备大锁阻塞、不被退休 |
| B 已签发后重复取链、A 再刷新 | B 固定到期不延长；A 刷新不删除 B |
| 两台设备、同一用户 | 各占名额，不恢复用户单路限制 |
| 同设备两个已确认且活跃的正式会话 | 两个生命周期都保留，同设备逻辑容量为 1 |
| 重启后旧 A 的停止、进度晚到 | B 保留；过期/停止状态不会复活 |
| 重启后仅由 Emby 轮询确认 B | 内部未脱敏的匹配身份正确传递，静默 A 可接替，B 获得正式播放期限 |
| 16 个并发下一片请求 | 准备有界、当前片保留、容量不超卖、候选不无限增长 |
| 提交时 SQLite 池表故障 | 用户候选淘汰、池变更一起回滚，当前播放保留 |
| 三 UID 连续故障 | 当前与残余合计不超过三个 UID；第四个被拒绝，残余到期后恢复分配 |
| A 旧 UID 请求在途，B 已完成故障切换 | A 的迟到结果被停止状态及代次检查拒绝，不能回滚设备目标 |
| 管理员旧代次释放、强制释放后的重播 | 旧代次拒绝，强制释放只影响对应会话，其他会话保留 |
| 缺设备身份、下载、手动任务、资料来源轮换 | 保持原有独立容量与来源/目标分离规则 |

## 自动检查

从 `backend` 运行：

```powershell
go test ./internal/service ./internal/httpapi ./internal/storage ./internal/client/emby -count=1 -timeout=180s
go test ./internal/service ./internal/httpapi -run 'TestDeviceSlot|TestDeviceAnalysis|TestMultiUIDAnalysis|TestPoolProtocol' -count=20 -timeout=180s
go vet ./internal/service ./internal/httpapi ./internal/storage ./internal/client/emby
go build ./cmd/server
```

检查结果：四个相关包完整回归通过；关键场景连续 20 轮通过；相关服务、HTTP、存储用例在 Linux Docker 内运行 Go race 通过；go vet、后端构建通过。

## 实机边界

没有事件的客户端无法可靠区分“正在播放”“仅预加载”“多个窗口”。保护首播和有界候选是明确的兼容策略，不能证明真实 CDN 并发；已淘汰候选的 CDN 地址也不会被立即撤回。超过一个下一片候选的客户端可能需要重新申请被淘汰的候选，须根据真实播放器事件时序验证后调整策略。

已确认会话无有效心跳时按五分钟失联期限回收；池仍尊重已保存设置。历史无 SlotKey 的租约继续独立计数，不把来源不明的旧记录强行合并。Yamby 实机需要通过反代登录建立可信设备关联，再验证退出、快速换片、自动下一集及多设备同时播放。
