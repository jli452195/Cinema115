# AnimeGarden 单次下载整理

入口在媒体详情页的 Garden 搜索结果中，展开“115 云下载”右侧按钮，选择“下载并整理”。主按钮仍是普通离线；蜜柑搜索和 RSS 订阅不参与此流程。

- 点击入口才读取这一条 Garden 资源的文件清单，按规范化 BTIH 缓存 30 分钟，十六进制和 Base32 共用缓存。搜索、筛选、悬停不会预取详情。缓存沿用站点现有的条数、体积、并发与冷却限制。
- 缺少完整清单、仅含 ISO 或没有视频时，可以直接普通离线。未解析出集号的视频仍可手动选择和填写季集，特典不自动映射到第 0 季。
- 在独立的整理弹窗内选择视频、目标目录和季集，搜索结果、筛选与滚动位置保留在后方。关闭按钮、Escape 或点击遮罩仅关闭整理弹窗；提交中禁止关闭。列表显示原名与整理后的名称，底部提交栏固定可见。偏移以原发布编号为依据，保留缺号和连集跨度；连续编号必须明确操作，最近一次批量编号可撤销。未知发布编号不参与偏移，行内填写的是目标季集。
- 确认前复用手动整理的 TMDB 命名、季集验证及冲突检查。目录仅用于本次任务，不改写全局配置。确认后以预览 ID 幂等创建任务；请求回执丢失后只重试同一 ID。
- 下载**整条磁力**，所选行只决定整理范围。Garden 清单顺序不能充当 115 的 wanted 索引。
- 固定主账号凭据和本次目录，在云下载目录下创建独立 `garden-任务编号` 文件夹。先持久化意图再写入；离线等待不占用整理锁。提交成功后立即查询一次，未完成时逐步退避为 2 秒、10 秒、30 秒、1 分钟、2 分钟、5 分钟，最多等待 24 小时。不因读取失败或任务暂时缺失重复提交；已确认完成后，等待整理锁或文件可见性时不再查询离线状态。
- 最多 4 个活跃任务，各由一个服务托管的工作协程独立推进，取消和退出时全部等待回收。慢查询、提交和整批整理不会占住其他任务的推进循环；文件整理仍使用原来的单路目录预约。阶段预算分别为提交准备 2 分钟、状态查询 30 秒、绑定扫描 90 秒、单次整理 30 分钟，包含客户端排队和重试。沿用原请求限速和轮询退避，不增加定时查询频率。保存失败会取消全部工作协程并上报服务错误；已经发出的写入无法撤回，结果不明确的文件仍保留待核对状态，禁止自动重放。
- 离线完成并确认任务身份、下载目录后，只遍历本次目录，将原始相对路径唯一绑定到实际 115 文件 ID。115 精确状态接口可能不返回 `wp_path_id`，此时通过本次扫描确认返回的 `file_id` 位于独立下载目录内，不另发目录归属查询；明确返回其他下载目录、结果不在本次目录内或没有归属证据时不能整理。路径缺失时有限重读，仍未匹配则停止，留待手动整理；不按同名文件猜测、不查询 SHA1。最多 1000 个可整理视频、300 个目录、12 层目录。
- 单文件种子有时会被 115 包成“原文件名/原文件名”。仅在所选文件和实际文件都只有一个、完整路径恰好为这一层同名包装、精确状态返回的结果 ID 匹配文件或其父目录时接受；保留真实网盘路径用于记录和恢复。其他目录、额外文件或缺少结果证据时仍拒绝绑定。
- 复用手动整理的批量重命名、移动及写后核验。执行器在每批写入前检查来源和目标冲突，省去绑定后的重复全计划检查。仅移动所选视频，不复制、不覆盖冲突文件。自深至浅清理确认为空的目录，未选视频、字幕包及其他文件保留。压缩字幕沿用独立的手动字幕导入流程。
- 目录分页出现总数变化、条目重复、偏移重置或不完整页时，丢弃本轮快照，从第一页重新读取；最多读 3 轮，异常后分别等待 1 秒、2 秒。改名、移动后的目录暂时未显示全部本批结果时，复用同一读取预算等待可见性。正常成功不增加请求或等待；重试耗尽后保留逐文件已确认/未确认结果，不自动重放写入。客户端保留 115 实际返回的分页偏移，不能用请求偏移替代。
- Garden 任务复用原有统计，覆盖创建临时目录、提交、状态读取、文件扫描、批量整理和空目录清理；进入批量执行器时不会重置统计。HTTP 请求数包含客户端实际重试，目录读取等阶段耗时包含请求排队，因此不与 HTTP / 等待耗时相加。
- 状态在“115 助手 → 手动整理 → 任务记录”显示。任务完成后不再检查文件位置。服务重启会将未完成任务标记为中断，不保存 Cookie，也不自动重新绑定账号或重放写入。
- 中断的 Garden 任务可在详情底部点击“检查并继续”。后端统一判断可恢复条件：已保存独立下载目录，且所有条目仍为 `pending/preparing`，没有改名、移动请求或意图；普通整理、清理、字幕及部分写入任务不提供直接恢复。账号必须仍是原主账号且版本一致。复用原任务 ID、目录和命名计划，不请求 Garden 或 TMDB，不重提离线。已绑定的网盘路径会还原为相对路径后重新核对。重复点击或恢复回执丢失不会创建第二个任务，已完成任务只返回结果。
- 手动恢复首先精确查询一次原离线任务：查询失败或不存在时，保留中断及原因，可稍后手动重试；仍在下载则恢复正常退避；完成后进入原整理流程。恢复重新计算本次执行统计及最多 24 小时的等待预算，保留原创建时间。顶部“刷新记录”始终只读取本地记录。详情保留筛选和位置；恢复失败提示会滚入视口，完成后按钮消失时焦点留在详情内。

管理员接口：`POST /api/admin/p115/garden-organize/files`、`/preview`、`/jobs`、`/resume`（`jobId`）。历史复用 `GET /api/admin/p115/manual-organize/jobs`，返回后端计算的 `resumable`，没有另建 RSS 或任务数据库。
