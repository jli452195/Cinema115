# 动态小号池实施任务清单

创建日期：2026-10-03。

后续清理：Emby 302 主动预热及独立文件准备模式已整体移除。下文预热相关任务与验收为历史记录；当前 PlaybackInfo 仅协商，正式取链通过准入后才按需准备文件，详见 [Emby 302 反代](emby-proxy.md)。

状态：动态池主链路、设备名额、可选心跳熔断及容量转交已实施。当前环境无法进行真实 Yamby/Emby/115 联动验证，按用户要求将实机演练从本轮任务及完成门槛中移除；不标记为实测通过。验收采用临时 SQLite、模拟上游、可控时钟、HTTP 协议测试和竞争检测。本轮补齐记录见第 16 节。实际行为和参数见 [动态播放池](dynamic-playback-pool.md)、[设备策略与容量转交验证](playback-device-policy-validation.md)。

## 1. 目标与实施边界

用户使用管理员共享池时，不再手动绑定具体 115 小号。系统按播放会话自动选取可用小号，遇到可分类的账号故障时在预算内切换；加入 API 限速、UID 容量控制、健康恢复和可观测性。

取消的是用户与管理员池账号的永久绑定。Emby 身份验证、媒体权限、个人网盘归属及播放子账号的永久身份继续有效。

### 已明确的方向

- [x] 本轮产出详细任务清单，后续实施按阶段推进。
- [x] 管理员共享小号改为动态调度，用户不再选择具体池账号。
- [x] 池账号失效可自动选择池内其他可用账号。
- [x] 增加限速，并把自查、问题修复及回归纳入实施流程。

### 本清单采用的建议基线

以下为上一轮讨论的建议，不能写成用户已逐项确认的产品决策。后续实施首先检查有无新指示；没有新指示时按本基线推进，并记录最终采用值。

| 事项 | 建议基线 |
| --- | --- |
| 用户身份 | 保留 Emby 登录与服务 ID + 用户 ID，不另建网站密码体系 |
| 来源类型 | 共享池、个人网盘、管理员明确指定的主网盘 |
| 已有普通用户默认来源 | 延续现有主网盘规则；本改造不把所有 Emby 用户自动加入共享池 |
| 共享池耗尽 | 明确报忙或不可用，不自动使用主网盘，不增加自动主盘兜底开关 |
| 个人网盘失效 | 拒绝新取链，不自动使用共享池或主网盘 |
| 播放子账号 | 仍只共享所有者已绑定个人网盘，不跟随公共池来源 |
| 调度单位 | 会话生命周期独立；同设备同 UID 合并计数；熔断策略跨设备事务转交名额；下载和手动秒传独立分配 |
| 动态切换边界 | 结束旧尝试后开始新尝试；每次尝试固定目标及凭据，禁止中途替换 |
| 限速含义 | API 请求速率、排队与会话准入；不承诺控制 302 后的 CDN 带宽 |
| 部署 | 第一版支持单个活动后端；明确阻止或不支持多活动实例，不能宣称分布式容量保证 |
| 兼容 | 无生产数据，不新增旧固定绑定的双轨兼容；开发数据变更需明确备份与重建范围 |
| 暂不包含 | 独立会员系统、收费有效期、地域调度、动态主资源盘、视频代理或转码 |

## 2. 总体验收条件

- [x] 共享池用户只配置来源模式，无需配置具体账号和目录；目录由被选小号解析。
- [x] 健康账号可自动参与新会话分配；失效账号被隔离，符合条件的请求能切换至其他 UID。
- [x] 选择与容量预占原子完成；并发请求不能一起越过上限。
- [x] 同会话重复取链、预热、拖动不反复占用名额，不无故变更目标。
- [x] 所有选取、重试、冷却等待和上游调用受同一请求截止时间约束。
- [x] 全池不可用时快速返回明确错误，不扩大主网盘压力。
- [x] 切换不绕过实时 Emby 权限、子账号生命周期或个人网盘归属限制。
- [x] 不把已经签发的直链计为可即时撤回；会话准入不是对实际 CDN 连接的精确控制。
- [x] 目标 UID 写入串行、不同 UID 最多四路写入的既有约束保留。
- [x] 日志、持久化调度记录和管理列表不包含 Cookie、令牌或完整直链。
- [x] 自动测试及模拟灰度有记录；真实客户端验证不作为本轮完成门槛，不能声称已实测通过。
- [x] 后端、前端和文档一致：用户会话页按当前策略说明多设备并行、心跳熔断及逻辑容量转交。

- [x] 将共享池来源表达为明确的池模式，不再使用 `AssignedAccountID` 作为用户播放条件；确定最终字段和枚举。
- [x] 删除普通用户指定池账号的写接口参数，拒绝伪造或过期参数，不能静默接受。
- [x] 邀请仅记录个人/共享池待遇；注册共享池用户不立即执行 115 小号分配。
- [x] 空池时允许完成 Emby 注册，播放明确失败；不得将来源重写为主网盘。
- [x] 新建池设置：启用状态、UID 会话上限、候选数、总预算、请求速率、短队列上限及健康探测策略。
- [x] 池条目支持启用、停止新分配、健康状态和安全错误原因；个人配置不进入池。
- [x] 同 UID 多配置共用容量和账号级速率额度，各配置独立保管及验证凭据。
- [x] 定义会话分配记录：服务/用户/设备/媒体/会话标识、配置 ID、UID、凭据版本、目录、分配代次、状态和过期时间。
- [x] 定义下载和手动秒传任务记录及生命周期，避免把它们假装成持续播放。
- [x] 配置、必要的租约恢复信息和冷却截止时间按职责持久化；Cookie、原始 token、直链及签名不得进入这些记录。
- [x] 最近使用账号只是短期偏好，可过期；不得重新形成固定绑定。
- [x] 明确开发数据备份/重建流程，只处理相关测试数据，不顺带清除个人网盘与其他业务数据。
- [x] 统一前后端错误码、字段和可见范围，普通用户不获得池内敏感资料。

**自查与阶段验收：** 数据库失败后不发布内存成功状态；重复提交幂等；不能把字段缺失误认为主网盘；旧请求不能写入固定账号绑定。

## 5. P2：结构化故障与健康状态

依赖：P1。调度重试必须依赖错误类型，不能匹配中文报错文本。

- [x] 补齐统一的结构化错误分类及来源/目标归属矩阵；已有认证、目录、429、网络/5xx、权限和不确定写入处理，不将当前状态机误写成已覆盖全部 115 业务限制码。
- [x] 修复当前部分网盘核验路径将底层错误统一转换成“登录或目录不可用”的问题：保留内部错误类别，对用户仍给安全文案。
- [x] 区分故障发生于源账号、候选目标、校验来源还是 Emby；源账号失败不能归罪于目标池账号。
- [x] 定义 `unknown / ready / cooldown / invalid_credentials / invalid_directory / draining / disabled` 等状态及转换条件。
- [x] Cookie 失效隔离具体凭据配置；明确属于 UID 的限流/封控作用于该 UID，不能误伤独立凭据或借同 UID 配置规避限制。
- [x] 探测核验 UID、凭据和目录，成功不等同于永久授权；每次实际请求继续实时核验。
- [x] 健康探测有独立低优先级预算、退避与抖动，不因页面轮询重复探测。
- [x] 半开恢复只允许有限探测；失效凭据更新后重新检查，旧结果不能覆盖新版本。
- [x] 维护下线停止新分配；凭据清空、删除或身份变化立即禁止使用旧快照签发新直链。
- [x] 提供手动重新检查入口，限制重复点击和探测风暴。

**自查与阶段验收：** 使用可控上游模拟每种错误；取消请求不降低账号健康；文件不存在不隔离整个账号；临时超时不被持久标为 Cookie 失效。

## 6. P3：会话识别、租约和容量预占

依赖：P1、P2。此阶段先验证准确计数，再接自动换号。

- [x] 从经过认证的 Emby 响应/会话信息建立用户与设备关系，不信任客户端自报 `UserId`。
- [x] 播放会话 ID 与服务、用户、设备、媒体源共同约束，不能凭可猜的会话 ID 复用他人分配。
- [x] 通过协议测试覆盖 PlaySessionId、登录设备关联、开始/进度/Ping/停止事件及字段缺失：缺会话 ID 仅唯一匹配，歧义忽略；熔断缺可信设备拒绝并提示重新登录，并行保守独立计数。不要求真实播放器报文采集。
- [x] 按已认证会话区分正式生命周期，同会话重复取链合并；同设备多个会话可共享一个 UID 逻辑名额。不能据此识别真实视频连接，也不保证区分客户端复用同一身份的多个窗口。
- [x] 实现 `reserved → active → released/expired`，为准备中、活跃和孤立会话定义有限存活时间。
- [x] 在同一临界区检查 UID 容量并预占，网络 I/O 在锁外执行。
- [x] 失败、取消、超时释放未激活预占；释放幂等，重复停止不减成负数。
- [x] 会话续租需有认证及精确关联，错误令牌、歧义和迟到旧代次不能续租；合法客户端自报进度不构成不可伪造的观看证明。
- [x] 302 返回后不能马上释放播放名额；已离开反代的 CDN 流量不能直接观测，应明确租约估算误差。
- [x] 服务重启后从非敏感租约元数据恢复保守占用，结合 Emby 会话进行校对；不能简单归零后立即超发。
- [x] 无法读取 Emby 会话时采用有界保守恢复，避免同时出现无限占坑或放开所有容量。
- [x] 租约、历史偏好和过期索引有数量上限及清理机制。
- [x] 单活动实例限制落实到部署和运行约束；未来多实例必须另做共享协调，不能共用 SQLite 就宣称支持。

**自查与阶段验收：** 并发竞争最后一个名额、重复申请/释放、取消、漏报停止、伪造会话、同 UID 多配置、服务重启均覆盖；运行竞争检测，不出现超发、死锁和 goroutine 泄漏。

## 7. P4：调度器和有界自动切换

依赖：P2、P3。

- [x] 候选过滤排除主账号、个人网盘、禁用、排空、错误目录、冷却及容量已满条目。
- [x] 相同 UID 的多个配置不作为多个独立容量节点；一次失败切换避免反复尝试同 UID。
- [x] 已有有效会话复用租约；不因其他账号更空闲主动迁移正在播放的会话。
- [x] 新会话按负载选择，同负载依次参考本地可信副本、用户近期偏好与分配代次轮换。
- [x] 副本信息未知时正常调度；禁止为了排序逐账号调用 115 搜索。
- [x] 选择与预占在同一原子操作内完成，同分候选稳定打散，防止第一个账号成为热点。
- [x] 切换通过受控状态机更新租约代次，旧尝试结果不能覆盖新尝试。
- [x] 每次尝试固定配置 ID、UID、凭据版本、目录和目标文件；尝试之间允许新选择。
- [x] 账号认证失败、可分类目标故障按策略切换；Emby 拒绝、源文件错误和请求取消不切换。
- [x] 115 限流遵守冷却与 Retry-After，不通过无限轮询账号扩大请求；可能的全局限流启用全局退避。
- [x] 未确认写入保留原目标意图，本次不盲目跨账号继续写；后续请求有独立的重复写保护。
- [x] 准备失败释放未签发预占。并行策略已签发换号保留最多两分钟残余；熔断策略优先借用原健康 UID 名额，成功时事务释放旧播放占用，失败保留旧设备；跨 UID 新目标需空位。逻辑容量不代表 CDN 并发。
- [x] 并发取链只允许一个请求执行会话换号，其他请求复用新代次或明确失败。
- [x] 池空、全忙、全失效和全冷却分别返回可理解错误，重试等待可取消且有上限。
- [x] 候选次数、单次尝试预算与总预算以统一 deadline 管理，嵌套组件不得重置预算。

**自查与阶段验收：** A 失效后切至 B；A/B 均失效停止；不回主盘；没有权限时不接触池；同 UID 不绕限；旧 A 请求晚返回时不能发出旧结果。

## 8. P5：接入鉴权、缓存、预热、下载和手动秒传

依赖：P4。此阶段是主链路改造，不得仅替换首次分配函数。

- [x] 将媒体授权拆分为用户/条目授权与所选目标核验，目标动态选择不影响 Emby 的授权结果。
- [x] 调整 `MediaAuthorization.CheckCurrent / MatchesSelection / Revalidate`，检查当前来源、租约代次和目标版本。
- [x] 取链返回前再次检查来源切换、撤销、账号删除和凭据版本，保持慢请求的 Emby 权限复核。
- [x] 改造 `PlaybackCacheSnapshot.Select` 和 `SelectionMatches`，共享池不再依赖静态用户绑定表。
- [x] 直链缓存必须在鉴权、租约选择及目标实时核验后访问；缓存命中不能跳过容量预占。
- [x] 缓存键包含用户/媒体/UA、实际目标 UID、配置与凭据版本、目录及必要的租约代次；换号后旧缓存不能命中。
- [x] 校验进行中的请求合并作用域，避免不同租约或目标共用错误结果。
- [x] 保留秒传资料与 UID 文件副本分离、可信 SHA1、来源冷却和事务成功后更新索引。
- [x] 分布式校验只使用已授权且已记录的来源；来源切换不得改变播放目标。
- [x] 采用跳过动态池预热的最终策略，正式取链独立鉴权，避免预热造成双重占用和双重上传。
- [x] 无可靠会话关联的预热跳过池写入或采取明确的短期保守策略，不能大规模预占播放容量。
- [x] 前台优先于预热和健康探测，用户浏览媒体库不触发池文件写入。
- [x] 下载仍要求 Emby 下载权限与全局入口同时允许；不依赖播放开关。
- [x] 下载使用独立的有界取链配额/租约规则；明确无法精确知道 CDN 下载结束，不能把任务名额当带宽保证。
- [x] 手动秒传继续选择目标用户：池用户在任务启动时动态选择一次，记录实际目标，不要求预先绑定小号。
- [x] 手动长任务运行中固定目标；写入开始后不自动转移目标，结果不明不自动重试。
- [x] 副本清理按 UID + 文件归属处理，不把用户换号视为可删除旧副本的依据；避免删除活跃租约正在使用的文件。
- [x] 覆盖分享 STRM、pickcode、外部 SHA1、原文件下载及已有支持的其他入口，禁止遗留路径直接默认主盘。

**自查与阶段验收：** 冷启动、缓存命中、目标文件丢失重建、预热竞争、换号、权限撤销、下载、手动秒传端到端测试通过；正常缓存命中不引入全池扫描。

## 9. P6：统一 API 限速与排队
