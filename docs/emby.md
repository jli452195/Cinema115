# Emby 入库索引

从右上角管理菜单进入「Emby」（`/emby`），点击「媒体库同步」卡片进入 `/emby/library`。在此填写服务器地址和 Emby 控制台创建的 API Key，点击「测试连接并读取媒体库」。首次读取不默认勾选任何媒体库，请手动选择需要同步的媒体库后保存。重新读取时保留仍存在的已选媒体库，不根据名称自动添加；实际同步范围使用媒体库 ID，媒体库名称可以自定义。升级不会清空已经保存的选择。

点击「开始全量同步」。后台按唯一条目 ID 排序，每页读取 200 条电影、剧集与分集，只索引匹配字段，不逐集请求详情。大型动漫库按名称排序会出现相邻页重复条目，已改用 ID 排序并保留重复检测。离开页面不会中断；整个快照完成后才切换当前索引。失败或重启中断时保留已有索引，页面提示后手动重新同步。更换服务器或同步范围后需要重新全量同步。没有定时全量扫描，仅每五分钟检查一次服务器连接。

## 后续通过 Webhook 更新

保存配置后复制页面生成的 Webhook 地址，填入 Emby 通知配置。使用 Emby 能访问的 Cinema115 地址：NAS 单容器部署使用 NAS 映射端口，Windows 开发使用后端 3002，不能使用仅本机可达的 localhost。复制地址中含独立密钥，不使用管理员 JWT 或 Emby API Key。

「Emby 能访问的 Cinema115 地址」可通过区域内的「保存地址」或右上角「保存配置」保存到服务器，刷新页面、换浏览器和后端重启均会恢复。单独保存地址无需连接 Emby，不会更改现有媒体库索引或 Webhook 密钥。电脑开发时可填写 `http://192.168.0.24:3002`；局域网浏览页面使用 `http://192.168.0.24:5173`。Vite 开发服务监听 `0.0.0.0:5173`，页面中的 `/api` 由 Vite 代理到后端。

- 请求方式 POST，类型 `application/json; charset=utf-8`。
- 启用媒体库「已添加新媒体」「媒体已移除」，关闭按剧集分组；有媒体更新事件时可同时启用。
- 点击测试，Cinema115 中应出现 `system.webhooktest` 或 `system.notificationtest` 和最近通知时间；两种测试事件都不会修改索引。Emby 4.9.5.0 的通知测试入口已实际收到 `system.notificationtest`。
- 再用一次实际添加或移除媒体验证。已按 `library.new` / `library.deleted` 及常见新增、修改、删除别名接入，读取 `Item.Id` 或 `ItemId`，并校验 `Server.Id`。已实际收到 Emby 4.9.5.0 的 `library.new`，包括《二十世纪电气目录》（TMDB 153217）的第 11 集；删除事件仍需真实环境验证。未知事件或缺少条目 ID 会显示诊断信息，不能视作索引已更新。

通知先写 SQLite，约十秒后消费。相同条目待处理通知合并；处理时重新向 Emby 读取条目与所属媒体库，范围外的条目不会加入。尚未完成刮削的条目最多尝试六次，间隔逐步增加；失败后显示原因，可手动全量同步修复。完整同步期间收到的通知保留并在快照切换后处理，重启也会恢复待处理队列。

媒体库归属通过 `ParentId=所选媒体库 ID`、`Ids=条目 ID` 与 `Recursive=true` 向 Emby 精确查询。聚合媒体库的父目录链只有物理目录，不能仅用 Ancestors 判断是否属于勾选的库。缺少 TMDB ID 或季集号的条目单独统计为刮削补查，已匹配的其他影视正常显示；仍有无法识别条目时，未匹配结果暂不判定为缺失。需在 Emby 补全对应元数据才能完成识别。

Webhook 不是 Emby 的完整变更日志。Cinema115 停机期间 Emby 若未重发通知，或刮削变化没有触发已配置事件，索引可能过时。这种情况下手动全量同步；不通过定时全库扫描补偿。连接失败、通知积压或已知处理失败时，前端将结果标为待更新，不据此判断媒体缺失。

## 页面与持久化

从 `/emby` 的「缺集检测」进入 `/emby/missing`。按季只检查第 1 集至该季已入库的最大集号：例如已入库 1、2、3、4、6、7、8，仅显示缺第 5 集；只入库第 4 集时显示缺第 1-3 集。最后入库集号以后的集数、整季未入库和特别篇不参与检测，不读取总集数或播出日期。

检测复用当前服务、当前已选媒体库的完整入库索引，同一 TMDB 剧集跨媒体库和版本合并去重，多集合并文件按有效集号范围计算；没有 TMDB ID 的剧集按各自 Emby 剧集 ID 独立检测，不按同名合并。页面提供剧名/TMDB ID 搜索和分页，使用紧凑的横向卡片展示海报、缺集总数和两行以内的缺号摘要，点击「缺集明细」在弹窗中查看全部季和集号，保持列表卡片高度稳定。

海报优先复用本地 TMDB 详情缓存中的地址，以 w185 小图显示；没有地址时，使用索引中已有的 Emby 剧集 ID，直接取最大 160×240、质量 75 的 WebP 缩略图，不查询 Emby/TMDB 详情。卡片接近可见范围时才下载，一份已解码的 Blob 同时供海报和光影背景使用。翻页时保留当前卡片，仅准备新页可见区域及附近 100px 内的小图，随后整体切换，最多等待 1.5 秒，慢图继续共用原请求，不阻塞检测文字；不预取尚未翻到的页。页面内保留最多 48 张近期缩略图，当前卡片使用中的图片不回收，其余按最近使用顺序淘汰；换页后返回可复用已解码图片，离开检测页或更换登录令牌时取消请求并释放全部 Blob。Emby 图片经管理员接口鉴权，API Key 仅用于后端请求头；按当前服务及媒体库范围独立缓存到 `data/emby-images`，容量 200 MiB，上游最多两路并行，同图并发合并，磁盘图片七天后按需后台复核、九十天保留期，浏览器私有缓存一天。Emby 明确返回无图时缓存一小时，前端无图记录保留五分钟；Emby 也没有海报时显示占位图标，不自动增加 TMDB 查询。

页面顶部采用与追更管理一致的滑动分段导航，搜索明确提交，统计和同步时间紧凑展示。点击「刷新」仅重新读取本地索引，不触发 Emby 全库扫描或自动补资源。未建立当前范围索引时引导全量同步；已有索引在后台同步、连接异常或通知积压时仍可查看。资料补查及缺少分集归属/季集号统一放在中性的资料状态入口中，点击浮层查看条目数与影响，不追加网络请求或推挤卡片，各项计数可能重叠而不相加；同步失败、连接异常和真实入库通知失败仍直接提示，不把未关联 TMDB 视为整个检测失败。刷新失败保留上次结果。

增量通知在缺少 TMDB 编号等资料时，仍将已完整读取的本地条目与资料补查重试在同一事务中保存；没有 TMDB 的剧集和新增分集不必等补查成功才更新缺集结果。补查仍保留有界重试，缺少必要分集信息的条目不参与缺集计算；网络或分页失败不提交部分读取结果。未关联 TMDB 不代表 TMDB 未收录或已删除，不增加 TMDB 查询，也不自动排除媒体。

误刮削或幽灵条目可从「缺集明细」点击「从缺集检测移除」。同一个弹窗先列出待排除的标题、原 TMDB 绑定、实际 Emby Series ID、来源媒体库 ID 和已入库正式分集记录数，确认后只排除本地缺集检测及其统计；缺集数是计算结果，不代表要删除的文件数。卡片若合并了多个来源，会明确列出全部来源并一起排除，不按同名或 TMDB 编号全局排除。不调用 Emby 删除接口、不删除任何 Emby、115 或 STRM 文件，不自动验证 TMDB 是否已删除。

排除记录独立保存在 SQLite，按 Emby 服务（地址与 Server ID）、具体 Series ID 和当时 TMDB 绑定生效，重启、全量同步、增量通知或调整所选媒体库不会清掉手动决定。在 Emby 修正 TMDB 编号并更新本地索引后，新绑定正常参与检测。提交时重新核对预览范围及来源证据，条目或范围变化会拒绝陈旧确认。顶部「已排除 N 项」展示当前服务的全部排除来源记录（含当前未选媒体库），支持剧名/TMDB 搜索、分页和逐项「恢复检测」，恢复仅撤销对应排除记录，是否显示缺集由当前索引决定。

媒体库页面右上角「查看日志」进入 `/logs?module=Emby&level=ALL`，自动筛选 Emby 的全部日志等级。记录连接测试、配置保存、全量同步排队及真实执行结果、Webhook 接收与索引应用、刮削重试及最终失败、连接异常和恢复。同一次全量同步共用 `EMBY-...` 编号；通知接收、处理及重试通过 `EMBY-EVENT-通知编号` 关联。通知入队不代表索引已更新，测试通知也不修改索引。

分页进度至多每十秒汇总一次并记为 DEBUG，不逐文件记录；正常状态轮询不产生日志。连续连接异常只记录首次，恢复时再记录一次；Webhook 鉴权失败每分钟最多提醒一次。日志不记录 API Key、Webhook 密钥、完整通知正文或带凭据地址。所有模块共享本次后端运行期间最近 2000 条内存日志，重启清空，不影响数据库中已有同步状态与通知队列。

看板和推荐卡片批量查询本地索引，不逐张访问 Emby。电影和剧集分别按 TMDB ID 匹配；分集使用剧集 TMDB ID 与季、集编号，跨版本去重，并支持一个文件包含连续多集。详情页季标题显示总集数、已入库数量和分段进度条，展开后列出合并区间的缺失集数。只比较 TMDB 播出日期不晚于浏览器当地今天的分集，未播出和日期待定的分集不计入分母、缺集或媒体版本查询；TMDB 只有日期，无法精确到当日播出时刻。进度条蓝色表示已入库，灰色表示已播出但缺失；连续同色合并为一个节点。对于整季没有可靠播出日期的情况，折叠季卡改按 TMDB 集号范围显示：只把已入库范围内部的断档标为缺集，首集之前和最后一集之后保持待确认，不把尾部未入库误报为缺集。悬停显示缺集、整季已入库或已追平最新播出。TMDB 未收录但 Emby 已入库的集号单独标为额外入库，不扩展本季总集数。未播完但已播分集齐全只表示追平，不表示完结。索引未知或待更新时不判断缺集。

进入剧集详情时，通过 `GET /api/admin/tmdb/tv/:id/schedules` 一次读取整部剧已有的 SQLite 播出缓存，接口不等待 TMDB。缺少的季在滚动至附近时通过 `/schedule/:number` 补充，过期数据先展示再后台更新；失败时保留旧数据并提示。点击「刷新播出信息」可立即重新查询 TMDB，替换改期、删集后的播出表。完整分集简介只在展开季后通过 `/season/:number` 读取，每次显示二十集，可继续加载更多。TMDB 请求最多四个并发，Emby 媒体参数独立保留两个名额。

后端启动后按批次为当前勾选媒体库内已入库剧集预热 TMDB 季目录与播出表，成功数据跨重启复用；预热网络请求每次至少间隔一秒，全局最多四个请求，不触发 Emby 全库扫描。近期播出或日期待定的季缓存一小时，全部分集已播超过三十天的季缓存七天。目录每六小时重新验证，新增媒体对应的新剧集随后进入预热范围。缺集仍在前端计算，每分钟重新检查当地日期；详情页可见时每三十秒读取本地 Emby 索引，因此 Webhook 入库或删除后页面自动跟进，隐藏页面暂停轮询。

电影的媒体版本直接展示在详情页，默认展开第一个版本。剧集的媒体版本位于季风琴内各集的简介下方，默认折叠，滚动至附近才加载；前端同时最多发出两个媒体版本请求。收起季列表会保留本页已加载的版本，切换影视后清空。点击版本标题可展开视频与音频参数，多个音轨可通过下拉菜单切换。一个 Emby 条目的多个媒体源分别展示为不同版本。每页读取 20 个 Emby 条目，更多版本可继续加载；剧集先精确筛选季集号再分页，不会将其他集混入。STRM 的分辨率、编码、大小是否可用取决于 Emby 的探测结果，未提供的字段显示为「—」。

索引、同步状态和通知队列保存在 `data/cinema115.db`；API Key 和 Webhook 密钥随配置加密保存在 `data/emby-config.enc`，不写入 `.env`，不在配置接口回显 API Key。加密依赖原有 `JWT_SECRET`，备份与迁移时保留它和 `data` 数据卷。现有 Docker 的数据卷已经覆盖这些文件，无需增加数据库容器或额外端口。运行中数据库备份使用项目的 dbtool，不能只复制 WAL 模式下的主 DB 文件。
