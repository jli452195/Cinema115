# 网站邀请码注册

管理员进入「用户管理 → 注册邀请」，可一次生成 1–20 个邀请码，有效期可选 1、7、30 天，默认 7 天。每个邀请码只允许注册一个普通网站用户。邀请列表分页显示备注、创建人、时间、状态和使用者；未使用的邀请码可以撤销。已注册账号由原用户管理功能停用或重置密码。

生成后可复制邀请码或 `/register#invite=...` 链接。链接默认使用当前浏览器的站点地址，管理员可以指定可供接收者访问的 HTTP(S) 站点地址；该地址仅保存在管理员浏览器，不用于后端网络请求。完整邀请码只在创建响应中返回，离开邀请面板后不再显示，丢失时撤销并重新生成。

注册页读取 URL fragment 自动填码，随后清除地址栏 fragment，仅在组件内存中保留邀请码。打开链接和检查邀请码不消耗注册资格。用户填写用户名、密码和确认密码后提交；成功返回登录页面并预填用户名，不保存密码、不自动创建 Emby 用户或绑定 115 账号。

后端使用 128 位安全随机数生成邀请码（32 个十六进制字符，按 8 位分组），另生成随机记录编号。SQLite `website_invites` 表仅保存 SHA-256 摘要及管理信息，摘要唯一；碰撞时整批回滚并重试。注册先检查邀请码以减少无效请求的密码计算，然后复用 Argon2id 密码哈希。在单个事务内有条件核销邀请码、插入普通用户并记录使用者；过期、撤销、已使用的邀请不能核销，用户名冲突等错误回滚整个事务。并发使用同一码只能一次成功。密码计算不占用数据库事务。

公开接口为 `POST /api/auth/invite/check` 与 `POST /api/auth/register`，共用单实例每分钟 30 次的固定窗口限制，与登录限流独立；请求体限制 4096 字节、请求超时 15 秒，沿用密码计算并发限制。所有响应禁止缓存，不把邀请码放在 API URL 或日志中。管理员接口为 `GET/POST /api/admin/invites`、`POST /api/admin/invites/:id/revoke`，使用现有管理员鉴权。接口忽略前端角色，注册账号固定普通用户。

验证：`go test ./internal/storage ./internal/httpapi -run 'TestWebsiteInvit'`；启动前端开发服务后执行 `node scripts/website-invites-ui.cjs`。浏览器验证使用模拟 API，不创建真实用户。
