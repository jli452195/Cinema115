# 播放设备策略：实现与模拟灰度

## 使用方式

管理端「Emby 反代」页面新增独立「播放设备策略」表单。策略为可扩展枚举，不是播放权限开关：

- `parallel`：多设备并行，默认值，保留原有行为。
- `heartbeat_takeover`：单设备心跳熔断，默认静默 60 秒，可设 30 至 180 秒；已保存的合法配置保留。

管理员 GET/POST `/api/admin/member-playback/device-policy` 读取或保存 `{ "mode": "heartbeat_takeover", "silenceSeconds": 90 }`。策略与播放租约一起保存在 SQLite 用户播放文档中，重启保留。此设置独立于原文件下载开关、邀请模板和 Emby 权限；不改写 Emby 用户策略。

## 完成清单

- [x] 默认保持多设备并行，使用枚举供未来新增策略。
- [x] 服务端校验枚举与 30 至 180 秒范围，只有管理员可读写。
- [x] 按 Emby 服务、用户和成功登录得到的可信设备播放器关联准入；身份缺失时熔断策略拒绝并提示重新登录，不猜测补绑。
- [x] 在选取账号、访问 115 和返回缓存直链之前执行准入；涵盖池、主网盘、个人网盘和个人共享来源。
- [x] 登录、浏览、授权下载和手动任务不创建设备播放占用。
- [x] 有效心跳持续时拒绝其他设备；暂停上报同样保留占用。
- [x] 无心跳时，初次签发给予静默窗口；刷新 URL 和同设备预加载不能反复延长初始窗口。
- [x] 同设备继续复用池名额，保留正式会话、首播与有界预加载候选的原有规则。
- [x] 其他设备静默后，先准备新请求，提交前再次核验；准备失败、取消、心跳恢复、数据库失败均不退休旧设备。
- [x] 并发准备保留一个设备的准入资格；原设备可继续刷新并报告心跳，网络操作不持有用户互斥锁。
- [x] 新授权与旧会话退休事务提交；旧代次停止、进度和在途请求不能影响新设备。
- [x] 退休事件标识保留 24 小时，防止旧播放地址重新取链；旧设备新建播放会话仍按当前策略竞争。
- [x] 熔断模式优先继承健康 UID，准备阶段借用原名额（包括可信设备正常停止后的名额），同 UID 满额时仍可转交。提交时删除退休会话池记录与可识别的旧播放残余；跨 UID 新目标仍需可用容量，失败保留旧设备。主网盘/个人来源接替旧池播放也事务释放旧池占用。多设备并行保留原残余策略。
- [x] 支持认证且唯一匹配的 `/Sessions/Playing/Ping`，仅 Emby 返回成功才更新已有租约；缺标识、歧义、错误令牌和拒绝响应不续租。
- [x] 策略改变时使旧策略的在途授权失效，需重试；不主动终止已签发播放，也不清空历史租约。
- [x] 成功接替记录不含凭据的诊断日志，冲突返回 `USER_DEVICE_CONFLICT`，缺设备返回 `PLAYBACK_DEVICE_REQUIRED`。

## 已验证场景

采用临时 SQLite、模拟时钟与 Emby/115 测试服务，不使用真实账号，不清理运行数据。

| 场景 | 预期与结果 |
| --- | --- |
| 89 秒、90 秒边界 | 前者拒绝，后者允许准备 |
| 准备期间旧设备恢复心跳 | 新设备提交失败，旧设备保留 |
| 32 台设备并发首次请求 | 只有一台取得准备资格 |
| 新设备取链失败、取消、新 UID 满额 | 原设备保留，无准备租约泄漏；原健康 UID 满额可借用转交 |
| 一个 UID、容量 1，跨设备连续接替 100 次 | 有/无正常停止两组均保持准备与提交计数 1；成功后残余 0 |
| 跨 UID 故障切换 | 成功后旧 UID 占用 0、新 UID 占用 1；不占用或删除下载名额 |
| 借用来源在准备期间到期 | 准备名额自动独立计数，提交再次核验容量，不能超配 |
| 原设备在挑战者准备时刷新 | 不被网络锁阻塞，不删除挑战者准备；无心跳刷新不能无限占位 |
| 数据库池表写入失败 | 用户文档与池文档均不部分发布 |
| 新设备接替后旧进度/停止/在途签发 | 不续租、不释放、不继续签发 |
| 主网盘、个人、个人共享 | 均遵守设备准入和接替规则 |
| 不同用户或不同 Emby 服务 | 不互相阻塞 |
| 同设备连续 20 次刷新与预加载 | 初始保护不顺延，池会话记录保持有界 |
| 重启 | 策略、占用及退休隔离保留 |
| HTTP 第二设备连续 20 次 GET/HEAD | 409，无 Location，不触发 115 探测或取链 |
| HTTP 缓存刷新、合法 Ping | 同设备允许；只有精确且成功的 Ping 续租 |
| HTTP 持久证据模拟超时后接替 | 新设备 302，旧 URL 409，旧设备新会话在新设备活跃时仍 409 |
| 切回多设备并行 | 两台设备新请求可播放，已退休旧会话仍需新建会话 |
| 非管理员、未知策略、越界阈值 | 拒绝配置修改 |

验证命令（backend 目录）：

```text
go test ./internal/service ./internal/httpapi ./internal/storage ./internal/client/emby -count=1 -timeout=180s
go test ./internal/service ./internal/httpapi -run 'TestDevicePolicy|TestPoolProtocolNegotiationRedirectAndStop|TestUserPlaybackAdminReleaseRoutes' -count=20 -timeout=180s
go vet ./internal/service ./internal/httpapi ./internal/storage ./internal/client/emby
go build ./...
```

前端：`npm run build`。四包回归、20 轮模拟灰度、vet、后端和前端构建均通过。

容量转交修改后重新运行四包完整回归、20 轮 `TestDevicePolicy|TestPoolProtocol` 模拟灰度、vet 和前后端构建，均通过。模拟灰度包含两组各 100 次单 UID 满额跨设备接替（正常停止、心跳超时），重复 20 轮合计 4,000 次接替。

Linux 临时容器内补齐 GCC/musl，启用 `CGO_ENABLED=1`，运行 `go test -race ./internal/service ./internal/httpapi ./internal/storage -count=1 -timeout=240s`：三个包的完整测试均通过，无数据竞争报告（服务约 202 秒、HTTP 约 69 秒、存储约 27 秒）。测试容器退出后自动删除，代码和主机模块缓存只读挂载。前端构建保留现有的大分包体积提示，不影响构建成功。

## 使用边界与验证范围

默认 60 秒是本项目的设备接替策略，不是 Emby 官方离线秒数。上表 89/90 秒验证使用显式保存的 90 秒配置；新默认、边界与剩余待办验证见 [本轮记录](pool-policy-followup-validation.md)。5 分钟失联租约继续兜底，设备静默超时只允许新设备尝试接替，不主动清空旧设备。

同 UID 接替优先借用旧名额，不需要额外空位；若旧 UID 不健康而必须换号，新 UID 仍需有可用容量。成功提交后，旧设备会话和可识别的播放残余不再计费；只有旧地址的拒绝标记保留。缺设备信息的记录不猜测转交，不影响下载、手动秒传或其他用户。此策略接受旧 CDN 链接继续使用，容量只代表逻辑授权，可能低估真实视频连接；上游限流与故障处理仍保留。设备标识不是硬件证明。

从并行切到熔断时，若已有多个设备持续上报，不自动选择赢家或踢人；后续取链按策略拒绝冲突，正常停止其他设备或等待静默后收敛。切回并行不复活已退休的播放会话，重新发起播放即可。

按用户要求，当前环境不安排真实 Yamby 等客户端验收，不将其作为未完成任务。设备关联、心跳、切集预加载、强退超时、停止及旧事件使用上述模拟协议验证；测试结论不覆盖具体客户端版本的心跳频率、后台行为和错误提示。直连 Emby 或其他绕过反代的入口不受本策略控制。

本次未启动或替换运行服务，也未将已保存的设备策略切到熔断。
