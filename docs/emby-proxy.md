# Emby 302 反代

## 正常播放协商与正式取链去重

客户端首次 PlaybackInfo 请求按原有 `IsPlayback`、`AutoOpenLiveStream` 参数直接转发给 Emby，不再先发送免探测请求；未提供的参数保持省略，明确的 true/false 保持不变。反代保留用户凭据、设备能力和媒体源选择，只强制 `EnableTranscoding=false`。Emby 可以按正常播放协商探测原始来源，补齐时长、分辨率和音视频轨道。响应保留会话、媒体源、字幕等已有信息，并对支持的分享、`/api/redirect115/` 或 `/play115/` 原文件直放来源改写播放入口；禁转码及禁重新封装仍强制执行。普通媒体及 Emby 的拒绝响应不被绕过，也不重复发送一次协商请求。

正式取链继续优先从实时条目权限查询中取得媒体源，跳过重复 PlaybackInfo。只有内部回退查询使用 `IsPlayback=false`、`AutoOpenLiveStream=false`，避免再次启动播放。

`/api/redirect115/pickcode/SHA1/文件名` 中的 SHA1 优先匹配本地唯一且已验证的秒传资料。没有本地资料、来源关联及目标副本记录时，先在固定目标账号按 SHA1 查询，命中后核验目标文件身份，使用目标返回的大小、名称建立资料并直接复用，跳过主账号查询和秒传。明确未命中才查询主账号，并复用本次查询结果；查询失败不触发写入。同 SHA1 多大小、已知来源冲突和未确认副本继续按原流程核验。后续用户可复用资料，但文件副本、凭据和保存目录仍按目标账号隔离；不会因外部 SHA1 或文件名直接建立可信来源关联。二次校验仍需已验证的可读来源，片段哈希仅在 115 接受秒传后保存。

管理菜单 → Emby → **Emby 302 反代**（`/emby/proxy`）。该功能复用已有的 Cinema115 分享 STRM，不改写文件，也不参与生成。Emby 客户端改为连接反代入口，仍使用原 Emby 用户登录。

## 分享 STRM 格式

Cinema115 生成 `/api/share115/{分享码}/{SHA1}/{提取码}/{文件ID}`，例如 `/api/share115/sws8jb636j9/3C57FCFD33B9476B43C6BCED7D20B5887EFB2A4E/fwgl/3532903049309717944`。提取码必须非空，不接受 `-` 占位。SHA1 必须是 40 位十六进制，解析统一大写；文件 ID 保留为字符串并校验正 uint64。拒绝查询参数、编码分隔符和额外路径。GET、HEAD、Emby 反代、本地 STRM 映射、下载与手动秒传共用新格式。兼容已有 `/api/?share_code=...&id=...&receive_code=...`，三个参数各出现一次，顺序不限；忽略额外参数（包括 SHA1），拒绝空提取码、重复参数、无效编码或越界 ID。新旧格式共用分享文件身份及缓存隔离，旧文件无需改写，生成仍只输出新格式。

路径 SHA1 是外部提示，不建立可信来源关联或直接写入秒传资料；分享取链仍按分享码、提取码和文件 ID 核验，秒传保留上游元数据核验。

## 配置

1. 填写 Emby 原服务器地址，例如 `http://192.168.0.3:8096`。不要填反代地址。容器内 `localhost` 指向 Cinema115 自身。
2. 设置独立监听端口，默认 `8097`，可选 `1024～65535`，不能与管理服务的 `HTTP_PORT` 使用相同端口。保存成功后立即生效；端口占用或保存失败时保留原配置和监听。
3. 在 115 助手配置主账号。302 源文件统一由主账号读取；按 Emby 权限及用户来源取链；共享池按会话选号和有界故障切换，个人来源失效拒绝新取链。两者均不因故障回退主网盘，每次尝试固定凭据。
4. 按 STRM 分享格式识别，不限制 HTTP/HTTPS 地址的来源主机和端口，例如 `.24:3002` 与 `.3:8115` 可以混用。`/api/` 路径必须包含 `share_code`、`id`、`receive_code` 各一次，允许额外参数（忽略，不转发、不写入日志、不影响直链缓存键）；分享码为 1～128 位字母数字，文件 ID 为无前导零的正十进制 uint64，提取码为 0～32 位字母数字（可显式为空）。必要参数缺失、重复、格式不符或查询编码无效仍拒绝。旧签名 STRM 格式及 `/api/stream/share/...` 播放入口已废除，旧链接需重新生成普通参数格式；现有普通 STRM 无需修改。不会访问 STRM URL，只解析参数并调用固定的 115 接口；其他工具的不兼容路径和参数格式不会自动适配。
5. 如果 Emby 返回本地 `.strm` 文件路径，填写 Emby 中对应 Cinema115 `STRM_ROOT` 的目录前缀。例如同一媒体目录分别挂载为 Emby 的 `/media` 和 Cinema115 的 `/strm`，填写 `/media`。相对目录必须一致；只允许读取根目录内的普通 STRM 文件。Emby 已返回 HTTP 源地址时不需要映射。
6. 启用并保存。客户端连接 `http://NAS_IP:8097`；如果有 HTTPS 网关，按实际外部地址连接。

配置加密保存到 `DATA_DIR/emby-proxy.enc`，重启恢复。监听失败不会影响管理页面，可修正端口后重新保存。关闭功能即使账号已删除也可操作。端口切换会让旧连接在短暂退出窗口后断开，播放器需要重新连接。

来源严格模式及来源地址配置已移除。旧配置中的 `strictStrmOrigin` 和 `strmBaseUrl` 会被忽略，下次保存时去除；即使以前开启严格模式，也不再限制来源主机或端口。本地文件映射、根目录越界与符号链接校验仍然生效。

也支持其他工具的路径形式：`http://NAS:9527/s/{分享码}_{提取码}_{文件ID}`，扩展名可省略，例如 `/s/abc_pass_123` 与 `/s/abc_pass_123.mp4` 等价。空提取码（如 `/s/abc__123`）直接拒绝；可选扩展名为 1～16 位字母数字，只允许单个扩展名。问号后的内容作为可选文件名提示整体忽略，不用于覆盖路径里的分享参数，例如 `/s/abc_pass_123.mp4?/电影.mp4`。路径必须完整匹配，不接受额外路径段、文件 ID 尾随字母或编码后的分隔符。仍校验 HTTP/HTTPS 地址、分享参数格式和文件 ID 范围。不访问原工具地址；反代播放、本地 STRM 文件和单文件秒传共用此解析规则，两种链接形式归一化后复用同一文件的直链缓存。

## 网盘 pickcode STRM

支持 TgtoDrive 等工具的 `http://NAS:端口/play115/{pickcode}/{文件ID}/{SHA1}/{字节大小}/{文件名}`。完整提取五个字段：文件 ID 保留为字符串以避免大整数精度损失，SHA1 统一大写，大小为正的 int64，文件名按 URL 路径解码一次。五段均必填；文件 ID 须为正的 uint64，大小溢出、编码分隔符、控制字符、空文件名、额外路径和查询参数均拒绝。此格式自动接入原文件播放和下载中的按需文件准备流程，也支持通过已配置的目录映射读取本地 STRM。客户端须连接 Cinema115 的 Emby 反代端口；正式取链无需访问原工具，首次 Emby 协商探测仍可能依赖原工具。

play115 的 SHA1、大小和文件名直接作为本次秒传声明，优先复用本地目标副本，再查询目标账号；未命中时跳过主账号元数据读取直接准备秒传。既有来源关联不覆盖声明；相同 SHA1 不同大小按声明大小选择资料。只有 115 要求校验片段且无已接受片段或合格副本时，才按 PickCode 读取主账号，同时核对声明的文件 ID、SHA1 和大小。成功取链核验或秒传成功并核验目标后才持久保存资料，不建立外部 PickCode 的可信来源关联。文件名、大小与文件 ID 纳入相关缓存键；参数格式、路径分隔符检查仍执行。

支持其他工具生成的 `http://NAS:端口/api/redirect115/{pickcode}`，也支持 `{pickcode}/{文件名}`、`{pickcode}/{SHA1}` 和 `{pickcode}/{SHA1}/{文件名}`；文件名可省略或 URL 编码。路径中的 SHA1 必须是 40 位十六进制（不区分大小写）。已绑定用户优先用该 SHA1 匹配本地唯一且已验证的文件资料，命中后使用资料中的真实大小、文件名和校验片段，跳过主账号元数据查询；不把外部文件名作为可信元数据。无本地资料及冲突时可先查询目标网盘，命中且核验通过后跳过主账号；目标明确未命中再查询主账号。优先查询最多等待 5 秒，超时、限流及凭据错误直接失败。同 SHA1 对应多个大小、或与已有来源关联冲突时回到主账号查询核验。外部 SHA1 本身不会建立可信的 PickCode→文件来源关联。主机、端口和协议只用于识别数据，不会被反代访问。pickcode 必须是 6～64 位字母数字，查询参数、非法文件名和上述格式之外的额外路径会被拒绝。

上述两种格式的末尾文件名兼容未编码的 `#`（如 `标题 #1.mp4`），按文件名字符保留，与 `%23` 编码等价。只兼容已确定的文件名位置，pickcode、SHA1 等身份字段中的 `#` 仍拒绝；文件名仍只解码一次，拒绝目录分隔符、控制字符及无效编码。此兼容不增加网络请求，也不改变首次 PlaybackInfo 协商和正式取链去重。

使用个人网盘或共享池的用户在本次选定目标中查找相同 SHA1，命中后取链，否则由主账号读取资料并秒传到目标目录。共享池故障可在预算内切换其他 UID；个人来源不换号，均不因秒传失败回退主账号直链。未特别指定来源的已有用户仍使用主网盘。

正式 `/cinema115/play` 取链会优先复用当前用户条目权限查询（`GET /Users/{Id}/Items/{Id}?Fields=MediaSources`）返回的、与 `MediaSourceId` 唯一匹配的静态 STRM 媒体源，避免再次调用 Emby `PlaybackInfo`。这只减少反代内部的重复读取，不改变客户端已经收到的完整 PlaybackInfo。缺少媒体源、来源不明确、需要打开的动态流、存在 OpenToken/LiveStreamId 或不支持原文件直放时，保留原 PlaybackInfo 查询流程；因此不会把动态媒体错误当成静态 STRM。每次取链仍重新检查用户和条目权限，不能使用旧媒体源或旧直链绕过权限。

首次完整 PlaybackInfo 由 Emby 正常生成，可能访问 STRM 原工具以探测文件；原工具 Cookie 失效或响应缓慢时，首次协商仍可能被拖慢。Cinema115 正式取链直接解析 STRM，不访问原工具。本方案保留媒体信息探测机会，不承诺首次协商脱离旧工具，也不会自动恢复此前已清零的续播位置或已观看标记。

分享参数 STRM 仍优先尝试朋友账号直接读取分享；朋友账号不可读时才用源账号读取元数据并秒传。两种形式共用直链缓存和用户权限校验；缓存默认 9 分钟，失败不缓存，账号凭据始终固定在本次请求开始时。

## 手机客户端下载

支持 `GET/HEAD /Items/{Id}/Download` 及带 `/emby` 前缀的入口，兼容 Yamby 查询参数中的 `X-Emby-Token`。下载单独核验真实登录身份、`EnableContentDownloading` 和条目访问权限；条目明确禁止下载或为文件夹时拒绝，下载权限缺失时也拒绝。多媒体源须明确选择 `MediaSourceId`，不能猜测版本。每次请求包括缓存命中均重新检查权限。

分享 STRM 沿用用户的当前来源和会话目标、分享直取和受限后秒传规则；pickcode STRM 沿用上述源账号读取、朋友账号秒传规则。使用下载器实际 UA，UA 不同时缓存隔离；相同用户、媒体源、账号和 UA 可复用播放建立的直链，但不能绕过下载权限。未支持的源仍交回 Emby 原下载接口。日志显示「下载取链结果」及 `/Items/{Id}/Download`，调试详情记录实际返回的 CDN 地址。

成功后返回无正文的 HTTP 302；文件名、文件大小、Range 和断点续传的最终行为由客户端与 CDN 决定。本项目不接收整段视频，也无法确认文件是否下载完成。长时间下载期间 CDN 地址失效，需要客户端重新请求下载入口取链。

## NAS / Docker 网络

项目 `compose.yaml` 使用 host 网络，不需要端口映射。管理服务通过 Compose 的 `environment.HTTP_PORT` 配置，compose 默认 `8115`；Emby 反代端口在网页修改并立即生效。两者不能使用相同端口，并需避免 NAS 端口冲突、放行防火墙。

如果自行切换为 bridge 网络，需删除 `network_mode: host` 并显式映射端口。例如管理服务的 `HTTP_PORT=8115`、网页反代监听 `8098`：

```yaml
ports:
  - "8115:8115"
  - "8098:8098"
```

然后执行 `docker compose up -d --build`，或在 NAS 容器管理界面添加对应 TCP 映射并重建容器。网页保存不能修改 Docker 的网络配置。也可使用不同宿主机端口，例如 `18097:8097`，此时网页保持 `8097`、客户端使用 `18097`。

上述映射仅适用于 bridge 网络。host 部署不要添加 `ports:`，管理服务修改 `HTTP_PORT` 后重建容器；反代端口通过网页修改，无需重建容器。

## 播放行为和范围

缓存管理独立页面为 **/emby/cache**，从 Emby 分类页的「缓存管理」卡片或反代设置页右上角进入。直链缓存时长在反代设置页修改并保存。页面与缓存管理接口均仅允许网站管理员访问；接口为 `GET /api/admin/emby/proxy/direct-links`，`DELETE` 同路径清空，`DELETE /api/admin/emby/proxy/direct-links/{id}` 移除单条。

直链缓存默认 **9 分钟**，设置页可调整为 0～30 分钟，0 表示关闭；旧配置缺少该字段时自动采用 9 分钟，已明确保存为 0 的配置保持关闭。缓存从成功取链时开始计时，命中不顺延。每次仍校验 Emby 用户、条目、实际媒体源和 STRM；缓存仅省略重复的 115 取链/秒传解析。缓存以 Emby 服务和用户、媒体源、分享参数、本次目标账号、租约代次及凭据版本、目录和播放器 UA 隔离，键为摘要。相同条件下并发请求合并取链，失败结果不缓存；发起请求被取消时本次合并请求可能失败，下次播放重新取链。

分享取链统一使用 `GET https://proapi.115.com/os_windows/2.0/share/downurl`，显式传入 `dl=0`，携带本次明确选定账号的 Cookie 和播放器 UA。旧 `/app/share/downurl` 接口实测会自动接收文件，即使传入 `dl=0` 也会发生，因此已停止使用，失败时也不回退旧接口。新接口在真实朋友账号中已验证取链和 CDN Range 读取成功，未出现对应文件或接收记录；115 上游行为仍可能变化。朋友分享受限时才进入源账号辅助秒传分支，源文件元数据取链也使用新接口。

程序不再清理网盘文件，历史接收文件及秒传文件均由用户在 115 中手动删除。直链缓存清空也不会删除网盘文件。

「直链缓存管理」展示全部/分享直取/秒传播放数量、用户、媒体源、取链账号、CDN 域名、建链时间、到期时间、剩余秒数和命中次数，可搜索、单条移除或清空。管理员可展开和复制完整 CDN 直链（包含签名）、首次建链的播放器请求头与取链 UA，点击建链请求编号查看日志。缓存命中不会更新建链请求头。Cookie、Emby Token 等登录凭据不返回。该缓存仅保存在内存，最多 512 条；过期记录在读取、查询或新取链时移除，保存反代配置和重启后清空。清空/移除只影响临时地址，不删除朋友网盘文件，也不能撤回已经发给播放器的地址。清空后旧的进行中请求不再写回缓存。

秒传目标直链命中时检查对应本地文件缓存记录仍为可用并刷新最后取链时间；本地记录已移除或状态异常则丢弃该直链并提示重新解析。直链命中不向 115 重新查询文件，外部删除文件或 CDN 提前失效时可能仍命中旧地址，可在面板移除后重试。9 分钟是本服务的复用时间，不改变也不保证 115 的有效期；302 后无法观察客户端 CDN 失败并自动刷新。命中日志显示「直链缓存命中」，播放结果注明命中与否。

设置页提供「反代调试日志」，默认关闭，保存后对新请求生效，随反代配置保存并在重启后恢复。每个 HTTP 请求结束后合并为一条记录，播放结果或错误显示为摘要，展开查看解析步骤。开启调试后额外记录方法、固定路径模板、路由、状态、耗时、客户端请求头、反代响应头和实际返回的完整 CDN Location，缓存命中也记录。正常图片、会话进度和普通透传每 30 秒在后续请求到达时汇总次数；不足一个窗口暂不输出，没有后台计时线程。异常单独保留，不合并不同用户的播放请求。

完整 CDN 地址只通过管理员日志与缓存接口提供，保留签名原文，不受日志摘要 1,000 字限制。UA、Range、Accept、响应 Content-Type 等常用诊断头可见；Cookie、Authorization、Emby Token、未知头的值隐藏，Referer/Origin 仅保留协议和主机，不记录请求正文或入站查询凭据。单个头值上限 2 KiB、头集合上限 16 KiB，超出明确标记截断。日志步骤上限 64 条 / 16 KiB。播放器直接请求 CDN 的真实请求头不可由反代观察；展示的 115 取链 UA 用于复现，不表示本次缓存命中重新请求了 115。WebSocket 的结束日志在连接关闭后出现。Yamby 开启「播放 STRM 文件内的原始路径」会绕过改写入口，调试开关无法观察绕过本服务的流量。

Emby 4.10 不支持 `/Users/Me`，可能将 `Me` 当作用户 GUID 并返回 HTTP 500。现在通过反代观察 Emby 成功的 `POST /Users/AuthenticateByName` 或 `POST /Users/{Id}/Authenticate` 响应，记录令牌摘要与真实用户 ID 的关联。首次使用或升级后，已有播放器须通过 **反代地址退出并重新登录一次**；直接向原 Emby 登录、仅粘贴旧令牌、使用无用户身份的管理 API Key 或仅使用 Emby Connect 交换令牌不能建立此关联，会返回 HTTP 401 并提示重新登录。

身份摘要按 Emby 服务器地址隔离，加密保存在 `emby-playback-identities.enc`，不保存登录密码或原始令牌，最多保留 4096 条，记录有效期 180 天；正常重启或更换反代监听端口会保留。每次播放仍使用播放器原始令牌请求 `/Users/{真实ID}`、用户条目权限和 PlaybackInfo，核验用户 ID 一致、未停用且允许播放。撤销令牌、禁止播放或条目无权访问时，不会进入 115 秒传。客户端的 UserId、DeviceId、SessionId 以及会话列表均不作为身份依据。身份记录失效或被清理后需重新登录。

上游失败日志包含固定接口类别和实际 HTTP 状态，例如“用户权限查询 GET /Users/{Id}失败：上游 HTTP 500”；不会输出请求地址、令牌或上游错误正文。日志中的外层 HTTP 502 表示代理查询失败，上游具体状态以该诊断为准。

转发诊断会记录请求类别及耗时，不记录原始 URL。图片请求因客户端断开、取消加载或反代停止而取消时不记录日志，避免浏览海报时刷屏；播放等其他请求取消仍记录为 DEBUG。上游操作取消但客户端请求仍有效记录为 WARNING。真正的上游超时保留 ERROR（HTTP 504），连接或响应失败保留 ERROR（HTTP 502），包括图片服务的真实故障。旧版的「Emby 转发失败：请求已取消」没有这些上下文，不能据此认定 115 直链失效。

在「实时日志」模块下拉框选择 **Emby 302** 查看播放日志；反代设置页右上角「查看日志」会进入 `/logs?module=Emby%20302&level=ALL`，自动筛选该模块及全部等级。与其他模块共用最近 2,000 条内存日志，重启清空；选择「全部」也能看到 302 日志。每两秒刷新，支持暂停、等级筛选和关键词搜索。记录配置生效、PlaybackInfo 检查、未改写原因、权限校验、媒体源选择、STRM 解析、115 取链耗时与结果、CDN 域名和 302 响应；同一次请求以 `302-...` 编号关联。统一接口 `/api/admin/logs` 仅允许管理员读取，不记录 Cookie、Emby Token、提取码、源地址或带签名的完整直链。302 发出之后的 CDN 下载发生在客户端，本服务无法据此判断播放成功。

- 普通请求（登录、海报、字幕、播放进度、WebSocket）反代到 Emby。客户端正常上报播放进度，视频流量不经过 Cinema115。
- 对 Emby 判断可直接播放的匹配分享源，改写 PlaybackInfo 中的播放入口。播放时使用客户端 Emby 凭据校验用户状态、播放权限、条目可见性和实际媒体源；不使用管理员 API Key 代替用户授权。也支持原客户端的 `Videos/:id/stream.*?Static=true` 请求。
- 按实际 MediaSourceId 选择版本，不通过标题或 TMDB ID 猜测。多版本缺少源编号时返回错误，不选第一个。
- 使用所选账号、播放器 User-Agent 获取 115 临时直链并返回 302，`GET` 和 `HEAD` 均支持；按配置短期复用直链，不转发 115 Cookie 给播放器。管理员缓存页可查看完整 CDN 地址，开启调试后日志详情也记录实际返回地址。
- 非匹配来源走原 Emby 链路。转码与封装转换已禁用：播放协商强制关闭 EnableTranscoding，移除转码入口，拒绝动态流和 HLS/DASH 请求。无兼容原文件直放源时返回 NoCompatibleStream，请更换播放器。共享池仅对可分类的目标故障有界换号，源文件错误、取消及不确定写入不会触发换号，不静默转发视频。
- 一套反代配置对应一个 Emby 服务，统一由主账号读取源文件，共享池按用户稳定沿用成功分配的小号 UID。

自动测试使用模拟 Emby / 115 验证协议和边界，并不证明真实 115 对所有客户端的 UA、IP、CORS 或临时链接限制兼容。上线后需用实际客户端验证开播、拖动、暂停续播、字幕及转码拦截：匹配直放请求应返回 302，客户端随后访问 115 CDN；转码请求应被拒绝，不能启动 Emby 转码。

## 单文件秒传验证

在 Emby 302 页面下方的「单文件秒传验证」选择动态共享池用户并保存。源账号固定为主账号，任务启动时自动选择池小号及其已验证目录，记录实际目标。运行期间保持原快照，写入开始后不换号重发；管理端不提供个人网盘写入目标。

打开一个现有 `.strm` 文件，粘贴其中的完整播放地址，点击「开始单文件秒传」。与 302 播放复用相同的新旧分享格式及参数检查，新路径不允许查询参数，旧查询格式允许并忽略额外参数，不比较来源地址。不访问粘贴的服务地址，也不读取本地路径。

源取链接口保留文件名和大小；新接口缺少 SHA1 时，仅秒传分支通过同一源账号的 `/share/search` 查询同一分享，最多检查 1,000 个结果。搜索名称只是筛选条件，必须核对完整文件 ID、名称、大小和 40 位 SHA1；无法匹配则停止，不根据同名文件猜测，不回退旧取链接口。普通分享直放不执行这次元数据查询。使用目标账号调用 115 上传初始化，如要求二次校验，则以相同 User-Agent 从源直链读取指定字节范围并计算 SHA1，再提交校验。CDN 请求不携带账号 Cookie。严格检查 HTTP 206、Content-Range 和字节数；片段上限 8 MB，不接受整文件响应。`status=2` 且有目标文件 ID 或 PickCode 才表示成功；`status=1` 表示需要普通上传并停止，不调用 OSS 上传。

验证开始时固定账号凭据、目录和来源设置。并发验证会被拒绝；相同请求编号在最近记录内不会重复提交写操作。接口超时、响应无法确认或服务重启中断时记录「结果待确认」，不自动重试写请求，请先核查目标目录。修改样本或重新保存配置后会生成新的请求编号，因此这不是长期文件缓存去重。

配置和最近 20 条验证记录保存在数据目录的 `instant-upload.enc`。记录保存账号编号、文件元数据、状态及目标文件标识，不保存 Cookie、分享提取码、源地址或签名直链。过程日志进入统一的 **Emby 302** 模块。该记录用于诊断，不是播放缓存清理清单，当前不会自动删除验证文件。

管理接口（均要求管理员认证）：`GET/POST /api/admin/emby/instant-upload` 读取或保存配置，保存时提交 `{ "userId": "目标 Emby 用户 ID" }`；`POST /api/admin/emby/instant-upload/run` 提交 `{ "id": "唯一请求编号", "strm": "STRM 内容" }`。后端核验用户状态及共享池来源，启动时选择目标小号和目录。HTTP 200 时仍需检查结果中的 `status`。

本地实测：一个 7,576,026,635 字节的视频跨账号秒传成功，耗时约 2.09 秒，真实二次校验读取了 188,677 字节；随后查询目标目录，文件大小、SHA1 和 PickCode 均一致。该结果证明此样本的秒传链路可用，不代表所有文件、账号和网络环境均能成功。

## 朋友账号播放与缓存

实际取链成功、准备返回 302 时会写入一条「播放取链结果」日志：显示经 Emby 校验的用户名与用户 ID、条目、实际选中的媒体源、播放方式和取链账号名称/UID/配置编号。播放方式区分「朋友分享直取」「新建秒传文件」「复用同 SHA1 文件」「源账号分享直取」；本次实际读取源文件信息时额外显示源读取账号。账号名称与凭据在请求开始时一起固定。结果日志不记录 Cookie 或直链，也不代表客户端已经开播；播放信息阶段的「入口已改写」不产生该结果日志。

「Emby 用户管理」（`/users/list`）设置主网盘、动态共享池或个人来源。共享池由服务端持久记录用户成功分配的 UID，健康时保持，确认故障后才有界切换；新目标成功提交后更新分配。媒体库和播放权限继续在 Emby 管理。

个人账号播放总开关已移除。用户身份以 Emby 服务 ID + 用户 ID 为准，未指定来源的已有用户默认使用主网盘，个人邀请需完成网盘绑定。正式取链用播放器自身凭据核验用户、条目及媒体源权限。

秒传目录在 115 助手的小号卡片中设置，根目录须明确填写 `0`。多个会话使用同一小号时共用其目录。换 UID 必须先验证新凭据及目录，成功后事务切换，旧目录和副本不转移。每次播放固定账号和目录，网盘文件由用户手动管理。

「缓存管理」（`/emby/cache`）展示临时直链缓存与网盘文件复用记录，可仅移除本地记录。网盘自动清理已停用，旧清理接口返回 410；旧配置中的清理开关不会生效。临时直链缓存的过期规则不变。

调度键包含 Emby 服务、真实用户、令牌摘要、播放会话、条目及媒体源。不信任客户端 UserId；原始 token 不进入池持久化。同一会话目标稳定，变更凭据、目录、停用或删除账号后旧结果不能直接签发。

未命中短期直链缓存时，先用本次固定的朋友 Cookie 和实际播放器 UA 请求分享直链。成功且直链不要求额外 Cookie 时直接返回 302，不要求文件 SHA1、不读取源账号、不创建网盘缓存。已有秒传文件缓存也不会跳过这一步；分享恢复可读且短期直链到期后可直接播放，旧网盘文件保留，由用户手动管理。

当分享取链接口明确提示违规、审核、仅本人可读、访问权限不足或文件不可见/不存在时，进入秒传资料流程：先查询同一分享文件的本地资料，未命中才用本次固定的主账号读取元数据。不会因朋友看到“文件不存在”就直接判断源文件已删除。共享池目标登录或目录失效可有界切换；网络故障或 HTTP 5xx 首次短冷却复核原 UID，连续第二轮失败才允许切换；限流遵守冷却，HTTP 429 全局退避。提取码错误、未知接口错误、源文件故障或不确定写入均停止。个人来源仍直接返回错误。分类只依据接口明确错误信息，不猜测未知数字错误码。直链要求额外 Cookie 或返回域名无效也停止；302 之后的客户端 CDN 失败无法自动触发备用流程。

首次目标查询调用 115 的 `/files/shasearch?sha1=...`，以完整 SHA1 在朋友账号整个网盘中查找。该接口返回单个候选，未提供 SHA1。正式播放用同一目标凭据和播放器 UA 直接取候选直链，通过下载响应的文件 ID（对象键）、pickcode、SHA1 和大小完成核验；字段完整时不另查元数据。仅 SHA1 缺失时补查精确元数据，身份或大小冲突直接停止。候选在下载核验成功前不得写成 ready 副本。仅 HTTP 200 且 JSON 恰好包含 `{"state":false,"error":"文件错误"}` 两个字段时按约定视为未命中，不再追加普通搜索；登录失效、限流、网络错误、未知或缺字段响应均停止。命中但身份或大小冲突时也停止。未命中才秒传，直接写入该账号明确配置的保存目录（根目录需明确填写 0），不创建额外缓存子目录。

上传凭据内存缓存 5 分钟，保存目录身份缓存 10 分钟，按账号配置与 Cookie 隔离。已验证的 pickcode → 朋友文件映射按源账号、源 Cookie、目标账号配置/凭据/目录隔离，以哈希指纹随加密文件记录持久保存；重启后命中也可跳过源解析与搜索。同一目标账号的有效 SHA1 文件映射可复用。正常取链不增加存在性检查；同一请求按目标文件 ID 去重，避免不同映射重复取链。凭据配置变化须用新凭据重新核验。源解析或目标取链失败不会回退返回源账号直链，不向播放器发送账号 Cookie。

绑定网盘的正式分享 STRM 播放在直链缓存未命中时，直接用本次固定的目标凭据读取分享，不先查询登录状态或保存目录；成功直取通常只需一次 115 请求。仅明确分享不可读、即将进入秒传处理时，再通过实时目录请求同时核验凭据与保存目录，失败不读取源资料、不写入文件。直链缓存命中（包括等待其他请求合并取链）仍做实时凭据与目录检查；PickCode、主网盘及下载保持原检查流程。成功目录核验可供同请求后续秒传预检复用，不以目录缓存替代播放授权。

动态池仍先做容量预占、排除已知失效/冷却账号并固定目标；分享成功不刷新完整目录健康记录及后台探测时间，也不能覆盖更新的目录故障。尚未发现的目录故障不阻断本次无需写入的分享直取，故障恢复时须完成真实目录核验。前台故障遵循[动态播放池](dynamic-playback-pool.md)的原 UID 恢复与有界切换规则，分享密码等文件错误不触发秒传；提交前仍复核用户、账号配置与会话代次。调试计时将“STRM 读取解析”与“播放授权及账号准备”分开，实际执行目录检查时记录“115 登录与目录合并核验”。独立文件准备的成功回执阶段标为“目标文件元数据核验”，不表示已经获取播放直链。

目标下载接口发生文件相关拒绝时，先用同一目标凭据普通搜索当前 UID 的 SHA1；完整未命中可进入重建，不必逐个核查历史副本。搜索仍返回已失败的文件 ID 时才绕过元数据缓存调用 `/files/get_info`，不重复取链。登录、限流、网络和无效直链错误不启动恢复。HTTP 200、`state=false`、无冲突的业务码 20018，或成功响应中与请求文件 ID 严格一致且 `aid=120`（永久删除），可确认文件不存在；登录和限流优先识别，HTTP 404、空成功响应、普通“文件错误”和未知错误不作为删除证据。该约定来自 p115client 文档、不存在 ID 及清空回收站后文件的只读实测。精确元数据兼容 `fid/pc/sha/s/cid/n` 与完整字段名，字段冲突、未知区域或文件 ID 不一致均停止；本地产生的字段校验错误保留具体原因，不再泛化为网络错误；如果精确接口仍报告文件存在，不强行重新秒传。错误日志保留固定接口路径、数字业务码或 HTTP 状态及本地分类，不输出上游原文或 Cookie。

确认文件不存在后，事务删除该 UID + 文件 ID 的 ready 副本及其来源映射，使关联直链缓存不能再通过记录核验，并清理该文件的元数据缓存；保留可信秒传资料、片段、其他 UID 副本和未确认上传意图。随后普通 SHA1 搜索排除本请求刚确认失效的 ID；只有完整搜索未找到其他候选才允许重建。同一次恢复最多核查 3 个候选，共用 5 秒只读预算（包含后续搜索、候选取链和目录刷新；提前完成即返回）。重新秒传前核验原保存目录，允许复用同配置、同凭据、同目录最近 30 秒内的真实核验；命中不续期，超时重新请求 115。核验失败清除旧缓存，上传失败立即清除目录和上传凭据缓存，不改存根目录。首次恢复及进程重启后没有可复用核验时仍需查询；日志分别记录请求数、排队限速及 HTTP 耗时。每次播放请求最多重新秒传一次，沿用目标 UID 串行和未确认写入冷却。未知、网络、登录、限流或下载受限错误停止上传，重复取链失败短暂退避 5 秒。正常已命中路径不支付恢复查询成本。

直链缓存命中后若对应本地副本已不存在，本次请求清除该链接并重新解析一次；数据库错误不启动此恢复。反代已经返回 302 后播放器与 CDN 之间的错误不可直接感知，未发现的远端删除仍可能受现有直链缓存有效期影响，不增加每次播放的远端轮询。

同一进程内查找和秒传串行，等待请求会复查文件，避免重复写入。上传前持久保存操作意图；预检失败且尚未提交上传时允许重试。写入结果不明时，下次先搜索 SHA1：找到即可恢复复用；未找到且 30 秒冷却结束后允许再次秒传。冷却期限持久保存，重试不会延长，旧版无期限的历史记录不阻塞重试。搜索接口失败仍停止，不把错误视为未命中。历史记录的 SHA1、编号、状态及原因汇总在当前请求日志中。115 搜索索引若尚未更新，再次秒传可能产生重复文件。核查网盘后可以移除本地记录。当前仅支持单进程，不应让多个实例共享同一记录文件。

PlaybackInfo 仅协商媒体源与改写播放入口，不触发 115 取链或秒传。正式播放、下载分别鉴权，通过准入后按需准备文件与获取直链。相同 UA 复用未过期直链，不同 UA 通过文件映射重新取链；缓存时间为 0 时，同时到达的相同请求仍合并，完成后不保存链接。

秒传结果未确认后的 SHA1 未命中复用最多 3 秒，查询失败退避 5 秒；按目标账号、凭据版本、目录及文件隔离，错误绝不作为未命中触发上传。成功文件映射优先于退避，上传的 30 秒冷却期限不因查询延长。

开启「反代调试日志」并保存后，播放诊断从 HTTP 请求进入反代开始计时，日志步骤带 `[+N ms]` 相对时间。入口分段区分配置快照、Emby 用户权限、条目权限、媒体源确定、STRM 读取、账号检查、直链缓存等待及 115 取链、缓存核验与响应；Emby 请求另记取得连接、首字节和总耗时。关闭开关后不输出步骤时间轴、入口分段、秒传链路分段及 HTTP 连接计时，不安装这些 HTTP 追踪回调；常规播放结果、错误和解析总耗时仍保留。不同 HTTP 请求不混算；这些时间无法覆盖点击播放后请求尚未到达反代的客户端等待，也不包含返回 302 后的 CDN 下载与解码。

秒传提交失败时，播放错误和文件记录保留第几次提交、HTTP 状态、115 数字返回码或响应解密/解压/解析失败阶段，不再统一隐藏为“秒传未确认”。LZ4 失败同时记录密文/解密后长度、分块位置、声明长度与剩余长度，不输出原始响应或凭据。仅上传响应在已完整解出 JSON 时允许协议末尾的 1～2 字节，截断或损坏的实际压缩块仍拒绝。

提交后响应无法确认（例如解压失败或连接中断）时，仅本次提交请求在最多 3 秒查询窗口内，分别等待 250 ms、750 ms 后补查目标账号 SHA1，最多两次；命中后核验 SHA1 和文件标识并恢复取链，不重放上传。查询失败即停止，明确 HTTP 错误和取消请求不启动这轮补查。确认期间仍持有缓存操作锁，因此其他网盘缓存操作最多会多等待这段查询窗口，正常成功路径不增加查询。仍未确认及后续冷却请求返回 HTTP 503、Retry-After 和 WARNING 日志；冷却期限不因读取延长。播放器是否按 Retry-After 自动重试取决于客户端。旧日志缺少分块信息时，不能据此确定原始解压失败的根因。

网盘文件完全由用户手动删除；程序没有定时清理任务，也不提供删除网盘文件的清理入口。历史缓存子目录保留。直链缓存清空和文件记录移除都不会删除云端内容；手动删除后的旧直链可能在本地缓存过期前仍被返回，可在缓存页面移除直链后重试。

播放配置、最多 100,000 条账号副本记录和 100,000 条文件资料保存在 cinema115.db 的独立 SQLite 表中。文件资料、来源索引、校验片段和账号副本分别存储，沿用 WAL 和同步事务；不保存 Cookie、分享提取码、STRM 地址或签名直链。启动时建立内存 Map，按资料编号、来源哈希、SHA1、副本编号和来源映射定位，无需在播放路径复制或扫描整库。播放只更新变动的资料/副本行，上传意图、成功结果立即提交；仅最后使用时间变化时，每条副本最多每 30 秒持久化一次，异常退出可能丢失这段时间内的使用时间，不丢失已提交的文件状态。首次启用数据库存储会在单个事务内导入原 playback-cache.enc，原文件保留为备份，后续不再读取其记录或向其中写入。

管理接口包括 GET /api/admin/emby/playback-cache、GET /users、GET /users/{userID}/avatar、POST /bindings/{userID}、POST /bindings、POST /forget、POST /forget-material（提交 id）；旧 POST /policy 和 POST /cleanup 返回 410。移除资料不会删除副本记录，移除副本记录不会删除资料，均不会删除云端文件。账号保存目录使用 PUT /api/admin/p115/accounts/{accountID}/playback-directory，包含 revision 和 parentCid。以上接口均须管理员认证。


真实样本的朋友缓存首次秒传加取链约 2.65 秒，真实二次校验读取 107,849 字节；第二次缓存复用加取链约 0.49 秒。两次目标账号直链均在不携带 Cookie 的情况下成功返回 Range 206。完整 302 路由的权限、GET/HEAD、缓存复用与失效账号行为通过模拟 Emby/115 测试；实际播放器开播与拖动仍需在对应用户客户端确认。

### 播放秒传请求优化

首次解析文件后，如果既没有已保存的校验片段、也没有已知账号副本，会在目标账号 SHA1 查询前启动请求内的源直链预取，与目标查询、上传预检和首次提交重叠。预取只获取直链，不提前读取视频字节；收到有效二次校验范围后才发送 Range 请求。资料/片段/副本命中时继续按需读取，不增加这类预取请求。目标查询命中时可能多一次源直链查询，但不会提交秒传；查询失败、请求取消或秒传结束时，均取消并等待预取任务退出。预取失败不会影响不需要校验的成功秒传。所有凭据使用本次请求快照，预取直链不持久保存。独立调用秒传客户端时仍在上传预检通过后启动预取。

115 请求使用独立共享连接池，每主机最多保留 8 条空闲连接、总计 128 条，空闲连接保留 3 分钟，支持 HTTP/2 和容量为 64 的内存 TLS 会话缓存。连接关闭后再次访问相同服务时，可在上游支持的情况下恢复 TLS 会话，日志显示「TLS会话=恢复」；首次访问新 CDN 主机仍需建连。连接池不保存 Cookie 或账号选择，保留系统代理与证书校验。片段读取仍严格验证 206、Content-Range 和长度，并读取至正常 EOF 以允许连接复用。

日志新增「秒传分段计时」，分别显示源直链预取耗时、校验阶段等待直链的剩余耗时、秒传 POST 和片段 CDN 的 DNS/TCP/TLS/请求开始至首字节耗时、连接复用状态，以及片段读取和 SHA1 计算耗时。预取与提交耗时存在重叠，SHA1 计算包含在片段读取时间内，不能把这些数值直接相加。HTTP 首字节从该请求开始计时，可能包含连接建立和重定向；DNS/TCP/TLS 为观测到的阶段累计时间。日志不包含请求 URL、Cookie、签名或原始上游错误。首次取链实际改善取决于源取链耗时与网络延迟，不保证固定加速幅度。

文件资料按完整 SHA1 + 文件大小独立归档，保存文件名、元数据验证时间、来源哈希索引，以及已验证的二次校验字节范围和片段 SHA1。资料跨目标账号复用；pickcode 来源索引绑定主账号配置编号，分享来源索引包含分享编号、提取码和文件编号的哈希。主账号 Cookie 更新不清空文件资料，更换主账号配置不会把其 pickcode 解释成旧账号文件。每份资料最多保留 64 个来源索引及 64 个校验片段，超出时移除最旧项。

有资料时跳过主账号元数据查询，先在绑定账号查找文件；确认未命中后，使用资料发起秒传。115 要求二次校验时，先复用完全相同字节范围的已验证 SHA1；缺失时，按 UID 最近调度时间轮换，尝试最多 3 个已记录的共享小号或个人网盘来源，全部尝试共用 4 秒预算（到时立即结束，不保证尝试满 3 个），再尝试本次固定的主账号来源。副本以实际 UID + 文件 ID 归属，配置编号只提供当前独立凭据；读取前核对 UID、文件 ID、SHA1 和大小，相同 UID 重建配置可经重新验证复用。只有 status=2 明确成功后才保存新片段哈希；签名、上传密钥、Cookie、片段内容和临时 URL 均不保存。已有资料及片段可以在主账号暂不可用时支持新目标秒传，但新校验范围缺少可读来源时仍会停止并保留资料。

共享小号和已完成绑定的个人网盘凭据在播放请求开始时一并固定，仅作为只读校验来源；每次尝试固定写入和取链目标；动态池仅在旧尝试结束后按故障类型有界选择其他 UID，写入结果不明不换号重试。源文件身份变化、账号失效和资料移除均不会触发整文件上传。该流程通过模拟协议和跨账号测试验证，未假定 115 会始终使用相同的二次校验范围。

尚无可信资料时，pickcode 来源通过 /files/supervision 读取文件信息，元数据按明确的源账号配置、Cookie 与 pickcode 缓存 10 分钟。已有可信资料但二次校验区间未命中时，主账号来源及已知副本改用一次取链响应同时核验文件 ID、SHA1 和大小，省去先查 supervision 的请求；仅当取链响应缺少 SHA1 时补一次精确文件查询，字段冲突或无效则停止。临时源直链及凭据只在本次请求内使用，不写入文件映射记录。片段日志区分区间命中与未命中，只有 115 明确接受秒传后才保存新片段；不同区间即使长度相同也不能复用。恢复保存目录仅复用最近 30 秒内的真实核验，耗时与账号上传预检分别记录，不将删除文件等同于目录有效。

上传返回 status=2 后，即使只有 pickcode，也直接取目标账号直链；缺少 SHA1 才通过 /files/get_info 精确查询回执对应文件，文件内容只比较 SHA1。只有 fileID 的回执先精确查询 pickcode。此阶段不再依赖整个网盘搜索索引。失败日志区分目标取链、精确查询、文件身份和 SHA1 校验，并记录回执 fileID/pickcode，不输出 Cookie 或上游原始错误正文。

播放元数据请求采用独立于后台扫描的凭据隔离队列，保留请求间隔及 405/429 退避；共享 HTTP 连接池。SHA1 专用查询及命中元数据核验共用最多 5 秒预算，提前完成即返回，超时停止本次秒传。目标存在同 SHA1 的未确认上传记录时仍使用 `/files/search`，提交结果不明后的只读补查也保持普通搜索；不使用专用接口的“文件错误”解除写入冷却。普通搜索先接受有效的精确匹配，不因不准确的 count 拒绝已命中的文件；没有匹配而分页结果异常时仍停止。

首次 STRM 自带有效 SHA1、未匹配本地可信资料且目标无该 SHA1 副本记录时，可将专用查询与源元数据核验并行。外部 SHA1 仅用于只读提前查询；必须等待源文件核验，实际 SHA1 一致才采用命中或未命中结果，不一致则取消并等待提前查询退出，再按实际 SHA1 查询。源核验失败、请求取消或处理结束时同样回收任务。所有查询固定本次目标凭据；提前查询不建立可信来源关联、不切换写入账号、不提交秒传。可信资料和文件映射命中时不增加这类提前查询。

“文件错误”作为未命中是基于 p115client 文档和当前实测的接口约定，并非 115 提供的独立 not-found 错误码。若上游后续将其他故障返回为完全相同的响应，可能重复秒传；其他响应变化一律停止。专用接口的延迟仍受上游影响，不能保证固定耗时。


分布式校验只读取已记录播放副本的必要范围，不扫描个人网盘。个人来源即使切换到主盘或小号池播放仍可参与；停用、解绑、清空凭据或未完成目录绑定的个人配置不进入新请求。管理员只看到个人/已移除账号副本总数，无法读取个人 UID、目录、文件标识或 Cookie。用户扫码前明确告知校验用途。

同一目标 UID 的请求串行，不同 UID 最多 4 路并行；来源 UID 独立限流，忙碌来源直接跳过以免交叉等待。失败暂时冷却，不把失败当作文件不存在。未知错误短暂退避；可识别的凭据错误及限流使用较长冷却。资料与片段在事务中合并，管理端移除记录等待活动操作结束，避免记录被进行中的请求重新写回。后台健康检查优先让出前台等待请求，并保留有界恢复机会。运行计数仅统计本次启动，主盘读取包括元数据及片段请求，不等同于实际 HTTP 请求数。

播放鉴权错误分类：请求上下文已取消时记录 HTTP 499 和调试信息，不判定绑定失效；Emby 身份查询超时返回 504，连接或响应故障返回 502。只有真实用户权限、绑定状态或请求期间来源绑定变化才拒绝为 403。查询失败不修改用户绑定，后续请求仍重新校验。

SHA1 搜索诊断在反代调试开启时记录每次 HTTP 的 DNS、TCP、TLS、首字节、连接复用耗时，并汇总实际请求数、已请求分页数、实际重试数、排队及限速等待、HTTP 总耗时。等待中取消不计为已发请求或分页；失败仍返回错误，不能作为未命中提交秒传。搜索耗时包含这些子阶段，汇总和明细不能重复相加。

收到二次校验挑战时，会重新读取内存中的已持久保存片段资料。如果其他目标用户在本请求等待 SHA1 搜索期间完成相同范围的秒传校验，直接复用 115 已接受的片段 SHA1，不再读取来源。不复用尚未提交成功的临时片段，不增加额外网盘查询。现有目标文件映射继续优先命中；未命中时执行上述目标 SHA1 查询策略，未增加目录探测或将超时视为文件不存在。

副本归属与目标查询使用 UID + SHA1 索引（命中仍核对大小），配置编号不作为副本占用或查找条件。按最近使用排序，最多优先尝试一个本地副本，失败后查询网盘当前状态；不沿历史副本逐份请求。每次使用当前请求固定凭据，正式取链同时核验身份，因此同 UID 更换配置可复用副本但不能复制凭据。配置编号仅保留作权限可见性来源和操作配置；个人网盘与已移除配置记录仍受管理端可见性限制。界面仅以 UID 筛选，不加载账号列表、不显示配置名称，运行统计折叠。

本轮优先减少请求：没有新增恢复时的源直链投机预取，也没有缩短 115 限速间隔；校验范围命中仍不读主网盘。正常本地副本正式播放通常一次下载请求；首次 SHA1 命中且下载响应字段完整时，通常一次候选查询加一次下载请求。SHA1 缺失、上游结果矛盾和恢复目录核验可能增加必要查询。

文件资料页面只展示已保存校验片段数量，不展示逐条字节范围及片段哈希；后台保留最多 64 个已被 115 接受的区间，仍按文件 SHA1、大小及完整区间匹配，删除副本不删除这些资料。

所有来源使用[独立播放会话记录](single-playback.md)，同用户允许多会话，播放协商不准备网盘文件，正式取链通过准入后准备文件；动态池此时才选择目标。播放协商保留并向取链入口传递 Emby 的 PlaySessionId。缓存命中也必须持有有效租约并重验权限。下载不创建用户播放记录，但使用独立池租约键、共享 UID 总容量，并按保守 TTL 回收；不能根据播放停止通知释放下载占用。详见 [动态播放池](dynamic-playback-pool.md)。

反代对 `ItemId`、`MediaSourceId`、`PlaySessionId`、`UserId`、`Static`、`api_key` 和 `X-Emby-Token` 查询参数按名称大小写不敏感读取。URL 解码后的值完全相同可以重复，转发时合并为一个规范名称；值不同（包括空值与非空值）返回 HTTP 400，不选择其中任意一个。PlaybackInfo 和播放开始、进度、停止事件的 JSON 顶层身份字段也检查同名重复及与查询参数的冲突；可选字段的单个 `null` 视为未指定，空事件体保留原有转发行为。事件体最多 16 KiB，检查通过后原样转发。冲突请求在播放授权和会话捕获前拒绝，不释放现有会话。这是请求参数校验，不对媒体库文件、STRM 或多版本列表去重。

分享 STRM 中的 SHA1 也可作为秒传资料提示：仍先用本次目标账号尝试分享直取，只有明确不能读取分享时才进入原秒传流程。提示仅匹配本地唯一且已验证的资料；没有匹配、存在歧义或与已知来源冲突时重新核验源资料，沿用有界只读提前查询及源 SHA1 一致性检查。提示本身不建立可信来源关联、不改变目标账号。旧查询格式没有 SHA1，继续按原来源索引和核验流程处理。

正式取链复用当前用户条目查询中的唯一静态媒体源时，若已读取的地址属于已知分享格式且确定语法无效（例如缺少必填提取码），直接返回 HTTP 422，省去一次无法修复该错误的 PlaybackInfo 查询。动态媒体源、选择不唯一、元数据不完整、未知地址格式以及本地 STRM 暂时读取失败仍走原协商流程；首次客户端 PlaybackInfo 继续返回完整媒体源和音轨、字幕信息。Emby 当前用户与条目权限检查保留。
