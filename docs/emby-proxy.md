# Emby 302 反代

管理菜单 → Emby → **Emby 302 反代**（`/emby/proxy`）。该功能复用已有的 Cinema115 分享 STRM，不改写文件，也不参与生成。Emby 客户端改为连接反代入口，仍使用原 Emby 用户登录。

## 配置

1. 填写 Emby 原服务器地址，例如 `http://192.168.0.3:8096`。不要填反代地址。容器内 `localhost` 指向 Cinema115 自身。
2. 设置独立监听端口，默认 `8097`，可选 `1024～65535`，不能与管理服务的 `HTTP_PORT` 使用相同端口。保存成功后立即生效；端口占用或保存失败时保留原配置和监听。
3. 明确选择本功能使用的 **115 账号配置**。不继承分享生成账号，不自动选择唯一账号；删除、清空凭据后返回配置错误，不切换其他账号。每次播放解析固定本次账号凭据。
4. 按 STRM 分享格式识别，不限制 HTTP/HTTPS 地址的来源主机和端口，例如 `.24:3002` 与 `.3:8115` 可以混用。`/api/` 路径必须包含 `share_code`、`id`、`receive_code` 各一次，允许额外参数（忽略，不转发、不写入日志、不影响直链缓存键）；分享码为 1～128 位字母数字，文件 ID 为无前导零的正十进制 uint64，提取码为 0～32 位字母数字（可显式为空）。必要参数缺失、重复、格式不符或查询编码无效仍拒绝。旧签名 STRM 格式及 `/api/stream/share/...` 播放入口已废除，旧链接需重新生成普通参数格式；现有普通 STRM 无需修改。不会访问 STRM URL，只解析参数并调用固定的 115 接口；其他工具的不兼容路径和参数格式不会自动适配。
5. 如果 Emby 返回本地 `.strm` 文件路径，填写 Emby 中对应 Cinema115 `STRM_ROOT` 的目录前缀。例如同一媒体目录分别挂载为 Emby 的 `/media` 和 Cinema115 的 `/strm`，填写 `/media`。相对目录必须一致；只允许读取根目录内的普通 STRM 文件。Emby 已返回 HTTP 源地址时不需要映射。
6. 启用并保存。客户端连接 `http://NAS_IP:8097`；如果有 HTTPS 网关，按实际外部地址连接。

配置加密保存到 `DATA_DIR/emby-proxy.enc`，重启恢复。监听失败不会影响管理页面，可修正端口后重新保存。关闭功能即使账号已删除也可操作。端口切换会让旧连接在短暂退出窗口后断开，播放器需要重新连接。

来源严格模式及来源地址配置已移除。旧配置中的 `strictStrmOrigin` 和 `strmBaseUrl` 会被忽略，下次保存时去除；即使以前开启严格模式，也不再限制来源主机或端口。本地文件映射、根目录越界与符号链接校验仍然生效。

也支持其他工具的路径形式：`http://NAS:9527/s/{分享码}_{提取码}_{文件ID}`，扩展名可省略，例如 `/s/abc_pass_123` 与 `/s/abc_pass_123.mp4` 等价。空提取码写为 `/s/abc__123`；可选扩展名为 1～16 位字母数字，只允许单个扩展名。问号后的内容作为可选文件名提示整体忽略，不用于覆盖路径里的分享参数，例如 `/s/abc_pass_123.mp4?/电影.mp4`。路径必须完整匹配，不接受额外路径段、文件 ID 尾随字母或编码后的分隔符。仍校验 HTTP/HTTPS 地址、分享参数格式和文件 ID 范围。不访问原工具地址；反代播放、本地 STRM 文件和单文件秒传共用此解析规则，两种链接形式归一化后复用同一文件的直链缓存。

## 网盘 pickcode STRM

支持其他工具生成的 `http://NAS:端口/api/redirect115/{pickcode}`，也支持后面附加一个 URL 编码文件名；文件名可省略。主机、端口和协议只用于识别数据，不会被反代访问，因此 Docker 内部地址、NAS 地址和其他工具地址都可以直接使用。pickcode 必须是 6～64 位字母数字，查询参数、片段和额外路径会被拒绝。

识别后由 `/emby/proxy` 中明确选择的 115 源账号调用 115 接口获取文件信息和直链。未绑定或绑定同一个源账号配置时直接返回源账号直链；绑定其他账号时，先用源账号读取 pickcode 文件 SHA1，在绑定账号网盘中查找同 SHA1 文件；找到则直接取链，否则秒传到配置的保存目录再取链。不会访问 STRM 中的原地址，秒传失败也不会回退到源账号直链。旧 `thirdPartyUrl` 配置会被忽略，下次保存时移除。

分享参数 STRM 仍优先尝试朋友账号直接读取分享；朋友账号不可读时才用源账号读取元数据并秒传。两种形式共用直链缓存和用户权限校验；缓存默认 9 分钟，失败不缓存，账号凭据始终固定在本次请求开始时。

## 手机客户端下载

支持 `GET/HEAD /Items/{Id}/Download` 及带 `/emby` 前缀的入口，兼容 Yamby 查询参数中的 `X-Emby-Token`。下载单独核验真实登录身份、播放权限、`EnableContentDownloading` 和条目访问权限；条目明确禁止下载或为文件夹时拒绝，下载权限缺失时也拒绝。多媒体源须明确选择 `MediaSourceId`，不能猜测版本。每次请求包括缓存命中均重新检查权限。

分享 STRM 沿用用户绑定账号、分享直取和受限后秒传规则；pickcode STRM 沿用上述源账号读取、朋友账号秒传规则。使用下载器实际 UA，UA 不同时缓存隔离；相同用户、媒体源、账号和 UA 可复用播放建立的直链，但不能绕过下载权限。未支持的源仍交回 Emby 原下载接口。日志显示「下载取链结果」及 `/Items/{Id}/Download`，调试详情记录实际返回的 CDN 地址。

成功后返回无正文的 HTTP 302；文件名、文件大小、Range 和断点续传的最终行为由客户端与 CDN 决定。本项目不接收整段视频，也无法确认文件是否下载完成。长时间下载期间 CDN 地址失效，需要客户端重新请求下载入口取链。

## NAS / Docker 网络

项目 `compose.yaml` 使用 host 网络，不需要端口映射。管理服务通过 Compose 的 `environment.HTTP_PORT` 配置，compose 默认 `8115`；Emby 反代端口在网页修改并立即生效。两者不能使用相同端口，并需避免 NAS 端口冲突、放行防火墙。

如果自行切换为 bridge 网络，需删除 `network_mode: host` 并显式映射端口。例如管理服务的 `HTTP_PORT=8115`、网页反代监听 `8098`：

```yaml
ports:
  - "8115:8115"
  - "8098:8098"
```

然后执行 `docker compose up -d --build`，或在 NAS 容器管理界面添加对应 TCP 映射并重建容器。网页保存不能修改 Docker 的网络配置。也可使用不同宿主机端口，例如 `18097:8097`，此时网页保持 `8097`、客户端使用 `18097`。

上述映射仅适用于 bridge 网络。host 部署不要添加 `ports:`，管理服务修改 `HTTP_PORT` 后重建容器；反代端口通过网页修改，无需重建容器。

## 播放行为和范围

缓存管理独立页面为 **/emby/cache**，从 Emby 分类页的「缓存管理」卡片或反代设置页右上角进入。直链缓存时长在反代设置页修改并保存。页面与缓存管理接口均仅允许网站管理员访问；接口为 `GET /api/admin/emby/proxy/direct-links`，`DELETE` 同路径清空，`DELETE /api/admin/emby/proxy/direct-links/{id}` 移除单条。

直链缓存默认 **9 分钟**，设置页可调整为 0～30 分钟，0 表示关闭；旧配置缺少该字段时自动采用 9 分钟，已明确保存为 0 的配置保持关闭。缓存从成功取链时开始计时，命中不顺延。每次仍校验 Emby 用户、条目、实际媒体源和 STRM；缓存仅省略重复的 115 取链/秒传解析。缓存以 Emby 服务和用户、媒体源、分享参数、明确绑定账号及凭据版本、目录和播放器 UA 隔离，键为摘要。相同条件下并发请求合并取链，失败结果不缓存；发起请求被取消时本次合并请求可能失败，下次播放重新取链。

分享取链统一使用 `GET https://proapi.115.com/os_windows/2.0/share/downurl`，显式传入 `dl=0`，携带本次明确选定账号的 Cookie 和播放器 UA。旧 `/app/share/downurl` 接口实测会自动接收文件，即使传入 `dl=0` 也会发生，因此已停止使用，失败时也不回退旧接口。新接口在真实朋友账号中已验证取链和 CDN Range 读取成功，未出现对应文件或接收记录；115 上游行为仍可能变化。朋友分享受限时才进入源账号辅助秒传分支，源文件元数据取链也使用新接口。

程序不再清理网盘文件，历史接收文件及秒传文件均由用户在 115 中手动删除。直链缓存清空也不会删除网盘文件。

「直链缓存管理」展示全部/分享直取/秒传播放数量、用户、媒体源、取链账号、CDN 域名、建链时间、到期时间、剩余秒数和命中次数，可搜索、单条移除或清空。管理员可展开和复制完整 CDN 直链（包含签名）、首次建链的播放器请求头与取链 UA，点击建链请求编号查看日志。缓存命中不会更新建链请求头。Cookie、Emby Token 等登录凭据不返回。该缓存仅保存在内存，最多 512 条；过期记录在读取、查询或新取链时移除，保存反代配置和重启后清空。清空/移除只影响临时地址，不删除朋友网盘文件，也不能撤回已经发给播放器的地址。清空后旧的进行中请求不再写回缓存。

秒传目标直链命中时检查对应本地文件缓存记录仍为可用并刷新最后取链时间；本地记录已移除或状态异常则丢弃该直链并提示重新解析。直链命中不向 115 重新查询文件，外部删除文件或 CDN 提前失效时可能仍命中旧地址，可在面板移除后重试。9 分钟是本服务的复用时间，不改变也不保证 115 的有效期；302 后无法观察客户端 CDN 失败并自动刷新。命中日志显示「直链缓存命中」，播放结果注明命中与否。

设置页提供「反代调试日志」，默认关闭，保存后对新请求生效，随反代配置保存并在重启后恢复。每个 HTTP 请求结束后合并为一条记录，播放结果或错误显示为摘要，展开查看解析步骤。开启调试后额外记录方法、固定路径模板、路由、状态、耗时、客户端请求头、反代响应头和实际返回的完整 CDN Location，缓存命中也记录。正常图片、会话进度和普通透传每 30 秒在后续请求到达时汇总次数；不足一个窗口暂不输出，没有后台计时线程。异常单独保留，不合并不同用户的播放请求。

完整 CDN 地址只通过管理员日志与缓存接口提供，保留签名原文，不受日志摘要 1,000 字限制。UA、Range、Accept、响应 Content-Type 等常用诊断头可见；Cookie、Authorization、Emby Token、未知头的值隐藏，Referer/Origin 仅保留协议和主机，不记录请求正文或入站查询凭据。单个头值上限 2 KiB、头集合上限 16 KiB，超出明确标记截断。日志步骤上限 64 条 / 16 KiB。播放器直接请求 CDN 的真实请求头不可由反代观察；展示的 115 取链 UA 用于复现，不表示本次缓存命中重新请求了 115。WebSocket 的结束日志在连接关闭后出现。Yamby 开启「播放 STRM 文件内的原始路径」会绕过改写入口，调试开关无法观察绕过本服务的流量。

Emby 4.10 不支持 `/Users/Me`，可能将 `Me` 当作用户 GUID 并返回 HTTP 500。现在通过反代观察 Emby 成功的 `POST /Users/AuthenticateByName` 或 `POST /Users/{Id}/Authenticate` 响应，记录令牌摘要与真实用户 ID 的关联。首次使用或升级后，已有播放器须通过 **反代地址退出并重新登录一次**；直接向原 Emby 登录、仅粘贴旧令牌、使用无用户身份的管理 API Key 或仅使用 Emby Connect 交换令牌不能建立此关联，会返回 HTTP 401 并提示重新登录。

身份摘要按 Emby 服务器地址隔离，加密保存在 `emby-playback-identities.enc`，不保存登录密码或原始令牌，最多保留 4096 条，记录有效期 180 天；正常重启或更换反代监听端口会保留。每次播放仍使用播放器原始令牌请求 `/Users/{真实ID}`、用户条目权限和 PlaybackInfo，核验用户 ID 一致、未停用且允许播放。撤销令牌、禁止播放或条目无权访问时，不会进入 115 秒传。客户端的 UserId、DeviceId、SessionId 以及会话列表均不作为身份依据。身份记录失效或被清理后需重新登录。

上游失败日志包含固定接口类别和实际 HTTP 状态，例如“用户权限查询 GET /Users/{Id}失败：上游 HTTP 500”；不会输出请求地址、令牌或上游错误正文。日志中的外层 HTTP 502 表示代理查询失败，上游具体状态以该诊断为准。

转发诊断会记录请求类别及耗时，不记录原始 URL。图片请求因客户端断开、取消加载或反代停止而取消时不记录日志，避免浏览海报时刷屏；播放等其他请求取消仍记录为 DEBUG。上游操作取消但客户端请求仍有效记录为 WARNING。真正的上游超时保留 ERROR（HTTP 504），连接或响应失败保留 ERROR（HTTP 502），包括图片服务的真实故障。旧版的「Emby 转发失败：请求已取消」没有这些上下文，不能据此认定 115 直链失效。

在「实时日志」模块下拉框选择 **Emby 302** 查看播放日志；反代设置页右上角「查看日志」会进入 `/logs?module=Emby%20302&level=ALL`，自动筛选该模块及全部等级。与其他模块共用最近 2,000 条内存日志，重启清空；选择「全部」也能看到 302 日志。每两秒刷新，支持暂停、等级筛选和关键词搜索。记录配置生效、PlaybackInfo 检查、未改写原因、权限校验、媒体源选择、STRM 解析、115 取链耗时与结果、CDN 域名和 302 响应；同一次请求以 `302-...` 编号关联。统一接口 `/api/admin/logs` 仅允许管理员读取，不记录 Cookie、Emby Token、提取码、源地址或带签名的完整直链。302 发出之后的 CDN 下载发生在客户端，本服务无法据此判断播放成功。

- 普通请求（登录、海报、字幕、播放进度、WebSocket）反代到 Emby。客户端正常上报播放进度，视频流量不经过 Cinema115。
- 对 Emby 判断可直接播放的匹配分享源，改写 PlaybackInfo 中的播放入口。播放时使用客户端 Emby 凭据校验用户状态、播放权限、条目可见性和实际媒体源；不使用管理员 API Key 代替用户授权。也支持原客户端的 `Videos/:id/stream.*?Static=true` 请求。
- 按实际 MediaSourceId 选择版本，不通过标题或 TMDB ID 猜测。多版本缺少源编号时返回错误，不选第一个。
- 使用所选账号、播放器 User-Agent 获取 115 临时直链并返回 302，`GET` 和 `HEAD` 均支持；按配置短期复用直链，不转发 115 Cookie 给播放器。管理员缓存页可查看完整 CDN 地址，开启调试后日志详情也记录实际返回地址。
- 非匹配来源走原 Emby 链路。转码与封装转换已禁用：播放协商强制关闭 EnableTranscoding，移除转码入口，拒绝动态流和 HLS/DASH 请求。无兼容原文件直放源时返回 NoCompatibleStream，请更换播放器。115 解析失败不会自动切换账号或静默转发视频。
- 当前一套反代配置对应一个 Emby 和一个明确选定的源文件账号。「Emby 用户管理」（`/emby/users`）可按 Emby 用户 ID 绑定个人账号，优先读取分享直链；分享受限时由源账号辅助秒传、复用缓存，返回个人账号直链。

自动测试使用模拟 Emby / 115 验证协议和边界，并不证明真实 115 对所有客户端的 UA、IP、CORS 或临时链接限制兼容。上线后需用实际客户端验证开播、拖动、暂停续播、字幕及转码拦截：匹配直放请求应返回 302，客户端随后访问 115 CDN；转码请求应被拒绝，不能启动 Emby 转码。

## 单文件秒传验证

在 Emby 302 页面下方的「单文件秒传验证」分别选择源文件取链账号、目标账号和目标缓存目录，再保存。两个账号都必须明确指定；可以点击「填入已保存的 302 源账号」主动复制源账号，不会自动选中任何账号。单文件验证同样不限制 STRM 来源地址。目录可用选择器选择或填写 ID，根目录必须明确填写 `0`。切换目标账号会清空原目录。

打开一个现有 `.strm` 文件，粘贴其中的完整播放地址，点击「开始单文件秒传」。与 302 播放复用相同的普通分享链接格式和参数检查，允许额外参数，不比较来源地址。不访问粘贴的服务地址，也不读取本地路径。

源取链接口保留文件名和大小；新接口缺少 SHA1 时，仅秒传分支通过同一源账号的 `/share/search` 查询同一分享，最多检查 1,000 个结果。搜索名称只是筛选条件，必须核对完整文件 ID、名称、大小和 40 位 SHA1；无法匹配则停止，不根据同名文件猜测，不回退旧取链接口。普通分享直放不执行这次元数据查询。使用目标账号调用 115 上传初始化，如要求二次校验，则以相同 User-Agent 从源直链读取指定字节范围并计算 SHA1，再提交校验。CDN 请求不携带账号 Cookie。严格检查 HTTP 206、Content-Range 和字节数；片段上限 8 MB，不接受整文件响应。`status=2` 且有目标文件 ID 或 PickCode 才表示成功；`status=1` 表示需要普通上传并停止，不调用 OSS 上传。

验证开始时固定账号凭据、目录和来源设置。并发验证会被拒绝；相同请求编号在最近记录内不会重复提交写操作。接口超时、响应无法确认或服务重启中断时记录「结果待确认」，不自动重试写请求，请先核查目标目录。修改样本或重新保存配置后会生成新的请求编号，因此这不是长期文件缓存去重。

配置和最近 20 条验证记录保存在数据目录的 `instant-upload.enc`。记录保存账号编号、文件元数据、状态及目标文件标识，不保存 Cookie、分享提取码、源地址或签名直链。过程日志进入统一的 **Emby 302** 模块。该记录用于诊断，不是播放缓存清理清单，当前不会自动删除验证文件。

管理接口（均要求管理员认证）：`GET/POST /api/admin/emby/instant-upload` 读取或保存配置，`POST /api/admin/emby/instant-upload/run` 提交 `{ "id": "唯一请求编号", "strm": "STRM 内容" }`。配置字段为 `sourceAccountId`、目标 `accountId`、`targetCid`、`targetPath`。验证结果中的 `status` 应单独检查，HTTP 200 不一定表示秒传成功。

本地实测：一个 7,576,026,635 字节的视频跨账号秒传成功，耗时约 2.09 秒，真实二次校验读取了 188,677 字节；随后查询目标目录，文件大小、SHA1 和 PickCode 均一致。该结果证明此样本的秒传链路可用，不代表所有文件、账号和网络环境均能成功。

## 朋友账号播放与缓存

实际取链成功、准备返回 302 时会写入一条「播放取链结果」日志：显示经 Emby 校验的用户名与用户 ID、条目、实际选中的媒体源、播放方式和取链账号名称/UID/配置编号。播放方式区分「朋友分享直取」「新建秒传文件」「复用同 SHA1 文件」「源账号分享直取」；本次实际读取源文件信息时额外显示源读取账号。账号名称与凭据在请求开始时一起固定。结果日志不记录 Cookie 或直链，也不代表客户端已经开播；播放信息阶段的「入口已改写」不产生该结果日志。

「Emby 用户管理」（`/emby/users`）将所有用户合并为紧凑卡片，展示头像、Emby 管理员/普通用户权限、当前播放账号和用户 ID，支持搜索、筛选、复制 ID。每张卡片只有一个 115 账号选择器，可明确选择个人账号或“使用 302 源账号”；单卡保存只修改该用户，不覆盖其他卡片。刷新有未保存修改时先提示。用户列表读取失败保留绑定，用户已删除时标记并允许手动移除。头像通过管理员接口按可见卡片加载，读取失败使用名字首字，不向浏览器暴露 Emby API Key。

个人账号播放总开关已移除，旧配置中的 `enabled` 不再控制播放：有绑定直接生效，未绑定使用 302 明确配置的源账号，允许零绑定。用户列表使用 Emby 设置中与反代地址一致的服务器和 API Key 读取；保存个人账号时核验用户存在且未停用。播放仍使用播放器自身凭据核验用户、条目及媒体源权限，管理 API Key 不用于授权播放。

秒传保存目录在「115 助手」（`/helper115`）对应账号卡片中设置。目录选择器固定使用该卡片的账号，不存在全局当前账号或默认账号；根目录须明确填写 `0`。未配置目录仍可分享直取，需要秒传时会提示先配置。目录按账号持久保存到 SQLite，多名 Emby 用户绑定同一账号时共用该账号的保存目录。清空登录凭据或更换真实 115 UID 会清空目录设置。每次播放固定账号凭据和目录，保存后对新请求生效。本次不迁移旧用户绑定中的父目录，需要在账号卡片重新设置。

「缓存管理」（`/emby/cache`）展示临时直链缓存与网盘文件复用记录，可仅移除本地记录。网盘自动清理已停用，旧清理接口返回 410；旧配置中的清理开关不会生效。临时直链缓存的过期规则不变。

绑定以真实 Emby 用户 ID 和服务器地址为准，不信任播放器查询参数中的 UserId。未绑定用户使用 302 配置中明确选择的源账号；已绑定用户的目标账号失效时停止播放，不回退其他账号。服务器地址改变后需重新读取用户并保存绑定。任务开始时固定源账号、朋友账号凭据及设置。

未命中短期直链缓存时，先用本次固定的朋友 Cookie 和实际播放器 UA 请求分享直链。成功且直链不要求额外 Cookie 时直接返回 302，不要求文件 SHA1、不读取源账号、不创建网盘缓存。已有秒传文件缓存也不会跳过这一步；分享恢复可读且短期直链到期后可直接播放，旧网盘文件保留，由用户手动管理。

当分享取链接口明确提示违规、审核、仅本人可读、访问权限不足或文件不可见/不存在时，使用本次固定的源账号读取同一分享文件，核实文件是否仍可读。不会因朋友看到“文件不存在”就直接判断源文件已删除。朋友登录失效、提取码错误、风控限流、网络超时、HTTP 错误或无法分类的接口失败均停止，不换账号尝试。分类只依据接口明确错误信息，不猜测未知数字错误码；真实返回的未知错误需补充对应分类后才能启用备用流程。直链要求额外 Cookie 或返回域名无效也停止；302 之后的客户端 CDN 失败无法自动触发备用流程。

源账号读取成功后，调用 115 的 /files/search，以完整 SHA1 在朋友账号整个网盘中搜索，并核对结果 SHA1。只比较 SHA1，不要求文件名或大小相同；多个同 SHA1 文件可任选一个有效结果复用。命中后直接使用该文件 ID、pickcode 和播放器 UA 取朋友直链，不准备上传凭据。搜索失败、分页不完整或缺少取链标识时停止，不视为未命中。已确认未命中才秒传，直接写入该账号明确配置的保存目录（根目录需明确填写 0），不再创建 Cinema115-cache-* 子目录。文件名、大小和必要的片段校验仍是 115 秒传协议参数，不是文件等同性判据。

上传凭据内存缓存 5 分钟，保存目录身份缓存 1 分钟，按账号配置与 Cookie 隔离。已验证的 pickcode → 朋友文件映射按源账号、源 Cookie、目标账号配置/凭据/目录隔离；映射命中可跳过源解析与搜索。映射取链失败后重新按 SHA1 搜索，确认文件已不存在才重新秒传。源解析或目标取链失败不会回退返回源账号直链，不向播放器发送账号 Cookie。

同一进程内查找和秒传串行，等待请求会复查文件，避免重复写入。上传前持久保存操作意图；预检失败且尚未提交上传时允许重试。写入结果不明时，下次先搜索 SHA1：找到即可恢复复用，仍未找到则保留待核查状态，不自动重复上传。核查网盘后可以移除本地记录。当前仅支持单进程，不应让多个实例共享同一记录文件。

网盘文件完全由用户手动删除；程序没有定时清理任务，也不提供删除网盘文件的清理入口。历史缓存子目录保留。直链缓存清空和文件记录移除都不会删除云端内容；手动删除后的旧直链可能在本地缓存过期前仍被返回，可在缓存页面移除直链后重试。

配置和最多 2,000 条文件记录保存在 playback-cache.enc，不保存 Cookie、分享提取码、STRM 地址或签名直链。管理接口包括 GET /api/admin/emby/playback-cache、GET /users、GET /users/{userID}/avatar、POST /bindings/{userID}、POST /bindings、POST /forget；旧 POST /policy 和 POST /cleanup 返回 410。账号保存目录使用 PUT /api/admin/p115/accounts/{accountID}/playback-directory，包含 revision 和 parentCid。以上接口均须管理员认证。


真实样本的朋友缓存首次秒传加取链约 2.65 秒，真实二次校验读取 107,849 字节；第二次缓存复用加取链约 0.49 秒。两次目标账号直链均在不携带 Cookie 的情况下成功返回 Range 206。完整 302 路由的权限、GET/HEAD、缓存复用与失效账号行为通过模拟 Emby/115 测试；实际播放器开播与拖动仍需在对应用户客户端确认。
