# 影视追更

登录后，电影和剧集详情页提供「追更」按钮。提交后显示「已追更」，可在右上角账号菜单进入「我的追更」（`/follows`），按全部、电影或剧集筛选；每页 20 条，可打开详情或取消自己的订阅。

用户申请流程：

- 影视标题、海报和日期由后端读取 TMDB，不采用浏览器提交的元数据。电影和剧集使用各自的编号空间。
- 已入库电影无需申请；后端在提交时再次查询配置媒体库的现有索引。入库查询异常不冒充未入库，未建立索引时仍可提出申请。
- 剧集订阅以整个剧集为目标，后续检查范围约定为全部正片季，不含特别篇。已有部分分集仍可追更。
- 普通用户和管理员都可以订阅。身份只来自认证信息，不能通过请求参数替其他人操作。
- 每个用户最多同时追更 500 部。同一用户重复提交不新增记录，也不改变原申请时间。
- 多个用户追更同一影视时，共用一份影视申请；取消仅停用自己的订阅，不影响其他用户。重新订阅恢复原关联。
- 列表读取本地 Emby 索引，电影已存在时显示「已入库」。剧集有部分分集不判定完成。当前申请初始状态为「待处理」。

SQLite 版本 9 新增 `follow_requests` 和 `user_follows`。前者保存一份影视信息及处理状态，后者保存用户身份、影视关联、订阅状态和申请时间。事务确保申请与订阅同时提交；取消记录保留以支持重新订阅。环境变量管理员使用固定身份 `admin`，普通用户使用网站账号的稳定编号，因此订阅用户列不外键绑定只包含普通用户的 `website_users` 表。

接口均位于 `/api/me/follows`，要求登录：

- `GET ?kind=movie|tv&offset=0`：仅列出自己的有效订阅，省略类型查询全部。
- `GET /:kind/:id`：读取本人订阅及当前入库状态。
- `POST /:kind/:id`：创建或恢复本人订阅。
- `POST /:kind/:id/cancel`：取消本人订阅，重复取消无副作用。

管理员在右上角菜单进入「追更管理」（`/follows/manage`），按类型、处理状态、片名或 TMDB ID 筛选有效申请。同一影视展示一行及订阅人数；全部用户取消后不再展示。管理员可以标记「待处理」或「处理中」，填写最多 500 字的用户可见说明。「搜索资源」会进入对应影视详情并打开已有 Bot 搜索浮窗，搜索及 STRM 生成仍由管理员主动操作。

处理说明和状态显示在用户的详情页追更按钮下方及「我的追更」，刷新后可见。保存使用记录版本检查，避免多个管理页面互相覆盖；不能通过管理接口把未确认入库的影视直接标记为完成。

追更申请通知复用「Telegram → Bot 配置 → 独立通知聊天 ID」，不依赖消息接收开关。未配置 Bot 或通知聊天时仍保存申请，历史申请不会自动补发。通知的网站链接在「追更管理 → 通知设置」填写；支持 NAS 的同端口地址，Windows 开发时可填写 Vite 地址。留空时通知只提供影视信息和进入管理页的说明，不从请求 Host 或 115 设置推断地址。

一轮追更从无人订阅变为有人订阅时开始，并将申请和通知在同一 SQLite 事务保存。同一轮新增订阅者不重复通知；最后一人取消会撤销尚未发送的通知，重新有人订阅则开启新一轮，处理状态回到待处理。已开始发送的通知可能无法撤回。通知使用已有的持久化队列，每秒最多一条、失败最多尝试 8 次，退避间隔从 30 秒到 15 分钟；队列记录保留七天。消息绑定创建时的 Bot 编号和聊天 ID，更改配置不会把旧通知转发到新目标。

SQLite 版本 10 在 `follow_requests` 增加处理说明、修改时间、记录版本和轮次，新增 `follow_settings` 保存通知网站地址。Telegram 日志以「追更通知」区分申请通知与 STRM 生成通知。

管理员接口（仅管理员可用）：

- `GET /api/admin/follows?kind=&status=&q=&offset=0`：有效申请列表，每页 20 项。
- `POST /api/admin/follows/:kind/:id`：保存 `status`、`note` 和读取时的 `revision`。
- `GET/POST /api/admin/follows/settings`：读取或保存通知网站地址 `baseUrl`。

下一阶段接入 Emby Webhook 自动完成、连载追平判断及站内通知。生成 STRM 只代表资源生成，不能直接作为追更完成依据。
