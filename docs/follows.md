# 影视追更

登录后，电影和剧集详情页提供「追更」按钮。提交后显示「已追更」，可在右上角账号菜单进入「我的追更」（`/follows`），默认显示「追更中」，完成记录单独放在「已完成」。两组均支持全部、电影或剧集筛选；每页 24 张卡片，可打开详情或取消自己的订阅。

用户申请流程：

- 影视标题、海报和日期由后端读取 TMDB，不采用浏览器提交的元数据。电影和剧集使用各自的编号空间。
- 已入库电影无需申请；后端在提交时再次查询配置媒体库的现有索引。入库查询异常不冒充未入库，未建立索引时仍可提出申请。
- 剧集订阅以整个剧集为目标，后续检查范围约定为全部正片季，不含特别篇。已有部分分集仍可追更。
- 普通用户和管理员都可以订阅。身份只来自认证信息，不能通过请求参数替其他人操作。
- 每个用户最多同时追更 500 部。同一用户重复提交不新增记录，也不改变原申请时间。
- 多个用户追更同一影视时，共用一份影视申请；取消仅停用自己的订阅，不影响其他用户。重新订阅恢复原关联。
- 列表读取本地 Emby 索引，电影已存在时显示「已入库」。剧集有部分分集不判定完成。当前申请初始状态为「待处理」。

SQLite 版本 9 新增 `follow_requests` 和 `user_follows`。前者保存一份影视信息及处理状态，后者保存用户身份、影视关联、订阅状态和申请时间。事务确保申请与订阅同时提交；取消记录保留以支持重新订阅。环境变量管理员使用固定身份 `admin`，普通用户使用网站账号的稳定编号，因此订阅用户列不外键绑定只包含普通用户的 `website_users` 表。

接口均位于 `/api/me/follows`，要求登录：

- `GET ?status=ongoing|completed&kind=movie|tv&offset=0`：仅列出自己的有效订阅，默认 ongoing（追更中），省略类型查询全部类型。响应 counts 返回当前类型下各状态数量，不受分页影响。
- `GET /:kind/:id`：读取本人订阅及当前入库状态。
- `POST /:kind/:id`：创建或恢复本人订阅。
- `POST /:kind/:id/cancel`：取消本人订阅，重复取消无副作用。

管理员在右上角菜单进入「追更管理」（`/follows/manage`），按类型、处理状态、片名或 TMDB ID 筛选有效申请。同一影视展示一行及订阅人数；全部用户取消后不再展示。管理员可以标记「待处理」或「处理中」，填写最多 500 字的用户可见说明。「搜索资源」会进入对应影视详情并打开已有 Bot 搜索浮窗，搜索及 STRM 生成仍由管理员主动操作。

处理说明和状态显示在用户的详情页追更按钮下方及「我的追更」，刷新后可见。保存使用记录版本检查，避免多个管理页面互相覆盖；不能通过管理接口把未确认入库的影视直接标记为完成。

追更申请通知复用「Telegram → Bot 配置 → 独立通知聊天 ID」，不依赖消息接收开关。未配置 Bot 或通知聊天时仍保存申请，历史申请不会自动补发。通知的网站链接在「追更管理 → 通知设置」填写；支持 NAS 的同端口地址，Windows 开发时可填写 Vite 地址。留空时通知只提供影视信息和进入管理页的说明，不从请求 Host 或 115 设置推断地址。

一轮追更从无人订阅变为有人订阅时开始，并将申请和通知在同一 SQLite 事务保存。同一轮新增订阅者不重复通知；最后一人取消会撤销尚未发送的通知，重新有人订阅则开启新一轮，处理状态回到待处理。已开始发送的通知可能无法撤回。通知使用已有的持久化队列，每秒最多一条、失败最多尝试 8 次，退避间隔从 30 秒到 15 分钟；队列记录保留七天。消息绑定创建时的 Bot 编号和聊天 ID，更改配置不会把旧通知转发到新目标。

SQLite 版本 10 在 `follow_requests` 增加处理说明、修改时间、记录版本和轮次，新增 `follow_settings` 保存通知网站地址。Telegram 日志以「追更通知」区分申请通知与 STRM 生成通知。

管理员接口（仅管理员可用）：

- `GET /api/admin/follows?kind=&status=&q=&offset=0`：有效申请列表，每页 24 项。
- `POST /api/admin/follows/:kind/:id`：保存 `status`、`note` 和读取时的 `revision`。
- `GET/POST /api/admin/follows/settings`：读取或保存通知网站地址 `baseUrl` 及自动资源开关 `autoEnabled`。

## 订阅自动资源

开启自动资源后，一轮追更仍只由第一位订阅者创建一个任务，后续订阅者不会重复搜索。任务先等待一次最新的 Emby/TMDB 入库检查：电影已完整入库、剧集已追平或当前没有需要补充的已播内容时结束本轮自动任务；媒体库不存在该影视，或剧集已播数大于已入库数时，才使用 TMDB 中文标题搜索资源 Bot。检查暂时失败时保留任务并在五分钟后复核，不抢先搜索。

资源匹配优先采用完全一致的 TMDB ID；候选没有 ID 时，仅接受归一化后的中文标题完全相同且年份完全相同的结果。明确的电影／剧集类型冲突会被拒绝，不使用英文名、包含匹配或模糊匹配，也不检查分享内的季、集和文件范围。

匹配链接提交到 `/115/share` 页面背后的公共后台批次队列，与网页手动 Bot 搜索和 Telegram 生成串行执行。批次使用「115分享STRM」明确保存的账号、Cookie、输出目录、播放地址和转存设置，不保存追更专用账号，也不回退其他账号；提交时固定整批配置。Telegram 连续消息和订阅批次共用「批次收集等待」设置，默认五秒。STRM 生成成功后只把申请更新为「处理中／资源待确认」，不主动扫描或通知 Emby；最终入库状态继续由 Emby webhook 或全局同步确认。

SQLite 版本 12 新增持久化的订阅 Bot 任务，版本 13 将未开始任务改为先检查入库。实时日志提供独立「订阅」模块，记录首次检查、跳过原因、Bot 搜索、匹配入队和最终结果。

## 自动入库检查与站内通知

生成 STRM 不等于入库。后台使用当前所选 Emby 媒体库的本地索引确认结果：

- 电影：实际入库后自动完成。
- 剧集：忽略第 0 季，只比较已播出的正片。同一剧集多个版本取季号、集号并集，合并集文件按起止集号展开，重复版本不重复计数。
- 连载剧已播正片全部入库时显示「已追平 · 继续追更」；仍缺已播集数时显示已入库／已播数量。
- TMDB 标记 `Ended` 或 `Canceled`、全部正片已播且已入库时自动完成；未来集数不算缺集，也不能让完结剧提前完成。播出日期按 UTC 日历日期比较。
- 空剧集条目和只有特别篇视为正片未入库，不请求播出进度。索引未知、过期资料、缺少日期或不完整季信息不会误报完成，会显示等待复核。

Webhook 成功写入 Emby 索引时，在同一事务将受影响影视加入持久化检查队列；更新 TMDB 编号会同时检查旧、新影视，删除条目会查找原所属剧集。全量同步发布和 Emby 配置保存后复核有效追更，不新增定时全库扫描。正常单集更新通过条目主键定位相关影视。

单个后台消费者每两秒领取最多十项，逐项执行，每项最长两分钟。为覆盖新集开播但未收到 Webhook 的情况，仅有效追更剧集每小时复核，电影每六小时复核；失败五分钟后重试。TMDB 复用已有压缩缓存，仅刷新过期资料。服务重启重新安排有效订阅；全部用户取消后停止检查。队列版本防止处理中到达的新事件被旧检查结果覆盖。

顶部铃铛进入「站内通知」（`/notifications`），显示入库完成、追平、正片更新和恢复待处理的消息。通知与检查结果在同一事务保存，用户下次登录仍可查看；重复事件和重启不会重复通知未变化的结果。删除一个版本但其他版本仍包含该集时不会产生缺集。新增集已经补齐时继续显示追平，并通知新的入库进度。

站内通知每页 20 项，支持逐项及全部已读，未读角标在可见页面每分钟更新；点击影视标题先标为已读再进入详情。「全部已读」只影响点击时已加载的最大通知编号之前的通知，不吞掉同时到达的新消息。取消追更后不再收到该影视的新通知，历史通知保留。详情页和追更列表刷新后可看到最新进度。

通知接口要求登录，身份仅取认证用户：

- `GET /api/me/notifications?before=0`：通知列表、是否还有下一页和未读数量；下一页传当前最后一条通知编号。
- `GET /api/me/notifications/unread`：自己的未读数量。
- `POST /api/me/notifications/read`：`{"id":123,"all":false}` 标记一条；`all:true` 标记不大于指定编号的自己的通知。

SQLite 版本 11 新增 `follow_checks` 和 `website_notifications`。每部被追更影视仅一条检查汇总，保存状态、已播／已入库集数、检查时间、下次检查时间、版本和简短异常提示；不重复保存百万集索引或缺集区间。迁移保留既有申请、用户及媒体索引，无需重新同步 Emby。

管理页通过「待处理／处理中／已完成」按钮切换，默认进入待处理，保留类型与搜索筛选。按钮数量按当前类型、关键词统计，管理员按影视计数，不重复计算订阅人数。

两个页面复用 `FollowCard.vue`，手机单列、平板两列、电脑三列，宽屏四列。标题最多两行并支持悬停查看全文，处理说明最多两行，点击在弹窗内查看完整内容。卡片底部操作对齐，管理操作仅在管理员页面显示。点击「处理申请」在弹窗编辑状态和说明，失败时保留输入并在弹窗显示错误；保存期间禁止重复提交和关闭，已完成申请只能更新说明。分页步长为 24，支持旧网址偏移量，向前翻页不会产生负偏移。

已完成分组采用后台确认的 completed 状态，连载剧 caught_up（已追平）仍归追更中。后台检测到资源删除或新季需要继续追踪时，原申请自动回到未完成分组。切换状态或类型重置分页，URL 保存选择，刷新、前进后退均可恢复；已完成记录不会被删除。
