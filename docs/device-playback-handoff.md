# 同设备播放接替：任务清单与注意事项

第二阶段已实现稳定设备名额，最新规则与验收见 [设备名额验证](device-slot-validation.md)。下文暂借名额、满池未确认请求被拒绝、设备网络串行等描述属于第一阶段历史行为；当前设备名额复用不依赖正式会话接替，准备与提交失败仍保留旧播放。

## 规则

同用户可同时播放多个会话。设备接替只优化具有可靠设备关联的连续播放，不恢复用户单路限制。

- 身份来自 Emby 成功登录响应的 SessionInfo.DeviceId、Client，按服务、用户生成摘要；不相信播放 URL 的 DeviceId、IP 或 UA。已有登录记录缺少设备信息时继续独立播放，通过反代重新登录后获得设备关联。
- 仅正式播放、有 PlaySessionId、相同播放来源的唯一旧会话可以成为候选；下载、后台任务、预热及准备中的会话不接替。
- 新签发后 60 秒内，旧播放至少静默 30 秒才允许快速接替；超过此窗口要求至少静默 90 秒。最近有效播放事件优先于签发时间，持续上报的播放不接替。一次接替后至少间隔 30 秒。
- 同设备请求有界串行，其他设备不阻塞；多候选、缺身份或活跃旧会话按独立播放处理，仍受 UID 容量限制。
- 新播放先准备文件/直链，提交前重新检查旧代次和活动证据。准备失败、取消、旧播放恢复或数据库失败均保留旧播放。
- 签发直链本身不再确认接替。新会话须有已被 Emby 接受的 Playing/Progress，或精确匹配且新鲜的 LastPlaybackCheckIn；准备期间收到的事件可以用于提交，签发之后收到的事件也可触发事务接替。完全早于本地会话建立的事件不会猜测关联，等待后续事件或轮询证据。
- 未确认新会话按独立容量提交，原先暂借的准备名额须在事务中重新检查容量；满池时拒绝这次签发并保留旧播放。此阶段尚未实现预加载共享固定设备槽位。
- 相同 UID、配置与目录的健康池租约可暂借旧名额准备，新旧文档事务提交后完成名额转交；下载和残余记录不参与借用。换 UID 按正常容量分配，旧 UID 保留最多两分钟残余，不搬迁文件副本。
- 接替后旧会话禁止新的取链，迟到事件不能影响新会话；正常停止仍允许原地址重播。
- 同影片且新旧会话具有相同备用事件标识时，接替后的新会话不再接受缺会话 ID 的通知；要求带 PlaySessionId 的事件或继续按到期规则处理。不能区分的旧通知不猜测归属。
- 浏览产生的 LastActivityDate 不作为续租或接替活动证据；LastPlaybackCheckIn 须在最近 90 秒内、不晚于服务端当前时间，且不早于本代次最近签发。轮询续租以证据时间计算，重复读取同一快照不延长到期。播放器不报告进度时无法保证静默就是真正停止。
- 用户播放记录的失联期限为 5 分钟；池租期默认 5 分钟，仍尊重已保存的池设置。普通停止事件在同一事务中删除匹配用户记录、标记匹配池记录的短期残余。
- 逻辑名额继承不能撤回已签发 CDN URL，短时间可能存在实际连接重叠。

## 验收注意事项

自动测试不能证明 Yamby 所有版本都会提供稳定设备 ID；需在真实客户端通过反代登录后验证。无可靠设备身份时宁可保留独立会话。此功能不等于全局失联回收，完全不再打开的客户端仍使用原到期机制。候选时间为本项目策略，不是 Emby 官方超时。

不会清理或猜测关联原有无设备信息的历史记录。设备标识是客户端经 Emby 认证会话关联的逻辑标识，不是硬件证明；共享同一客户端身份的多窗口且旧窗口不报告进度时仍可能被视为连续播放。

## 实机验收（需播放器操作）

- [ ] Yamby 通过反代重新登录，确认正式取链日志不再提示缺少可信设备信息。
- [ ] 开始播放、强退，达到静默条件后重开：出现接替完成日志，同 UID 逻辑占用不重复增加。
- [ ] 另一台设备持续播放：新设备独立计数，旧设备上报不被释放。
- [ ] 正常停止、原地重播和连续切片：核对精确停止通知与不同代次的行为。
