# 动漫统一设置与 RSS 自动归档

更新：2026-10-22。对应 R-12、R-13、R-16、R-17、R-18、R-19；不替代 P4 完整流程验收。

## 设置入口

选番页右上角“设置”进入 `/anime/settings`，返回时保留站点、季度、日期和页码。参考 ANI-RSS 的分类设置：桌面左侧分类，手机横向切换，使用项目已有蓝色与中性色。

- RSS 设置：检查间隔（默认 15 分钟，允许 10–1440 分钟）、齐集自动归档、长期停更归档（默认 60 天，可选 90 天或关闭）。修改后手动保存。
- 下载与整理：复用原目录选择组件，选择后立即保存；已有任务继续沿用启动时的目录。打开设置只读取本地配置，打开目录选择器才请求 115。
- 分类切换保留 RSS 输入；离开时可确认放弃。保存中或回执不明时阻止新提交及路由离开，按原幂等键和正文核对。版本冲突保留输入，重新读取前确认放弃。

RSS 设置使用独立 revision，修改它不会改变目录设置版本或使已固定的下载目标失效。接口为管理员 `GET/PATCH /api/admin/anime/rss-settings`，写入需要 `Idempotency-Key`。

## 齐集自动归档

所有启用来源的目标单集都已整理成功，并且没有未完成、失败或待确认的下载任务、没有尚未认领的已选资源时，整条订阅进入 `archived`。每个显式规格分别核对；主源完成不会提前停止尚未齐集的备用来源。

集数取本地 Bangumi 篇章正片集数，可在单部订阅的“篇章总集数”中覆盖。2026-10-22 修正：新保存的默认值来自 `eps`，不使用包含 OP、ED 的 `total_episodes`；0/缺失视为未定，手动填写优先。篇章首集优先用显式发布编号，再用已确认的篇章对应或长度一致的范围；否则仅用已保存的篇章开播日与 TMDB 唯一同日单集、单段命名映射反推发布编号。单纯的命名偏移、TMDB 季长度或 RSS 最小集号均不能证明篇章起点。无法确定时继续订阅，可在“归档编号（高级）”填写篇章首集对应的发布编号。补番起点之前的集数不要求补齐。

RSS 观测成功后评估，最后一个整理任务成功时也在同一事务中评估，不必再等下一轮 RSS。归档保留本地执行历史，不删除网盘文件、不检查用户二次整理后的文件位置，不增加 115 请求。

## 长期停更

按本工具首次发现新匹配资源的时间计时，不按旧资源的发布日期。所有启用来源都持续静默才归档，任一来源有新匹配资源便延后整条订阅的停更判断。

| 时长 | 行为 |
| --- | --- |
| 14 天 | 订阅配置的归档编号区域显示弱文字提示 |
| 30 天 | 该来源改为每天检查一次 |
| 60 天（默认）或 90 天 | 无待处理工作时归档为长期停更 |

关闭停更归档仍保留提示和降频。RSS 失败重置静默起点；超过 48 小时没有成功检查时，下一次成功重新计时，不把停机时间当作烂尾。恢复或取消归档清除旧静默记录，恢复时安排尽快检查，同时遵守上游冷却期限。已整理资源不会因此重下。

归档原因在本地保存为齐集、长期停更或手动，页面按原因显示简短说明。来源不可用、正在读取、新来源尚未初始化或编号不确定时，不猜测齐集。

## ANI-RSS 参考与差异

只读核对用户 ANI-RSS 页面与 [固定源码版本](https://github.com/wushuo894/ani-rss/tree/d59e52db3b971cf03ba54f5447deaad587ac0175) 的 `DownloadService`、`ItemsUtil`、`BgmTask`、`AniService`。其自动禁用以主 RSS 下载计数达到 Bangumi 总集数为主，已有任务或部分跳过也可能计数；长时间不更新主要是提醒。本项目以所有启用字幕组实际整理成功为准，长期停更策略单独配置，不复制完结搬迁。

## 每条 RSS 的缺集摘要（2026-10-22）

订阅卡片复用 `AnimeCard`，海报右下角逐行显示全部字幕组胶囊，最多五条 RSS。绿色表示目标集数已整理，蓝色表示进行中，红色表示已发布范围内有尚未整理的集数；初次检查或规则变更待更新时显示中性色。订阅启用、暂停、归档状态单独显示；手动或停更归档不等同于齐集完成。胶囊不再追加进度条或“另 N 组”，下载记录页提供文字状态和具体缺集区间。订阅卡片通过共用组件的 `highlight=false` 关闭海报蓝色流光和标题悬停变蓝，保留中性阴影与键盘焦点反馈。

检测按每条 RSS 的保存规则和补番起点独立计算。例如发布到第 10 集，整理记录缺第 7 集，只报告第 7 集，不要求尚未发布的 11、12 集。连续发布编号和篇章范围复用自动归档的计算；没有总集数也能检查已发布范围内的缺口，但不猜测完结。来源授权快照与实际整理成功回执共同证明覆盖，其他字幕组不代替本组，修改集号正则后不沿用旧编号解释。

SQLite v57 新增一张来源摘要表。RSS 观测、整理回执、规则或总集数发生变化时只将对应摘要标记失效；现有后台 runner 的独立本地通道每轮最多更新八条，每五秒检查一次，重启直接读取已完成的摘要。没有变化时不重新解析历史；计算时先读一致快照、释放数据库连接，再解析并按代次条件保存，防止旧结果覆盖新配置。

打开列表仅批量读取本页来源、条目和摘要，移除了逐张卡片的历史任务统计；列表不携带缺集区间，详情才读取区间。复用原页面缓存和本地刷新节奏，没有新增逐卡片轮询。此功能不请求 RSS/115，也不检查整理后的文件是否仍在原位置。摘要更新一般等待一个后台检查周期，批量失效可能需要多个周期；页面沿用原刷新时机。

验证使用临时 SQLite 和全 API 拦截的浏览器：覆盖缺第 7 集、字幕组隔离、补齐、连续编号、起点、未知总数、规则变更、取消及关闭重开；相关四包 Go 回归、vet、后端构建、前端构建、20 组订阅编辑与 5 组列表浏览回归通过。320px 明暗主题、五条来源与长名称、减少动效均检查，无真实订阅或 115 写入。Gemini CLI 返回了代码审查意见，已调整文字对比和减少动效；首轮桥接在返回意见后超时，后续复审正常退出并给出 PASS。

## 减少后台来源请求（2026-10-22）

三站保留各自的读取实现、缓存和限流，不合并站点确认函数。保存新来源、交互式预览仍核对上游条目和字幕组；后台使用服务端已确认并保存的来源身份，直接读取资源。内部确认信息不从 HTTP 输入接收，读取预算、冷却及资源响应校验保持原规则。

| 普通后台轮询，缓存均已过期 | 原请求数 | 当前请求数 |
| --- | --- | --- |
| 蜜柑 | 条目、RSS，共 2 次 | RSS，1 次 |
| AniBT | 字幕组、RSS，共 2 次 | RSS，1 次 |
| Garden | 条目、字幕组资源、指定组资源，共 3 次 | 指定组资源，1 次 |

复用 v57 摘要判断单条 RSS 是否齐集，不扫描云端文件。只有当前代次的摘要为完成、来源健康且活动记录仍对应当前配置时，才停止远端读取；未知总数、缺集、未完成或已失效的摘要仍继续读取。主来源齐集不停止未完成的备用来源。恢复订阅、配置变更或未收尾的轮询保留原恢复检查，在途回执不因摘要变为完成而失去授权。

已齐集来源沿用原调度时间做本地归档评估，不请求 RSS/115、不更新最后成功读取时间；因此之后切换自动归档设置和长期停更判断仍可生效。已齐集来源不受 RSS 成功时间超过 48 小时的限制，其他健康条件仍保留，避免较慢的字幕组完成时被已停止轮询的来源阻塞。

未增加表、迁移、持久业务状态、缓存层或后台循环；`LocalOnly` 仅为本轮调度返回值。请求数通过模拟传输计数验证，未执行真实订阅或 115 操作。

验证：三站冷读各 1 次、缓存命中零请求、错误及错组响应保持拒绝；齐集/备用源隔离、SQLite 重开、恢复、规则失效、在途齐集、停止读取超过 48 小时及后续开启自动归档均通过。`animefeed`、`mikan`、`garden`、`anibt`、`service`、`storage` 六包完整 Go 回归、相关 vet、全后端构建及 Codex 后端自审完成。本轮没有前端变更。

## RSS 轮询与操作日志（2026-10-23）

复用日志页的“订阅”模块及现有固定容量缓冲区。轮询日志以订阅 ID 关联，显示番名、站点和字幕组；下载与整理日志使用下载任务 ID，优先显示冻结命名方案的番名、字幕组原始集号及修订版本，缺少命名资料时回退资源标题。三站读取实现、轮询周期和下载流程保持各自原有行为。

- INFO：首次检查、选中待下载资源、RSS 读取恢复、订阅操作、成功安排任务重试或核对，以及入队、115 确认离线任务、开始下载、离线完成和整理完成。
- WARNING：新发现的待确认资源、首次读取异常、异常分类变化或用户操作未完成。明确说明重试、等待冷却或人工处理；同一 RSS 读取错误的后续失败降为 DEBUG，相同下载进度与任务异常不重复输出。文件已整理但临时目录清理回执未知时，单条 WARNING 同时说明已完成文件移动和待核对的清理结果。
- DEBUG：无新增轮询仅保留“读取 N 条，暂无新资源”；115 状态暂不明确时保留首次说明。每次 RSS 结果只输出一条；删除阶段计时包装及所有调用，不再显示耗时、请求读写次数、限速等待、HTTP 时间或额外的缓存性能行。底层公共计时能力继续供播放诊断等模块使用。

RSS 结果、任务状态与整理结果均在本地写入成功后记录；离线完成不等于整理完成，目录冲突及回滚不输出成功。状态写入返回同一事务已经读取并确认的任务，提交与文件读取复用原有结果回读，整理复用原有检查点；配置保存与操作顺序重放不重复记录成功结果，删除前保留番名。动态内容沿用现有脱敏；不增加 RSS/115 请求、数据库查询、持久表、缓存层或循环。日志页面布局、等级颜色、全量读取接口和现有刷新机制未调整。

专项测试覆盖轮询结果单条输出、重复异常、恢复、入队去重、操作重放、删除后名称、00 集及动态元数据脱敏；新增实际状态变化去重、目录不匹配、写入回滚、提交回执后确认、整理成功与移动/清理回执未知场景。返回的状态与已提交数据行一致，失败不返回可发布结果。使用临时 SQLite 和模拟 RSS/115，无真实订阅或网盘文件操作。

## 连续编号误报修复与三站采样（2026-10-22）
