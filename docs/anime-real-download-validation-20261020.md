## 找到并修复的问题

### 1. 移动成功被当成未知写入

115 移动接口实际返回 `{"state":true,"errno":"","error":""}`。旧解析器要求错误码必须是数字，因此虽然文件已经移动成功，本地仍进入未知结果恢复，等待后再读取目录确认。

现在仅在文件变更回执解析中兼容空字符串 `errno`。仍要求明确成功，并拒绝重复字段、矛盾错误码、部分失败和异步任务回执；没有放宽离线任务身份或任务不存在的判断。正常成功可以直接推进回收，不增加移动后的例行核对。

修复前后各用一组隔离空目录验证移动；实际位置正确，诊断目录已全部回收。

### 2. 刚受理任务的空结果 ID 触发一分钟退避

一次额外的精确状态读取捕捉到：任务存在，`status=0`、`file_id=""`、`percentDone=100`、`display_percent=99`。这组进度不能证明文件已完成，旧解析器还会因为空文件 ID 将其视为读取失败，转入约一分钟退避。

现在允许精确匹配任务的空结果 ID 表示“结果尚未就绪”。仅对本工具已收到接受回执、状态为 0、结果 ID 为空且提交授权后不足 20 秒的任务，沿用原有约 5 秒、20 秒检查点。仍不认定下载完成；持续未知、网络失败、限流和身份冲突保留原有退避及拦截规则，不重发离线提交。

### 3. 本地资源确认等待兜底扫描

修复后复测时，按钮点击到创建本地下载任务仍出现约 4.6 秒等待，来自资源确认 worker 的 5 秒兜底扫描。

现在开始订阅和 RSS 观测成功提交本地事务后，通知资源确认 worker 立即处理；每批最多 4 条，处理满批后继续唤醒下一批。通知队列容量为 1，RSS 读取循环不监听此通知，持久化到期时间及错误退避仍生效。

这项本地唤醒在两条真实复测之后完成，已通过集成测试和完整回归，**尚未另起真实下载复测这项改动**。没有为验证再次下载整批资源。
