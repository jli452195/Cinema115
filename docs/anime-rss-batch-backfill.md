# RSS 合集补缺

合集沿用原 RSS 调度、115 下载、整理及自动归档链路，不增加设置或独立任务队列。

- 识别为合集的标题只作为候选，不代表包内文件已符合规则。蜜柑、AniBT 在现有种子核验中保留完整清单；Garden 复用已有详情清单与缓存，清单不完整时不自动下载。
- 对每个视频的文件名应用本 RSS 的全部匹配正则、任一排除正则、编号规则、篇章范围和下载起点。目录名及合集标题的规格标签不能代替文件名通过筛选。
- 普通单集编号明确才可补缺；ISO、未知编号、默认 SP、单个视频的多集编号不展开。自定义编号沿用 RSS 现有规则。
- 同集同规格采用当前可用的最高修订版；筛选后同集仍有不同规格时不猜选。已经选定的单集或合集不会因为后来发布修正版而重新下载。
- 在领取任务的同一 SQLite 事务中，排除本 RSS 已整理及已选中待处理的集数。不同 RSS 的覆盖独立；已有失败任务仍使用原手动重试入口。
- 没有符合规则的待补集时记录跳过，不创建 115 任务。合集选过的单集再次发布时也跳过，普通轮询在本地过滤，无需再次读取它的种子。
- 每个合集只提交一次磁力。115 仍可能下载整个种子；整理时只移动冻结的待补视频及唯一对应的外挂字幕，其他文件在任务成功后随本任务临时目录清理。命名、文件对应或字幕命名存在问题时停止自动整理，不清理源目录。
- 按实际整理成功的集数更新本地进度，继续使用现有总集数与归档策略。TMDB 不限制可整理集数；总集数未知时不因当前合集已经处理完就按齐集归档。

验证覆盖逐文件正则、混合规格、00、自定义编号、修订版、重叠合集与尾部补集、重复轮询、RSS 独立去重、清单持久化、字幕跟随、超出 TMDB 集数的命名、配置变更拦截，以及整理和临时目录清理的模拟链路。没有向真实 115 账号提交下载或更改目录。
