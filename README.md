# Cinema115

电影详情中的「查看系列」进入站内 `/collection/:tmdbId`，展示 TMDB 系列海报、简介及按上映时间排列的电影，未公布日期的放在最后。卡片显示 Emby 入库标识并进入 `/movie/:tmdbId`；长系列每次展示 30 部，入库检查每批最多 100 条。管理员接口 `GET /api/admin/tmdb/collection/:id` 复用 TMDB 客户端五分钟缓存，支持加载失败重试，TMDB 密钥不发送到浏览器。

首页 `/` 默认显示看板，使用 TMDB 展示电影和剧集的中文片名、海报、年份与用户评分，支持类型、出品地区、年份、热门／最新／TMDB 评分排序及分页。页面统一使用浅色顶部导航，不再显示侧边栏或手机抽屉。点击品牌返回首页，电影和剧集分别进入 `/movie`、`/tv`；放大镜进入独立搜索页 `/search`，支持聚合、电影、剧集、演员四种范围；关键词 `q`、范围 `scope=multi|movie|tv|person` 和页码 `page` 保存在 URL 中，刷新和前进后退可恢复。右上角头像打开管理菜单，可进入 115 网盘、Telegram 配置、查看日志、Emby 及退出登录；115 功能分类页位于 `/115`。评分排序至少需要 100 人评价；搜索按 TMDB 相关度返回，聚合模式使用综合搜索并过滤人物结果，保留上游分页，部分页面可能较少或没有影视结果；聚合仅显示本页影视数量。搜索结果复用影视卡片及 Emby 入库标识，旧看板搜索链接自动转入新页面。点击海报进入站内影视详情。IMDb、豆瓣评分暂未接入。

演员搜索通过管理员接口 `GET /api/admin/tmdb/people?query=姓名&page=1` 查询 TMDB 表演部门人物（含配音），展示照片、姓名与代表作，过滤其他工作人员并沿用上游分页。点击进入 `/person/:tmdbId`，由 `GET /api/admin/tmdb/person/:id` 读取简介及参演影视；支持电影／剧集筛选、分批加载和 Emby 入库标识，返回搜索保留姓名及页码。两个接口复用 TMDB 客户端的有界五分钟缓存。

剧集和电影分别使用 `/tv`、`/movie` 路由，切换片库会同步更新地址栏。支持直接访问、刷新和浏览器前进后退；未登录时先显示登录页，登录后继续进入原路由。NAS 单端口部署由后端提供页面回退，无需额外配置反向代理。

影视详情路由为 `/movie/:tmdbId` 和 `/tv/:tmdbId`，例如 `/movie/550`、`/tv/1399`。详情页展示淡背景图、海报、中文片名、简介、TMDB 评分、上映／首播日期与演员；电影有系列时提供 TMDB 系列链接，IMDb 仅提供条目链接。剧集显示季列表（含特别篇），展开时按需请求分集资料，同一页面重复展开复用结果。当前不推断入库状态，也未接入资源搜索或播放按钮。

详情与分集分别使用管理员接口 `GET /api/admin/tmdb/detail/:kind/:id`、`GET /api/admin/tmdb/tv/:id/season/:number`，使用 SQLite 压缩缓存并在过期后后台重新验证。剧集季标题一次读取 `/api/admin/tmdb/tv/:id/schedules` 的精简播出缓存；完整简介在展开季后读取，长剧每次显示二十集。缺集区间由前端计算，缓存字段和全局预热规则见 [Emby 入库索引](docs/emby.md)。无效参数返回 400，找不到条目返回 404；页面提供缺图占位、加载失败重试，并在切换影视时取消旧请求。

在根目录 `.env` 的 `TMDB_API_KEY` 中填写 TMDB 账户「设置 → API」里的 API Key（v3 auth），可从 https://www.themoviedb.org/settings/api 获取。密钥只供后端访问固定的 TMDB API，浏览器通过管理员鉴权接口 `/api/admin/tmdb/genres` 和 `/api/admin/tmdb/browse` 查询，海报直接从 `image.tmdb.org` 加载。成功请求在后端缓存 5 分钟，单次最多等待 18 秒；未配置密钥、连接失败、海报缺失和空结果均有页面提示。Docker Compose 将密钥传入后端运行环境，不写入前端或镜像；修改后本地重启后端，NAS 使用 `docker compose up -d` 重新创建配置发生变化的容器。

「115分享STRM」包含基础设置、普通分享、转存再分享和日志四个标签。基础设置新增「分享审核中自动重试」，默认关闭；开启并保存后默认间隔 30 分钟、最多重试 6 次，可自行调整。网页按当前分享标签执行，Telegram 使用保存的默认模式。

视频后缀与元数据后缀在基础设置中并排配置。元数据默认 `srt,ass,ssa`，可增加 `nfo` 等后缀，留空则不下载配套文件。匹配的元数据按原始内容、后缀和目录层级保存，不生成 STRM，也不受视频最小文件大小限制；单文件最多 32 MB。元数据下载失败会保留原有文件并阻止转存流程清理源目录。包含子目录、Bot 默认转存与审核重试统一使用开关。

该页面的「日志」按任务显示原链接、新链接、状态、生成数量、重试次数和下次执行时间，支持筛选、搜索、分页及清理已结束记录。任务与重试队列保存在 SQLite，关闭网页后仍可继续，服务重启保留审核等待任务。已创建新分享的重试只复用新链接生成，不会重复转存，临时目录保留待核对。详见 [审核重试说明](docs/reshare.md)。右上角管理菜单中的「查看日志」继续提供 INFO / DEBUG 等级的实时过程记录。

本地测试脚本、截图、验收 STRM 和排查资料集中放在 [`tests/`](tests/README.md)，开发服务日志位于 `tests/runtime/`。Docker 构建排除此目录及 Go 测试源码、测试夹具；本地单元测试仍可正常运行。

纯 Go 后端与 Vue 3 前端。当前支持管理员登录、115 扫码/Cookie 登录、分享目录分页浏览、STRM 下载和媒体代理。

## NAS 部署（Docker）

生产环境使用根目录 `Dockerfile` 和 `compose.yaml`，多阶段构建后只运行一个容器，由 Go 同时提供前端页面与 API，默认通过 `http://NAS_IP:8115` 访问。根目录 `.env` 配置 NAS 访问地址和账号；`compose.yaml` 使用 `./data:/data` 与 `/vol1/1000/媒体库:/strm` 两条挂载。页面填写 `strm`、`strm2` 等相对目录，在同一个媒体库中生成。完整步骤见 [NAS Docker 部署](docs/docker.md)。

配置 `.env` 并创建挂载目录后执行：

```sh
docker compose config --quiet
docker compose up -d --build
```

## Windows / 本地开发

在项目根目录将 `.env.example` 复制为 `.env`，填写管理员账号、密码和随机 `JWT_SECRET`。配置仅由后端读取。

```powershell
cd backend
go mod tidy
go run ./cmd/server
```

```powershell
cd frontend
npm install
npm run dev
```

已安装 Air 时在 `backend` 执行 `air -c .air.toml`。不要同时运行两个后端占用 3002。

## 分享播放与 Emby

1. 登录管理员后台，在「115 网盘」扫码并确认，等待后端获取 Cookie 并保存成功。
2. 点击右上角管理菜单「115 网盘」，再进入「分享播放 / STRM」卡片，输入分享链接和提取码。
3. 选择生成目录（例如 `strm` 或 `strm2`），点击「一键生成 STRM」。自动分页读取视频、按配置扫描子目录，直接保存到媒体库中的对应子目录。默认不转存；打开「转存再分享」后先转换为自己的分享。预览和单个下载仍使用原分享。
4. 把 STRM 放进 Emby 媒体库。Emby 必须能够访问 STRM 中的 Cinema115 地址。

根目录 `.env` 可选配置：

```dotenv
# 相对 backend 工作目录；默认保存到项目根目录 data。
DATA_DIR=../data
```

在「分享播放 / STRM」填写 Emby 能访问的「STRM 播放地址」，点击「保存生成设置」。地址保存在服务器并立即生效，不从环境变量读取；首次未配置时页面默认填入当前访问地址。已有 STRM 不会自动改写。

STRM 写入固定的 Cinema115 代理地址。每次播放用已登录账户请求最新 115 直链，并转发 Range、HEAD 和媒体响应头；不会落盘保存视频。代理流量经过后端，受后端带宽限制。

新生成的链接格式为 `/api/?share_code=分享码&id=文件ID&receive_code=提取码`，可直接拼接使用，不要求签名、过期时间或管理员 JWT。无提取码的分享使用 `receive_code=`。后台分享管理接口仍需管理员登录。旧的 `/api/stream/share/{token}` 地址继续支持。

新播放链接没有 Cinema115 设置的过期时间，能否播放取决于分享是否有效和后端 115 登录状态。旧路径中的播放凭证仍按原有效期校验。更换 `JWT_SECRET` 会使旧路径凭证失效，也会使原有加密登录会话无法解密。

115 登录凭证统一通过网页扫码或 Cookie 登录设置，不从环境变量读取。Cookie 用 AES-GCM 加密保存在 `data/p115-session.enc`，目录已被 Git 忽略。热重启后会恢复；115 撤销或过期的 Cookie 仍需重新登录。退出 115 登录会移除保存的会话。

「115 网盘」的 Cookie 登录页默认隐藏凭证。留空点击「测试 Cookie」会验证服务器已保存的凭证；填写新值时只测试输入内容，不修改原配置。「验证并保存」在 115 验证通过后才替换凭证。状态区会区分未配置、已连接、已失效和暂时无法验证；网络故障不会被误判为登录失效。

批量生成支持播放服务地址、视频后缀、最小文件大小、是否扫描子目录和起始目录 ID（默认 `0`）配置。预览中可进入文件夹并设为起始目录。页面支持添加、选择、移除多个相对目录选项；移除选项不删除服务器文件。挂载 `/vol1/1000/媒体库:/strm` 后，页面填写 `strm` 对应 NAS 的 `媒体库/strm`，填写 `strm2` 对应 `媒体库/strm2`，不需要分别挂载。子目录自动创建。Windows 开发默认根目录为项目 `data/media`，可用 `.env` 的 `STRM_ROOT` 配置。

生成时直接保留分享的文件夹层级，不加批次目录，不打包 ZIP。每次重新写入全部匹配的 STRM，同名文件替换为本次生成的内容；其他工具移走文件后，可再次生成。结果只统计新增数量（本次成功写入数，包含同名替换），Emby 可直接读取该目录。普通选项保存在当前浏览器，分享链接和提取码不持久化到浏览器配置。

`POST /api/admin/p115/share/generate` 使用管理员 JWT 鉴权，接收 `url`、`password`、`cid`、`baseUrl`、`outputDir`、`videoExtensions`、`minSizeMB`、`recursive`，返回 JSON：`directory`、`count`（本次成功写入数）、`skipped`、`total`；页面默认开启 `recursive`。`GET /api/admin/p115/share/generation-config` 返回默认配置和目录的实际路径。单次扫描限制为 5 分钟、500 页、20 层目录、20000 个条目和 10000 个视频，超限需缩小起始目录。扫描失败不写文件；每个文件先完整写入临时文件，再替换目标，重试会重新写入。

「转存再分享」开关保存到服务器，供网页和 Telegram 共用。开启后在 115 创建独立临时目录，等待所有子文件完整转存后创建分享，显式设置并确认长期有效，再校验完整分享快照、生成 STRM，最后将临时目录移入回收站并复查分享。不会清空回收站。失败时保留目录及任务记录。网页实时显示阶段、条目数和等待原因，支持停止等待；单个等待阶段最多 90 秒，整个任务最多 5 分钟。

右上角管理菜单「Telegram 配置」展示功能卡片，点击「Bot 配置」可填写 Bot Token、允许的聊天 ID、测试连接及启停消息接收。配置加密保存并立即应用，无需重启；留空 Token 会保留原值。Bot 配置只从网页读取。在 STRM 页面点击「保存生成设置」后，一条消息可发送多个分享链接，只处理允许的聊天。Bot 确认接收数量后按顺序逐条处理并回复结果，单条失败继续处理后续链接。同一消息中相同分享与提取码去重，重新发送仍会生成。完整说明及失败处理见 [转存再分享与 Telegram](docs/reshare.md)。

浏览器不支持所有 MKV、HEVC 或音频格式，此项目不做转码。不兼容的文件可交给 Emby 转码播放。生成 STRM 仅证明播放入口已创建，并不证明当前账户有权获得 115 直链。

右上角管理菜单「查看日志」可查看网页和 Telegram 发起的 STRM 生成、转存再分享日志，支持 ALL、INFO、DEBUG、ERROR、WARNING 等级筛选、关键词搜索及暂停更新。页面默认 INFO，显示消息批次数量与当前序号、遍历模式、115 分享链接（含实际提取码）、任务开始、输出目录、转存模式、固定密码匹配提示和目录分页；每成功写入 10 个文件记录数量进度，例如 `STRM 生成成功：10/100`、`20/100`，末尾不足 10 个也补齐最终数量。分母是本次筛选后计划生成的 STRM 数量。生成结束时以 INFO 显示成功与失败文件数、生成阶段耗时以及整项任务总耗时；中断时显示已扫描但未处理的文件数，不将尚未处理的文件算作失败。逐文件完整路径、详细执行阶段和过滤记录在 DEBUG；WARNING 保留取消、无匹配视频或遗留临时目录，ERROR 保留失败与超时。ALL 仍显示全部等级。页面每 2 秒刷新，保留本次后端运行期间最近 2,000 条日志，重启清空；转存任务检查点独立保存在 `data/cinema115.db`。日志接口需要管理员登录，按需显示分享链接及提取码，不记录 Cookie、Bot Token 或管理员登录凭证。

## 数据库

右上角管理菜单「Emby」进入 `/emby` 功能入口页，点击「媒体库同步」卡片打开 `/emby/library`，支持指定媒体库首次全量索引与 Webhook 后续更新，看板卡片和影视详情按 TMDB ID 显示入库状态。配置方法、事件验证与备份说明见 [Emby 入库索引](docs/emby.md)。

使用纯 Go SQLite，无需额外数据库服务。首次启动会事务导入旧 `data/reshare-jobs/*.json`，保留原文件备份；新任务只写 `data/cinema115.db`。账号配置和加密登录凭证沿用原存储。数据库随 `./data:/data` 挂载持久化；运行中备份使用镜像自带 `/app/dbtool`，不要只复制主 `.db` 文件。查询接口、迁移失败处理和恢复步骤见 [数据库迁移与备份](docs/database.md)。
